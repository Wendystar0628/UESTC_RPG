# ENG-GATES · 验收与门禁

> **范围**：测试三档与何时跑、12 项门禁各验什么（各文档文件头 `gates` 字段以这里的编号为准）、入口与交付分工。
> **不在本文**：审查视角、命令行规则与截图方式（ENG-GATES-SHOTS）；一票否决与收尾清单（ENG-GATES-VETO）；门禁命令、选域、缓存和阈值实现，以 `scripts/gate.ps1` 和 `scripts/gates/` 为准；各门禁的判据细则在对应系统文档的验收节；预算数值见 ENG-BUDGET。
> **查阅**：先读 §0；测试三档看 §1.1；门禁表看 §1.2；入口看 §1.3

## 0 结论

1. **门禁 12 项**（D-238、D-254），编号见 §1.2，删掉的不复用；文件头 `gates` 字段只用这些编号，全局不变量 INV-1 至 INV-12 不是门禁（§1）。
2. **测试分三档**（D-167、D-232）：快检（每次推送前，只有编译、受影响的测试、G4）、核心专项（碰到启动、行走、存档时）、集中测试（其余全部 G 项，阶段收尾由主会话发起，全量跑完统一修复）（§1.1）。
3. **统一入口 `scripts\gate.ps1 [-Paths <路径...>] [-BaseRef <基线>]`**：默认快检，按改动加核心专项（§1.3）。
4. **检查按 demo 阶段**：判据按数量级，日常每项几分钟内跑完，整图大样本只在阶段收尾跑（WF-RULE §15）。
5. **截图默认串只有一份**，在 ENG-GATES-SHOTS §1.1；**一票否决 23 条**，任一条即不通过（ENG-GATES-VETO §1）。

子文档：

- **ENG-GATES-SHOTS**（审查视角与截图）：截图、选视角、写命令行参数、排时季抽样时读。
- **ENG-GATES-VETO**（一票否决与收尾清单）：评审、集中测试、收尾时读。

### 0.1 接入要点

- **门禁或测试报出游戏代码的失败**：先按 ENG-FAILS 登记类别，再修（D-285）。
- **准备推送**：跑 `scripts\gate.ps1 [-Paths <路径...>] [-BaseRef <基线>]`，快检（编译、受影响的测试、G4）通过就推；碰启动、行走与碰撞、存档时加跑核心专项，专项失败按 WF-RULE §14 分级；其余 G 项留到集中测试（§1.1）
- **只改了 `docs/`、注释或说明文字**：不跑门禁；只想看效果：`--pose` 截几张自己看，不算门禁（§1.1）
- **交付门禁检查或测试接口**：接进 `scripts\gate.ps1` 这同一个入口（§1.3）

## 1 门禁与测试节奏

门禁编号以本文为准。命令、选域、缓存和阈值实现在 `scripts/gate.ps1` 与 `scripts/gates/`。

### 1.1 测试三档


| 档 | 什么时候跑 | 跑什么 |
| --- | --- | --- |
| 快检 | 每次推送前，由指挥统一编译后跑（WF-FLOW §3.1） | 只有三项：编译（含分析器）、按改动选出的受影响测试（G2）、G4 架构检查 |
| 核心专项 | 改动碰到核心体验时，一段工作做完、准备推送时跑一次 | 只有三类：启动与进出（G5 核心范围）；行走不穿地、不掉出世界（G15 路线加改到区域撒点与入树检查，改游泳或身体时加对应项）；存档不丢不坏（G20 往返、损坏、退出时保存） |
| 集中测试 | 阶段收尾由主会话发起，全量跑完、统一修复；主线闸口通过后和收尾前各至少一次 | 其余各项（G3、G5 注册检查、G6、G7 的季节与预设出图、G10、G14、G21、`--import` 日志），同时做风格评审 |

- **阈值按数量级看**：门禁里预算、数量、精度这类阈值超了，实测仍在同一量级又不挡核心体验的，记为已知问题照常推送，阈值按实测调（WF-RULE §15）。
- **按改动选**：gate.ps1 比对 `origin/main`，只取自己的路径；G2 按改动所在的模块挑测试（命名空间过滤），契约改动才全跑。
- **专项失败**按 WF-RULE §7 处理，不挡推送的登记即可。整图专项（整图撒点、整图往返）只在阶段收尾跑。
- **不静默放过**（D-244）：有改动却选出 0 项门禁或 0 个测试，算未完成，不算通过；共用夹具改了，带上使用它的测试；容差与样本量只在共用测试规则常量里（STD-CODE §6），时间预算只在本文，别处引用。
- **时间预算**（D-246）：快检里单个测试不超过 2 s，超过的标 `Slow`，只在阶段收尾的集中测试里跑，平时不跑；核心专项每项几分钟内跑完。门禁记下每个测试的耗时与结果（只留最近一段），快检里超时的由巡逻列出。
- **增长预算**：测试代码不超过生产代码的四成；一次提交新增的测试代码不超过生产新增的一半（提交后钩子提示）；巡逻按周比对测试个数与代码量，超出就提示精简。
- **定期削减**：集中测试时列出长期没失败过又慢的、与别的测试守同一件事的，由主会话决定删。
- **按依赖选**：改了公共层（契约、平面几何、分区公共工具、共用测试夹具），带上依赖它的全部测试。
- **测试只锁本包输出**（D-199）：可以锁本包产物和"原有条目的字节与顺序不变"；不锁别的包会合法增减的全局集合或指纹，跨包不变量写成按 id 核对的规则。
- **G5 范围**：完整 G5 只在主线最终闸口要求，局部证据不标"完整 G5 通过"。
- **集中测试发现的问题**：按回报格式登记，主会话按"核心体验优先"排序后分派，按提交定位引入的包。
- **看画面**：改了看得见的东西，施工方在回报或【知会】里注明一句；推送后怎么看见 ENG-GATES-SHOTS §1.3。集中测试时主会话只看固定机位总览一份，风格负责人看英雄帧，声音听评可由同一人或另一个子代理担任。

### 1.2 门禁表

只有下面 12 项（D-238、D-254）；G8、G9、G11–G13、G16–G19 的编号不再使用，也不复用。

| 门禁 | 验什么 | 档 |
| --- | --- | --- |
| G1 类型 | 编译警告当错误（含非穷举 `switch`）、命名与格式；导入日志无 ERROR | 快检（编译）；集中测试（导入日志） |
| G2 单元测试 | 纯 .NET 与引擎内单测，测行为；类别标签与写法见 STD-CODE §6 | 快检（受影响模块）；集中测试（全部） |
| G3 归属 | 改动文件在文档文件头的 `paths` 中有归属；当前 Git 源码（含未跟踪但非忽略的新源码）的 `.uid` 齐全且不重复；构建产物及其本地 UID 不纳入入库检查 | 集中测试 |
| G4 边界 | 命名空间依赖方向、禁用 API、创建权与读写权、着色器白名单、自有生产手写代码的类型合计约 600 行与方法约 80 行规模（STD-CODE §5）、新文件放置与补丁式命名（WF-RULE §16）、补丁式代码（STD-CODE §4；规则在 `scripts/gates/arch/` 与各程序集的 `BannedSymbols.txt`，ENG-ARCH §2） | 快检 |
| G5 注册与启动进出 | 无界面注册检查（模块与 ID、认领、调色板、世界文件、存档段）；启动核心 = Boot → Title → 新游戏 → 关窗口退出不报错 | 核心专项（启动核心）；集中测试（注册检查） |
| G6 构建 | 导出 release 能跑；报安装目录与压缩包体积，按数量级判断与内容相称（D-125）；素材与代码许可已登记 | 集中测试 |
| G7 固定机位 | `scripts/shots/poses.txt` 出图拼总览，看一眼：比例、收边、不死黑、`--ui=0` 只剩 3D 画面；集中测试时再加每季一张、三个预设各拍一次总览 | 碰画面的推送后由主会话跑；集中测试 |
| G10 性能 | 导出 release，在几个固定机位测帧时与存档、关闭耗时，前后对比明显变慢再查；帧时目标见 `budgets.json` 的 `deviceTargets`、`frameStutter` | 集中测试 |
| G14 界面 | 键盘能走完全程、减少动态效果生效、3D 里没有标签与地图元素 | 集中测试，看一眼 |
| G15 行走与碰撞 | SYS-WALK-BOUNDS §7：固定路线走一遍，加改到区域附近撒点走跑跳，不穿透、不掉出、卡住不超过 3 s；传送落点；自动门 | 核心专项；整图撒点在集中测试 |
| G20 存档 | SYS-SAVE-FORMAT §1.4、§2：往返（判据只在 SYS-SAVE-FORMAT §1.4）、损坏退回上一代、三代全坏只能新游戏、退出时保存 | 核心专项 |
| G21 声音 | SYS-AUDIO §10，显式 `--audio=on`：素材许可登记、一次听评 | 集中测试 |

### 1.3 入口与交付分工

入口 `scripts\gate.ps1 [-Paths <路径...>] [-BaseRef <基线>]`：默认跑快检，改动碰到核心体验时加核心专项；`-Smoke` 只跑主线冒烟；`-Full` 跑集中测试全量；`-Only G7,G10` 只跑指定门禁；入口先核对引擎版本，要显卡的门禁经构建锁一次只跑一个（WF-BUILD §4）。
