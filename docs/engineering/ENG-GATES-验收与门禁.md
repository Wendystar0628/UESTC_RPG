# ENG-GATES · 验收：测试三档与门禁 G1–G21

> **范围**：测试三档与何时跑、门禁 G1–G21 各验什么（各文档文件头 `gates` 字段以这里的编号为准）、入口与交付分工。
> **不在本文**：审查视角、命令行规则与截图方式（ENG-GATES-SHOTS）；一票否决与收尾清单（ENG-GATES-VETO）；门禁命令、选域、缓存和阈值实现，以 `scripts/gate.ps1` 和 `scripts/gates/` 为准；各门禁的判据细则在对应系统文档的验收节；预算数值见 ENG-BUDGET；工作包分工见 ENG-WP。
> **查阅**：先读 §0；测试三档看 §1.1；G1–G10 看 §1.2；G11–G21 看 §1.3；入口看 §1.4

## 0 结论

1. **门禁共 G1–G21**，子项写作 G19a、G21b；文件头 `gates` 字段只用这些编号，全局不变量 INV-1 至 INV-12 不是门禁（§1）。
2. **测试分三档**（D-167）：快检（每次推送前）、核心专项（碰到启动、行走、存档时）、集中测试（大量开发后由主代理发起，全量跑完统一修复）（§1.1）。
3. **统一入口 `scripts\gate.ps1 -Wp WP-xx`**：默认快检，按改动加核心专项；只改 `docs/`、注释时不跑（§1.4）。
4. **检查按 demo 阶段**：判据按数量级，日常每项几分钟内跑完，整图大样本只在阶段收尾跑（WF-RULE §15）。
5. **截图默认串只有一份**，在 ENG-GATES-SHOTS §1.1；**一票否决 24 条**，任一条即不通过（ENG-GATES-VETO §1）。

子文档：

- **ENG-GATES-SHOTS**（审查视角与截图）：截图、选视角、写命令行参数、排时季抽样时读。
- **ENG-GATES-VETO**（一票否决与收尾清单）：评审、集中测试、收尾时读。

### 0.1 接入要点

- **准备推送**：跑 `scripts\gate.ps1 -Wp WP-xx`，快检必须通过；碰启动、行走与碰撞、存档时加跑核心专项；其余留到集中测试（§1.1）
- **只改了 `docs/`、注释或说明文字**：不跑门禁；只想看效果：`--pose` 截几张自己看，不算门禁（§1.1）
- **交付门禁检查或测试接口**：接进 `scripts\gate.ps1` 这同一个入口（§1.4）

## 1 门禁与测试节奏

门禁编号以本文为准。命令、选域、缓存和阈值实现在 `scripts/gate.ps1` 与 `scripts/gates/`。

### 1.1 测试三档


| 档 | 什么时候跑 | 跑什么 |
| --- | --- | --- |
| 快检 | 每次推送前，由指挥统一编译后跑（WF-FLOW §3.1） | 编译（含 G4 分析器）、受影响程序集的单元测试、归属检查；内核、契约、注册声明或地图数据受影响时加 G5 无界面注册检查；资源有变化时加 `--import` |
| 核心专项 | 改动碰到核心体验时，一段工作做完、准备推送时跑一次 | 只有三类：启动与进出（G5 核心范围）；行走不穿地、不掉出世界（G15 路线加改到区域撒点与入树检查，改游泳或身体时加对应项）；存档不丢不坏（G20 往返、损坏、退出时保存） |
| 集中测试 | 大量开发后由主代理发起，全量跑完、统一修复；主线闸口通过后和收尾前各至少一次 | 全部门禁全量，同时做风格评审和预算归因 |

- **阈值按数量级看**：门禁里预算、数量、精度这类阈值超了，实测仍在同一量级又不挡核心体验的，记为已知问题照常推送，阈值按实测调（WF-RULE §15）。
- **按改动选**：gate.ps1 比对 `origin/main`，只取自己的路径；只改 `docs/`、注释或与运行无关的说明文字时不跑任何门禁。
- **测试只锁本包输出**（D-199）：可以锁本包产物和"原有条目的字节与顺序不变"；不锁别的包会合法增减的全局集合或指纹，跨包不变量写成按 id 核对的规则。
- **不重复测没变的东西**：输入、依赖、工具链与选项未变，复用上次通过的快检结果；显式 Full、窗口、截图和导出每次执行；失败后有改动才重跑（CORE-INDEX §0）。
- **G5 范围**：碰到启动的包推送时按"启动与进出核心范围"验收；完整 G5 只在主线最终闸口要求，局部证据不标"完整 G5 通过"。
- **集中测试发现的问题**：按回报格式登记，主代理按"核心体验优先"排序后分派，按提交定位引入的包。
- **看画面**：改了看得见的东西，施工方在回报或【知会】里注明一句；主会话推送后跑 `scripts/shots/fixed_shots.ps1`，看一眼总览，不做像素比对、不立基线。
- **集中测试的看图与听评**：主代理看覆盖层差异、预算归因、巡检评分三份报告；风格负责人给联表打分并评审英雄帧，声音听评（G21h）可由同一人或另一个子代理担任。

### 1.4 入口与交付分工

入口 `scripts\gate.ps1 -Wp WP-xx`：默认跑快检，改动碰到核心体验时加核心专项；`-Smoke` 只跑主线冒烟；`-Full` 跑集中测试全量；`-Only G7,G9` 只跑指定门禁；入口先核对引擎版本，要显卡的门禁经构建锁一次只跑一个（WF-BUILD §4）。

各检查器与测试的交付分工见 ENG-WP；全部由 WP-27 接进同一个入口。
