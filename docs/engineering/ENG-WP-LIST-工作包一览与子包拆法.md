# ENG-WP-LIST · 工作包一览与子包拆法

> **范围**：本文列出每个工作包一行：规格文档、依赖、阶段、主线版交什么，三个插入项，主线闸口之后的细节待办与候选包，以及子包拆法。
> **不在本文**：阶段与闸口、开工波次与推送顺序、主代理工程维护、待验证：ENG-WP；独占目录以 `ownership.json` 为准；施工状态见 WF-STATUS；额度见 ENG-BUDGET §3。
> **查阅**：先读 §0；各包一行看 §1；插入项看 §1.1；闸口之后的细节待办看 §1.2；候选包看 §1.3；子包拆法看 §2
> **读者**：子代理只读本包在包表里的那一行和派工简报，用 `grep "^| WP-xx "` 取；主代理派工和排细节时读全文。

## 0 结论

1. 包表每包一行：规格文档、依赖、阶段、主线版交什么；独占目录看 `ownership.json`，状态看 WF-STATUS（ENG-WP-LIST §1）。
2. 玩家身体与游泳、共享单车是插入项，各有前提和排期（§1.1）。
3. 细节待办在主线闸口通过后排期，不影响主线版；候选包不占 WP 编号，定下归属后才进包表（§1.2、§1.3）。
4. 拆出的子包共用原包的目录和程序集，各自独占其中一个子目录，沿用原包的行（§2）。

### 0.1 接入要点

- **开工时**：看本包在包表里的行和派工简报；主责的文档（文件头 `owners` 里有本包）读熟它的 §0 和本包负责的小节；改文件的边界与契约申请见 WF-BUILD §1（§1）
- **做拆出的子包**：沿用原包的行，只独占其中一个子目录（§2）

### 1.2 细节阶段待办

主线闸口通过后排期，不影响主线版。格式：牵头包：做什么（协作包）。

- WP-01：以 GitHub 整包发布前（D-181），用没装开发环境的账户走通导出包的安装、退出、更新继续与回到旧版（OPS-RELEASE）；发版说明写明删除 `settings.json` 即恢复画面设置（SYS-GRAPHICS §6）。
- WP-06：横向、纵向各自的灵敏度与反转选项（WP-35b）。
- WP-07：先做地面、地垫、自动门、走廊的材料、遮挡与声音反馈，再扩到其他类别（WP-42、43、53c、53d、13、52、室内包）。
- WP-08：15 处开放室内都在，逐处兑现（WP-44、36、48c、17、31a–c、51、52、27）。

## 2 子包拆法

拆分后的子包共用原包的目录和程序集（不新建 csproj），各自独占其中一个子目录；原包的额度按面积比例分，WP-32、WP-45 按职责分。例外：WP-51 的 51a、51b 和 WP-53 的 53b、53c 各有自己的 gen 程序集，由 WP-00 在 D0 建好；WP-31 的三个子包按楼内视角额度各自核算。子包之间只经契约、数据格式或约定接口交接，先定格式的一方先交。
