# ENG-PERF-STREAM · 流式加载、本机烘焙与内存

> **范围**：本机烘焙、缓存与加载（§1.1）；帧内请求、挂载与六条不变量（§1.2）；碰撞级与室内包（§1.3）；外围与目的地预取的做法（§1.4）；主线程与 C#（§2）；内存与显存（§3）；安装包与磁盘布局（§4）。
> **不在本文**：速度律、格上限与预取规则的数值（ENG-BUDGET-LOD §1、§2）；容器、着色器、剔除（ENG-PERF）；植被与阴影（ENG-PERF-LIGHT）；自适应与测量（ENG-PERF-ADAPT）。
> **查阅**：先读 §0；本机烘焙与加载看 §1.1；不变量看 §1.2；零分配看 §2；内存看 §3

## 0 结论

1. **主线程只挂载，不生成**：几何烘焙成 TileBundle，发布版随包附全图缓存（ENG-ARCH §4），缺失时在工作线程本机补烘；画面可见时每帧最多激活 1 格、主线程 ≤ 1.0 ms，整屏盖住时放开（§1.1、§1.2）。
2. **绝不卡帧、不穿地靠六条不变量**：常驻 L4 与外围 O2、父格等子格就绪再切、字节 LRU、看门狗、碰撞未就绪就冻结物理、楼体至少显示 I0（§1.2）。
3. **目的地已知的移动**不靠速度外推，直接把目的地各环、室内包与碰撞格插到队列前面（§1.4）。
4. **逐帧路径零分配**；内核按格自记显存与内存账（§2–§3）。

### 0.1 接入要点

- **生成几何或碰撞**：确定性 `Build()`，不读世界状态和画面设置；主线程只挂载；碰撞数据入树前加完全部形状（§1.1、§1.3）
- **逐帧代码**：零分配，不用 LINQ、闭包、装箱、字符串拼接，参数名缓存成 `StringName`，批量调引擎 API（§2）
- **新增烘焙产物或缓存类别**：按格烘、按格判鲜（ENG-ARCH §4）；进全图预烘与随包缓存，不进启动集（§1.1、§4）

## 1 流式加载

### 1.1 本机烘焙、缓存与加载

- **烘焙与随包**：烘什么、随包发、查找顺序、判鲜和格式都在 ENG-ARCH §4；缺失或损坏时由同一个 `Build()` 在工作线程本机补烘，存成 `.tbin` 写进本机缓存。
- **加载**：`res://` 资源用 `LoadThreadedRequest`（无优先级、无取消，队列主线程自管）；缓存由工作线程读入、校验、建 GPU 资源。
- **缓存**：`Build()` 无世界状态与画面设置输入，所以缓存跨存档跨画质共用；容量上限与淘汰顺序见 `budgets.json` 的 `cache`。读坏的处理见 ENG-ARCH §4；格的烘焙、挂载、室内、渲染与碰撞任何一处出异常，都由地图运行时轮询汇入同一个加载故障（查询故障不带副作用），转到不依赖三维世界的失败页；不阻塞画面的请求显示最近已就绪祖先；连续 60 s 无进展才按停滞处理。
- **补烘时机**（缓存缺失时）：扉页期间先烘起始视角周围与平面地图底图；开始页起后台把全图各级、室内与碰撞补齐；按需请求排在最前，队列顺序：碰撞 → 已知目的地 → 室内入口预取 → 常规。
- 切图先卸后装，显存峰值是"最大一张图 + 全局常驻"。录像、读档、切图时流式管理器改同步（含现烘），格全部挂载完再推进，结果才能复现。

### 1.2 帧内请求、挂载与六条不变量

帧内顺序以 `game/contracts/Runtime/World/WorldContracts.cs` 的 `FramePriority` 为准；画面可见时每帧最多激活 1 格、主线程 ≤ 1.0 ms；被扉页或加载界面整屏盖住时不受这两条限制，多格连续挂载，只给盖住的界面留出刷新余量，限额只为可见时不卡帧而设（D-260）；新挂上的块淡入（时长以 `FrameClock` 为准）。L0、L1 按 360° 环带加载（旁观可 0.3 s 转身）。

**绝不卡帧、不穿地的六条不变量**：

1. 当前图的 L4 与外围 O2 常驻块常驻，不参与淘汰。
2. 父格要等 4 个子格都"已加载、已挂载"才切换可见性；缺 L0 时显示最近已就绪祖先。
3. 按字节 LRU 淘汰，最细级优先，正在显示的祖先不淘汰。
4. 看门狗：连续 3 帧挂载超预算 2 倍，激活预算减半并暂停 250 ms。
5. 行走时角色所在格及 8 邻格的碰撞未就绪就冻结物理，宁可停住也不用粗数据先走。
6. 镜头在任何楼体里至少显示这栋楼的 I0 兜底层；行走要跨进的开放楼层 IF 与碰撞未就绪，就在门槛前 1 m 软停（WLD-INTERIORS-BUILD §1.3）。

### 1.3 碰撞级与室内包

碰撞级 C 与渲染级别无关，只按步行需求加载；碰撞作为 Collision 参与者进入唯一流式导演和挂载队列，按完整 body 切片推进，预算以 `KernelBudgets` 为准；body 入树前加完全部形状（Jolt 对已在空间里的 body 逐个加形状是 O(n²)），整屏盖住时仍共用加载界面刷新份额（§1.2）。室内包整体加载、按层显示，切换只改可见性；行走时离开放入口 ≤ 25 m 预取（WLD-INTERIORS-BUILD §1）。开放楼层的 `FloorY` 与 `Height` 以提供者的 `InteriorLayout.Storeys` 为准，随室内 resident 元数据保存；加载预备阶段一次发布到冻结室内索引，热命中只恢复布局，不重新生成平面或编译地形。

### 1.4 外围与目的地预取

外围 O2 常驻，O1 流式并与校内共用挂载预算，外围没有碰撞。路径已知的移动（点位跳转、传送、旁观切行走的降落、读档、切图、标题页转实时、新游戏）不靠速度外推，规则与到达保证以 ENG-BUDGET-LOD §2 为准；做法是把目的地的各环、室内包与碰撞格插到常规队列之前，跳转被打断时删掉旧目的地未发出的请求。

## 2 主线程与 C#

- 节点的 `ProcessPriority` 定顺序；界面直接读源，不采样不缓存；`*Module.cs`（gen 里，纯函数）与 `*Node.cs`（主线程）分开。主线程份额见 `KernelBudgets.cs`。
- **零分配**：逐帧路径不 `new` 引用类型、不用 LINQ、闭包、装箱、字符串拼接；参数名缓存成 `StringName`；`Godot.Collections` 每次跨边界都封送，热路径不用；调引擎 API 一律批量。
- **GC**：F1 一圈不出现可见卡顿（GC 单次暂停 ≲ 5 ms）。线程边界见 ENG-BUDGET-RULES §1 第 16 条。

## 3 内存与显存

显存与进程内存不设逐项静态上限（ENG-BUDGET §2）。内核按格自己记字节账，每帧用 `Performance` 总量复核，报警口径同 ENG-BUDGET §4；显存总量经 DXGI 查询（SYS-GRAPHICS），逼近预算时先收紧 LRU 字节上限，再按 ENG-PERF-ADAPT §1.1 降级。格子只释放自己的实例与 TileBundle，共享材质、图集、数据纹理归创建方与登记处。不泄漏：F1 跑两圈，显存与实例数不持续上涨，编译计数不变；同图重载 3 次同理（SYS-MAPS §3.5）。

## 4 安装包与磁盘布局

安装包由主 PCK、.NET 运行时和全图烘焙缓存组成，不设体积上限，导出时按数量级判断与内容相称（D-125）；没有各图启动集（ENG-ARCH §4）。启动顺序见 SYS-TITLE §1。
