# ENG-PERF-MEASURE · 测量与调优

> **范围**：性能怎么测与怎么调：机器与剖析权限（§1）、AI 采集批次（§2）、以最新数据为准（§3）、诊断档（§4）、不采用的工具（§5）、调优规则与判停（§6）。
> **不在本文**：数据格式、指标口径、异常判据与保留（ENG-PERF-DATA）；预算与目标数值（ENG-BUDGET）；门禁判据与命令行（ENG-GATES、ENG-GATES-SHOTS）；自适应与帧节奏（ENG-PERF-ADAPT）。
> **查阅**：先读 §0；机器与权限看 §1；AI 批次看 §2；引用数据看 §3；诊断档看 §4；不采用的工具看 §5；调优看 §6

## 0 结论

1. **引用性能数前先取最新**：先跑 `perf.py latest`，只用同比较键、同口径、有效且不过时的数据；作者游玩数据不作 A/B 基线（§3，DECISION-336）。
2. **AI 只经一个入口采集**：`scripts/perf/run.ps1`，在隔离桌面里跑固定机位套、路线套、传送套；不建吞吐模式（§2，DECISION-334）。
3. **隔离桌面只判成本**：体验类只来自作者自己开着记录的游玩会话，不排作者录制（§2，DECISION-331）。
4. **准备与采样分开**：就绪后先做采样前稳定，每场景重复取中位，改动按 A/B/A，读回不符即作废（§2）。
5. **诊断档按 `deepen` 开**：带采集条件标记，不进基线（§4，DECISION-335）。
6. **调优按轮**：第 0 轮标定、至多 3 轮调优，只按成本口径，按判停收尾（§6，DECISION-339）。
7. **剖析不提权**（§1，DECISION-323）。

### 0.1 接入要点

- **引用性能数或定调优方向**：先跑 `python -I -X utf8 scripts/perf/perf.py latest`；只经 `perf.py` 读性能数据，不打开逐帧原始文件；引用写会话 ID（§3）。
- **为性能采集写脚本或加场景**：只经 `run.ps1` 与它的场景计划，不另起采集入口与数据格式（§2）。
- **比较改动前后**：按 A/B/A，基线是同批 A 运行，不拿别批的最新数据或作者会话当基线（§2、§3）。
- **在隔离桌面里看到帧率、帧间隔或卡顿**：不据此判体验，只判成本（§2）。
- **开诊断工具**：按分析器的 `deepen` 条目开，诊断运行不进基线与常规均值（§4）。

## 1 机器与剖析权限

成本、回归与份额核算在开发机上测，剖析在普通权限的后台进程里做，不提权（DECISION-323）。

## 2 AI 批次

- **隔离桌面**：`run.ps1` 在已登录会话里另建的不可见桌面上起游戏，不操作作者桌面。那里的帧间隔被外部节奏钉住、GPU 占用偏低，所以帧率、帧间隔分位、low、掉帧、卡顿、帧节奏、加载时长与 GPU 占用都不作判断，只判成本口径（ENG-PERF-DATA §3.2、§4）；不追帧间隔被钉住的成因（DECISION-331）。
- **入口**：`scripts/perf/run.ps1` 是 AI 采集的唯一入口，复用构建锁、独立 profile、隔离桌面与正式退出；冻结本批条件，`--perf-out` 指向 `output/perf/runs/<行号-主题>/<a1|b1|a2>/`，写 `run.json`，跑完调分析器。不建吞吐模式：成本口径不需要它。
- **场景套**（场景计划在 `scripts/perf`，只引地图数据的编号）：
  - 固定机位套：几个固定点位的默认状态与夏夜雷雨，流逝暂停、静置采样；另含开放室内门厅朝外、行走贴地与新游戏落地位姿（ENG-BUDGET §2、§4）。回答渲染成本与回归。
  - 路线套：行走与旁观持续移动各一条，起点经一次实走确认后冻结。回答移动中的挂载、GC、编译与渲染 CPU 尖峰。
  - 传送套：`travel-sequence` 的少量已验证点。回答到达尖峰、挂载与等待边界。
- **采样前稳定**：准备与采样分开；真实就绪、流式排空、管线编译计数连续若干帧不增、进入实时满规定时长、GPU 处于最高性能状态（NVML P0）后才起录；帧数与时长见 `run.ps1` 的常量。
- **重复与 A/B/A**：每场景按 `run.ps1` 规定的次数重复、取中位（DECISION-334）；改动按 A/B/A，改动前跑 A、改动后跑 B、再回 A。A/B/A 只指运行协议，不指场景套。
- **作废**：请求起点与实际落点、模式、轨迹不符的运行作废；首轮采样出现管线编译增量的运行作废重跑；协议不完整的不进比较。作废的原始数据与原因都保留。
- **未完成与污染**：非零退出与超时强杀的运行保留原始数据，标未完成；受污染的运行保留污染标记。
- **启动测量**：启动目标的体验测量不开诊断档（EventPipe、`--gpu-profile`、Nsight）；性能记录开着时照常计时（DECISION-256，开销目标见 ENG-PERF-DATA §7）。

## 3 以最新为准

- **先取最新**：引用性能数或定调优方向前，先跑 `perf.py latest`；只用同比较键、同 `calc`、同口径、状态有效且不过时的当前数据（比较键与状态见 ENG-PERF-DATA §6）；过时的先重测。
- **只经 `perf.py` 读**：用它的 `latest`、`show`、`compare`、`slice`、`anomalies`，不打开逐帧原始文件；比较键不同的差异不下结论。
- **基线**：作者游玩数据用来定位问题、作体验证据，不作 A/B 基线；A/B 的基线是同批 A 运行。
- **引用**：写会话 ID，文档不抄测得的数；新数据推翻旧结论时，旧结论当场作废。

## 4 诊断档与 `deepen`

分析器对反复出现、无事件原因的异常写 `deepen` 条目，AI 按它开诊断档重跑（`--gpu-profile`、本机 `dotnet-trace`、Nsight）；诊断运行各带采集条件标记，不进基线，只记诊断与常规的比值（DECISION-335）。

## 5 不采用的工具

不往游戏里接进程内剖析器与逐系统打点，不做关记录时的黑匣子；PresentMon 不进诊断档（DECISION-335）。

## 6 调优规则与判停

体系建成后做第 0 轮标定与至多 3 轮调优，只按成本口径；每轮先取最新数据，改动按 A/B/A，任一判停条件成立就停，不加第 4 轮（DECISION-339）。
