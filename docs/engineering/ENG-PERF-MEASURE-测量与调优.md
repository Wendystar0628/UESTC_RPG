# ENG-PERF-MEASURE · 测量与调优

> **范围**：性能怎么测与怎么调：机器与剖析权限（§1）、AI 采集（§2）、以最新数据为准（§3）、诊断（§4）、不采用的工具（§5）、调优（§6）。
> **不在本文**：数据格式、指标口径、索引与保留（ENG-PERF-DATA）；预算与目标数值（ENG-BUDGET）；门禁判据与命令行（ENG-GATES、ENG-GATES-SHOTS）；自适应与帧节奏（ENG-PERF-ADAPT）。
> **查阅**：先读 §0；机器与权限看 §1；AI 采集看 §2；引用数据看 §3；诊断看 §4；不采用的工具看 §5；调优看 §6

## 0 结论

1. **引用性能数前先取最新**：先跑 `perf.py latest`，用各场景最新一次 AI 采集与它和上一次的差；作者游玩数据不作比较基线（§3，DECISION-336）。
2. **AI 只经一个入口采集**：`scripts/perf/run.ps1`，在固定提交的临时工作树里跑，隔离桌面上固定机位套、路线套、传送套每场景采一遍；主检出照常提交；不建吞吐模式（§2，DECISION-334、DECISION-354）。
3. **隔离桌面只判成本**：体验类只来自作者自己开着记录的游玩会话，不排作者录制（§2，DECISION-331）。
4. **诊断按需用现成工具**：根因不明时跑一个场景加一种工具查出处，不登记、不比基线（§4，DECISION-359）。
5. **调优由作者派任务开始**：每改一批采一遍和上一次比，进入预算线内且没有明显痛点就停（§6，DECISION-339、DECISION-348）。
6. **剖析不提权**（§1，DECISION-323）。

### 0.1 接入要点

- **引用性能数或定调优方向**：先跑 `python -I -X utf8 scripts/perf/perf.py latest`；只经 `perf.py` 读性能数据，不打开逐帧原始文件；引用写会话 ID（§3）。
- **为性能采集写脚本或加场景**：只经 `run.ps1` 与它的场景计划（`scenarios.json`），不另起采集入口与数据格式（§2）。
- **比较改动前后**：改前改后各采一遍，看 `perf.py` 给的差值与变化比例，按数量级判断；不拿作者会话当基线（§3）。
- **在隔离桌面里看到帧率、帧间隔或卡顿**：不据此判体验，只看成本（§2）。
- **查根因**：根因不明才用 `run.ps1 -Scene <场景> -DiagnosticTool <工具>`，结果只用来定改法（§4）。

## 1 机器与剖析权限

成本、回归与份额核算在开发机上测，剖析在普通权限的后台进程里做，不提权（DECISION-323）。

- **机器**：开发机（RTX 4080），`--gpu-index` 选卡；不设中档参考机（ENG-BUDGET §4）。
- **剖析权限**：开发机的 GPU 性能计数器对所有用户开放，Nsight 逐绘制抓帧与硬件计数器在普通权限的后台进程里跑，不以管理员身份启动代理会话；上屏帧率与帧间隔（PresentMon）要另给权限，只在体感卡而帧时正常、或验收稳帧时由作者手动开，不进体系。
- **运行条件**：从项目运行、窗口模式；命令行与截图默认串以 ENG-GATES-SHOTS §1 为准，画质只由命令行决定、不读 `user://`（ENG-GATES-SHOTS §1.1）；AI 采集按 §2 以无边框全屏开 3840×2160，不沿用那里的默认尺寸；测量时自动调节关闭；叠加层与录屏关掉，因为它们改变帧时序。
- **构建配置**：作者启动与测量用 Debug 程序集，CPU 数偏悲观；不同构建配置的数不互比。

## 2 AI 采集

- **隔离桌面**：`run.ps1` 在已登录会话里另建的不可见桌面上起游戏，不操作作者桌面。那里的帧间隔被外部节奏钉住、GPU 占用偏低，所以帧率、帧间隔分位、low、掉帧、卡顿、帧节奏与 GPU 占用都不判体验，只看成本口径（ENG-PERF-DATA §3.2、§4）；不追帧间隔被钉住的成因（DECISION-331）。
- **固定提交的临时工作树**：采集与诊断只在 detached 到选定提交的临时 Git 工作树里跑，`run.ps1` 拒绝在主检出或挂着分支的树上跑；原始数据与派生写回主检出的 `output/perf`。采集期间主检出照常提交、推送。
- **入口**：`run.ps1 -Batch <来源名> [-Suite fixed|route|travel] [-Scene <场景>]` 是 AI 采集的唯一入口，复用构建锁、独立 profile、隔离桌面与正式退出；来源名要新起，已有数据保留不覆盖；每场景一个目录、写 `run.json`，跑完调分析器并打印 `perf.py latest`。不建吞吐模式：成本口径不需要它。
- **场景套**（场景计划在 `scripts/perf/scenarios.json`，只引地图数据的编号）：
  - 固定机位套：几个固定点位的默认状态与夏夜雷雨，流逝暂停、静置采样；另含开放室内门厅朝外、行走贴地与新游戏落地位姿（ENG-BUDGET §2、§4）。回答渲染成本与回归。
  - 路线套：行走与旁观各一条多段路线，跨多个流式格与细节环，行走那条进一栋开放楼。回答移动中的挂载、GC、编译与渲染 CPU 尖峰。
  - 传送套：`travel-sequence` 的少量已验证点，分有预取与直接下令两种。回答到达尖峰、挂载与等待。
- **采集条件**：隔离桌面上以无边框全屏（非独占）渲染到预算分辨率，画质与世界条件只经命令行参数设置，不碰设置文件（DECISION-353）。
- **缓存同版**：采集树的烘焙缓存要与所采提交同版；切到改过烘焙输入（ENG-ARCH §4）的提交后带 `-PrepareBake` 采，否则运行时补烘的分配、GC 与挂载会算进样本，这组数据作废。
- **采样段**：游戏到真实就绪（进入游玩、镜头转场结束、加载界面撤下）后起采样段，每场景采一遍；时长见场景计划。
- **启动测量**：启动目标的体验测量不带诊断工具（EventPipe、`--gpu-profile`、Nsight）；性能记录开着时照常计时（DECISION-256，开销目标见 ENG-PERF-DATA §7）。

## 3 以最新为准

- **先取最新**：引用性能数或定调优方向前，先跑 `perf.py latest`：按场景列最新一次 AI 会话的指标、上一次的值、差值与变化比例，以及预算线与等待；`--origin play` 列作者会话。提示口径不符时先跑 `analyze.py`。
- **只经 `perf.py` 读**：`latest [--scene <场景>]`、`show <会话>`、`compare <前> <后>`（只比同场景、同来源），不打开逐帧原始文件。
- **基线**：作者游玩数据用来定位问题、作体验证据，不作比较基线。
- **引用**：写会话 ID，文档不抄测得的数；新数据推翻旧结论时，旧结论当场改掉。

## 4 诊断

采集回答哪里慢、慢多少；诊断只在要定改法而根因不明时，用现成工具查是哪段代码或哪个渲染步骤（DECISION-359）。开不开、用哪个，由 AI 看指标、预算线与痛点定，分析器不生成诊断条目。

- **入口**：`run.ps1 -Scene <场景> -DiagnosticTool <gpu-profile|EventPipe|Nsight>`，跑一个场景加一种工具，产物放诊断目录并打印摘要；不登记、不进记录、不和基线比、不判有效、不去重。
- **`--gpu-profile`**：游戏内逐步骤 GPU 耗时，用来排序哪个渲染步骤贵，不当绝对值。
- **EventPipe**：本机 `dotnet-trace` 附着游戏进程，解析器在 `scripts/perf/cpu`；收集器要在游戏还活着时停下，方法名才解析得出，所以游戏在样段结束后等收集器停完再退出；样本是墙钟栈采样，占比不写成 CPU 利用率。
- **Nsight**：普通权限（§1）抓 GPU 帧，只看相对占比。
- **结果**：看得懂就用；不完整（比如方法名没解析出来）就换工具或重跑，不为它建判据。
- **不常开**：常规批次、门禁与启动目标的体验测量都不带诊断工具（§2）。

## 5 不采用的工具

不往游戏里接进程内剖析器与逐系统打点，不做关记录时的黑匣子；PresentMon 不用（作者定）。

- **Tracy、Perfetto**：要自己编引擎，锁定的官方二进制用不上。
- **Optick**：只支持 C++。
- **`Performance.AddCustomMonitor`、`EngineProfiler`**：只在连着调试器时生效，且走 Variant，不适合常驻记录。
- **GPU 引擎计数器加密轮询**：每读一次就是毫秒级，逐帧 GPU 计时与 NVML 驱动样本已经覆盖。
- **`GetThreadTimes`**：分辨率远粗于一帧。
- **逐帧 `QueryProcessCycleTime`**：线程多时每次调用超出逐帧开销目标，进程 CPU 只按慢采样记。
- **ETW 与 WPR 环形会话**：要管理员，与 §1 冲突。
- **逐系统打点**：要在各属主处逐个加计时，EventPipe 的栈采样不改代码就能定位到方法。
- **进程内 `EventListener`**：在派发线程上持续分配，帧级精度已经够用。
- **黑匣子**（记录关着时常开内存环、卡顿时落盘）：违背记录开关只管记不记的语义（ENG-PERF-DATA §1.2）。
- **PresentMon**：要另给权限，只按 §1 由作者手动用。

## 6 调优

调优由作者派任务开始；合理区间、停线与明显痛点的线以 `budgets.json` 为准（DECISION-339、DECISION-348）。

- **起点**：先按当前代码采一遍全套作起点。
- **挑项**：按 `perf.py` 的指标与 `budgets.json` 的线，先改越线最多或痛点最明显的；从没越过上沿的项不挑；同一根因并成一批；根因不明的按 §4 查。
- **每批采一遍**：每改一批采一遍，和上一次比，按数量级看。
- **碰画面的改动**：由主会话跑固定机位截图评审，画质不降才留，因为 DECISION-318 不靠降画质达标。
- **停**：进入预算线内（越线的项修到停线）且没有明显痛点就停。
- **改不动的**：写进回报：指标、会话 ID、试过的改法与原因；超出预算线一个数量级的才按 ENG-FAILS 登记失败。
- **定稿**：按实测在 `budgets.json` 或 `KernelBudgets.cs` 定稿初值，主会话删去 ENG-BUDGET §5 对应条目；文档只写会话 ID（§3）。
