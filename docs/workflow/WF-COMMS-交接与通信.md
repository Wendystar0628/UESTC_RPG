# WF-COMMS · 交接与通信

> **范围**：本文规定会话之间经哪些文件交接、`.collab` 里文件怎么放、怎么命名和写、任务单与请求文件的格式、契约申请与完成回报的格式、来信怎么发、Codex 会话怎么派活。
> **不在本文**：一个包从派工到评审的各步：WF-FLOW；git 与推送：WF-RULE §7；全员的来信与等待规则：WF-RULE §2–§5；命令行与会话号：`.collab/tools/README.md`。
> **查阅**：先读 WF-COMMS §0；三种渠道怎么选看 WF-COMMS §4.4；目录与文件看 WF-COMMS §1；命名与写法看 WF-COMMS §2；任务单、请求文件、契约申请与完成回报看 WF-COMMS §3；来信与消息看 WF-COMMS §4；Codex 会话与引导信箱看 WF-COMMS §5。

## 0 结论

1. **经文件交接，消息只在事件发生时发**（WF-COMMS §1、§4）：交接目录是 `E:\Project\UESTC_RPG\.collab\`；任务单和请求文件是唯一依据，上下文重置后照它们的"状态"接着做，对不上以 Git 为准。
2. **任务单与请求文件只追加、不改写，来信一条一个新文件**（WF-COMMS §2、§4）。
3. **在用的和结案的分开放**（WF-COMMS §1）：`tasks/<类>/` 与 `requests/` 下只放在用的；`archive/`、`logs/` 不用读，搜索默认跳过。
4. **来信按收件方分收件箱，一条一个文件**（WF-COMMS §4，D-207）：开头标【需定】【待审】【知会】，一件事、5 行以内。
5. **来信留档，消息送达**（WF-COMMS §4.4）：给 Codex 会话发话先写来信，再发一句消息；不急的排队，要当轮改变对方手上的事才走引导信箱。
6. **完成回报只有一种短头部样式，不超过 8 行**（WF-COMMS §3.4）。

### 0.1 接入要点

- **写契约申请**：开头用 WF-COMMS §3.3 的六行短头部，正文不贴证据。
- **做完交回**：回报照 WF-COMMS §3.4，条目只写编号，证据只给路径。
- **给主会话或 Astra 发话**：在对方收件箱 `notes/<收件方>/` 新建一个文件；给 Astra 的再按 WF-COMMS §4.4 发一句消息（排队或引导信箱）。
- **新建任务单或请求文件**：按 WF-COMMS §2 命名，确认编号没被占用，不覆盖别人的文件。

## 1 交接目录与文件

各方经协作目录 `E:\Project\UESTC_RPG\.collab\` 交接。它在主检出里，但登记在本机的 `.git/info/exclude`，不进 git、不推送。

| 路径（相对 `.collab\`） | 谁写 | 写什么 |
| --- | --- | --- |
| `requests/contract-<包号>-<主题>.md` | 任何代理 | 契约或共享工程文件的申请（WF-FLOW §5）；Astra 在末尾写结论和提交 |
| `requests/review-<包号>-<主题>.md` | Astra 主线程 | 请主会话审美评审：截图或录像路径、可调参数位置与现值；主会话在末尾写结论或新值 |
| `tasks/claude/<nnn>-<主题>.md` | 主会话建单、写评审；施工子代理写一行现状 | 施工单（WF-FLOW §2）；过程流水记到 `logs/tasks/` |
| `tasks/astra/`、`tasks/misc/` | Astra；主会话 | Astra 的计划与子单；其他任务单与简报 |
| `side/cards/s<nnn>-<主题>.md` | 主会话 | 旁路单（WF-FLOW §6.1）；Sol 会话在末尾写"状态" |
| `research/INDEX.md`、`research/<日期>-r<nnn>-<主题>/` | 主会话追加索引与审计；调研子代理写报告与总览 | 调研索引与各方向报告 |
| `notes/<收件方>/<YYYYMMDD-HHMMSS>-<发件方>-<短词>.md` | 发件方 | 来信收件箱（WF-COMMS §4）：`notes/opus/` 发给主会话，`notes/astra/` 发给 Astra |
| `notes/codex-app-done.md` | Codex 会话 | 脚本握手：做完一件活追加一行"[任务号] 一句话结果"，只有脚本读 |
| `status/施工状态.md`、`HANDOVER.md` | 主会话 | 施工状态与待派工队列的活表；主会话交接单（WF-STATUS） |
| `logs/tasks/` | 各单的执行方 | 过程流水 `<任务单名>.log.md` |
| `archive/` | 挪入时 | 结案的任务单、处理完的请求与来信、已审计的调研、已交出的旁路单 |
| `tools/` | 主会话 | 脚本、会话号与状态，索引见 `tools/README.md` |

**结案即挪走**：
- 主会话在任务单末尾写"结案"后挪进 `archive/tasks/<类>/`；处理完的请求挪进 `archive/requests/`；来信由收件方处理完挪进 `archive/notes/<收件方>/`；已审计且采纳项都已入队的调研挪进 `archive/research/`。
- 挪动只改位置不改内容；目标已有同名文件就先看清，不覆盖。
- 任务单只放目标、范围、已定取值、交付标准、评审结论和一行现状；过程流水放 `logs/tasks/`。
- `archive/`、`logs/` 不用读，搜索默认跳过（`.ignore`）；要查旧事点名路径搜，不要删改 `.ignore`。

## 2 命名与写法

- 任务单与请求文件只追加、不改写，每条带时间，路径一律写绝对路径；唯一的例外是 `research/INDEX.md` 的"Opus 审计"一列（调研子代理标"待审"，主会话审计后改写）。
- **文件名一看就懂**（D-208）：规范文档的文件名是"编码-中文简题.md"（WF-DOC §3）。
- **任务单**："三位编号-主题"：施工单 `tasks/claude/<nnn>-<主题>.md`、调研目录 `research/<日期>-r<nnn>-<主题>/`、旁路单 `side/cards/s<nnn>-<主题>.md`。编号各自递增，新建前确认没被占用；子单在编号后加 a、b。流水文件与任务单同名，后缀换成 `.log.md`。
- **请求文件**：`<类型>-<包号>-<主题>.md`，类型是 `contract`、`review`；先确认文件不存在再创建，已有同名时末尾加 `-2`、`-3`。

## 3 任务单、请求文件、契约申请与完成回报

### 3.1 施工单与旁路单

- **施工单**：正文写 WF-FLOW §2 列的各项；末尾依次是"状态"（一行现状加指向流水的一行）、"Opus 评审（时间）"（主会话写，通过或逐条修改意见）。
- **旁路单**：正文写在哪做、交付什么、能改什么、不许做什么；末尾"状态"由 Sol 会话写过程与结果。

### 3.2 请求文件

正文按 WF-COMMS §1 的"写什么"；后续各方只在末尾追加，每条带时间和署名。

### 3.3 契约申请的短头部（D-201）

开头六行写完要主会话或 Astra 看的东西，正文不贴证据：
1. 申请什么：改哪份契约或共享件；
2. 为什么：3 行以内，说结果不说过程；
3. 影响哪些包；
4. 要主会话定的事：逐条，没有写"无"；
5. 依赖与时机：没有写"无"；
6. 证据：日志、截图的路径，一行列完。

### 3.4 完成回报

中文，交给派你的一方，不超过 8 行；条目只写编号，不复述内容：

```
工作包：WP-18 南区 · 提交 <短号> · 改动 game/gen/zones/south/**
完成：MAP-QSH-SOUTH §1–§5；未完成：MAP-QSH-SOUTH §6（可选），未做
门禁：scripts\gate.ps1 -Wp WP-18 快检通过；核心专项 G15 前四项通过
截图：output/render-review/WP-18-*.png
预算：三角形 7.4% / 8%，绘制调用 5.1% / 6%
专项行：存档、天气与画质、时季矩阵、声音；各系统文档规定了回报行，不涉及的写"不涉及"
可调参数：位置与现值（结果看得见或听得见时）
申请与配合：契约修改申请 <路径>或"无"；需其他包配合的事；做过的假设
```

- 截图存 `output/render-review/`（不进 git），命名规则见 CORE-CONVENTIONS。
- 门禁运行方式与判据见 ENG-GATES §1–§2。

## 4 来信与消息

### 4.1 什么时候发

**消息只在事件发生时发**，内容一句话，细节都在任务单里；不发进度汇报，不互相轮询；几张单在 10 分钟内先后到待评审时，合成一条消息。

| 方向 | 什么时候发 |
| --- | --- |
| Sol 会话、Astra → 主会话 | 门禁失败、旁路单完成、待评审、受阻需要决定；写进 `notes/opus/` |
| 主会话 → Astra | 文档改了、契约冻结了、某个包阻塞了、新任务；写进 `notes/astra/`，再按 WF-COMMS §4.4 发一句消息 |

### 4.2 一条来信一个新文件（D-207）

写给谁，就在谁的收件箱 `notes/<收件方>/` 新建一个文件，名为 `<YYYYMMDD-HHMMSS>-<发件方>-<短词>.md`；时间取真实读数，发件方写 `opus`、`astra`、`sol` 之一。写完不改，不往别的文件里追加。收件方处理完把文件挪进 `archive/notes/<收件方>/`，收件箱里只剩没处理的。主会话的收件箱由事件等待脚本带回全文后自动挪走。

### 4.3 三级标记与写法

- **三级标记**（D-201）：写给主会话的来信第一行开头标一种：【需定】要主会话拍板（观感、跨两侧的取舍、作者级的事）；【待审】有推送、申请或报告等主会话审；【知会】只是告诉一声。事件等待只为【需定】【待审】和失败、冲突叫醒，【知会】攒着下次一并看。
- **一条只讲一件事，5 行以内**：要点写全，细节放在任务单或请求文件里给路径。
- **纯工程判断自己定**：Astra 侧能按契约、架构和现有规则判断的工程事，自己定，记一条【知会】，不写成"请主会话决定"。
- **不向作者出选项**：需要确认的事写进任务单或请求文件并通知主会话（WF-RULE §2）。

### 4.4 来信、排队消息与引导信箱

| 渠道 | 是什么 | 什么时候用 |
| --- | --- | --- |
| 来信 `notes/<收件方>/` | 留档的全文，收件方开工时读，处理完挪进 `archive/` | 每次发话都写，细节都在这里 |
| 排队消息（`codex queue`） | 一句话指向来信，等对方这一轮结束后送到；对方空闲时直接开新一轮 | 不急、不用打断的事；对方空闲时叫醒 |
| 引导信箱（`codex_app_steer.py`） | 一句话，对方下一次调用工具时送进当前这一轮，只送一次 | 要马上改变对方手上的事：方向错了、卡在问题上、新规则要当轮生效 |

- 派一整件活用 `codex_app_run.py`（WF-COMMS §5），不用这三种。
- Astra 发给主会话只写来信，由主会话的事件等待脚本带回（WF-COMMS §4.2、§4.3）。
- 只写了信没发消息的，巡逻会在信超过 15 分钟没处理时提醒主会话补发。

## 5 Codex 会话与引导信箱

**Codex 侧会话都在 Codex 应用里**（D-203、D-212）：Astra 和 Sol 会话都是作者开着的会话。主会话派活一律发进对应会话，用 `tools/agents/codex_app_run.py`；它在消息末尾附任务号，会话做完在 `notes/codex-app-done.md` 追加"[任务号] 一句话结果"，看到这一行才算这一轮结束。模型、推理档和速度跟着会话走；要新会话，请作者在应用里开好再登记会话号。不用 `codex exec` 另起后台线程。

**引导信箱的机制**：`tools/agents/codex_app_steer.py` 在会话正在跑时把消息放进 `.collab/steer/`，钩子在它下一次工具调用后送进当前这一轮，只送一次；等待超时没被取走就撤回改为排队，会话空闲直接排队。什么时候用见 WF-COMMS §4.4，用法见 `.collab/tools/README.md`。
