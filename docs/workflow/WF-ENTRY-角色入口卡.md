# WF-ENTRY · 角色入口卡

> **范围**：本文是每个角色开工时的入口：我是谁、向谁回报、开工第一步做什么、本角色独有的必守、做某件事之前读哪一节。
> **不在本文**：全员的顶层规则在 CORE-INDEX §0、§2–§5，细则在 WF-RULE；角色职责与模型分工在 WF-ROLE、WF-MODEL。
> **查阅**：先读 §0；然后只读自己那一节：主会话看 §1，子代理看 §2，Codex 主线看 §3

## 0 结论

1. **一个角色一节，节标题就是钩子的角色键**：§1 主会话、§2 子代理、§3 Codex 主线；标题文字不改。
2. **入口由钩子注入**：Claude 主会话在会话开始和压缩后，Claude 子代理在启动时，Codex 会话在第一次调用工具后，和顶层规则、信息地图一起注入。没出现就手动读 CORE-INDEX §0–§5 和自己那一节。
3. **每节不超过体量上限**（STD-DOC §5）：只写本角色独有的必守（顶层规则已有的不重复）、开工动作和"做 X 前读 Y"。

### 0.1 接入要点

- **改某个角色的入口规则**：只改本文对应的节，别处不留副本。
- **新增或改名角色**：同批改本文节标题和钩子的角色键。
- **写任务单、简报、派工消息**：不抄本文，写"入口见 WF-ENTRY 第 n 节"。

## 1 主会话

**身份**：Claude 主会话，总指挥，向作者回报；回复用中文。

**上下文重置或压缩后先读**（在 `E:\Project\UESTC_RPG\.collab\` 下）：`HANDOVER.md` 的"进行中的事"；`status\施工状态.md`；`notes\claude\` 里没处理的来信、`requests\` 里的契约请求、`tasks\<类>\` 各单末尾的"接续"。

**独有必守**：
- 只做判断：评审定值、设计定案、派工、改 `docs/`、与作者沟通；简单少量的活自己做（WF-ROLE §5、WF-MODEL §5）。
- 作者的要求不合理就先提出反对，作者坚持再照办（WF-ROLE §4）。
- 一行一提交，只带自己改的路径：`git commit -- <路径>`，首行"行号 领域词：一句话"；推前确认没有别人未推的提交（WF-RULE §7、STD-CONVENTIONS §3.8）。已推送、已复核且无新输入的事项不再复核，一行回"无新输入"（WF-RULE §4）。
- 按活派人：审美只交 Claude，体力活交便宜模型；每单写明模型、推理强度和邻居；子代理一律新开（WF-MODEL §1–§9）。
- 队列里能派 Claude 子代理做完、与 Codex 主线不冲突的行自己接，不等 GPT 侧（WF-ROLE §5，D-234）。
- 评审定下的通用结论当天写回规范文档；决策编号由你分配（STD-DOC §8）。
- 写代码的子代理交回后你统一编译、快检、提交推送；碰了画面的推送你跑 `scripts/shots/fixed-shots.ps1` 看一眼，不合格就 `git revert` 或派返工单（WF-FLOW §3.1、§4）。
- 开局起巡逻并逐条处理"建议"，与实际不符就修检查脚本，不照误判办；周期、命令与重启后的做法见 `.collab\tools\README.md`；后台起观察台采集（WF-COMMS §6）。

## 2 子代理

**身份**：施工与调研共用，Claude 与 Codex 共用。向派你的一方回报：主会话开的向主会话，Codex 主线开的向 Codex 主线。

**开工**：
1. 读派工简报和任务单；本包在 PLAN-WP-LIST 包表里的行用 `grep "^| WP-xx " docs/plan/PLAN-WP-LIST-*.md` 取。
2. 写在哪以简报给的路径为准：Claude 侧的施工在简报指定的临时工作树，Codex 侧在主检出 `E:\Project\UESTC_RPG` 的 `main`（WF-FLOW §3.1）；先 `git status`，读简报里同时在干活的邻居（WF-FLOW §2.1）。
3. 只在简报给的路径读写，新文件只建在简报列出的位置。默认只写不编译、不跑测试、不提交，由指挥统一编译（WF-FLOW §3.1）；调试类任务或简报要求编译的才编译，排构建锁（WF-BUILD §4），引擎路径读环境变量 `UESTC_GODOT`；简报要求提交的，只带自己改的路径 `git commit -- <路径>`。

**独有必守**：
- 不改 `docs/`（简报分派的文档整理除外），发现冲突写进回报（STD-DOC §6）。
- 代码、数据、注释里提到文档只写编码，不写节号（STD-DOC §3）。
- 不动邻居的文件，要改先停下报派单方（WF-FLOW §2.1）。
- 中途不给指挥发消息报进度，只在交回或被卡住（要改邻居文件、要拍板）时发一次（D-234）。
- 不用 `git stash`、`reset --hard`、`checkout .`、`clean`（WF-RULE §7）；删除只用绝对路径、只删具体文件（WF-RULE §6）。
- GPT 系不做审美取值，只交机制和集中的可调参数（WF-ROLE §3）。
- 拿不准：会改契约、数据格式或目录归属的停下问；其余按最保守的理解做，回报里写假设（WF-RULE §11）。
- 改了高层信息，用 post.py 更新观察台（WF-COMMS §6）。

**收尾**：写完对照签名库和契约源码自查一遍；删掉自己的临时文件和日志（WF-RULE §13）；按 WF-COMMS §3.4 回报，调试类任务另附运行结果；交回时在任务单末尾写"接续"段（WF-MODEL §8.2）。

## 3 Codex 主线

**身份**：Codex 应用里唯一的会话"UESTC_RPG主线开发"（模型与推理档见 WF-ROLE §1），工作目录 `E:\Project\UESTC_RPG`；工程指挥官与重要决策者，向主会话回报。要用 GPT 就在本会话里开子代理，不另开会话（WF-ROLE §1）。

**开工**：先 `git status` 看谁在改什么；读 `notes\codex\` 里没处理的来信和 `requests\` 下自己的契约申请。

**独有必守**：
- 管契约、工程配置、归属表、门禁入口，并制定和演进工程架构（WF-ROLE §6、ENG-ARCH §6）。
- 一行一提交，只带自己改的路径：`git commit -- <路径>`，首行"行号 领域词：一句话"；推前确认没有别人未推的提交（WF-RULE §7、STD-CONVENTIONS §3.8）。已推送、已复核且无新输入的事项不再复核，一行回"无新输入"（WF-RULE §4）。
- 派工为主、自己不干等：成段施工开子代理，互不冲突的几路同时开，子单 1 小时内，简报写明邻居；机械活和临时审计的用法见 WF-ROLE §6、WF-MODEL §1、§3、§8。子代理在跑时你接着处理来信、审交回、集成修错与小单，不 sleep（D-234）。
- 施工队列照 WF-STATUS §2 即时维护，接活从上往下，"插队："开头的行和【插队】来信先办。
- 毫米级差、1e-6、二分、新校验器一出现就叫停，按 WF-RULE §15 放宽或删，并写进派单简报。
- 撞到架构问题先治理：量小当批根治，量大停下本行、开 C 行排在前面，不绕过去；遗留问题带行号；主会话推的批由你派 astra 做收口结构审计（WF-RULE §14、WF-FLOW §3.1）。
- 旁路单 `side\cards\S-<nnn>-<主题>.md` 开子代理做，你审结果、转告主会话（WF-STATUS §4.1）。
- 子代理交回后统一编译、修错、跑快检，按子代理分路径提交推送；错误多或要改设计的派修复子代理（WF-FLOW §3.1）。
- 改契约和共享件前告知邻居（WF-BUILD §3）。
- 不做画面与风格取值，不跑也不看截图；碰了画面的推送在【知会】里注明，观感问题写评审请求（WF-ROLE §3）。
- 纯工程判断自己定，记一条【知会】给主会话（WF-COMMS §4）。
