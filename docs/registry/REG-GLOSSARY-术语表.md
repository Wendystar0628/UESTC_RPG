# REG-GLOSSARY · 术语表

> **范围**：本文把各文档里的专有说法统一解释一遍，按领域分组，每条一两句，并给出细则所在的小节。
> **不在本文**：规则和数值本身（以每条指向的文档为准）；编号写法与跨文档约定（STD-CONVENTIONS）；已定决策（REG-DECISIONS）；RPG 扩展点（ENG-ROADMAP）。
> **查阅**：先读 §0；遇到不懂的词直接 grep；按领域找：作品与默认状态看 §1，世界状态与时间看 §2，天气看 §3，美术看 §4，箱庭、地形与外围看 §5，室内看 §6，观察与行走看 §7，平面地图看 §8，开始页与存档看 §9，多地图看 §10，界面看 §11，音频看 §12，画面与性能看 §13，工程与流程看 §14，一词多义看 §15

## 0 用法

- 每条的写法：**术语**（代码名或别名，如有）：解释（细则所在的小节）。引用写法见 STD-DOC。
- 解释只帮读懂，不抄规则和数值；与细则不一致时以细则为准，并报给主会话。
- 一个词有几种意思的，见 §15；编号前缀（P、V、E、A、R、G、O、D 等）的速查见 STD-CONVENTIONS §3.2。

### 0.1 接入要点

- **遇到不懂的专有说法**：grep 本文；规则以每条指向的小节为准。
- **一个词有几种意思**：看 §15，写文档时按"怎么区分"一栏写全称。

## 1 作品与默认状态

- **电光年华**：作品名，英文 *Electric Years*；校园题材的独立 RPG，第一张地图是电子科技大学清水河校区（CORE-INDEX §0）。
- **落金初灯**：清水河默认状态的名字：秋季傍晚、晴、自动天气、正常流逝；新游戏的终态和新存档的初值（SYS-TIME §0、SYS-MAPS §2）。
- **默认状态**：每张图在 `map.json` 里声明的世界起点；清水河上就是落金初灯（SYS-TIME §0）。
- **落金**：落日的金色光斜铺过校园，不是银杏叶（SYS-TIME §2）。
- **初灯**：白昼与灯火交接时第一批亮起的灯（ART-COLORSCRIPT §3）。
- **初灯组**：比其余路灯早亮的一组灯具：主路灯、银杏大道、时间广场外圈等（ART-COLORSCRIPT §3、MAP-QSH-ATMOSPHERE §2）。
- **交班的钟**：宣邦楼钟楼的钟面，指针跟随当前钟点；蓝调里钟面亮起，是"白昼交班"的画面（SYS-MOTION-LIFE §2）。
- **观光模式**：当前唯一的玩法，没有任务和可点选的东西；对应规则集 `sightseeing`（ENG-ROADMAP §1、§3）。
- **规则集**（`RulesetDescriptor`、`IRuleset`）：决定"这一局按什么规则运行"的一组配置，只在新游戏和读档时切换（ENG-ROADMAP §3）。
- **生活痕迹**：人刚离开时留下的东西。画面里不出现人，人只以整齐完好的痕迹出现（WLD-LIFE-FAUNA §2、WLD-RENOVATION）。
- **偶发事件**：全片唯一的偶发事件"看不见的晚归者"（SYS-MOTION-LIFE §3）。

## 2 世界状态与时间

- **世界状态**：三个量：钟点、季节、天气；由 `IWorldState` 提供，内容代码只读（SYS-TIME §0）。
- **世界时间**（`WorldHours`）：同一世界实例内单调递增的小时数，只向前走（SYS-TIME §1）。
- **钟点**（`Clock`）：由世界时间换算的美术钟点；换季时数字可能变小，但太阳不倒走（SYS-TIME §1）。
- **季节值**（`SeasonPos`）：0–4 的连续循环量，季节不自动推进（SYS-TIME §0）。
- **流逝倍率**（`Flow`）：世界秒与真实秒之比，有固定几档（SYS-TIME §1、ENG-ARCH §3）。
- **下一次出现**：设钟点的语义：前进到未来最近的那个钟点，拨到更早的钟点就是到次日（SYS-TIME §1）。
- **动画时钟**（`AnimTime`）：真实秒的循环时钟，驱动风、水、一拍二；不受世界时间影响（SYS-MOTION §1.2）。
- **真实秒**：帧间隔累加的秒数，不读系统时钟；偶发事件、转场、一次性声按它计（SYS-MOTION §1.1）。
- **一拍二**：按固定步频步进、帧间不插值的动画节奏；CPU 与着色器同拍（SYS-MOTION §2.2、DECISION-158）。
- **美术日月**：按美术轨迹而非天文计算运行的太阳和月亮（SYS-TIME §2）。
- **主光**：场景里唯一一盏方向光，白天是太阳，夜间是月亮（ART-SKYLIGHT §3）。
- **无影蓝调**：阴影强度为 0 的一段，主光在其中完成日月交接（SYS-TIME §2）。
- **黄昏带、晨昏带**：太阳高度落在黄昏或黎明区间的时段，带内不发生自动天气转移（SYS-WEATHER-PROCESS §1.2、DECISION-162）。
- **换季转场**：季节一律正向转场：扬起、起雾、落定；同时一阵风从西湖推过全校（SYS-MOTION §3）。
- **转场**：观者触发的过渡的统称（改时间、换季、跳转、传送、模式切换、读档、换图等），不算偶发事件，不能硬切（SYS-MOTION-LIFE §3、SYS-MOTION §3）。
- **回到落金初灯**（`ResetDefault`）：一键回到本图默认状态，不移镜头，不换世界实例（SYS-TIME §1、SYS-WEATHER-PROCESS §1.6）。
- **世界实例**（`IWorldState.Instance`）：一段连续演化的世界，读档、新游戏加 1；切图和回到落金初灯不加（SYS-SAVE-FLOW §2.2）。
- **关键帧**：调色板按太阳高度索引的色彩关键帧，每季一套（ART-COLORSCRIPT §1.1）。
- **英雄帧**：必须单独手调、逐张验收的 12 个时季天气组合，也是点位推荐状态的来源（ART-COLORSCRIPT §1.5）。
- **灯光通道**：由灯光时刻表驱动的一组灯光强度通道（ART-COLORSCRIPT §3）。

## 3 天气

- **天气**：第三个世界量；对外是"天气格 + 自动 / 手动"，对内是天气向量（SYS-WEATHER §0）。
- **天气格**：界面上固定的几格加"自动"（SYS-WEATHER §1）。
- **内部状态**（`WeatherKind`）：天气格背后的细分状态（SYS-WEATHER §1、ENG-ARCH §3）。
- **天气向量**（`WeatherVec`）：每帧插值的连续分量；所有天气表现只读它和它写出的全局参数（SYS-WEATHER-PROCESS §2）。
- **阴度**（`Overcast`）：天气向量里的阴天程度 0–1，影响投影强度、有效太阳高度和调色板修正（SYS-WEATHER §6）。
- **天光方向**（`overcast_dir`）：阴雨雪时明暗分阶改用的方向（SYS-WEATHER §6、ART-STYLE-SHADING §1.1）。
- **`h_eff`**（有效太阳高度）：太阳高度按阴度与降水下调后的值，灯光通道按它求值，所以阴雨天灯提前亮；界面昼夜主题不用它（SYS-WEATHER §6、ART-COLORSCRIPT §3）。
- **自动天气**：前向随机过程，只走验证过的转移边，只向前推进（SYS-WEATHER-PROCESS §1.1）。
- **转移边**：两个天气状态之间允许的一次转移（SYS-WEATHER-PROCESS §1.1）。
- **前瞻队列**：始终保持的已生成天气队列，供快进和预报行用，进存档（SYS-WEATHER-PROCESS §1.4）。
- **天气剧本**（`weatherProfile`）：一张图用的天气参数库，清水河用 `chengdu`（SYS-WEATHER-PROCESS §1.3、SYS-MAPS §2）。
- **天气种子**：每个存档一个，随存档走（SYS-WEATHER-PROCESS §1.4）。
- **钉住**（`Pin`）：应用点位推荐时把推荐天气固定一段时间，之后自然演化（SYS-WEATHER-PROCESS §1.6）。
- **保持晴**（`Quiet`）：默认状态的天气是"自动 + 保持晴到本季黄昏带结束"，新游戏和回到落金初灯时生效（SYS-WEATHER-PROCESS §1.6）。
- **进图补算**：每张图一份天气过程，离开时冻结，进图时补算到当前世界时间（SYS-WEATHER-PROCESS §1.5、SYS-MAPS §4）。
- **太阳雨**：雨转雨后初晴那条转移边开头的一段，不是新的天气格（SYS-WEATHER §2、SYS-WEATHER-PROCESS §1.3）。
- **初晴**：降水之后放晴：洗过的蓝天，积水慢慢干掉，可能出彩虹（SYS-WEATHER §2）。
- **云内闪、远雷**：雷雨只画远处云内的闪电，远雷与之同步；都不算偶发事件（SYS-WEATHER §5、SYS-AUDIO-AMBIENCE §3）。
- **彩虹**：雨后初晴的天象状态，不算偶发事件（SYS-WEATHER §5）。

## 4 美术与光照

- **三渲二**：用三维实时渲染做出日式动画背景美术的画风，基调清透干净（ART-STYLE §1）。
- **分阶明暗**：明暗按阈值分成几阶而不是连续渐变（ART-STYLE-SHADING §1.1）。
- **影明度比**（r）：影与受光的 OKLab 明度之比；影色从固有色推导（ART-STYLE-SHADING §2.1）。
- **天光色**（`ambient.sky`）：每个关键帧的天光颜色，中性材质的影随它偏色（ART-STYLE-SHADING §2.1、ART-STYLE §2.1）。
- **室内暖影**：室内的影色向室内暖调推导（ART-STYLE-SHADING §2.4、WLD-INTERIORS-BUILD §3.1）。
- **透光**：树叶、花瓣、窗帘、灯罩、薄布按逆光透射处理（ART-STYLE-SHADING §3.5）。
- **描线**：后处理描线，线色由底色压暗再染暖棕或青灰，禁止纯黑（ART-STYLE-LINES §1）。
- **柔光**：白天只让高光晕开，黄昏以后才叠全帧柔光；属风格底线（ART-STYLE-LINES §2.1、SYS-GRAPHICS §2）。
- **移轴、镜头光斑、暗角**：与光柱同属风格默认的后期项，玩家可以单独关（ART-STYLE-LINES §2、SYS-GRAPHICS §2）。
- **色名、色号**：色名是唯一的取色途径，每个色名对应一个固定色号和调色板纹理的一列（ART-STYLE §2.5）。
- **调色板纹理**（`palette`）：存当前色、灯照色、室内影色、室内受光色与植被季相行的全局纹理，每帧按天色更新（ENG-PERF §1.5、ART-COLORSCRIPT §1.1）。
- **剖切**：镜头穿进物体时，外壳换成剖切变体，不露空洞（SYS-VIEW-MEDIUM §2）。
- **介质**（`MediumKind`）：镜头所处的介质：空气、室内、地下、水下、雾海（SYS-VIEW-MEDIUM §1）。
- **视觉精度**：分底线和细节密度两层（ART-FIDELITY §0、DECISION-176）。
- **底线**：任何位置、任何距离、任何画面预设都要成立的精度要求；只有飞行才到的位置只判底线（ART-FIDELITY §2.0）。
- **精度区**（K1–K5）：按"多常被近看"划分的区，各有细节密度和判定距离（ART-FIDELITY §0）。
- **判定距离**（d_K）：从这个距离往外满足本区的细节密度，更近只判底线（ART-FIDELITY §0）。
- **金样**：开工初期做出、经评审作为全体照做标准的样件（ART-MODELING-PROPORTION §6）。
- **一票否决**：满足任意一条就直接判不通过的清单（ENG-GATES-VETO §1、ART-FIDELITY §3）。

## 5 箱庭、地形、边界与外围

- **箱庭**：把校园做成一块切下来、浮在雾海上的模型（WLD-OUTSKIRTS-DIORAMA）。
- **大箱庭**：箱庭扩成"校园加门前一圈街区"，线内能看不能进，线外是雾海（WLD-OUTSKIRTS §0）。
- **校界**：`world/geo.json` 的校界环；行走的边界（WLD-OUTSKIRTS-DIORAMA §1、WLD-OUTSKIRTS §1）。
- **前沿线**：校界外第一条道路的对侧路缘；旁观在低空能飞到的最远处，也是外围 O0 与 O1 的分界（WLD-OUTSKIRTS §1）。
- **截面线**：箱庭的外缘，闭合多边形，外围 O1 与 O2 的分界（WLD-OUTSKIRTS §1、WLD-OUTSKIRTS-BAND §1.1）。
- **地层截面**：沿截面线切下的平涂地层，像动画的剖面设定图（WLD-OUTSKIRTS-DIORAMA §2）。
- **雾海**：箱庭四周低平的分层雾面，用面片做，不用体积雾（WLD-OUTSKIRTS-DIORAMA §4）。
- **清水河银带**：雾海顶面上沿清水河走向画的静止银色亮带（WLD-OUTSKIRTS-DIORAMA §4、WLD-OUTSKIRTS-BAND §1.1）。
- **雾中楼顶**：从雾海里探出的外围楼顶，即外围 O2（WLD-OUTSKIRTS-BAND §2.2）。
- **远景环**：环形卡片与雪山，画远处的楼群、城市和山，即外围 O3（WLD-OUTSKIRTS-DIORAMA §5、§6）。
- **外围分层**（O0–O3）：O0 街道带、O1 外围街区、O2 雾中楼顶、O3 远景；与审查视角 E 不同号（WLD-OUTSKIRTS-BAND §2.2、DECISION-157）。
- **距离环**：外围按离校界、前沿线的距离分成的几段（O0 街道带、O1 第一排、O1 后排、O2 之外），外围精度按所在环定级（WLD-OUTSKIRTS-BAND §2.1）。
- **可达空间**（活动范围）：旁观镜头能到的空间，参数在 `map.json` 的 `roam`（SYS-BORDER §2.1、SYS-VIEW §2.3）。
- **边缘雾**（`edge_fog`）：旁观接近水平边界时朝外一侧的雾变浓（SYS-BORDER §2.3）。
- **校界形心**（`MapDescriptor.Center`）：活动范围的中心（SYS-MAPS §2）。
- **"前方暂未开放"**：旁观飞到可达空间边缘时的提示（SYS-BORDER §3.1）。
- **地形分层**：清水河不做平地，按"平缓底板 + 少量强垂直 + 遮挡与揭示"主动设计地形（DECISION-180、WLD-TERRAIN-SHAPE §2.1）。
- **地形评估器**（`ITerrain`）：把地形覆盖层和世界文件合成确定性高度函数的纯函数，渲染与碰撞读同一份（WLD-TERRAIN-APPLY §1）。
- **地形操作**：地形覆盖层里的一条矢量操作，每条带 ID 和理由（WLD-TERRAIN-APPLY §1）。
- **垫层**（`PadY`）：楼与大实体坐的平台标高（WLD-TERRAIN-APPLY §2.3）。
- **道路走廊**：道路多边形加中心线的强约束区，地形迁就路（WLD-TERRAIN-APPLY §2.2）。
- **常水位**（`waterY`）：每个水体自己的水面标高（WLD-TERRAIN-SHAPE §4.1）。

## 6 室内与门

- **开放室内**：精选开放、行走能进的室内；开不开放只看有没有注册室内提供者（WLD-INTERIORS §0、MAP-QSH-INTERIORS §4）。
- **开放清单**（`interiors.json`）：本图开放室内的清单，以后加一栋楼只在这里加一项（WLD-INTERIORS-ACCESS §4）。
- **室内提供者**（`IInteriorProvider`）：给一栋开放楼出布局、几何、碰撞、导航和声学的模块；注册即开放（ENG-ARCH §3）。
- **I0、IS、IF**：室内的三级：兜底层、只留壳、完整（ENG-BUDGET-LOD §1、WLD-INTERIORS-BUILD §1.1）。
- **进楼衔接**：镜头在任何楼体里永远不显示空壳；行走跨进开放室内前，内容与碰撞必须就绪（WLD-INTERIORS-BUILD §1.3、ENG-PERF-STREAM §1）。
- **软停**：要跨进的开放楼层没有就绪时，角色在门槛前平滑停住，就绪后恢复（WLD-INTERIORS-BUILD §1.3）。
- **简化室内**：旁观飞进关着的楼时看到的简化内容，不做碰撞和生活痕迹（SYS-VIEW-MEDIUM §2）。
- **窗卡**：关着的楼的窗里画的室内映射，不与真实房间对应（WLD-INTERIORS-ACCESS §3）。
- **门厅卡**：关着的门的门玻璃里画的门厅视差图层（WLD-INTERIORS-ACCESS §3）。
- **开放入口**：开放楼的入口门固定敞开，配暖光池、地垫和开放牌，作为"能进"的信号（WLD-INTERIORS-ACCESS §2）。
- **自动门**：开放室内里能进的房门和开放路线上的防火门、玻璃门：观者走近自动推开，闭门器缓缓关上，不加交互键（WLD-INTERIORS-ACCESS §2.1、SYS-WALK-BOUNDS §3、DECISION-027）。
- **关着的门**：实体门扇与外墙连成一条碰撞（WLD-INTERIORS-ACCESS §2、§3）。
- **封口**：开放范围的边界，用现实里本来就有的东西收口（WLD-INTERIORS-ACCESS §1、WLD-INTERIORS-BUILD §5）。

## 7 观察模式、行走与跳转

- **观察模式**（`ViewMode`）：旁观（`Fly`）与行走（`Walk`，新游戏的开局模式，DECISION-242）（SYS-WALK §0）。
- **旁观**：自由飞行、穿透一切（SYS-VIEW §2.1）。
- **行走**：有重力和碰撞，以眼高走、跑、跳、潜行（SYS-WALK §2）。
- **镜头不会自己动**：不做环绕、俯视、导览和自动运镜；观者触发的跳转、传送、模式切换、回位不算（SYS-VIEW §2.5）。
- **观者状态**（`IObserverState`）：观者自己在哪；"画面从哪看"读 `ICameraRig`（ENG-ARCH §3、ENG-ROADMAP §3）。
- **输入占用**（`LockInput`）：大地图、开始页、加载界面按原因各自取得的占用（ENG-ARCH §3、ENG-ROADMAP §3）。
- **主网**：行走必须能走、执行走廊标准的那部分路网（SYS-WALK-BOUNDS §1）。
- **行走走廊**：主网中线两侧一定宽度以及开放室内的可走部分，精度要求更密（ART-FIDELITY §5.1）。
- **可行走数据**：登记的禁行区、涉水区、开放泳区多边形，运行时按位置查（SYS-WALK-BOUNDS §1）。
- **回位**：进了不能待的地方（泳区以外的深水、禁行区），直接硬切回最近的安全点（SYS-WALK-BOUNDS §4，DECISION-248）。
- **安全点**：行走着地时记下的点，供模式切换、回位和读档修复（SYS-WALK-BOUNDS §4）。
- **碰撞级 C**：与渲染级别无关、本机烘焙的碰撞数据，只在行走模式下加载（SYS-WALK-BOUNDS §7、ENG-PERF-STREAM §1）。
- **表面类型**（`SurfaceTag`）：碰撞体的语义，不是材质，脚步材质另用 `FootMat`（ENG-ARCH §3、SYS-AUDIO-FOLEY §1.3）。
- **碰撞未就绪冻结物理**：行走时角色周围碰撞没有就绪就冻结物理，宁可停住（ENG-PERF-STREAM §1）。
- **点位**：精心选的观景位姿，各带旁观位姿、行走落点、推荐状态和进场路径（UI-NAV-WAYPOINTS §1）。
- **推荐状态**：点位附带的钟点、季节和天气，来源是英雄帧（UI-NAV-WAYPOINTS §1、SYS-WEATHER-PROCESS §1.6）。
- **仅旁观**：没有行走落点的点位（UI-NAV-WAYPOINTS §1）。
- **进场路径**（`EntryPath`）：跳到点位时的进入方式（UI-NAV-WAYPOINTS §1、ENG-ARCH §3）。
- **跳转**（飞过去）：到点位或标记的飞行过渡，按距离自动选方式，途中不穿楼（UI-NAV-WAYPOINTS §2.1）。
- **已知目的地预取**：路径已知的移动把目的地各环插到加载队列之前（ENG-PERF-STREAM §1、UI-NAV-WAYPOINTS §2.3）。
- **到达保证**：到达帧要求目的地各环就绪，加载界面停到就绪（ENG-PERF-STREAM §1、UI-NAV-WAYPOINTS §2.3）。

## 8 平面地图与传送

- **平面地图**：只活在界面层的校园平面图：小地图与大地图；3D 画面里不叠加标记（SYS-ATLAS §0）。
- **版图**（地图风格）：底图画成芯片版图式的校园平面（SYS-ATLAS-UI §1.2、UI-VISUAL §1）。
- **底图**：从世界模型烘焙的地图 SDF、地标线描与标注，所以和艺术化处理后的环境一致（SYS-ATLAS-UI §1.1）。
- **小地图**：左上角常驻，是漫游态唯一常驻的元素（SYS-ATLAS-UI §2）。
- **大地图**：按 M 打开，有图层筛选、图例、目录页、传送卡、自定义标记和追踪（SYS-ATLAS-UI §3）。
- **传送**：经加载界面的地图传送瞬移，只能从大地图触发（SYS-ATLAS-TRAVEL §3、UI-NAV-WAYPOINTS §2.4）。
- **可传送标记**：只有锚点、观景点、可进入室内的门口、路线起点四类（SYS-ATLAS-TRAVEL §1）。
- **锚点**（平面地图）：校园里本来就有的导览设施，在大地图上是可传送标记；3D 里点它没有反应（SYS-ATLAS-TRAVEL §2）。
- **追踪**：选定一个目标，在小地图上标出方向或路线折线；同一时间只有一个（SYS-ATLAS-UI §3.5）。
- **自定义标记**：观者在大地图上放的钉，存进存档（SYS-ATLAS-UI §3.5、SYS-ATLAS §3）。
- **可进入的室内**（图层）：由开放清单自动生成的门口标记和轮廓高亮（SYS-ATLAS-TRAVEL §1）。
- **解锁策略**：由规则集给出；观光是全部可用，`proximity` 只留给 RPG（SYS-ATLAS-TRAVEL §4、ENG-ROADMAP §3）。
- **`atlasRect`**：平面地图的页面范围，写在 `atlas/markers.json`（SYS-ATLAS-UI §1.3）。
- **`IAtlasService`**：管标记、解锁、追踪和传送的服务；与 `IMapService` 是两回事，不得混名（ENG-ARCH §3、DECISION-138）。

## 9 开始页与存档

- **启动序列**：雾色、扉页、交叉淡化成实时的 T0，全程没有进度条（SYS-TITLE §1）。
- **扉页**：T0 的三维静帧，由截图机的出图脚本生成；片名块由界面层实时画在上面（SYS-TITLE §1）。
- **T0**（云隙望穹）：开始页的静止机位，在活动范围之外，只在 `--title=1` 下有效（SYS-TITLE §2.1、ENG-GATES-SHOTS §1）。
- **开始页**：背景是最近一个存档的世界，流逝停住；没有存档时是落金初灯的预览（SYS-TITLE §2）。
- **加载界面**：唯一遮住画面做加载或重建的全屏界面，新游戏、继续、返回标题、传送、换图、需要“应用”的画面设置、存档退出、截图与门禁换机位都用它；带一条进度条，走满后淡出（SYS-TITLE §3.1）。
- **云卡**：T0 里的云片，只在开始页出现（SYS-TITLE §2.1）。
- **交还控制**：加载界面淡出、把镜头交给观者的那一刻（SYS-TITLE §3）。
- **应用状态**（`IAppFlow`）：Boot、Title、Entering、Playing、Leaving、Quitting；偶发事件、自动保存、小地图只在 Playing 里有（SYS-TITLE §3）。
- **存档位**（`SlotId`）：三个自动存档位，每个装一条世界线（SYS-SAVE §1）。
- **世界线**：从一次新游戏开始到被另一次新游戏覆盖为止的一串存档（SYS-SAVE §1）。
- **代**（gen）：每次保存写一个新文件，代号严格递增，保留最近几代，不覆盖不改名（SYS-SAVE §1）。
- **继续**：开始页上进入最近保存的可读存档位（SYS-SAVE §1）。
- **存档段**（`[SaveSection]`）：各模块在自己的服务或节点上声明的一段存档；字段有增减就升版本、写迁移函数（SYS-SAVE §2、SYS-SAVE-FORMAT §1.4）。
- **安全时刻**：可以拍快照的时刻；不满足就顺延（SYS-SAVE-FLOW §1.2）。
- **落定**（落定快照、落定状态）：存档记的是世界的落定状态，读档后过渡直接落到终点，不续播（SYS-SAVE-FLOW §1.2、SYS-SAVE §0）。
- **续跑等价**：同一构建下，存档读回后给相同输入，世界和天气与没退出时逐帧一致（SYS-SAVE-FLOW §2.3）。
- **预览读档**（`LoadScope.Preview`）：开始页用的读档，视角和行走留作"继续"的终点（SYS-SAVE-FLOW §2.1）。

## 10 多地图

- **地图**（`MapId`）：一张可加载的图；现在只有清水河，但从第一天起按多张图写（SYS-MAPS §0）。
- **按图数据**：放在按图目录里的数据；天气剧本、音频库、画面预设是全局数据（SYS-MAPS §1.1、§1.1）。
- **`map.json`**（`MapDescriptor`）：每张图的描述：ID、名字、种子、数据范围、活动范围、默认状态等（SYS-MAPS §2）。
- **`map_rect`**（`dataRect`）：全图数据纹理覆盖的范围；不等于箱庭包围盒（SYS-MAPS §7、ENG-PERF §1.5）。
- **地图包围盒**（`Bounds`）：箱庭包围盒，取截面线的包围盒（SYS-MAPS §2）。
- **`MapScope`**：各区 gen 程序集的特性，标明它属于哪张图；加载一张图只启用"通用 + 当前图"的模块（SYS-MAPS §6、ENG-ARCH §2）。
- **通用模块**：不认识任何具体图、只读本图数据的生成模块（SYS-MAPS §6）。
- **切图**（`IMapService.Prepare` 加唯一终点到达）：只用一个 World3D，先卸后装；世界时间、季节和实例都不变（SYS-MAPS §3.2）。
- **`IMapAware`**：跨图常驻的节点换数据的接口，在加载界面下调用（ENG-ARCH §3）。

## 11 界面

- **信息与光**：界面的视觉语言：叠在暖色手绘世界上的一层冷光精密仪器；光是信号不是装饰（UI-VISUAL §0）。
- **清蓝**：界面主色，只在界面层，不进 3D 材质（UI-VISUAL §3.1、§2.1）。
- **晶白**：白天的界面主题（UI-VISUAL §3.3）。
- **深屏**：夜间的界面主题；辉光只出现在深屏上（UI-VISUAL §3.3）。
- **交班**（界面）：晶白与深屏之间的切换，按真实太阳高度离散切换（UI-VISUAL §3.4、§4）。
- **常驻件**：压在实景上的小件：小地图、时间读数、临时提示等；默认固定用深屏（UI-VISUAL §3.4）。
- **大页**：大地图、设置卡、存档页这类整页界面，随主题切换（UI-VISUAL §0）。
- **漫游态、界面态**：Playing 里的两种输入状态：鼠标被捕获，或鼠标可见（UI-NAV §4.1）。
- **1 号脚**：每个容器只切左上一个 45° 角，像芯片的 1 号引脚（UI-VISUAL-COMPONENTS §2）。
- **发丝线**：1 物理像素宽的线（UI-VISUAL-COMPONENTS §2）。
- **过孔灯**：表示状态的小圆点灯（UI-VISUAL-COMPONENTS §2）。
- **走线**：只用来表示连接关系的线（UI-VISUAL-COMPONENTS §2）。
- **衍射光边**：只给键盘焦点和选中项的冷色光边（UI-VISUAL-COMPONENTS §2）。
- **暖色点**（`ui.now`）：界面里唯一的暖色，只表示"太阳 / 此刻"（UI-VISUAL §3.2）。
- **时间环**：24 h 的天色光谱环，只能顺时针拖（UI-VISUAL-COMPONENTS §4.3、UI-NAV §3.1）。
- **天气签条、预报行**：天气格的签条式控件，以及展开时间卡时的一行天气预报（UI-VISUAL-COMPONENTS §4.4、UI-NAV §3.7）。
- **等待灯**：加载不做进度条，等待较久才亮三颗过孔灯（UI-VISUAL-COMPONENTS §4.5、SYS-TITLE §1）。
- **到达标题**：跳转或传送到达时压在画面上的地名标题（UI-NAV §3.4、UI-VISUAL-COMPONENTS §4.4）。
- **临时提示**：几秒内淡出的一行提示（UI-NAV §3.6）。
- **中央 60%**：屏幕中央区域里不放任何常驻件（UI-VISUAL-COMPONENTS §5）。
- **八个母题**：界面动效的八种样式，分三级使用（UI-VISUAL-MOTION §1.2）。
- **减少动态效果**：无障碍设置，每个动效母题都有替代（UI-NAV-WAYPOINTS §2.4、UI-VISUAL-MOTION §2.1）。
- **`HudModel`**：界面一侧读世界状态的只读转发，直接取源、不另存副本（SYS-TIME §1）。
- **署名**：常驻的 OSM 署名，在最上层；`--ui=0` 时也保留（ENG-RELEASE §7.1、UI-VISUAL §4）。

## 12 音频

- **声景七层**：环境声分七层，自然声跟美术太阳高度走，人迹跟钟点和窗灯通道走（SYS-AUDIO-AMBIENCE §1.1）。
- **床**：持续的环境声底子（SYS-AUDIO §1）。
- **散布**：按真实秒排程、落点取声景场候选位点的一次性声（SYS-AUDIO §1）。
- **同步提示**：其他模块经 `IAmbienceService.Cue` 发出、与画面同步的一次性声（SYS-AUDIO §1）。
- **发声器**（`AmbientEmitterDecl`）：环境声的声源声明，从世界模型离线生成，不在场景里手摆（SYS-AUDIO-AMBIENCE §1.2）。
- **声景场**：覆盖全图的离线网格，每格记地点量，运行时在听者处取样（SYS-AUDIO-AMBIENCE §1.2）。
- **按真实秒排程**（RateGovernor）：一次性声按真实秒排程，流逝倍率只决定"该有哪些声"，不改变多密（SYS-AUDIO §3）。
- **混音铁律**：增益乘在播放器音量上，总线音量保持常数（SYS-AUDIO §2）。
- **五组音量**：总、环境、动作、界面、音乐（SYS-AUDIO §7）。
- **人迹声**：人只以远处、听不清、来自看不见处的群声出现；听得清一票否决（SYS-AUDIO §4）。
- **观者声**：观者自己的脚步、落地、涉水和飞行风声；观者没有身体，但有声音（SYS-AUDIO-FOLEY §2）。
- **步相**：按水平位移推进的步态相位，视角晃动和脚步声共用，所以声画同相（SYS-AUDIO-FOLEY §1.2）。
- **`FootMat`**：与 `SurfaceTag` 正交的脚步与接触材质（SYS-AUDIO-FOLEY §1.3、ENG-ARCH §3）。
- **地面覆盖物**（`IGroundCover`）：脚下的湿润、积水、积雪、落叶、花瓣等覆盖量（SYS-AUDIO-FOLEY §1.3）。
- **声学网格**：全图常驻的离线声学数据（SYS-AUDIO-FOLEY §2.2）。
- **房间与门户**（声学）：开放室内声明的声学房间和房间之间的开口（SYS-AUDIO-FOLEY §2.2）。
- **界面音**（`UiCue`）：按动效频率分级的界面音效，高频事件默认无声（SYS-AUDIO §5）。
- **开场音乐**：开始页的一段原创小品，做好之前不放（SYS-AUDIO §6）。

## 13 画面设置与性能

- **设备档**（`DeviceTier`）：硬件分类，由首次分档得出，只决定推荐哪个预设和自适应的预算；主线之后才做（SYS-GRAPHICS §0、ENG-BUDGET §2、DECISION-233）。
- **最低配置**：适配的最低硬件，也是最低的设备档（ENG-BUDGET §2、DECISION-169）。
- **画面预设**（`QualityPreset`）：一组单项取值，每个设备档推荐其中一个；改过任何单项就显示为"自定义"（SYS-GRAPHICS §0、§1）。
- **单项**（`QualityKnob`）：画面设置的可调项，每项由一个负责包落到引擎上（SYS-GRAPHICS §3、ENG-ARCH §3）。
- **生效类别**（`ApplyClass`）：单项生效的代价：即时、分帧、加载、重启（SYS-GRAPHICS §3）。
- **风格底线**：任何画质下都不能关的画风；实时阴影和西湖倒影只能降到最差值（SYS-GRAPHICS §2）。
- **风格默认**：默认开、玩家可以单独关的风格项；关掉之后的画面不进验收（SYS-GRAPHICS §2）。
- **首次分档**：首次启动时在扉页后面判定设备档；主线之后才做（SYS-GRAPHICS §5）。
- **自动调节**（自适应画质）：主线之后才做；只往下调，不超过玩家所选，玩家手动改过的项被锁定（SYS-GRAPHICS §5、ENG-PERF-ADAPT §1.1）。
- **管线编译**：Godot 第一次遇到某个着色器、顶点格式、渲染状态的组合时编译渲染管线，可能卡帧；本作启动时在扉页下预热（ENG-PERF §2）。
- **预热**（`PipelineWarmup`）：启动时在扉页下把构建期定出的每个组合隐藏实例化一次，交给引擎预编译，一批做完（ENG-PERF §2、DECISION-261）。
- **着色器白名单**：登记在两个着色器目录里的文件；别处出现着色器 G4 拒绝（ENG-PERF §1.4）。
- **全局参数**（Shader Globals）：世界状态、天气、画质、地图和风格的全局着色器参数与数据纹理；每个参数只有一个写入方（ENG-PERF §1.5）。
- **`mat_table`**：按材质 ID 查描线参数、明暗档、湿润响应、透光与暖边系数的数据纹理（ENG-PERF §1.5）。
- **材质 ID**：材质库给每个 `ToonSpec` 分配的 ID，描线和卡通着色都按它查表（ENG-ARCH §3）。
- **`ToonSpec`**：内容代码取卡通材质的唯一方式，由材质库映射到白名单着色器（ENG-ARCH §3）。
- **细节级别**（L0+–L4）：按屏幕误差切换的建筑与地块级别，本机烘焙；新内容只做近中远三档（ENG-BUDGET-LOD §1、DECISION-232）。
- **格**（tile）：四叉树的格子，每级一种边长（ENG-BUDGET-LOD §1、ENG-PERF-STREAM §1）。
- **`TileBundle`**：一格一级的烘焙产物（ENG-PERF-STREAM §1、ENG-ARCH §4）。
- **流式不变量**：流式的几条硬约束：最远级与外围远层常驻、父格等子格、按字节淘汰、看门狗、碰撞未就绪冻结物理、进楼衔接（ENG-PERF-STREAM §1）。
- **父格等子格**：子格都就绪之后才在同一帧切换父子格的可见性（ENG-PERF-STREAM §1）。
- **流式屏障**：录像时每帧同步等本帧要用的格全部就绪，所以录像可以复现（ENG-GATES-SHOTS §1、ENG-PERF-STREAM §1）。
- **份额**：各内容模块按内容类分到的三角形、绘制调用、GPU 帧时和主线程预算；订阅用量的额度另见 WF-MODEL §9（ENG-BUDGET §3、§1）。
- **硬规则**：违反任何一条都不能推送的性能规则（ENG-BUDGET-RULES §1）。

## 14 工程与流程

- **接入要点**：每份规范文档 §0.1，写其他施工方碰到本文管的东西时必须遵守的规则（STD-DOC）。
- **查阅行**：范围块里的"查阅"一行，说明本文什么内容在哪一节（STD-DOC）。
- **小节目录**（`SECTIONS.md`）：由脚本生成，每份文档的每一节一行，供按关键词定位（STD-DOC）。
- **信息地图**：顶层 CORE-INDEX §1，写各类信息在哪、仓库目录和各域总纲入口；只列域，不列文档（STD-DOC §1）。
- **域总纲**：每个文件夹一份的 `<前缀>-INDEX`，写本域通用原则和本域文档树（STD-DOC §1、§3）。
- **主题文档**：域总纲下面的文档，每份管本域的一个主题（STD-DOC §1、§5.1）。
- **子文档**：主题文档按内容拆出来的文档，文件头写 `parent: <主题文档编码>`，不再往下套（STD-DOC §5.1）。
- **主会话**：开发期的编排者，维护文档和决策登记，审批契约变更、开放室内清单的增删和预算余量；"指挥"指主会话或 Codex 主线（WF-ROLE、DECISION-161、WF-FLOW §3.1）。
- **独占目录**：派工简报为本次任务指定的写入目录；同一批文件同一时刻只有一个写者（WF-FLOW §2.1）。
- **契约**：`Campus.Contracts` 程序集里的接口、record、枚举和 JSON schema；分批冻结，冻结后只增不改（ENG-ARCH §3、DECISION-134）。
- **桩**：契约、桩与拆除（ENG-ARCH） 交付的占位实现，让所有包第一天就能运行和截图（ENG-ARCH §5）。
- **编目先行**：共享部件的 ID 和参数先登记在 `PartCatalog`，各区按 ID 放，部件完成后自动换成真模型（ENG-ARCH §5）。
- **内核**：Godot 侧的核心模块；只有内核能创建渲染实例，也只有内核能计时（ENG-ARCH §2）。
- **Kernel 服务**：用 `[KernelService]` 注册的全局服务，需要新的全局对象一律这样做（ENG-ARCH §2）。
- **自动发现**：内核启动时扫描特性并注册，新模块打上特性就能接入，不改共享文件（ENG-ARCH §2）。
- **内容模块**（`IContentModule`）：gen 里按格出几何、部件和碰撞的纯函数模块（ENG-ARCH §3）。
- **认领**（`Claim`）：内容模块声明自己负责哪些要素或区域；冲突由 G5 报（ENG-ARCH §3）。
- **build 与 mount 分开**：生成在纯 .NET 里，挂载和动态物体只在主线程（ENG-ARCH §2）。
- **烘焙器**：调用与运行时同一个 `Build()`，按"格 × 级"存成产物（ENG-ARCH §4、ENG-PERF-STREAM §1）。
- **烘焙缓存**：几何类烘焙产物，发布时全图烘好随包发，玩家缓存缺失才在本机补烘；只重烘输入改到的格（DECISION-165、ENG-ARCH §4）。
- **世界文件**：`world/<区>.json`，每区一份，记录就是 `WorldFeature`；增删改直接改记录（STD-CONVENTIONS §3.1、MAP-QSH-ADDITIONS §0）。
- **世界模型**（`IWorldModel`）：解析世界文件、地形、外围与室内索引得到的只读模型，带空间索引（ENG-ARCH §3）。
- **门禁**：自动检查共 12 项（ENG-GATES §1.2），统一入口按改动路径选域；分快检、核心专项、集中测试三档（ENG-GATES §1、DECISION-167）。
- **快检、核心专项、集中测试**：测试的三档：每次推送前的快检，碰到核心体验才跑的专项，大量开发之后的全量测试（ENG-GATES §1）。
- **主线、主线版**：主线是玩家从启动到离开走得通的一条完整体验；主线版是各项活先交的最低可用版本（CORE-INDEX §0、WF-RULE §8）。
- **全局不变量**（INV-1–INV-12）：观光规则集的总约束，与门禁不同号；引用写"INV-n"（PRD-INVARIANTS、DECISION-156）。
- **审查视角**：门禁截图用的固定位姿与路线（ENG-GATES-SHOTS §1）。
- **截图默认串**：冻结世界状态、天气、画质、地图、开场、存档和声音的一组命令行参数（ENG-GATES-SHOTS §1）。
- **巡检点**：每个内容模块在自己区里登记的 3–4 个近景检查点，编号 1–4（ART-FIDELITY §4）。
- **时季矩阵**："时刻 × 季节"的抽样验收，集中测试时拼图看一眼（ENG-GATES-SHOTS §1.5、SYS-TIME §4）。
- **主检出**：仓库本身所在的目录，唯一的工作目录，始终在 `main` 上（WF-RULE §7、DECISION-211）。
- **构建锁**：编译、导入、烘焙、门禁、截图和基准排队用的锁，一次只跑一个（WF-BUILD §4、ENG-GATES §1）。
- **阶段**：主线闸口、闸口之后各区做细节、收尾做最后一次集中测试；P0–P3 的对应见 WF-STATUS §1。
- **P0**：项目最早的骨架与原型阶段；文档里仍标 P0 的待验证项按实测定值，验证前用文中的初值（WF-STATUS §1）。
