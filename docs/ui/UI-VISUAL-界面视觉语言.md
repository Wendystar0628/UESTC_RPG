# UI-VISUAL · 界面视觉语言：设计原则、色彩令牌、主题与实现边界

> **范围**：界面外观规范的根：设计原则、色彩分工与令牌、晶白与深屏两套主题、实现边界。主题是信息、芯片、光与计算，主色清蓝 #73C9F9，专业克制；界面、图标和锚点里不用银杏。字体、形状、图标、组件、画面布局与动效在子文档。
> **不在本文**：字体、形状材质、图标、组件外观与画面布局（UI-VISUAL-COMPONENTS）；动效与减少动态效果（UI-VISUAL-MOTION）；界面有什么、怎么操作见 UI-NAV；地图与传送卡见 SYS-ATLAS；开始页与过场见 SYS-TITLE；提示音见 SYS-AUDIO；额度见 ENG-BUDGET；门禁判据见 ENG-GATES G14。
> **查阅**：先读 §0，再按节号查；字体、形状、图标、组件、布局看 UI-VISUAL-COMPONENTS；动效看 UI-VISUAL-MOTION

## 0 结论

1. **一句话**：界面是叠在暖色手绘世界上的一层冷光精密仪器；**光是信号，不是装饰**。静止时只有平面、1 物理像素的发丝线和等宽数字，状态变了、确认了、正在进行才出现光和运动（§1）。
2. **主色清蓝 #73C9F9，场景暖、界面冷**：清蓝只在界面层，不进 3D 材质，世界里不放蓝色全息；深端 800、900 取校色，只作小面积；界面唯一的暖色点是窗灯色 #FFE0A8，只表示"太阳 / 此刻"（§2、§3）。
3. **两套主题**：白天"晶白"、夜间"深屏"，按真实太阳高度带回差离散切换，一道扫描前沿 0.6 s 扫过，不做连续混色；**常驻小部件固定用深屏**（§2.3、§3.4）。
4. **形状、字体、图标、组件、布局**见 UI-VISUAL-COMPONENTS：每个容器只切左上一个 45° 角，边线 1 物理像素（UI-VISUAL-COMPONENTS §2）。
5. **动效**见 UI-VISUAL-MOTION：八个母题按频率分级，每个都有"减少动态效果"的替代（UI-VISUAL-MOTION §1、§2）。
6. **一个 Theme，由代码生成**，随主题变的颜色走 `ui_panel` 着色器（§4）。

### 0.1 接入要点

- **取色**：只用 `game/style/palette/ext/ui.json` 里的色名，经 `UiPalette` 读；代码和着色器里不写十六进制色值（G4）；缺色名由 WP-35 登记（§3.6）
- **画面板、按钮、文字**：用 `UiThemeBuilder` 生成的那一个 Theme，不写零散的 `theme_override_*`；随主题变的颜色走 `ui_panel` 着色器按 `ui_night` 取值；界面着色器只用白名单里的 `ui_panel` 与 `ui_screen`（§4）

## 1 设计原则

- **只取结构，不取材质**：分层、编号、刻度、45° 走线、1 号脚切角、过孔、薄膜衍射是结构；彩色裸片、绿色电路板、CRT、全息箔一用就廉价。

**七条硬规则**：

1. **细线**：边线一律 1 物理像素，2 px 只给选中指示条。
2. **网格**：8 px 基准，所有元素对齐，界面与地图上都不画网格线；数字右对齐、等宽。
3. **留白**：面板内边距 ≥ 16 px；一张卡片一个主操作，每屏最多一个主按钮。
4. **单色加一点**：清蓝阶梯加冷灰加墨；暖色只表示"太阳 / 此刻"，一屏最多一处。
5. **光是状态**：闲置界面零发光；只有焦点、选中、"此处"、进行中会亮。
6. **数据要真**：界面上的每个数字都来自世界状态、存档或画面设置，不放装饰性数字。
7. **动有因、动有终**：动效只回应操作或状态变化；缓出、可打断、不回弹；揭示类效果每次打开只播一次。

**一律不做**：霓虹发光字、满屏辉光、赛博朋克配色、数字雨；常驻扫描线、CRT 弯曲、故障艺术、RGB 错位；四角全切或八角的厚 HUD 框、角括号、满铺电路纹；透视倾斜的面板、循环脉冲、待机呼吸、回弹与过冲；科幻字体、超粗正文；3D 世界里的蓝色全息标记、光柱信标、选中描边。

## 2 色彩分工与常驻件

### 2.1 场景暖，界面冷

场景本是暖对冷的冷暖对照（ART-SKYLIGHT §5），清蓝界面站进"冷的那一半"就不是外来物；唯一的暖色点取窗灯色。

- **界面色 `ui.*`** 只在界面层（放映层 9、界面 10、署名 11），不进 3D 材质、调色板纹理、光照和后期；
- **深端校色**（800、900）只用于字、1 px 线、小图标，单块要小。
- **暖色点** `ui.now` = `window.warm`：时间环上的太阳把手、推荐时刻的小点。**语义色**只在对话框、提示和数值警示里，总配图标和文字。
- **再现场景的画**（缩略图、存档截图、时间环的天色光谱、地图绿地）可以带场景色，光谱彩度压到 70%；季节花色和银杏金不进控件。常驻 HUD 里的清蓝克制、小面积（大页除外）。

### 2.2 与场景色不冲突的规则

1. **清蓝不直接贴在天上**（与天蓝太接近）：只出现在面板底上，或带 1 px 深色描边；小地图、锚点、光标都先有一层底。
2. **清蓝不当晶白主题的正文字色**（对比太低）：晶白里蓝字用 800 档，线与图形用 700 档，300–500 档只作填色、上面压墨字；深屏反过来，300–400 档是字和线。
3. **界面不吃场景后期**：暗角、分调、LUT 都在界面之前完成，`hdr_2d` 保持关。

### 2.3 高调画面上的面板与常驻件

晶白面板对清透高调的画面明度对比只有 1.05–1.16，会"化"进去，所以：

- **常驻小部件固定用深屏**（对画面明度对比 8–14:1）：小地图、时间卡、临时提示、到达标题推荐小条、速度条与观察模式、天气签条、右上图标钮（清单以 `ui_metrics.json` 的 `themeSwitch.pinnedDark` 为准）。交班时它们不跳变，扫描前沿只扫大页；小地图在深屏框里用夜间配色，读作"芯片版图"。
- **大页与对话框随主题**：大地图、设置卡、存档页、确认对话框，以及从开始页打开的这些页。大地图、存档页、对话框背后有 `scrim`；设置卡不压暗，但贴左整块、有外缘线，晶白下也分得开。
- **晶白的固定规格**：面板外缘一条 1 px 墨色描边 `line.panel`；设置"常驻件：随主题"时，晶白的常驻面板再加一层带蓝墨色的环境影。

## 3 令牌

**色值以 `game/style/palette/ext/ui.json` 为准，非色令牌（尺寸、字号、线宽、时长）以 `game/hud/style/ui_metrics.json` 为准。**色名前缀 `ui.`，阶梯写作 b-400、n-25；对比度按 WCAG 2.2 校验。

### 3.1 清蓝阶梯

以 #73C9F9 为 400 档排 50–950 共 11 档：浅端略偏青，深端渐移到蓝调天空的色相，夜里不显得外来；800 #1961A0、900 #003F8D 直接取校色。400 是主色（主按钮底、开关开、选中滑块、深屏的图形）；800 是晶白的强调字、焦点核、选中指示条，晶白的线与图形用 700；900 只作小面积。

### 3.2 中性、专用与语义色

- **中性与专用色**：中性是带一点蓝的冷灰阶梯。`ui.ink` 是晶白正文、标题与投影色（带蓝的墨，ART-STYLE 的"禁止纯黑"延伸到界面）；`ui.screen` 是**深屏面板底**；`ui.nighttext` 是深屏正文；`ui.iris.a / b` 是衍射光边两侧的冷色色散（偏青、偏紫），不出现暖色。
- **语义色**：成功（绿）、警告（琥珀）、危险（红），各有晶白字、深屏字和按钮实底三个值；危险按钮永远不是默认焦点。

### 3.3 两套主题的语义令牌

控件按语义令牌取色，不直接写阶梯名：`surface.*`、`text.*`、`line.*`、`primary.*`、`graphic`、`glow`、`scrim`、`shadow.float`、`over.title`；晶白与深屏各一份取值，在 `ui.json` 的 `themes`。

- 深屏的 `glow` 是 b-400 的细光，晶白无；`over.title`（直接压在画面上的标题）不随主题：白字加暗投影加背后 55% 的椭圆暗带。

### 3.4 昼夜切换

**不做连续混色**：面板底和字色同时线性混合时，对比度在中点塌到 1.0:1，1× 流逝下约 25 分钟读不清。

- **信号与回差**：看真实太阳高度（SYS-TIME §2），阴雨天不提前切；晶白时下穿 −0.5° 切到深屏，深屏时上穿 +0.5° 切回晶白，暂停在阈值附近不来回闪。
- **过渡**：一道扫描前沿 0.6 s 扫过随主题的画面，日落从左向右、日出从右向左（参数以 `ui_metrics.json` 的 `themeSwitch` 为准），每个像素只处于日态或夜态之一。没开大页时看不到交班，只有时间环上的日、月把手互换。快进途中不判断，结束后按终点判一次。
- **设置项**：界面主题"自动（默认）/ 晶白 / 深屏"，锁定时不切换；子项"常驻件：深屏（默认）/ 随主题"。开始页、过场字幕与标题卡、`over.title` 类压在画面上的标题不随主题（"影院处理"，SYS-TITLE）。

### 3.5 对比度规则

文字 ≥ 4.5:1，图形与控件 ≥ 3:1；G14 只检晶白、深屏两套主题下的正文、控件边、主按钮三组代表，不对每个令牌穷举。设计上必须遵守：

- 晶白主按钮填色 b-400 对面板对比太低，**必须加 1 px b-800 内描边**；暖色点对晶白对比太低，**必须加 1.5 px 墨描边**（深屏上不描边）。
- 禁用件按 WCAG 豁免，但要有可读的原因并保持可聚焦。**状态从不只靠颜色**：选中同时有底色和指示条或过孔灯，过孔灯有实心和空心之分。

### 3.6 登记

`ui.json` 由 WP-35 登记（ART-STYLE §2.5：界面色不分色号、不进调色板纹理）；`map` 部分是地图的色名 `map.*`，SYS-ATLAS 只引用色名。地图上不用暖色点；玩家、选中、追踪和可传送标记的"通电"状态是地图上唯一出现清蓝的地方。

## 4 实现边界

- **一个 Theme，由代码生成**：`UiThemeBuilder` 从 `ui.json`（色名）和 `ui_metrics.json`（尺寸、字号、时长）生成唯一的 Theme，运行时不修改。G4 禁止代码里写十六进制色值和 `main.tscn` 以外的共享 `.tres`。随主题变的颜色全部由 `ui_panel` 按全局参数 `ui_night` 取日、夜两值；悬停、流光、焦点、量化、常驻件的固定主题用 instance uniform。
- **两个白名单着色器分成两个文件**：`ui_panel`（切角、发丝线、辉光、M1/M5/M6/M7、交班前沿，不读屏幕）与 `ui_screen`（整页揭示与大页磨砂，读屏幕纹理）；着色器一旦出现屏幕纹理就会触发一次背景拷贝，不管分支走没走到。发丝线与辉光不用 `StyleBoxFlat` 的整数边框，也不走 3D 的 bloom。
- **主题切换**：唯一写 `ui_night` 的是 WP-35 的 `UiThemeClock`，它是扫描前沿的位置，不是颜色插值量；常驻件的材质写 instance uniform `pin_night = 1`，始终是夜值。凡是画面板和文字的地方都必须走这个机制，否则夜里会出现"浅底浅字"（G14 要抓的典型错误）。
- **`hdr_2d` 固定为关**：界面画在后期之后，颜色逐像素原样上屏。动效只改 `Modulate`、不在容器里的 `Position` 与 `Rotation`、instance uniform 和 `ui_night`。
- **大页按需创建、关闭即释放**：挂上 `ui_panel` 材质就占一个全局实例参数池的槽，只有释放节点才归还。
- **界面缩放**：拉伸比例已让界面随窗口等比放大，所以 **`ContentScaleFactor` 不乘系统 DPI**，否则 DPI 会被算两遍；设置"界面缩放"的最终值夹在"字不小于设计字号的 85%"与"逻辑视口不小于 1280×720"之间。
