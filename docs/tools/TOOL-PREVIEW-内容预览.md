# TOOL-PREVIEW · 内容预览

> **范围**：本文规定开发时怎样预览和回看内容：从开发入口启动，按实体 ID 找到对象，改了覆盖层或参数以后在同一机位、同一时季天气下回看，把机位记下来。这些功能只在开发构建里有。
> **不在本文**：命令行参数表（`game/kernel/boot/BootArguments.cs`；截图默认串见 ENG-GATES §1）；覆盖层的格式（CORE-CONVENTIONS §3.1）；`--gen=live` 与烘焙（ENG-ARCH §4）；同图重载（SYS-MAPS §3.5）；近景巡检点（ART-FIDELITY §8）。
> **查阅**：先读 §0；起点参数看 §1；按实体定位看 §2；机位文件看 §3；改了以后怎么回看看 §4

## 0 结论

1. **预览只读不写**：覆盖层（`overlay/<组>.d/` 分片）和各包自己的代码、数据文件是唯一的保存源。预览不写仓库里的任何文件，只在开发态的 `user://` 里记机位；代理照旧不在编辑器里打开或重存场景（ENG-ARCH §6）。
2. **一次回看的循环**：定位对象 → 改覆盖层或参数 → 在原机位、原时季天气下回看 → 满意后提交改过的文件。
3. **第一版只做整图重载和重启后恢复机位**：改数据用同图重载，改代码重新编译后重启；不做 C# 热重载，不做地图编辑器。
4. **读不进来时保留上一次有效的画面**：新数据校验不过就不卸载当前图，不崩、不黑屏。

### 0.1 接入要点

- **预览或回看自己的内容**：从开发构建启动，起点 `--pose`、`--focus=<实体 ID>`、`--pose-file` 三选一，同时给出以非零退出码结束（§1）
- **改了覆盖层或按图的 JSON 数据**：F5 校验并同图重载；改了着色器、调色板等启动时读的文件按 F7 重启；改了 C# 重新编译后带 `--pose-file` 启动（§4）
- **要保存调整**：位置和轮廓写进覆盖层的 `reshape`、`add`，参数改在负责包自己的文件里；预览不存盘（§0 第 1 条、§4）
- **说明截图从哪里拍**：F6 复制机位，把 JSON 贴进回报（§3）
- **新增点位或审查视角**：把机位交给负责的包登记（`waypoints.json` 归 WP-36，`review.json` 归 WP-27），预览不改这两份文件（§3）
- **只看效果的截图**：`--pose-file` 加 `--out=<绝对路径>.png`，不算门禁（§4）
- **数据校验不过**：画面保持上一次有效的结果，错误显示在屏幕上方、完整信息写日志（§4）
- **写导出版或门禁的启动参数**：`--focus`、`--pose-file` 和 F5–F7 只在开发构建里有，release 版按未知参数以非零退出码结束；两者属世界类参数，不能与 `--slot`、`--load` 同时给出（§1）

## 1 启动

起点三选一（同时给出以非零退出码结束）：`--pose=<编号>` 点位或审查视角；`--focus=<实体 ID>` 按实体定位（§2）；`--pose-file=<绝对路径>` 回到记下的机位（§3）。

- 世界参数的写法与截图默认串相同（ENG-GATES §1）；预览时常加 `--gen=live`（实时生成，不读不写烘焙缓存）、`--ui=1`、`--flow=0`。
- `--focus`、`--pose-file` 与 F5、F6、F7 只在开发构建（`OS.IsDebugBuild()`）里有。
- `--pose-file` 的文件读不到或字段不合法时以非零退出码结束；文件里的地图、模式、机位和世界参数覆盖命令行里的同名参数，其余参数照常。

## 2 按实体 ID 定位

- ID 是 `campus.json` 的实体或覆盖层新增的 `design:` 实体（CORE-CONVENTIONS §3.1），按 ID 查世界模型，不按名字找。
- **机位**：目标点取实体包围盒的中心，方位 200°、仰角 30°，距离取刚好装下包围盒的值（写法见 CORE-CONVENTIONS §1.2）；落在可达空间外时就近合法化（WLD-OUTSKIRTS §7.1），不退出。
- 查不到这个 ID 时以非零退出码结束，日志写明查不到的 ID 和本图的实体前缀。

## 3 记下机位

- **F6 复制机位**：把当前机位和世界参数写成一段 JSON 放进剪贴板，同时写到 `user://preview/last-pose.json`（开发态 `user://` 是 `UESTC_DEV`）；开发构建正常退出时也写一次。
- 字段含地图、观察模式、位置（行走时是脚位）、偏航、俯仰、钟点、季节、天气、动画时钟，名称与取值和命令行参数一致。
- **用途**：用 `--pose-file` 回到这个机位；贴进回报说明截图从哪里拍；新增点位或审查视角时交给负责的包登记。

## 4 改了以后回看

| 改了什么 | 怎么回看 | 机位与世界状态 |
| --- | --- | --- |
| 覆盖层、按图的 JSON 数据 | **F5**：后台重新解析并校验本图数据，通过后同图重载（`--gen=live` 下重新生成） | 落回按键那一刻的机位，钟点、季节、天气不变 |
| 只在启动时读的文件（着色器、调色板、树种表等） | **F7**：写下机位后自动重启，重启参数是原参数换上 `--pose-file` | 落回按键那一刻的机位与世界参数 |
| C# 代码（生成器、部件参数） | 关掉程序（自动写下 `last-pose.json`）→ 重新编译（资源有变再 `--import`）→ 带 `--pose-file` 重新启动 | 落回关掉时的机位与世界参数 |

- **校验不过**（JSON 语法、schema、两个覆盖层改同一个要素，以及 G5 会报的数据错误）：不卸载当前图，画面保持上一次有效的结果，屏幕上方显示一行错误；改好后再按 F5。
- **预览里不能做的**：拖动、摆放物体，改颜色或参数后直接存盘。
- 分工：WP-01 做参数解析、三个按键、机位文件与重启后落回；WP-08 做按实体 ID 查世界模型与后台重读校验；WP-46 让同图重载在开发构建里对预览开放（平时只在 `--gate=maptravel` 下启用）；WP-02 在 `--gen=live` 下重载时按同一个 `Build()` 重新生成。
