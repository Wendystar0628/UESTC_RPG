# TOOL-PREVIEW · 内容预览

> **范围**：本文规定开发时怎样预览和回看自己做的内容：从开发入口启动，用 `--pose` 放到机位，改了世界文件或参数以后在同一机位、同一时季天气下重新启动回看。按实体定位、机位恢复与热重载在主线之后（§3）。
> **不在本文**：命令行参数表（`game/kernel/boot/BootArguments.cs`；截图默认串见 ENG-GATES-SHOTS §1）；世界文件的格式（CORE-CONVENTIONS §3.1）；`--gen=live` 与烘焙（ENG-ARCH §4）；同图重载（SYS-MAPS §3.5）；近景巡检点（ART-FIDELITY §4）。
> **查阅**：先读 §0；起点参数看 §1；改了以后怎么回看看 §2；主线之后的预览能力看 §3

## 0 结论

1. **预览只读不写**：世界文件（`world/<区>.json`）和各包自己的代码、数据文件是唯一的保存源。预览不写仓库里的任何文件；代理照旧不在编辑器里打开或重存场景（WF-BUILD §4）。
2. **一次回看的循环**：改世界文件或参数 → 带原来那组 `--pose` 与世界参数重新启动 → 回看 → 满意后提交改过的文件。
3. **不做 C# 热重载，不做地图编辑器**：改数据或代码后重新启动，改了代码先重新编译。
4. **按实体 ID 定位、记下机位、重启后恢复机位、不重启的数据重读是主线之后的设计**，现在没有（§3）。

### 0.1 接入要点

- **预览或回看自己的内容**：从开发构建启动，起点用 `--pose=<编号>`，世界参数的写法与截图默认串相同；不要用 `--focus`、`--pose-file`，它们现在只被解析、不可用（§1）。
- **说明截图从哪里拍**：在回报里贴出整串命令行（§1）。
- **只看效果的截图**：`--pose` 配合截图参数，不算门禁（ENG-GATES-SHOTS §1.2）。
- **新增点位或审查视角**：把机位交给负责的包登记（`waypoints.json` 归 WP-36（点位与跳转），`review.json` 归 WP-27（门禁、截图与巡检自动化）），预览不改这两份文件（§1）。
- **改了世界文件、按图的 JSON、着色器、调色板或 C#**：重新编译（资源有变再 `--import`）后重新启动回看（§2）。

## 1 启动

起点是 `--pose=<编号>`：点位或审查视角。

- 世界参数的写法与截图默认串相同（ENG-GATES-SHOTS §1）；预览时常加 `--gen=live`（实时生成，不读不写烘焙缓存）、`--ui=1`、`--flow=0`。
- 新增点位或审查视角时，把机位和世界参数写进回报，交给负责的包登记。

## 2 改了以后怎么回看

| 改了什么 | 怎么回看 |
| --- | --- |
| 世界文件、按图的 JSON 数据、着色器、调色板、树种表等 | 关掉程序后带同一串参数重新启动（`--gen=live` 下重新生成） |
| C# 代码（生成器、部件参数） | 重新编译（资源有变再 `--import`）后带同一串参数重新启动 |

- 数据校验不过（JSON 语法、schema、重复 ID、引用了不存在的记录）时，加载按数据错误报出并退出；改好后再启动。
- 预览里不能做的：拖动、摆放物体，改颜色或参数后直接存盘。

## 3 主线之后

下面是预览的设计目标，建成前不要在命令里使用：

- **按实体 ID 定位**：按世界文件里的 ID（含 `design:` 开头的设计增补）查世界模型，机位取实体包围盒中心、方位 200°、仰角 30°，距离刚好装下包围盒；查不到 ID 以非零退出码结束。
- **记下与恢复机位**：把当前机位和世界参数复制成一段 JSON、开发态下记到 `user://`，下次启动回到同一机位与时季天气；开发构建里的按键只在开发构建有，release 版按未知参数处理。
- **同图重载**：改了世界文件或按图的 JSON 后，不重启而是后台重读校验、通过后同图重载并落回原机位；校验不过则保持上一次有效的画面，错误显示在屏幕上方、完整信息写日志。
