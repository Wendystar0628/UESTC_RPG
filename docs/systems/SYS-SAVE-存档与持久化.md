# SYS-SAVE · 存档与持久化：存档模型、存什么、保存时机、加载与一致性、安全

> **范围**：本文规定存档服务 `ISaveService` 给玩家的行为与边界：存档位与世界线，各存档段存什么、不存什么，保存时机与可靠性，读档流程与"状态一致"的定义，关游戏期间不计时，损坏与版本不兼容，设置类文件与存档的安全原则。
> **不在本文**：文件布局、DTO、写盘步骤（`game/kernel/save/`）；契约签名（`game/contracts/Save/`）；帧顺序（ENG-ARCH §3）；命令行与 G20（ENG-GATES）；性能额度（ENG-BUDGET §8）；各段的字段（各包）；开始页与继续过场（SYS-TITLE）；换图（SYS-MAPS）；天气过程（SYS-WEATHER）。
> **查阅**：先读 §0；存档位与世界线看 §1；各段存什么看 §2；保存时机、安全时刻与退出看 §4；读档顺序与世界实例看 §5；设置文件看 §8；安全看 §9

## 0 结论

1. **存档是 Kernel 服务 `ISaveService`，不加 Autoload**。各系统用 `[SaveSection]` 声明一段，自动发现。存档包只管容器、版本、保存时机、可靠性；各段存什么由各包负责（§2）。
2. **3 个存档位 `s1`–`s3`**，各装一条世界线，进入后持续自动保存；"继续"取最近保存的存档位。手动槽只在格式里预留（§1）。
3. **每次保存写新文件，保留 3 代，不覆盖**；禁止用 Godot Resource、ConfigFile、`StrToVar` 一类能创建对象的方式存读档（§3、§9）。
4. **保存时机**：退出、返回标题、新游戏交还控制时立即保存；漫游态每 5 分钟、关键动作落定后、窗口失焦时限频保存，在安全时刻拍快照（§4）。
5. **一致性**：读档后的状态等于存档那一刻的落定状态；在安全时刻拍的存档续跑等价；读档换一个世界实例（§5）。
6. **代价**：断电、强杀最多丢最近 5 分钟；过渡、偶发事件、打开的面板不续播；首版读档一律恢复成步行（§4、§5.3）。
7. **存档会被玩家互相分享，读档输入不可信**：最多把世界摆成合法状态，不执行代码、不创建任意对象、不耗尽内存（§9）。

### 0.1 接入要点

- **有要跨读档保留的状态**：在本包的 `[KernelService]` 或 `[KernelNode]` 上实现 `ISaveSection<T>` 并标 `[SaveSection]`；不自己读写 `user://`，不加 Autoload（§2）
- **决定一段存什么**：只存读档后重建不出来的落定状态；音频状态、打开的面板、偶发事件计时、画质统计、烘焙缓存、玩家身体与动物的瞬态都不进存档（§2、§5.3）
- **段的数据**：只放基础类型、向量、契约枚举和 ID，不放 `object`、Godot 类型或开放多态（§3.3）
- **段的字段有任何增减**（哪怕只加一个可选字段）：段版本加 1，并写迁移函数；迁移是纯函数，不碰 Godot、不读服务状态（§3.4）
- **`Capture` 与 `Restore`**：`Capture` 在任何时刻都给出落定值（过渡中取终点，空中、水里、骑行中取最近的岸上安全点），不做 I/O，全部段合计 p99 ≤ 0.3 ms；`Restore` 立即生效、不做过渡，核对长度与范围，修一处记一处（§4.2、§5.6）
- **存档里引用别的数据**：只存 ID，不存文件路径；ID 不复用，确需换 ID 时提交 ID 迁移表并升段版本（§3.4、§9）
- **关键动作落定要触发保存**：调 `ISaveService.Request`，由服务合并、限频、等安全时刻，只在漫游态有效（§4.1）
- **看到 `IWorldState.Instance` 变了**：做平滑、带回差或保留历史的系统把内部状态直接设成新世界的值，不做过渡（§5.2）
- **读写档案级设置文件**：先查文本有无 `Object(` 等写法再解析，只接受基本类型，写入走临时文件加替换（§8）
- **想用现实时间**：系统时钟只能在存档包里读、只写进 meta 用于显示，世界状态不读它（§6）

## 1 存档模型

- **存档位**：3 个，ID 是 `s1`、`s2`、`s3`。一个存档位装一条**世界线**：从一次新游戏开始，到它被另一次新游戏覆盖为止。进入游戏后这个存档位就是**当前存档位**（`ISaveService.Active`），自动保存都写到这里；观光期界面上没有"保存"按钮。
- **继续**：在健康状况为 `Ok` 或 `RecoveredOlderGen` 的存档位里，取最新可读一代保存时间最晚的那个，相同时按 `s1`、`s2`、`s3` 取。没有就不显示"继续"，开始页焦点落在"新游戏"（SYS-TITLE）。
- **新游戏**：有空位用第一个空位；三个都满时由开始页的存档页选一个覆盖并二次确认。旧世界线要等新世界线的第一代校验通过后才删。
- **代号与世界线号**：每个存档位内代号严格递增；世界线号等于这条世界线第一代的代号；回退只在同一条世界线内进行（§7）。
- **保留 3 代**：新一代校验通过后删掉同一世界线里更早的代，其他世界线的旧代一并删掉。存档位里永远至少有一代可读。
- **手动槽（预留）**：`m1`–`m9`，只在观者明确保存时写，只留 1 代。
- **单实例锁**：进程整个生命期独占一把锁，崩溃后由系统自动释放。打不开锁（另一个窗口在运行）时本进程只读存档，不写、不挪文件，并提示一次"另一个窗口正在运行 · 本窗口不保存"。
- 冷启动时在扉页后面读入"继续"的存档位并预览恢复，开始页 T0 显示的就是这个世界（§5.1）；开始页和进场过场期间不自动保存。

## 2 存什么、不存什么

恢复分三个阶段：`World`（世界与天气）→ 换图 → `Content`（按图内容与进度）→ `Pose`（视角与行走）。换图要先知道全局时间和那张图的天气；视角与行走在换图之后落位。

| 段 | 范围 | 负责 | 阶段 | 存 |
| --- | --- | --- | --- | --- |
| `maps` | 全局 | WP-46 | World | 当前地图；每张到过的图一条 `MapVisit`（最后位姿、模式、离开时的天气 epoch 与世界时间） |
| `world` | 全局 | WP-34 | World | `WorldHours`、钟点 offset、季节、流逝倍率、`AnimTime`（过渡进行中存终点） |
| `weather` | 全局 | WP-45a | World | 本存档的天气基础种子 |
| `map:<id>/weather` | 按图 | WP-45a | World | 天气过程状态与过去、前瞻各 24 h 的队列、手动与钉住窗口、湿润积水余量 |
| `map:<id>/atlas` | 按图 | WP-48c | Content | 自定义标记（每图 ≤ 50 个）、追踪目标、解锁状态 |
| `progress` | 全局 | WP-36 | Content | 到过的点位 |
| `view` | 全局 | WP-06 | Pose | 观察模式、旁观位姿、所在空间、速度档 |
| `walk` | 全局 | WP-42 | Pose | 脚位、朝向、潜行、步速档、安全点环 |

- 按图的段键是 `map:<MapId>/<段 ID>`。视角只存当前一份，每张图的最后位姿在 `MapVisit`。自定义标记的 ID 用按图递增的整数。
- 游玩时长、代号、世界线号、本局规则集 ID 存在 meta 里，不另设段；规则集的内容不进存档。
- **不存**（读档后重建）：音频状态；打开的面板、纯净模式；偶发事件的进度与计时；流式与画质的统计；玩家身体的姿态、湿度与平滑历史；泳态；动物的反应；骑姿与速度；开放室内房门与防火门的状态（存档时一律按关好记）。
- **游泳与骑行**：在水里或骑行中保存，`walk`、`view`、`maps` 与 meta 的位姿都指向同一个最近的岸上安全点。保存只记下这个点，不把人真的挪走。
- **共享单车**（SYS-WALK §13）：车辆一段由 WP-55 负责，按图记每辆可借车的停放归属；保存时借的车按归还记；旧档缺这一段时按基线初始化一次。
- **以后 RPG 的预留段**（ENG-ROADMAP §6 第 6 条）：`quest`、`inventory`、`character`、`flags`、`calendar`、`agents`，以及按图的 `map:<id>/objects`（记相对烘焙基线的差分，键用 `FeatureId`）。
- **档案级文件**不进存档，换存档位不变：`settings.cfg`、`input.cfg`、`graphics.cfg`、`engine_override.cfg`、`audio.cfg`（§8）。`user://cache/bake/` 是本机烘焙缓存，不是存档（SYS-MAPS §1.2）。

## 3 格式与迁移

### 3.1 容器

布局与写盘步骤以 `game/kernel/save/format/` 为准。规则：

- 一个文件依次是定长头、未压缩的 meta JSON、压缩的分段 JSON 正文、WebP 缩略图。**meta 可单独读**：存档卡只读它；读档仍校验整个文件的哈希。
- meta 记存档位、代号、世界线号、游玩时长、地图、世界时间、季节、天气、模式、位姿与空间、规则集、保存原因、系统时钟时间。**系统时钟时间只用于显示，从不进入世界状态**（§6）。
- 哈希（SHA-256）只发现损坏，不防修改，不加密：观光作品里改存档不算作弊。
- **不用"临时文件 + 改名"**：每代都是新建的文件，写了一半就断电，这一代校验失败，读档退到上一代。
- 未知段原样保留，写回时照抄；缺段用 `CreateDefault` 补。
- 版本三层：容器版本（RPG 开工只加段不改容器）、`format`、每段的 `v`。

### 3.2 缩略图

384×216 的 WebP。只在退出、返回标题、窗口失焦、新游戏交还控制时抓新图（抓帧前隐藏界面，最小化时沿用），其余保存沿用上一代；缩放编码放后台；解码时尺寸超限就丢弃。

### 3.3 序列化约定

- 每个包用源生成的序列化上下文，约定同契约的 `ContractJson.Options`：camelCase，枚举按字符串写，向量写成数组，ID 写成字符串。
- 每段一个只读 `sealed record`，只放基础类型、向量、契约枚举和 ID。
- 缺字段、未知字段、不认识的枚举字符串都按"这一段不合法"处理（§7）；快照里出现 NaN 与 ∞ 是 bug。只用带 `JsonTypeInfo` 的重载（G4）。

### 3.4 版本与迁移

- **段版本**：一段的字段有任何增减都升 `v`，纪律同契约的"只增不改"，旧构建遇到新档时只会只读，不会丢字段再写回去。
- **迁移**：每段自带逐版本的纯函数 `Migrate(v) → v + 1`，读档时在后台线程按链迁到当前版本；迁移后不立即写回，等下一次正常保存。
- **新于本构建**：容器版本、`format` 或任一已登记段的 `v` 比本构建新，整个存档位就是 `NewerBuild`：只读，不读档，不自动写（§7）。
- **金档**：每个发布过的格式各留一份，放在 `game/kernel/save/tests/golden/`，每份都必须能读，每步迁移单独测（G20）。
- **持久化 ID 换名**（CORE-CONVENTIONS §3.7）：ID 不复用，改名不改身份，平时不需要迁移。确需换 ID 时，负责数据的包提交旧 ID → 新 ID 的映射 `id-remap.json`，引用它的段各升一次 `v`，并补一份带旧 ID 的金档；真正删除的对象不给映射，读档时按 §5.6 修复。

## 4 保存时机与可靠性

### 4.1 时机

| 时机 | `SaveReason` | 限频 | 缩略图 |
| --- | --- | --- | --- |
| 关闭窗口、Alt+F4、菜单"退出" | `Quit` | 不限，立即（`FlushForQuit`） | 新抓 |
| 返回开始页 | `ToTitle` | 不限，立即 | 新抓 |
| 新游戏交还控制 | `NewGame` | 不限 | 新抓（P00 全景） |
| 漫游态累计 5 分钟 | `Interval` | 30 s 合并 | 沿用 |
| 跳转、传送、换季转场、"回到落金初灯"、换图落定 | `Settled`、`MapChanged` | 30 s 合并 | 沿用 |
| 窗口失焦 | `FocusLost` | 30 s 合并 | 新抓；最小化时沿用 |

- **合并与限频**：距上次成功保存不到 30 s 的请求挂起，到点再执行，期间再来的合并成一次；每次成功保存后 5 分钟计时从零开始；同一时间只有一次写盘。
- **只在漫游态保存**：开始页、进场过场、返回标题途中、退出途中、换图途中，`Request` 都被忽略（退出与返回标题走 `FlushForQuit`，不受限）。
- Godot 在 Windows 上收不到关机与注销消息，所以定时保存是唯一的兜底。

### 4.2 安全时刻与落定快照

- **安全时刻**同时满足：处于漫游态；没有雾幕；每一段的 `IsSettled` 都为真（世界没有快进与换季转场，天气没有手动替换的过渡，视角没有跳转传送，行走着地且不在水里、不在骑行与回位途中，没有正在换图）。条件不满足就顺延，**最多顺延 60 s**，到期拍强制快照。
- **落定快照**：每段的 `Capture` 在任何时刻都能给出落定值，所以退出时也能存。过渡、快进、跳转、降落、换图进行中取终点；空中、水里、骑行中取最近的岸上安全点（室内池取本层池岸）；电梯途中取目的站。
- 快照在主线程帧末拍，各段返回不可变的 DTO，不做 I/O，合计 p99 ≤ 0.3 ms（ENG-BUDGET §8）；序列化、压缩、哈希、写盘、读回校验都在后台。

### 4.3 写盘与失败

后台写成新文件，读回校验通过才删多余的旧代。写盘失败时只删自己刚写的不完整文件，旧代不动，记日志，下一个时机再试。写盘步骤以 `game/kernel/save/` 源码为准。

### 4.4 退出

1. 启动时关掉 `AutoAcceptQuit`，关闭请求到达后后台写完再 `Quit()`；`IAppFlow` 进入 Quitting，关闭输入。
2. 进场过场途中退出：先按"跳过"落到终态再保存。换图途中退出：等换图结束，最多 2 s；超时或失败就不写这一代，上一代仍有效。
3. 同步写设置文件，抓缩略图，拍强制快照交后台写盘；雾幕 0.3 s 淡入，Master 淡出；等待超过 1.5 s 亮三颗等待灯。
4. 保存成功、有意不写、或本来就不保存（`--save=off`、另一个窗口持有锁）时直接退出。
5. **保存明确失败时让观者选**：停在 Quitting，弹确认框"这次没能保存"，写明原因和上次成功保存的时间：**重试**（默认）、**返回游戏**（Esc 同此）、**仍然退出**（旧代不受影响）。

- **时限**：保存成功或有意不写时，关闭请求到进程结束 ≤ 1.5 s，硬上限 2 s；明确失败时等观者选，不计时。崩溃时不保存。

### 4.5 保存状态与失败反馈

保住旧代不等于观者知道这次没存上，所以保存结果一直摆在界面上。

- `ISaveService.State` 报告当前存档位、最近一次写盘的结果与原因（`save.error.*` 文案键）、最后一次成功保存的时间、不保存的原因。
- 存档页的存档卡与设置卡的"存档"一行持续显示"最近一次保存失败 · 原因 · 上次成功 21:40"，直到下一次保存成功；一串连续失败只在第一次时临时提示。退出时失败按 §4.4 让观者选。

## 5 加载与一致性

### 5.1 加载流程

读档发生在冷启动时（扉页后面读"继续"的存档位供 T0 显示）、在存档页换存档位、命令行指定存档。两种范围：`Full` 一次恢复全部阶段；`Preview` 恢复到 `Content` 为止，`Pose` 段只解析校验，留作"继续"的终点，交还控制时由 `CompleteResume()` 恢复。

1. **遮挡**：雾幕保持不透明（开始页阶段由扉页或云卡遮挡），输入关闭。
2. **后台读取**：读最新一代 → 校验 → 解压 → 解析 → 迁移；失败退到同一世界线的上一代（§7）。
3. **规则集、世界与天气**：先按 meta 的规则集定本局规则，再恢复 `maps`（只登记各图的 `MapVisit`，不动镜头）、`world`、`weather`；这一阶段结束时 `Instance` 加 1，`Active` 设为这个存档位。
4. **换图**：当前地图不是已加载的图时经 `Travel(LoadSave)` 换图（SYS-MAPS），位姿与模式取这张图的 `MapVisit`；换图不改 `Instance`，到达后不再请求保存。
5. **内容与落位**：恢复按图内容与进度，`Full` 再恢复 `view`、`walk`；缺的段补默认，全部立即生效、不做过渡，各段校验修复（§5.6），位姿按 WLD-OUTSKIRTS 合法化。
6. **预取**：恢复的位姿作为已知目的地预取各级格子；位于开放室内时等这一层与碰撞就绪再落地。
7. **撤遮挡**：就绪之前不撤。雾幕直达的读档，雾幕 2–3 s 淡出；从开始页按"继续"时，由继续过场落到 meta 里的位姿，交还控制那一帧调 `CompleteResume()`，`Instance` 不变，然后放开输入，恢复存档里的流逝倍率。

- 开始页期间世界流逝由 `IAppFlow` 冻结，不改写存档里的倍率。"继续"的是另一个存档位时，在继续过场的全遮段里对它做一次 `Preview` 读档（`Instance` 加 1）。

### 5.2 世界实例：`IWorldState.Instance`

- **定义**：世界实例是一段连续演化的世界，从一次读档或新游戏开始，到下一次读档或新游戏为止。`Instance` 是进程内计数，不进存档；开始页的预览恢复、新游戏、读另一个存档位各加 1；按"继续"进入正在预览的存档位不加，换图也不加。
- **时间单调只在同一实例内要求**：读档是换了一个世界，不是让同一个世界倒流。`IWorldControl` 仍不提供让时间倒退的方法；恢复走 `world` 段自己的实现。"回到落金初灯"不换实例。
- **换实例时直接落到新值**：做平滑、带回差或保留历史的系统（钟点弹簧、天气插值、界面主题回差、窗灯错开、画质统计、植被近池、声音平滑量等），看到 `Instance` 变了就把内部状态直接设成新世界的值，不做过渡；这一刻总在遮挡之下。

### 5.3 "状态一致"的定义

- **落定一致**（任何一份存档）：读档后的状态等于存档那一刻的落定状态（§4.2）。
- **续跑等价**（在安全时刻拍的存档）：同一构建、同一份数据，读档后给相同的输入和 dt 序列，世界（`WorldHours`、钟点、季节、流逝、`AnimTime`）与天气（选择、天气向量、前瞻队列）与没退出时逐帧逐位一致。
- **强制快照**（退出时、顺延满 60 s 时）：过渡直接落到终点，终点以前不等价，终点以后续跑等价。
- **不在一致性之内**：§2 列的"不存"各项，以及当前速度（读档后静止）、渲染侧的选级与淘汰、声景的具体时刻与变体选择。
- **补丁更新后读旧档**：世界状态仍然一致，画面可以不同；已生成的天气队列不变。

### 5.4 天气

自动天气的每次抽取由（种子、mapId、epoch、片段号、尝试号、用途）决定（SYS-WEATHER §6.4），种子每个存档一个：新游戏取一次熵（或用 `--weather-seed`），存进 `weather` 段，读档不重新取。已生成的队列（过去与前瞻各 24 h）也存，补丁调了天气参数，观者已经看到的天气和预报也不会变。读档不重置天气过程；换图时把本图队列补算到当前世界时间（SYS-MAPS）。

### 5.5 新游戏

- **交还控制时一律是落金初灯**：秋季、17:30、晴、自动天气、流逝 1×，天气保持晴到秋季黄昏带结束；旁观模式；默认图的 P00。
- **建实例**：先定规则集（观光恒为 `sightseeing`），取新种子，`Instance` 加 1，各段用 `CreateDefault` 建出初值，记下新的世界线号。
- **起点**：新游戏的世界过程只有一种（完整、简短、关、跳过都一样）：用本图的新游戏起点（清水河：秋 17:05 晴，SYS-MAPS）建实例，再由 `IWorldControl.FlowTo` 正向推到 17:30，交还时转 1×。某张图没写新游戏起点时，实例直接建在默认状态。
- **第一代**在交还控制的那一刻写（`NewGame`）；过场途中退出，先跳到终态再写。覆盖已有存档位要二次确认。

### 5.6 校验修复

各段在 `Restore` 里检查，每修一处记一条日志：

| 情况 | 修复 |
| --- | --- |
| 位置落在楼体里、碰撞检查不过，或在已不开放的室内 | 挪到 50 m 内最近的安全点；行走模式下找不到就切到旁观，提示"这里无法落地"；`NavSpace` 改为挪到的点所在的空间 |
| 行走的脚位在水里（旧档，或泳区已不开放） | 挪到最近的岸上安全点（室内池挪到本层池岸）；读档不发入水、落脚事件 |
| 位置超出可达空间或落在缓冲带里 | 按 WLD-OUTSKIRTS 的合法化规则就近投影进可达空间，不播推回动画 |
| 手动天气不合本季 | 按换季的替换表替换（SYS-WEATHER §1） |
| 点位、锚点、标记、`FeatureId` 已不存在；自定义标记出界或超限 | 从列表里去掉 |
| 存档里的地图已不存在 | 回到默认地图的默认出生点 |
| 共享单车的停放点已不存在 | 挪到登记的备选点；不复制、不丢车 |
| 数值越界 | 取最近的合法值 |

## 6 关着游戏的那段现实时间不计

- 读档后 `WorldHours` 就是存档里的值，不按"离上次退出过了多久"补算世界时间或天气。
- **不像动森那样跟现实走**：再进同一存档应看到离开时的那一刻；关一周再回来世界跳过 168 小时，违背"一切切换由观者触发、自然过渡"；改系统时钟就能操纵世界。
- 开始页停留不计（`IAppFlow` 冻结）；系统睡眠后第一帧 dt 夹到 0.1 s，等于不计；窗口失焦时世界照常流逝。
- 系统时钟只用于在存档卡上显示现实日期，是 G4 登记的例外：只能在存档包里读、只能写进 meta。

## 7 存档损坏与版本不兼容

读一个存档位时，从最新一代往旧代依次试，第一份通过全部检查（魔数与长度、哈希、解压上限、JSON 解析与深度、核心段反序列化）的就用它。

| 情况 | 处理 | 观者看到 |
| --- | --- | --- |
| 最新一代坏了，旧代可读 | 坏文件挪进 `corrupt/`，改用最新的可读代，记为 `RecoveredOlderGen` | 临时提示"最近一次保存不完整 · 已回到 5 分钟前" |
| 三代全坏 | 记为 `Corrupt`；文件先不动，观者在这个存档位开新游戏时才挪进 `corrupt/` | 存档卡"存档已损坏"，可选"新游戏" |
| 来自更新的版本 | 记为 `NewerBuild`：只读，不读档，不自动写；开新游戏要二次确认，旧文件挪进 `corrupt/` 并加 `newer-` 前缀 | "来自更新的版本" |
| 某一段不合法 | `maps`、`world`、`weather`、各图天气这四类核心段不合法，整代视为损坏，退到上一代；其余段换成默认并记一次修复 | — |
| 另一个进程占着锁 | 只读，不保存 | "另一个窗口正在运行 · 本窗口不保存" |

- `corrupt/` 里的文件**从不自动删除**；坏档和新版本的档不会被自动覆盖，观者明确确认之后才挪开。

## 8 设置类文件只接受基本类型

适用于 `settings.cfg`、`input.cfg`、`graphics.cfg`、`audio.cfg`。它们是档案级文件，仍用 ConfigFile 格式；音量要比界面更早拿到，所以 `audio.cfg` 独立成文件。门禁和基准不读任何 `user://` 文件。

ConfigFile 的解析器支持 `Object(类名, 属性…)` 写法，**在 `Load` 或 `Parse` 返回之前就已经按文件内容创建了对象**，读出来再查类型挡不住。所以：

1. **先查文本**：含 `Object(`、`Resource(`、`SubResource(`、`ExtResource(` 任一写法，整份不用，退到 `.bak`，`.bak` 也不行就用默认值并写日志。
2. **再解析**：每个键按登记表只接受 bool、int、float、String；类型不对或越界用默认值，未知的键忽略。
3. **只存基本类型**：向量、颜色拆成几个数字存；`input.cfg` 存物理键码和鼠标键号，不存 `InputEvent` 对象。
4. **写盘**：写临时文件、落盘、用替换覆盖并留 `.bak`；仍失败就放弃这次写盘，内存里的设置照常生效。
5. **`engine_override.cfg`**：引擎在任何 C# 代码运行之前就读它，没法先查文本，所以只写登记过的几个键。


## 9 安全：为什么禁止用 Resource 和 ConfigFile 存档

**威胁模型**：存档会被玩家互相分享，读档的输入不可信。实测：嵌了 GDScript 的 `.tres` 被加载时代码会执行；`ConfigFile`、`StrToVar` 会按文件内容创建对象。所以：

1. **存读档只经存档包**：正文只用 System.Text.Json 源生成，反序列化到登记过的 DTO；未知段只在容器层按原始字节保留。
2. **G4 禁止的写法**：全工程用 `ResourceLoader`、`ResourceSaver` 读写 `user://`；存档代码里用 ConfigFile、`StrToVar`、`BytesToVar*`、`GetVar`、Godot 的 `Json`，以及不带 `JsonTypeInfo` 的序列化重载。
3. **资源上限**：文件、meta、压缩与解压后正文、JSON 深度、缩略图都有上限，解压边解边计数，防解压炸弹（数值以存档包源码为准）。
4. **各段在 `Restore` 里核对内容**：数组长度（标记 ≤ 50、安全点环正好 16 槽、天气队列有上限）；数值有限且在合法范围。
5. **存档里只存 ID，不存文件路径**：读档不加载外部文件，也不联网。
6. **一票否决**（ENG-GATES §3）：丢档；读档时执行了存档里的代码或创建了存档指定的对象；存档被覆盖或删除导致无法回退；来自更新版本的存档被旧构建覆盖。
