# SYS-SAVE-FLOW · 保存时机与读档流程

> **范围**：本文规定保存时机与可靠性、安全时刻与落定快照、退出保存、保存状态反馈、读档流程、世界实例、"状态一致"的定义、新游戏的建档、校验修复、关游戏期间的现实时间不计。
> **不在本文**：存档位模型与各段存什么（SYS-SAVE）；容器格式、坏档处理、设置文件与安全（SYS-SAVE-FORMAT）；文件布局、写盘步骤（`game/kernel/save/`）；契约签名（`game/contracts/Save/`）；性能份额（ENG-BUDGET §3）；开始页与进入游戏（SYS-TITLE）；换图（SYS-MAPS）；天气过程（SYS-WEATHER）。
> **查阅**：先读 §0；保存时机、安全时刻与退出看 §1；读档顺序与世界实例看 §2；现实时间不计看 §3；待验证看 §4

## 0 结论

1. **保存时机**：退出、返回标题、新游戏交还控制时立即保存；漫游态每 5 分钟保存一次，在安全时刻拍快照（§1）。
2. **一致性**：读档后的状态等于存档那一刻的落定状态；在安全时刻拍的存档续跑等价；读档换一个世界实例（§2）。
3. **代价**：断电、强杀最多丢最近 5 分钟；过渡、偶发事件、打开的面板不续播；读档恢复存档时的模式（§1、§2.3，D-240）。
4. **关着游戏的时间不计**：世界时间只由存档里的值决定，不跟现实时钟走（§3）。

### 0.1 接入要点

- **`Capture` 与 `Restore`**：`Capture` 在任何时刻都给出落定值（过渡中取终点，空中、水里、骑行中取最近的岸上安全点），不做 I/O，不卡帧；`Restore` 立即生效、不做过渡，核对长度与范围，修一处记一处（§1.2、§2.6）
- **看到 `IWorldState.Instance` 变了**：做平滑、带回差或保留历史的系统把内部状态直接设成新世界的值，不做过渡（§2.2）
- **想用现实时间**：系统时钟只能在存档包里读、只写进 meta 用于显示，世界状态不读它（§3）

## 1 保存时机与可靠性

### 1.1 时机

| 时机 | `SaveReason` | 缩略图 |
| --- | --- | --- |
| 关闭窗口、Alt+F4、菜单"退出"（立即，`FlushForQuit`） | `Quit` | 新抓 |
| 返回开始页（立即） | `ToTitle` | 新抓 |
| 新游戏交还控制（建档） | `NewGame` | 新抓（出生点） |
| 漫游态累计 5 分钟 | `Interval` | 沿用 |

- **计时**：每次成功保存后 5 分钟计时从零开始；同一时间只有一次写盘。
- **只在漫游态定时保存**：开始页、加载界面、返回标题途中、退出途中、换图途中不触发定时保存（退出与返回标题走 `FlushForQuit`）。
- Godot 在 Windows 上收不到关机与注销消息，所以定时保存是兜底，不另接系统关机消息。

### 1.2 安全时刻与落定快照

- **安全时刻**同时满足：处于漫游态；没有雾幕或加载界面遮挡；每一段的 `IsSettled` 都为真（世界没有快进与换季转场，天气没有手动替换的过渡，视角没有跳转传送，行走着地且不在水里、不在骑行与回位途中，没有正在换图）。条件不满足就顺延，**最多顺延 60 s**，到期拍强制快照。
- **落定快照**：每段的 `Capture` 在任何时刻都能给出落定值，所以退出时也能存。过渡、快进、跳转、降落、换图进行中取终点；空中、水里、骑行中取最近的岸上安全点（室内池取本层池岸）；电梯途中取目的站。
- 快照在主线程帧末拍，各段返回不可变的 DTO，不做 I/O，不卡帧（ENG-BUDGET §3）；序列化、压缩、哈希、写盘、读回校验都在后台。

### 1.3 写盘与失败

后台写成新文件，读回校验通过才删多余的旧代。写盘失败时只删自己刚写的不完整文件，旧代不动，记日志，下一次再试。写盘步骤以 `game/kernel/save/` 源码为准。

### 1.4 退出

1. 启动时关掉 `AutoAcceptQuit`，关闭请求到达后后台写完再 `Quit()`；`IAppFlow` 进入 Quitting，关闭输入。
2. 加载界面或换图途中退出：先把这次进入落定（新游戏建好实例、继续换好世界），最多 2 s；超时或失败就不写这一代，上一代仍有效。
3. 同步写设置文件，抓缩略图，拍强制快照交后台写盘；雾幕 0.3 s 淡入，Master 淡出。
4. 保存成功、有意不写、本来就不保存（`--save=off`、另一个窗口持有锁），或写不成时（记日志，旧代不受影响）直接退出。

- 退出不卡住；崩溃时不保存。

### 1.5 保存状态与失败反馈

写不成就记日志，不弹框、不在界面上持续显示；`ISaveService.State` 报告最近一次写盘的结果与原因，供日志和诊断读。

## 2 加载与一致性

### 2.1 加载流程

读档发生在冷启动时（扉页后面读"继续"的存档位供 T0 显示）、在存档页换存档位、命令行指定存档。两种范围：`Full` 一次恢复全部阶段；`Preview` 恢复到 `Content` 为止，`Pose` 段只解析校验，留作"继续"的终点，交还控制时由 `CompleteResume()` 恢复。

1. **遮挡**：加载界面保持不透明（SYS-TITLE §3.1；冷启动预览阶段由扉页遮挡），输入关闭。
2. **后台读取**：读最新一代 → 校验 → 解压 → 解析；失败（含格式号或段版本对不上）退到同一世界线的上一代（SYS-SAVE-FORMAT §2）。
3. **规则集、世界与天气**：先按 meta 的规则集定本局规则，再恢复 `maps`（只登记各图的 `MapVisit`，不动镜头）、`world`、`weather`；这一阶段结束时 `Instance` 加 1，`Active` 设为这个存档位。
4. **换图**：当前地图不是已加载的图时经 `Travel(LoadSave)` 换图（SYS-MAPS），位姿与模式取这张图的 `MapVisit`；换图不改 `Instance`，到达后不再请求保存。
5. **内容与落位**：恢复按图内容与进度，`Full` 再恢复 `view`、`walk`；缺的段补默认，全部立即生效、不做过渡，各段校验修复（§2.6），位姿按 WLD-OUTSKIRTS 合法化。
6. **预取**：恢复的位姿作为已知目的地预取各级格子；位于开放室内时等这一层与碰撞就绪再落地。
7. **撤遮挡**：就绪之前不撤。读档后加载界面走满淡出；从开始页按"继续"时，位姿落到 meta 里的位姿，加载界面淡出的那一帧调 `CompleteResume()`，`Instance` 不变，然后放开输入，恢复存档里的流逝倍率。

- 开始页期间世界流逝由 `IAppFlow` 冻结，不改写存档里的倍率。"继续"的是另一个存档位时，在加载界面下对它做一次 `Preview` 读档（`Instance` 加 1）。

### 2.2 世界实例：`IWorldState.Instance`

- **定义**：世界实例是一段连续演化的世界，从一次读档或新游戏开始，到下一次读档或新游戏为止。`Instance` 是进程内计数，不进存档；开始页的预览恢复、新游戏、读另一个存档位各加 1；按"继续"进入正在预览的存档位不加，换图也不加。
- **时间单调只在同一实例内要求**：读档是换了一个世界，不是让同一个世界倒流。`IWorldControl` 仍不提供让时间倒退的方法；恢复走 `world` 段自己的实现。"回到落金初灯"不换实例。
- **换实例时直接落到新值**：做平滑、带回差或保留历史的系统（钟点弹簧、天气插值、界面主题回差、窗灯错开、画质统计、植被近池、声音平滑量等），看到 `Instance` 变了就把内部状态直接设成新世界的值，不做过渡；这一刻总在遮挡之下。

### 2.3 "状态一致"的定义

- **落定一致**（任何一份存档）：读档后的状态等于存档那一刻的落定状态（§1.2）。
- **续跑等价**（在安全时刻拍的存档）：同一构建、同一份数据，读档后给相同的输入和 dt 序列，世界（`WorldHours`、钟点、季节、流逝、`AnimTime`）与天气（选择、天气向量；自动天气是纯函数，同一世界时间同一结果）与没退出时逐帧逐位一致。
- **强制快照**（退出时、顺延满 60 s 时）：过渡直接落到终点，终点以前不等价，终点以后续跑等价。
- **不在一致性之内**：SYS-SAVE §2 列的"不存"各项，以及当前速度（读档后静止）、渲染侧的选级与淘汰、声景的具体时刻与变体选择。
- **补丁更新后读旧档**（格式号与段版本相同时）：世界状态仍然一致，画面可以不同；天气数据改了，同一世界时间的自动天气也可以不同。

### 2.4 天气

天气种子、手动与钉住、保持晴窗口存进 `weather` 段，读档不重新取种子，自动天气按世界时间求值即得；规则以 SYS-WEATHER-PROCESS §1.4、§2 为准。

### 2.5 新游戏

- **交还控制时的状态与流程**见 SYS-TITLE §3.1：落金初灯（默认状态，SYS-TIME §1.1）、行走模式、默认图的出生点（SYS-VIEW §2.4，D-242）；实例在加载界面下直接建在默认状态，不推流逝（D-087）。
- **建实例**：先定规则集（观光恒为 `sightseeing`），取新种子，`Instance` 加 1，各段用 `CreateDefault` 建出初值，记下新的世界线号。
- **第一代**在交还控制的那一刻写（`NewGame`）；加载途中退出，先落定终态再写。覆盖已有存档位要二次确认。

### 2.6 校验修复

各段在 `Restore` 里检查，每修一处记一条日志：

| 情况 | 修复 |
| --- | --- |
| 位置落在楼体里、碰撞检查不过，或在已不开放的室内 | 挪到 50 m 内最近的安全点；行走模式下找不到就切到旁观，提示"这里无法落地"；`NavSpace` 改为挪到的点所在的空间 |
| 行走的脚位在水里（旧档，或泳区已不开放） | 挪到最近的岸上安全点；读档不发入水、落脚事件 |
| 位置超出可达空间或落在缓冲带里 | 按 WLD-OUTSKIRTS 的合法化规则就近投影进可达空间，不播推回动画 |
| 手动天气不合本季 | 按换季的替换表替换（SYS-WEATHER §1） |
| 点位、锚点、标记、`FeatureId` 已不存在 | 从列表里去掉 |
| 存档里的地图已不存在 | 回到默认地图的默认出生点 |
| 共享单车的停放点已不存在 | 挪到登记的备选点；不复制、不丢车 |
| 数值越界 | 取最近的合法值 |

## 3 关着游戏的那段现实时间不计

- 读档后 `WorldHours` 就是存档里的值，不按"离上次退出过了多久"补算世界时间或天气。
- **不跟现实走**：再进同一存档应看到离开时的那一刻；世界的变化都由观者触发、自然过渡，改系统时钟不能操纵世界。
- 开始页停留不计（`IAppFlow` 冻结）；系统睡眠后第一帧 dt 夹到 0.1 s，等于不计；窗口失焦时世界照常流逝。
- 系统时钟只用于在存档卡上显示现实日期，是 G4 登记的例外：只能在存档包里读、只能写进 meta。
