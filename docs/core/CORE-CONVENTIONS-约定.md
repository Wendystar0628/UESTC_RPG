# CORE-CONVENTIONS · 约定

> **范围**：本文规定所有文档和代码共同遵守的写法：坐标与单位、方位角、时间写法、编号与命名、实体 ID 规则、确定性原则。
> **不在本文**：契约与帧顺序（`game/contracts/` 源码，说明见 ENG-ARCH §3）；命令行与门禁（ENG-GATES）；预算（ENG-BUDGET）；工作包与目录归属（ENG-WP、`ownership.json`）；按图文件归属（SYS-MAPS、MAP-QSH-*）；决策（CORE-DECISIONS）；术语（CORE-GLOSSARY）；文档写法（WF-DOC）。
> **查阅**：先读 §0；坐标、角度、单位看 §1；时间写法看 §2；ID、编号、命名、枚举纪律看 §3；确定性看 §4；路径看 §5

## 0 结论

- 单位米；x 向东、y 向上、z 向南；数据坐标直接当 Godot 世界坐标用；正北是 −z（§1.1）。
- 方位角从正北顺时针，单位度；Godot 节点的 `Rotation.Y = −A`（弧度）（§1.2）。
- 时间只往前走；钟点正文写 HH:MM，命令行与 JSON 写小数小时（§2）。
- 每张图一个坐标原点和投影；实体 ID 只在本图内唯一，按 ID 定位对象，不按名字（§1.1、§3.1）。
- 编号前缀各有固定含义，同号不同义时按 §3.3 的写法区分（§3.2、§3.3）。
- 色名是唯一的取色途径；枚举只追加不重排；已进 `main` 的持久化 ID 不复用（§3.5、§3.6、§3.7）。
- 同一构建加同一种子加同一串输入，得到同样的结果；随机只用契约的 `Rng` 与 `StableHash`（§4）。

### 0.1 接入要点

- **用坐标、角度、单位**：x 东、y 上、z 南，单位米；方位角从正北顺时针；地面高度读 `IWorldModel.Terrain`，不写死 y = 0（§1）。
- **写时间**：正文 HH:MM，命令行与 JSON 小数小时；世界时间只增不减（§2）。
- **起 ID 和名字**：前缀、大小写、命名空间、命令行取值按 §3；代码里不写地图 ID、实体 ID 的字面量（§3.1）。
- **加枚举值**：只在末尾追加；消费方写穷举 `switch`，不做二值判断（§3.6）。
- **删或改被引用的对象**：ID 不复用，改名不改身份，确需换 ID 给旧新映射（§3.7）。
- **生成或随机的结果要能复现**：只用契约的随机来源，细则见 ENG-ARCH §2（§4）。
- **写或改文档**：按 WF-DOC；**施工**：入口见 WF-ENTRY，核心准则见 CORE-INDEX §0。

## 1 坐标与单位

### 1.1 坐标系

- 单位米；x 向东、y 向上、z 向南。与 Godot 一样是右手系、y 向上，数据坐标直接当 Godot 世界坐标用，不做换算；正北就是 Godot 的前方（−z），偏航 0° 的相机朝北（D-144）。
- **每张图一个原点和投影**，写在该图 `campus.json` 的 `meta` 里，`map.json` 不重复（SYS-MAPS §2）。清水河的原点在经度 103.9282919、纬度 30.75316145，投影为 EPSG:32648。
- 地图之间的坐标互不相通；跨图引用一律写成"地图 + ID"。单图半径（离中心最远的可达点）不超过 8 km（SYS-MAPS §8）。
- **高度**：地面不是平的，全图约 −5…+10 m，地形写在地形覆盖层；地面高度、垫层、水位一律读 `IWorldModel.Terrain`，不写死 y = 0（WLD-TERRAIN）。
- **两套数学类型**：契约程序集只用 `System.Numerics`，Godot 侧用 `Transform3D`；两者之间只用内核提供的扩展方法转换（ENG-ARCH §2）。

### 1.2 角度

- **方位角**一律用罗盘方位：从正北开始顺时针，单位度。方位 A 的水平单位向量是 (x, z) = (sin A, −cos A)。
- **Godot 节点**：罗盘方位 A 对应 `Rotation.Y = −A`（弧度）。因为 Godot 绕 y 轴的正向旋转是从上往下看逆时针，与罗盘方向相反。偏航、日月方位、点位朝向、入口朝向一律按这条换算。
- **俯仰**：度，负值表示朝下看（UI-NAV-WAYPOINTS §1）。
- 契约里以 `Deg` 结尾的字段都是度；只有 Godot 节点的属性用弧度。
- **"目标点、方位、仰角、距离"的写法**（审查视角）：方位是从目标点看向相机的罗盘方位，相机朝向目标点时偏航 = 方位 − 180°（ENG-GATES-SHOTS §1）。

### 1.3 清水河的范围数

| 名称 | 约值 | 用途 |
| --- | --- | --- |
| 校界外接框 | x −991…989、z −1020…1021 | 行走边界（SYS-MAPS §2） |
| 箱庭（含外围街区）包围盒 | x −1250…1260、z −1400…1440 | 以 `map.json` 的地图包围盒为准（SYS-MAPS §2） |
| `map_rect` | x、z 都是 −1280…1280 | 全图数据纹理的覆盖范围；不等于箱庭包围盒（SYS-MAPS §7、ENG-PERF §1.5） |

### 1.4 其他单位

- 长度 m，速度 m/s；时间单位见 §2。
- **眼高**：行走 1.62 m（SYS-WALK）。
- **像素基准**：截图与界面都按 1920×1080；线宽按"内部高度 / 1080"换算（ENG-GATES-SHOTS §1、UI-VISUAL-COMPONENTS §5）。
- **颜色**：色彩计算在 OKLab / OKLCH 里做，明度写 L（OKLab）；十六进制色值只出现在调色板数据文件里（§3.5）。
- **音量**：dB；界面滑杆值 0–1（SYS-AUDIO）。

## 2 时间写法

| 量 | 单位与取值 | 要点 |
| --- | --- | --- |
| `WorldHours` | 小时，double | 同一世界实例内单调递增，暂停时不动；跨实例比较没有意义（SYS-TIME §1） |
| `Clock` | 小时，[0, 24) | 由 `WorldHours` 换算；换季时钟点数字可能变小，但太阳不倒走（SYS-TIME §1） |
| 钟点的写法 | 正文写 HH:MM；命令行与 JSON 写小数小时 | 17:30 写 `17.5`；17:05 写 `17.083333` |
| `SeasonPos` | [0, 4)，连续、循环；0 春、1 夏、2 秋、3 冬 | 季节不自动推进（SYS-TIME） |
| 流逝倍率 | 世界秒 / 真实秒；0 = 暂停，默认 1 | 取值集合见 ENG-ARCH §3 的 `Flow.Rate` |
| `AnimTime` | 秒；与世界时间无关 | 暂停、快进、倍速都不影响（SYS-MOTION §1.2） |
| 天气时长 | 分钟 | 队列项与命令行按分钟；`WeatherSpan` 按 `WorldHours`（SYS-WEATHER） |
| 真实秒 | 帧间隔累加 | 偶发事件、转场、界面动效按它；不读系统时钟 |

- **只能向前**：没有任何让 `WorldHours` 减小的方法；设定钟点是"跳到下一次出现"。
- **世界实例**：读档、新游戏是换一个世界实例，不算倒流；回到"落金初灯"和切图不换实例（SYS-SAVE-FLOW §2.2）。
- **不计入世界时间**：关着游戏的那段现实时间、开始页停着的时间。
- **系统时钟**只在存档元数据里读一次，只用于显示；其余代码不读（ENG-ARCH §2）。着色器不用内置 `TIME`，一律用 `anim_time`（SYS-MOTION §1.2）。

## 3 标识与命名

### 3.1 地图、实体与覆盖层

| 标识 | 格式 | 规则 |
| --- | --- | --- |
| 地图 ID（`MapId`） | 小写字母、数字、连字符，≤ 32 字符；与目录名相同，如 `qingshuihe` | 代码里不写地图 ID 字面量（地图内核和门禁夹具除外）；不用 "qsh" 指地图（D-137） |
| 实体 ID（`FeatureId`） | `campus.json` 的 `entities[].id`；清水河前缀 `qsh:`，形如 `qsh:<类型>:<编号>` | 只在本图内唯一；`qsh:` 是 OSM 管线的既有写法，属于数据，不是地图 ID；按 ID 定位对象，不按名字；通用代码里不写字面量；以后的图用自己的前缀 |
| OSM 来源 | `osm:way:N` 是原始快照里的 ID，`qsh:way:N` 是实体 ID，`qsh:source:way:N` 是路网的来源线 | 三种按用途并存，不改数据 |
| 设计增补 | `design:` 开头；锚点写 `design:anchor:Axx` | 只经覆盖层的 `add` 新增，写明理由（MAP-QSH-ADDITIONS） |
| 可行走区域 | `walk:` 开头 | 只在可行走覆盖层（SYS-WALK-BOUNDS §1） |
| 地形操作 | `design:terrain:` 开头，本图内唯一 | 只在地形覆盖层，每条写理由（WLD-TERRAIN-APPLY §1） |
| 环境发声器 | `amb:` 开头，本图内唯一 | 见 ENG-ARCH §3 |
| RPG 预留前缀 | `npc:`、`item:`、`quest:` | 观光数据不得使用（ENG-ROADMAP §3.1） |

- **覆盖层**：底板（各图的 `campus.json`、`network.json`，从 OSM 一次转出、不再重新生成，D-252）不手改；风格化改动、设计增补和删除都写进本图的覆盖层并写明理由；两个覆盖层不得改同一个要素（SYS-MAPS §1.1，D-173）。
- **清水河的数据勘误**：OSM 把东湖畔的雕像误标为"孙立人像"（`qsh:node:7867995301`），按吴立人像处理。

### 3.4 命名写法

**命名原则**（全项目，D-251）：
1. **编号-主题**：带编号的名字一律"编号-中文主题"，编号只做索引，意思靠主题读出。
2. **一物一名**：同一个角色或东西只有一种叫法——主会话、Codex 主线、Claude 侧、Codex 侧；Opus、Sonnet、Sol、Astra 只指模型。
3. **名字写内容，不写来源**：不用工作包号、会话名、日期、版本号当名字。
4. **不造缩写**：字母前缀与缩写都在 §3.2 登记，不再新增单字母前缀。
5. **同目录同写法**：语言与引擎有惯例的跟惯例（C# PascalCase，Godot 资源与着色器 snake_case，Python 下划线，PowerShell 与 cmd 连字符）。
6. **编号只增、不复用、不改义**（§3.7）。
7. **规则与实物同源**：文档写的格式、钩子提示与巡逻检查一起改，不留旧写法（D-200）。
8. **可读优先于简短**。

文件与编号的具体格式见 §3.8；以下是代码与数据里的名字。

- **命名空间**：PascalCase，按 ENG-ARCH §1 的分层与职责取，不跟目录的字面大小写（`game/gen/zones/south/` 对应 `Campus.Gen.Zones.South`）。程序集与目录的对应见 ENG-ARCH §2。
- **特性的 ID**：小写、点分（`[ContentModule("zone.south")]`）；区域私有的部件 ID 加区名前缀（ENG-ARCH §2、§5）。
- **存档段 ID**：小写字母、数字、连字符；按图的段在文件里展开为 `map:<id>/<段>`（SYS-SAVE §2）。
- **全局着色器参数**：小写下划线、不带前缀（`weather_a`）；C# 侧只用 `ShaderGlobals` 的常量，总线名只用 `AudioBuses` 的常量，不写字符串字面量（ENG-PERF §1.5）。着色器文件名以系统名作前缀，白名单见 ENG-PERF §1.4。
- **JSON**：字段 camelCase，枚举按字符串，向量写成数组；多态类型的类型字段写在每个对象的第一个字段（ENG-ARCH §3）。
- **命令行取值**：天气写连字符小写（`few-clouds`），季节写英文小写，预设、设备档和 `--quality-set` 的单项名见 ENG-GATES-SHOTS §1。
- **过场**：过场 ID 用 snake_case，`map.json` 里的角色名用 camelCase（SYS-MAPS §2）。

### 3.5 色名

- 色名是唯一的取色途径：色名 → 色号（固定，只增不改）→ 调色板纹理的一列（ART-STYLE §2.5）。内容代码只写色名，代码和着色器里不写十六进制色值（G4）。
- **写法**：小写，点分层，`<对象>.<状态或用途>`，如 `wall.lit`、`window.warm`；一段内多个词用驼峰（`water.poolGlow`）。后缀 `.lit`、`.shade`、`.deep` 分别是受光、影、深影（ART-STYLE §2.1）。
- **界面色**：前缀 `ui.`，阶梯写 `ui.blue.400`；不进调色板纹理（UI-VISUAL §3）。
- **登记与退役**：谁登记、写在哪、重名与退役色名的处理见 ART-STYLE §2.5；色名重复或色号冲突由 G5 报。

### 3.6 枚举与扩展纪律

以下写法现在就照做，以后加观察模式、规则集、RPG 子系统时才不用改既有语义（细则见 ENG-ROADMAP §2、§3.1）：

- **枚举只追加、不重排、不删值**：所在的契约组冻结后，枚举只能在末尾追加；JSON 与存档里按字符串存（D-134）。读到不认识的枚举字符串，按"这一段不合法"处理，不猜（SYS-SAVE-FORMAT §1.3）。
- **穷举 `switch`，`default` 报告未知值**：会追加值的枚举，消费方一律写穷举的 `switch`，`default` 拒绝或报错，不把未知值静默当成某个已知值。
- **不做二值判断**：不写 `mode == ViewMode.Fly ? … : …`；它会把以后追加的值静默归进某一边，编译器查不出，靠评审。
- **不写观光专属的常量**：解锁策略名、事件 ID、允许的观察模式这类观光规则，一律读规则集（ENG-ROADMAP §2）。
- **"观者在哪"与"画面从哪看"分开读**：前者读 `IObserverState`，后者读 `ICameraRig`。
- **换世界实例直接落到新值**：做平滑、回差、保留历史的系统看到世界实例变了，就把状态直接设成新值（SYS-SAVE-FLOW §2.2）。

### 3.7 持久化 ID 的稳定

存档、覆盖层、标记和其他数据文件按 ID 引用对象，ID 就是对象的身份。地图 ID、实体 ID（含 `design:` 增补）、点位 P、锚点 A、路线 R、室内入口 ID、区域 ID 与地点翻译键、存档段 ID 都按本节执行：

- **不复用**：ID 进了 `main` 以后，对象删掉了，ID 也不再分给别的对象；新对象取新号。
- **改名不改身份**：改显示名、译名、所在文件或分区，ID 不变；轮廓、高度、位置的调整走覆盖层，ID 也不变。
- **确需换 ID 时给旧新映射**：例如刷新 OSM 快照后同一个真实对象的 OSM ID 变了。负责数据的包随数据提交旧 ID → 新 ID 的映射；引用这些 ID 的存档段升版本，由存档迁移按映射改写（SYS-SAVE-FORMAT §1.4）。
- **真正删除不给映射**：读档时按 SYS-SAVE-FLOW §2.6 的校验修复处理。

## 4 确定性

同一构建加同一种子加同一串输入，得到同样的结果；时间不能逆转，所以不要求"倒回去复现"。细则（种子推导、禁用的随机与数学函数、遍历顺序）以 ENG-ARCH §2 为准。

- **唯一的随机来源**是契约的 `Rng` 与 `StableHash`；种子由世界种子、实体 ID、部件 ID、用途哈希而来，与生成顺序无关。
- **烘焙产物不依赖世界状态和画面设置**：改时间、换季、换天气、改画质不会让烘焙产物失效（ENG-PERF-STREAM §1）。
- **门禁与截图**只由命令行决定，不读 `user://`（ENG-GATES-SHOTS §1）。

## 5 路径

- 按图的数据都在 `game/data/maps/<地图>/` 下，一律由 `IMapContext.DataRoot` 拼出，代码里不写数据路径（SYS-MAPS §1、§6，D-139）。各文件的归属见 SYS-MAPS 与 `ownership.json`。
- `user://` 下的存档只有存档服务能读写；任何代码都不得用 `ResourceLoader`、`ResourceSaver` 读写 `user://`（ENG-ARCH §2、SYS-SAVE-FORMAT §3）。
