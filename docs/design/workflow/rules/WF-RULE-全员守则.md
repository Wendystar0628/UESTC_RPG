# WF-RULE · 全员守则

- **提醒钩子**：`.collab/tools/hooks/uestc-guard.cjs` 每条消息前读 WF-CORE §0 注入 Claude 主会话与 Codex 各会话，Claude 子代理在启动时、Codex 子代理在第一次调用工具时各注入一次；钩子按 WF-ENTRY 的节标题注入角色入口，按路线表注入接入要点，碰内容路径时注入并定期重注 CORE-CONTENT §0，新建代码、脚本或文档时注入本文 §1；钩子不另存准则文字，核心准则只在 WF-CORE 写一句、细则在本文。

## 1 不过度工程化（D-201）

本项目是作者的个人实验作品，不是商业交付级项目；作者不看证据链，多写的每一行都在白花额度。
- **不写**：证据溯源、来源链、哈希或校验和、proof、verification、attest 一类的脚本与报告，handoff 证据目录，逐字节证明，额外的审计报告。构建和生产代码里本来就要用的摘要照常写。
- **不自己加**：门禁、检查脚本、测试脚手架、全量回归、重复构建。只跑任务单要求的检查，默认是 `gate.ps1` 的快检；觉得需要更多检查，先写一条【需定】问主会话。
- **回报从简**：照 WF-ONBOARD §4 与 WF-COMMS §3 的短头部，证据只给路径。

## 2 不向作者出选项

主会话以外的所有会话、执行者和子代理（Astra、Sol 各会话、值班执行者，以及主会话和它们开的子代理），都不给作者出选项或确认框，不用 AskUserQuestion 一类的工具，也不在终端里停下等作者选择。
- 需要确认、拿不准、要拍板的事，写进任务单"状态"或请求文件，并通知主会话（Astra、Sol 在 `notes/opus/` 新建来信文件，格式见 WF-COMMS §4；子代理交给派它的一方转达）。
- 主会话能据项目信息判断的直接定；只有属于作者的决定才转问作者。只有主会话转达"作者已定"的，才算作者的决定。

## 3 不预判时间

模型凭推理感知时间，误差很大：不估"已经用了多久""还要多久"，回报、评审和流水里不写预计完成时间，只写做到哪一步。
- 要用时间时以真实读数为准：命令输出、文件时间戳、额度读数；时长和消耗速度用两次真实读数相减。
- 读时间不是硬性规定，不为写时间戳频繁读时钟；手边没有真实时间就只写日期，不凭推理填。
- 任务单按 D-184 写的预计工作量只用来定单子大小，不当作完成时间的预告。

## 4 不短轮询、不干等、不重复复核

- **等命令**：能前台一次跑完的前台跑（单次最长 10 分钟）；必须放后台的，隔几分钟查一次它的日志或进程，进程没了就直接读结果往下做，不等完成通知，通知可能送不到。必须轮询时间隔不短于 2 分钟，不连续反复读同一份日志。
- **每次被叫醒只读与这次事件有关的文件**，不重读已完成的任务单。
- **不重复复核**：已批准、已合入、已复核通过的事项，没有新输入（新提交、新基线、新条件）就不再复核，也不再回"已核"；收到提醒时先看有没有新输入，没有就一行写"无新输入，沿用 <时间> 的结论"。门禁同一组合只跑一次，见 ENG-GATES §2。

## 5 来信

给主会话的来信一条一个新文件，开头标【需定】【待审】【知会】之一，一件事、5 行以内；格式与收件箱见 WF-COMMS §4。

## 6 文件操作

对所有会话和子代理都适用（D-149–D-152）。

### 6.1 下载

需要的引擎、导出模板、SDK、素材、文档直接下载，不必请示；只用官方或可信来源，下完说明下了什么、多大、放在哪。第三方代码与插件、音频素材的许可与登记见 OPS-RELEASE §7。

### 6.2 临时文件

放会话临时目录或仓库里不进 git 的 `output/`，不放进源码和文档目录；不占项目目录、不影响构建的不必频繁清理。

### 6.3 删除

能不删就不删；要删只用绝对路径、只删具体文件，不用通配符或相对路径，不写 `cd X; … rm …`，因为 `cd` 失败后删除会落到当前目录上。复制文件时复制来的 `.uid` 也按绝对路径逐个删。

### 6.4 路径与格式

一律用绝对路径，命令行参数里的路径也一样；新建文本文件用 UTF-8 和 LF，保持文件原有换行风格；`.gitattributes` 是 `* text=auto eol=lf`。

### 6.5 只改分派给自己的文件

别的代理正在改的不碰。

### 6.6 向 `.collab` 追加含 Windows 路径的中文文本

先用 Write 写到临时文件，再 `cat 临时文件 >> 目标` 追加，不用 python heredoc 或 printf 带反斜杠；追加后用 grep 核一下确实落进去了。

## 7 git 安全

- **不用 `git stash`**：stash 栈是所有工作树共用的，pop 会弹掉别人的。临时放一边用 WIP 提交，或另建临时分支。
- 在自己的工作树里写，git 一律 `git -C <工作树>`；在自己的分支上小步提交；不推送、不合并，不碰 `main`、主检出和别的工作树。
- 远端只有 `main` 和标签；不推送别的分支，不强推。
- `override.cfg` 和 Debug 编译改写的 `packages.lock.json` 不提交。
- 生成文件（文档地图 `DOCMAP.md` 与 `SECTIONS.md`）冲突时取任一边后重跑 `gen_index.py`，不手工合并。

## 8 主线优先（D-168）

- 主线的定义见 CORE-INDEX §2。主线闸口（ENG-WP §1）通过之前，每个包只交主线版：能接进主线、跑得通、不崩、不挡路。
- **主线版可以**：用简化几何或体块、默认参数、占位贴图与占位声音；只做默认状态和最常见的组合；跳过边角情况。
- **主线版不可以**：改动或绕开契约、数据格式和目录归属；留临时接口；违反 CORE-INDEX §3 里关于内容的规则。
- **不为细节阻塞合入**：细节问题写进回报，留到主线闸口之后统一处理；细节阶段按各文档的完整规格推进，核心体验（主线流程、行走、存档、画面没有明显卡顿）的问题优先修。

## 9 测试最小（D-167）

- **只做认为最有必要的测试**：项目要把时间花在实现上，不按上架游戏的标准测。经常跑、几乎从不失败的检查不该每次跑；不为一批改动堆测试。
- 合入前只跑几分钟的快检；改动碰到启动、行走、存档时加跑对应的核心专项；其余测试全部留到大量开发之后集中测一次，由主会话发起。判据与命令见 ENG-GATES §2，`scripts\gate.ps1 -Wp <WP-xx>` 默认按改动自动选。
- **不重跑**：同一个包上次门禁全过、之后没改相关文件，不再原样重跑；交候选前跑一次，合并时候选已过的项不重复；施工不用 `-NoCache`。
- 开发中用 `--pose` 截图看效果不算门禁；只改文档的不跑门禁，跑 `check_docs.py`。

## 10 贴近主线，少给合并添活（D-199）

施工分支离 `main` 越远、碰的公共文件越多，合并时的冲突和返工越多。

### 10.1 开工和被恢复时先看主线变了什么

读 `logs/merged.log` 最近 24 小时的合入，挑出和本包相关的，先 `git rebase main` 再动手；之后每开始下一步之前，`main` 变了就再 rebase。

### 10.2 只往自己的文件里加

多包共用的数据只加本包条目，覆盖层按包分片，分片路径与序号写法见 CORE-CONVENTIONS。改动尽量落在本包独占目录。

### 10.3 测试只锁本包自己的输出

以及"原有条目的字节与顺序不变"；不锁别的包会合法增减的全局集合与指纹。

### 10.4 改架构或实现新设计时，一次迁完、不留旧的（D-209）

改的一方在同一批改动里把所有使用方迁到新设计，删掉旧设计、旧代码、旧测试和旧文档，禁止新旧多套并存；交候选前跑全仓 G2，回报里列出迁了哪些使用方。只有下游正在别的工作树施工、一次改不完时，允许一层过渡兼容，它活不过这张单结案，任务单里写明删除条件；牵涉下游包归属的先找 Astra 定迁移方案。

### 10.5 小步交付

一块能独立合入就先交候选；叠在未合入候选上最多一层；交候选前 `git rebase main`，再用 `git merge-tree` 对最新 `main` 预演，有冲突先自己解。

### 10.6 评审定下的通用规则以规范文档为准

开工时按文档做；决策编号（D-nnn）由主会话统一分配，需要新决策在回报里提。

## 11 拿不准就问

- 会改动契约、数据格式或目录归属的，停下来问主会话；不影响这些的，按最保守的理解做，并在回报里写明假设。
- 文档之间冲突，或文档与 CORE-DECISIONS 不一致：按 WF-DOC §6 的层级判定；判定不了的报主会话，不自己改文档。

## 12 写文档与记忆

- 只写对后续开发有用的现行规则，不超出这份文档的作用范围，能一句说清不写一段。
- 已在代码或数据里实现的（契约、接口签名、参数表、归属表、预算数值）不在文档里抄，写一句以哪处为准；禁止同一内容维护两套。
- 同一条信息只留一份权威，别处只给指向。
- 合入流水与状态历史交给 git 与合并日志，文档只记现在。
- 写文档也费输出额度：先列要点，再展开。
- 记忆文件同理：只留偏好与原因和指向，不抄规则。文档的具体写法见 WF-DOC。

## 14 工作树用完删（D-166）

自己另建、不交候选的临时工作树（试验、沙盒、对照），用完当场 `git -C E:\Project\UESTC_RPG worktree remove --force <绝对路径>` 加 `git -C E:\Project\UESTC_RPG branch -D <分支>` 删掉，不留给别人收拾；交了候选的工作树，合入后的删除见 WF-MERGE §2 第 7 步。
