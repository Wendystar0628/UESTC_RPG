# WF-ROLE · 参与者与分工

> **范围**：本文规定会话怎么运行，各模型擅长什么，哪些事只能由 Opus 侧做，事归谁、交叉处怎么办，总指挥只做什么，Astra 怎么当指挥。

## 0 结论

1. **主代理只有一个，就是主会话**（§5，D-166）：只做判断；施工者自测后自己提交推送（WF-INDEX §2）。
2. **视觉风格只由 Opus 侧做，GPT 模型不做任何审美工作**（§3）：玩家看得见、听得见的结果，参数和取舍由主会话评审定值。
3. **按模型长处分工**（§2）：Opus 管审美、判断与变通；Sonnet 做语言、看图和已定的活；Astra 管架构与工程指挥；gpt-6.1-sol 是工程施工的默认模型。
4. **Claude 侧子代理都开在主会话下**（§1）：Opus 与 Sonnet 都向主会话回报。
5. **Astra 当指挥，施工交 gpt-6.1-sol 子代理**（§6）。

### 0.1 接入要点

- **做画面、配色、质感、构图、造型、界面观感、参数取值或截图评审的决定**：只能是 Opus 侧；Astra、Sol 等 GPT 或非 Opus 的执行者不做（§3）。
- **Astra 的包有可见或可听的结果**：只交机制和集中的可调参数，观感问题写评审请求交主会话（§3、WF-FLOW §4）。
- **Opus 侧的包里有重工程问题**（性能结构、线程、确定性、契约）：请 Astra 评审（§4）。

## 1 会话与运行方式

- **Claude 侧只有一个账号**：主会话是 Claude Code 交互会话；Opus 与 Sonnet 施工子代理都由主会话用 Agent 工具在后台开，向主会话回报，不另设中间会话。额度见底的处理见 WF-QUOTA §5。
- **Codex 侧只有两个会话**：Astra 和 Sol 会话，都开在 Codex 应用里（D-203、D-212），作者能看到全过程；派活一律发进对应会话（WF-COMMS §5）。模型、推理档和速度跟着会话走，在应用里设；GPT 侧一律普通速度（D-197）。
- 角色、模型与职责的总表见 WF-INDEX §1；会话号与调用命令见 `.collab/tools/README.md`。

## 2 模型的长处与短板

分工按模型的长处来：要审美、判断和变通的给 Opus；要语言质感和看图、但不定风格的给 Sonnet；架构判断、工程架构与工程指挥给 Astra；工程施工默认给 gpt-6.1-sol，它的能力接近 Astra、性价比高得多、可以高并发。

| 模型 | 用在哪里 | 长处 | 短板与限制 |
| --- | --- | --- | --- |
| Claude Opus 5.5 | 主会话；Opus 子代理 | 审美、判断、变通：画面、风格、内容，跨系统取舍，需要 Opus 的文档撰写 | 额度最贵，按并发公式开（WF-QUOTA） |
| Claude Sonnet | Sonnet 子代理 | 价格约为 Opus 的一半：难度较低的施工（规格、尺寸、色名都已给全的简单部件，按已定预设填数据，覆盖层与数据改动，测试与小修），中文文档改写、文案、看图初筛、质感做法整理 | 不定风格，画面与风格的定值归主会话；需要审美判断的活交 Opus |
| gpt-6-astra（xhigh） | Astra 主线程；少数 gpt-6-astra 子代理（§6） | 架构判断与工程指挥：契约与程序集边界、注册器、依赖方向，并发、确定性、本机烘焙与流式、序列化与迁移、物理与碰撞、性能结构的方案定案；拆单、审查与集成 | 最贵的 GPT 档，主线程以指挥为主；不做审美工作，语言质感、看图和审美眼光是 GPT 模型的短板 |
| gpt-6.1-sol | Sol 会话及其子代理；Astra 侧包的默认施工模型 | 能力接近 Astra，额度充足，可高并发；复杂工程施工用 high 或 xhigh | 同属 GPT 模型，不做审美；契约和共享工程文件不自行改（Astra 定案并授权后可以施工）；设计文档只按确切文字打补丁 |

## 3 GPT 模型不做审美工作

- **视觉风格只由 Opus 侧做**：着色、调色、描线与后期的观感，材质与造型的观感，按参考场景移植质感（ART-STYLE §1），都只由 Opus 侧处理；参考场景里没有对应物的内容，也由 Opus 侧按同一套质感做法统一处理。
- **作者最终决定**：玩家看得见、听得见的观感与风格细节，最终由作者决定；主会话先定可见参数的初值（WF-FLOW §4），看截图只挑明显出错，观感好坏以作者反馈为准。Sonnet 可以整理质感做法，不定风格。
- **GPT 模型一律不做**：Astra、它的子代理、Sol 会话和它们的子代理，不做画面、配色、质感、构图、造型、界面观感、参数取值和截图评审方面的决定与调整。Astra 的包只交机制和集中的可调参数；调研里涉及观感的，只收集事实、做法和出处，结论由主会话下。
- **GPT 不做视觉核验**：不看截图挑细节，不做像素比对或逐张对照，也不为此专门跑截图，它爱抠细节，做了只是白费额度。出图交固定机位截图脚本，看一眼由主会话做（ENG-GATES §2）。

## 4 事归谁与交叉的地方

- **审批与施工分开**：主会话定设计、审美、内容取舍、可见参数、优先级与评审留用；Astra 定工程、契约及高传播风险的方案。实际施工按 WF-MODEL §1 的七问逐项判断，包归属（ENG-WP §2）与目录写权限不因施工模型改变。
- **可见构件一律由 Opus 施工**，哪怕已给全尺寸和截面；GPT 可承担它们的非可见部分，如碰撞、数据、接线和单测。Astra 名下封闭、已定的子任务可单独转给 Sol，不按包号整包改派，工程取舍与必要复核仍归 Astra。
- **Astra 的包里有可见结果的**：Astra 交机制和参数表，主会话定参数值。这类包有：启动雾幕、镜头手感、跳转、行走手感、过场播放、介质。
- **Opus 侧的包里有重工程的**：遇到架构问题请 Astra 评审。这类包有：建筑生成器的开间与立面规则、描线的计算着色器、材质库。
- **画面相关的契约**：Astra 起草，主会话确认字段够不够用（WF-FLOW §4）。

## 5 总指挥只做什么

**主会话的注意力只花在要判断的事上**：
- **评审与定值**：画面与风格的评审和定值，质感移植（实现交子代理）；评审里定下的通用结论当天写回规范文档。
- **设计定案与裁决**：设计定案、跨系统取舍、文档冲突裁决（WF-DOC §6）；决策编号（D-nnn）由它统一分配。
- **派工与分工**：派工、排优先级、按独占目录分工；施工者推送后评审，不合格回滚或派返工单（WF-FLOW §2、§4）。
- **宣布与审批**：按组宣布契约冻结（WF-FLOW §5）；审批契约变更、开放室内清单 `interiors.json` 的增删（D-164）、预算余量（D-161）。
- **集中测试**：在大量开发之后安排一次，看哪些报告、谁来打分，见 ENG-GATES §2。
- **文档与状态**：维护 `docs/design/`，有变化时通知受影响的工作包；施工状态的内容由它决定（WF-STATUS）；与作者沟通。
- **元规则**：作者提出明显不合理或代价过高的要求时，先指出来，再按作者的决定执行。

**其余随时派出去，主会话不自己动手**（简单又量少、主会话手上已有全部信息的活例外，直接做，WF-MODEL §5）：
- **不需要审美的任务和杂活**：默认先派 Sol。调研、旁路、机械活交 Sol 会话：补信息、数据转换与核对、按确切文字打文档补丁、批量旁路工程活写成旁路单（WF-FLOW §6）。
- **Opus 侧的施工任务**（画面、风格、内容类包与需要 Opus 的文档撰写）：写成任务单，直接开 Opus 或 Sonnet 子代理（WF-FLOW §2）。
- **细节阶段的小修**：先交对应包的子代理或 Sol，主会话只看结果。

## 6 Astra 当指挥，施工默认交 gpt-6.1-sol 子代理

**Astra 是代码工程架构师**：除了管契约、工程配置、归属表与门禁入口，开发中还负责制定并演进工程架构（模块边界、依赖方向、数据流、线程与生命周期、确定性与资源管理）。发现明显不好的架构设计，第一反应不是绕过去或打补丁糊过去，而是写清该怎么改（问题、改法、影响哪些包、怎么迁移），再派子代理修掉；改别人在用的接口照 D-209（WF-RULE §10）：同一批里迁完所有使用方、删掉旧的，牵涉观感取舍的交主会话。

**Astra 主线程尽量当指挥官**：
- 做：契约与共享工程文件的定案；Astra 侧包的拆单和派工；写子代理简报，写清目标、约束和验收条目；审查子代理交回的方案与代码，看架构、契约、确定性和资源寿命；跨包的集成取舍；回答主会话；改共享件前告知邻居。
- 尽量不做：亲自写实现、亲自跑长时间的测试与排查，这些先拆给 Sol 子代理，Astra 只看结果和关键差异。

**施工默认用 gpt-6.1-sol 子代理**：Astra 名下所有包的施工，默认由 Astra 用 `spawn_agent` 开 gpt-6.1-sol 子代理完成，复杂工程用 high 或 xhigh，包括内核、确定性、统计、契约与存档迁移相关的包。包的归属与审查权不变，仍由 Astra 派工、审架构与契约。

**gpt-6-astra 子代理只在下面几种情形开**（用 xhigh）：契约、共享接口或存档迁移的方案起草；跨包的根因排查，Sol 子代理两次没查出来或没修对；确定性、并发、资源寿命的方案本身要改，需要 Astra 级判断的那一段。其余一律用 Sol。施工范围以 Astra 明确授权的路径为准，不自动取得其他目录权限。
