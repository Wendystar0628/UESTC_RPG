# WF-COMMS · 交接与通信

> **范围**：本文规定会话之间经哪些文件交接、`.collab` 里文件怎么放、怎么命名和写、任务单与请求文件及批准行的格式、来信怎么发、Codex 会话怎么派活。
> **不在本文**：一个包从派工到合入的各步：WF-FLOW、WF-MERGE；值班唤醒脚本：WF-DUTY §1；全员的来信与等待规则：WF-RULE §2–§5；命令行与会话号：`.collab/tools/README.md`。
> **查阅**：先读 §0；目录与文件看 §1；命名与写法看 §2；任务单、请求文件与批准行看 §3；来信与消息看 §4；Codex 会话与引导信箱看 §5。

## 0 结论

1. **经文件交接，消息只在事件发生时发**（§1、§4）：交接目录是 `E:\Project\UESTC_RPG.wt\.collab\`；任务单和请求文件是唯一依据，上下文重置后照它们的"状态"接着做，对不上以 Git 为准；各角色重置后先读什么见 WF-ENTRY。
2. **任务单与请求文件只追加、不改写，来信一条一个新文件**（§2、§4）。
3. **批准行有固定格式**（§3）：单独成行，行首就是"批准合入："，唤醒脚本按行首匹配。
4. **在用的和结案的分开放**（§1）：`tasks/<类>/` 与 `requests/` 下只放在用的和没合入的；`archive/`、`logs/` 不用读，搜索默认跳过。
5. **来信按收件方分收件箱，一条一个文件**（§4，D-207）：开头标【需定】【待审】【知会】，一件事、5 行以内。

### 0.1 接入要点

- **写合并请求或契约申请**：开头用 §3 的六行短头部，正文不贴证据。
- **写批准行**：行首是"批准合入："，前面不加符号或空格（§3）。
- **给主会话或 Astra 发话**：在对方收件箱 `notes/<收件方>/` 新建一个文件（§4）。
- **新建任务单或请求文件**：按 §2 命名，新建前确认编号没被占用，不覆盖别人的文件。

## 1 交接目录与文件

各方经仓库外的交接目录 `E:\Project\UESTC_RPG.wt\.collab\` 交接，它不进 git。

| 路径（相对 `.collab\`） | 谁写 | 写什么 |
| --- | --- | --- |

**结案即挪走**：
- `tasks/<类>/` 下只放还在用的任务单，主会话在末尾写"结案"后挪进 `archive/tasks/<类>/`；`requests/` 下只放还没合入的，值班合入并写完"已合入"后挪进 `archive/requests/`；来信由收件方处理完挪进 `archive/notes/<收件方>/`；已审计且采纳项都已入队的调研挪进 `archive/research/`。
- 挪动只改位置不改内容；目标已有同名文件就先看清，不覆盖。
- 任务单里只放目标、范围、已定取值、交付标准、评审结论和一行现状；过程流水放 `logs/tasks/`。批准行与它的"已合入"行留在任务单里（脚本按它们判断已批未合）。
- `archive/`、`logs/` 不用读，搜索默认跳过；要查旧事点名路径搜，不要删改 `.ignore`。

## 2 命名与写法

- 任务单与请求文件只追加、不改写，每条带时间，路径一律写绝对路径；唯一的例外是 `research/INDEX.md` 的"Opus 审计"一列（旁路会话标"待审"，主会话审计后改写）。
- **文件名一看就懂**（D-208）：只看名字就能猜到内容；规范文档的文件名是"编码-中文简题.md"（WF-DOC §3）。
- **任务单**：文件名"三位编号-主题"：施工单 `tasks/claude/<nnn>-<主题>.md`、值班单 `tasks/sol/<nnn>-<主题>.md`、调研单 `side/cards/r<nnn>-<主题>.md`、旁路单 `side/cards/s<nnn>-<主题>.md`。编号各自递增，新建前确认没被占用；拆出的子单在编号后加 a、b。流水文件与任务单同名，后缀换成 `.log.md`。
- **请求文件**：`<类型>-<包号>-<主题>.md`，类型是 `merge`、`contract`、`review`；用不覆盖的写法创建（先确认文件不存在），已有同名文件时末尾加 `-2`、`-3`。
- **来信**：文件名见 §4。

## 3 任务单与请求文件的格式

### 3.1 施工单、值班单与旁路单

- **施工单**：正文写 WF-FLOW §2 列的五项；末尾依次是"状态"小节（一行现状加指向流水的一行；流水一行一事、带时间，写进 `logs/tasks/<任务单名>.log.md`）、"Opus 评审（时间）"小节（主会话写，通过或逐条修改意见）、批准行。
- **值班单**：正文写任务、做法和不许做的事；末尾"状态"由值班执行者写现状一行，流水写进 `logs/tasks/`。
- **旁路单**：正文写在哪做、交付什么、能改什么、哪些不许做；末尾"状态"由旁路会话写过程与结果。

### 3.2 请求文件

正文按 §1 的"写什么"；后续各方只在末尾追加，每条带时间和署名。

### 3.3 合并请求与契约申请的短头部（D-201）

开头六行写完要主会话看的东西，正文不贴证据：
1. 候选：分支、头提交、基线；
2. 改了什么：3 行以内，说结果不说过程；
3. 要主会话定的事：逐条，没有就写"无"；
4. 门禁：一行结果，例如"G1–G5 过，G2 实跑"；
5. 依赖与合入条件：没有就写"无"；
6. 证据：截图、日志的路径，一行列完。

再往下只写主会话需要知道的例外，不写逐项证明、测试计数明细、来源链和哈希。

### 3.4 批准行

格式 `批准合入：<候选提交或说明>，Opus，<时间>`，后面可接括号里的门禁组合或条件；写在合并请求或任务单的末尾，单独成行，行首就是"批准合入："，前面不加列表符号或空格——唤醒脚本按行首匹配，行首不对就叫不醒值班执行者。批准行一出现，值班就把它和当时其他能合的一起合掉（WF-MERGE §1）；合入后值班执行者在同一文件末尾追加"已合入：main=<短号>，<时间>，<执行者>"。

## 4 来信与消息

### 4.1 什么时候发

**消息只在事件发生时发**，内容一句话，细节都在任务单里；不发进度汇报，不互相轮询；几张单在 10 分钟内先后到待评审时，合成一条消息。

| 方向 | 什么时候发 |
| --- | --- |
| 值班与旁路执行者、Astra → 主会话 | 合入完成、门禁失败、条件未满足、卡死进程、调研完成、待评审、受阻需要决定；写进主会话收件箱 `notes/opus/` |
| 主会话 → Astra | 文档改了、契约冻结了、某个包阻塞了、新任务；写进 `notes/astra/`，同时用 `codex queue` 或引导信箱发进会话（§5） |

### 4.2 一条来信一个新文件（D-207）

写给谁，就在谁的收件箱 `notes/<收件方>/` 新建一个文件，文件名 `<YYYYMMDD-HHMMSS>-<发件方>-<短词>.md`；时间取真实读数，发件方写 `opus`、`astra`、`duty`（值班执行者）、`gemini`、`side`（Sol 旁路会话）之一。写完不改，不往别的文件里追加；值班一轮的通知合成一个文件。收件方处理完把文件挪进 `archive/notes/<收件方>/`，收件箱里只剩没处理的：写的一方不用读旧信，收的一方只读新文件。主会话的收件箱由事件等待脚本带回全文后自动挪走。

### 4.3 三级标记与写法

- **来信分三级**（D-201）：写给主会话的每条来信第一行开头标三种之一：【需定】要主会话拍板（观感、跨两侧的取舍、作者级的事）；【待审】有候选、申请或报告等主会话审；【知会】只是告诉一声（开工了、已核过、合入成功之类）。主会话的事件等待只为【需定】【待审】和失败、冲突叫醒，【知会】攒着下次一并看。
- **一条只讲一件事，5 行以内**：要点写全，细节放在任务单或请求文件里给路径。
- **纯工程判断自己定**：Astra 侧能按契约、架构和现有规则判断的工程事（接口细节、实现路径、测试写法、合并顺序），Astra 自己定，记一条【知会】，不写成"请主会话决定"。
- **确认与提问**：不向作者出选项，需要确认的事写进任务单或请求文件并通知主会话（WF-RULE §2）。

## 5 Codex 会话与引导信箱

**Codex 侧会话都在 Codex 应用里**（D-203）：Astra、Sol 旁路和 luna 都是作者开着的会话（值班里的 luna 与兜底的 Sol 例外：每次新开一个 Codex CLI 会话，D-210）。主会话、唤醒脚本给它们派活，一律发进对应会话：`codex queue --thread <会话号> --message <内容>`，作者在应用里能看到全过程。脚本用 `tools/duty/codex_app_run.py` 发，它在消息末尾附一个任务号，要求会话做完在 `notes/codex-app-done.md` 追加"[任务号] 一句话结果"，看到这一行才算这一轮结束。模型、推理档和速度跟着会话走；要新的会话，请作者在应用里开好再登记会话号。不用 `codex exec` 另起或续跑后台线程。

**要当轮生效的消息走引导信箱**：会话正在跑时，`codex queue` 的消息要等这一轮结束才送到。要它当轮就看到，用 `python -I tools/duty/codex_app_steer.py <会话号> <消息文件> [等待秒数]`：会话在跑，就把信放进 `steer/<会话号>.md`，钩子 `tools/hooks/uestc-steer.cjs` 在它下一次工具调用后把信送进当前这一轮，只送一次，送完挪进 `steer/delivered/`；等待超时没被取走就撤回、改为排队；会话空闲就直接排队。只在确实要马上改变对方手上的事时用，平常照常排队。
