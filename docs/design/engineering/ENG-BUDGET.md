## 1 结论

1. **引擎与渲染器**：Godot 4.7.2-stable .NET 版，渲染器 Forward+，Windows 默认 D3D12；Vulkan 只用于着色器调试和兜底（选择条件见 ENG-PERF §13）。版本锁定在 `tools/godot-version.txt`，升级要主代理评审。代码全部用 C#；着色器用 Godot 着色语言，计算着色器用 GLSL。
2. **材质与管线**：场景只用自写的 ShaderMaterial，共用 `toon.gdshaderinc` 和调色板。**着色器白名单**：共 25 个 `.gdshader`（空间与天空 22 个、画布 3 个，含天气的 `precip.gdshader`、界面的 `ui_panel` 和 `ui_screen`、开始页的 `cine_cloud`、平面地图的 `map_base`），加约 6 个计算 `.glsl`，以 ENG-PERF §1.4 为准；外围、室内、光柱都用现有着色器的分支，不新增。地块用 64 m 网格的四叉树组织（每张图一棵，§3），按屏幕误差选级。描线只用后处理（CompositorEffect）。阴影用引擎原生的 4 级 PSSM，自写的只有方向量化、阴影方向高度钳、退光线和日月交接；倒影、窗灯、路灯光斑自己实现（ENG-PERF §10）。
3. **深度**：反向 Z 由引擎提供（4.3 起），近裁剪面 0.05 m（§5）。
4. **速度与不卡帧**：漫游速度与离地高度挂钩，并随速度自动调高屏幕误差阈值。不卡帧靠 ENG-PERF §5 的六条不变量保证（第 5 条"碰撞未就绪冻结物理"只在行走模式下起作用；第 6 条：镜头在任何楼体里时至少显示这栋楼的 I0 兜底层，行走跨进开放室内楼层前 IF 与碰撞必须就绪，WLD-INTERIORS §6.4），外加两条全局约束：每次雾幕淡出之后（`--title=1` 时从标题页转为实时那一刻起）管线编译计数不增，Canvas 计数同样（G16）；主线程不生成几何。不靠"留出飞行距离"。
5. **防止超预算**：
   - 资源上限挂在画面预设上，帧率和毫秒目标挂在"设备档 × 它的推荐预设"上（§2）；
   - 每个工作包从总账领取额度：三角形、绘制调用（主通道、阴影）、GPU 帧时占比、主线程毫秒；各包的占比在精致预设下核算（§8）；
   - 总账只发出 96% 的三角形、89% 的主通道绘制调用、90% 的阴影绘制调用、98% 的 GPU 帧时，其余（4% / 11% / 10% / 2%）留给主代理作余量（§8、WLD-OUTSKIRTS §11.1）；
   - 主线程另有帧时余量（ENG-PERF §6），音频的 0.35 ms 从这里划出，开发机只剩约 0.15 ms（§8）；
   - 门禁做静态预测（G8，纯 .NET，不占 GPU）、统计回归检验（G10，测导出的 release 版）、管线编译检查（G16）、预设底线检查（G17）、存档的保存耗时（G20）和音频预算（G21g），见 ENG-PERF §12.5。
6. **时间、季节、天气、画面设置、界面与行走的影响**：
   - **时间与季节**只是全局着色器参数和几张全局数据纹理（调色板、灯光通道、树种表）里的连续量（ENG-PERF §1.5）。改时间、换季不重编译、不重建格子、不换模型；季节对植被和地面的影响全部靠阈值生长（ENG-PERF §9），不增加三角形。
   - **天气**同样只是全局参数和几张全局纹理（ENG-PERF §1.5）。降水池启动时就入树，运行时只改实例数和 instance uniform（ENG-PERF §9）；投影随阴度变淡，夜雨没有月影时阴影通道空跑（ENG-PERF §10.1）。天气的总开销单列一行（§8）。
   - **画面设置**只改运行时的选级和引擎参数，不改烘焙产物、碰撞和世界状态（§7 第 18 条）；会清空管线的设置不做成选项，所以切换设置永远不触发管线编译（§7 第 9 条）。
   - **阴影**：引擎每帧本来就重渲全部级联，所以主光转动不额外增加阴影开销；反过来，也没有"远级少更新"的省钱办法，阴影只能靠减少投影物来省（ENG-PERF §10.1）。换季转场时飘落池用满 160 片。
   - **界面**是 CanvasLayer 里的 Control，由引擎的 2D 渲染器绘制（UI-VISUAL、SYS-ATLAS）。漫游态只有小地图、署名和临时提示，小地图主线程 ≤ 0.02 ms、GPU 可忽略（SYS-ATLAS §10）；界面态和大地图打开时 GPU 不超过帧时的 1%（§8）；界面脚本与排版主线程平均不超过 0.2 ms（UI-NAV §9），画布渲染 CPU ≤ 0.3 ms 单列；大页磨砂只在独显档默认开（UI-VISUAL §12）。
   - **外围**（WLD-OUTSKIRTS）：校外一圈街区分 O0–O3 四层，同一视角三层合计不超过 WP-47 的份额；外围按最近可达距离定级（WLD-OUTSKIRTS §4.1），没有碰撞，不新增着色器。
   - **室内**（WLD-INTERIORS）：只开放精选的 15 处；镜头在楼内时室外大部分被室内遮挡体剔除，楼内视角按 §2 的楼内额度另算，不挤占室外各包的份额。
   - **开始页、过场、平面地图、存档、音频**：T0 不超过 V1 的开销，过场帧与 Playing 同位置同预算（SYS-TITLE §11.1）；传送走雾幕瞬移，与点位跳转同样豁免速度律（§4）；存档只在保存那一帧拍快照，写盘在线程池；音频不画东西，GPU 为 0，主线程从余量里划出（§8）。
   - **行走模式**相当于一直处在 E1 视角：水平速度不超过 12 m/s，近处总是 L0（§4）。碰撞数据本机烘焙（D-165），碰撞体只在主线程入树（§7 第 12 条）；角色控制器（CharacterBody3D + Jolt，120 Hz）的每帧额度由 P0 原型重定（§8）。
   - 预算的最坏情况是"最坏视角 × 四种世界状态组合"取最大（§2）。
7. **包体与本机烘焙**（D-165）：几何类烘焙产物只有四类不随包发，在玩家机器上由同一个 `Build()` 生成并写进本机缓存：L0–L3 的 TileBundle（含外围 O0、O1、I0）、碰撞级 C、室内包与碰撞包、平面地图底图。全图常驻的小数据（派生数据纹理、2 m 分类栅格与 8 m 安全点网格、声学数据、导航图）随启动集 `boot_<地图>.pck` 发布，不现烘。G6 上限：安装目录 ≤ 0.9 GB，分发压缩包 ≤ 0.7 GB；本机缓存默认上限 2.5 GB（§8）。

## 2 预设与设备档的预算

画面设置分流畅、均衡、精致、极致四个预设，另加自定义（SYS-GRAPHICS §1）。预算分两张表：

- **预设资源上限**挂在预设上：选了这个预设，不论跑在哪台机器上，都不得超过；
- **设备档目标**挂在"设备档 × 它的推荐预设"上：帧率、掉帧率、GPU 和 CPU 的 p95。

细节距离系数、倒影更新间隔和植被密度是设置值，不是预算，写在 SYS-GRAPHICS §1 和 `game/data/quality-presets.json` 里。自定义组合不保证预算，设置页显示显存估算（ENG-PERF §11.7）。

设备档是下面的 PC 四档，不做手机。分档的判定和自动调节见 ENG-PERF §11。

| 设备档 | 典型设备 | 推荐预设 | 帧率目标 |
| --- | --- | --- | --- |
| 核显低 | UHD 6xx、Vega 8 | 流畅 | 30 |
| 核显高 | Iris Xe、Arc 核显、Radeon 680M、780M | 均衡 | 60 |
| 独显中 | GTX 1660、RTX 3050、RX 6600 | 精致 | 60 |
| 独显高（显存预算 ≥ 8 GB） | RTX 4070 及以上；开发机 RTX 4080 属于本档 | 极致 | ≥ 60，跟随刷新率 |

预算按每个预设最坏的视角计（E1–E7、F1，以及外围的 V1、V11；外围的最坏视角见 WLD-OUTSKIRTS §11.2，T0 不超过同一世界状态下的 V1，SYS-TITLE §11.1），并且乘以下面四种世界状态组合，取最大值。楼内视角另按下文的"楼内视角额度"核算。

| 组合 | 世界状态 | 为什么是最坏 |
| --- | --- | --- |
| 秋黄昏（默认状态） | 秋、17:30、晴 | 影子最长，远处的投影物会把影子投进近处几级，阴影的投影物最多；窗灯与路灯同时亮着一部分；飘落叶压满 |
| 夏正午满叶 | 夏、12:50、晴 | 叶量最大；荷花满塘、积雨云；四级阴影里的植被投影物最多。取晴天：白天阴雨时投影只是变淡，阴影通道照常跑（ENG-PERF §10.1），晴天的云最少、阴影最实 |
| 冬夜 | 冬、21:00，`--weather=snow --weather-intensity=1` | 降水池约 4000 片雪花，进光锥提亮；积雪满（步道也白）；路灯光斑 ×1.5；亮窗约 75%，光晕面片最多；月影变淡但阴影通道照常跑 |
| 夏夜雷雨 | 夏、21:30，`--weather=thunderstorm --weather-intensity=1` | 透明、特效和后期压得最满：降水池满 8192（含 512 个溅落）、远雨幕、闪电；湿路面的灯条和积水倒影步进；满叶；灯按有效太阳高度提前全亮（ENG-PERF §10.3）。夜雨没有月影，阴影通道空跑，所以它压的是透明、特效和 CPU，不压阴影 |

其他组合（含其余天气）不单独核算预算，只进 SYS-TIME §8 和 SYS-WEATHER §9 的验收；SYS-WEATHER §9 估计的其他天气增量都小于夏夜雷雨。

**预设资源上限**：

| 资源 | 流畅 | 均衡 | 精致 | 极致 |
| --- | --- | --- | --- | --- |
| 内部渲染像素 | ≤ 0.75 MP | ≤ 1.0 MP | ≤ 2.1 MP | ≤ 3.7 MP；4K 输出时 ≤ 4.9 MP |
| 主通道三角形 | 70 万 | 120 万 | 250 万 | 400 万 |
| 阴影三角形（各级合计） | 25 万 | 50 万 | 120 万 | 200 万 |
| 主通道绘制调用 | ≤ 800 | ≤ 1000 | ≤ 1500 | ≤ 2000 |
| 阴影绘制调用（各级合计） | ≤ 400 | ≤ 800 | ≤ 1500 | ≤ 2500 |
| 着色器 | 白名单（ENG-PERF §1.4），四档相同 | 同左 | 同左 | 同左 |
| 阴影图（四档都是 16 位） | 2048²，2 级，600 m（8 MB） | 2048²，2 级，1000 m（8 MB） | 4096²，4 级，1600 m（32 MB） | 8192²，4 级，1600 m（128 MB） |
| 纹理显存 | ≤ 384 MB，四档相同（同一套纹理，见下） | 同左 | 同左 | 同左 |
| 几何显存（含 MultiMesh 实例数据） | ≤ 400 MB | ≤ 400 MB | ≤ 600 MB | ≤ 1 GB |
| 渲染目标与阴影图（不含约 70 MB 固定开销） | ≤ 200 MB | ≤ 200 MB | ≤ 300 MB；4K 输出 ≤ 450 MB | ≤ 450 MB（1440p）；4K 输出 ≤ 700 MB |
| 显存合计 | ≤ 1.2 GB（核显占系统内存） | 同左 | ≤ 1.8 GB | ≤ 3 GB |
| 进程内存（不含显存） | ≤ 3 GB | ≤ 3 GB | ≤ 4 GB | ≤ 4 GB |

- **纹理四档相同**：没有纹理质量选项（SYS-GRAPHICS §1），全套纹理常驻，不随预设变化，所以只能取一个上限。按流畅、均衡的显存合计取 384 MB（安装包的贴图 ≤ 250 MB，ENG-PERF §8，放得下；大面积颜色来自调色板，不靠贴图）。美术需要更多纹理时，要同时放宽流畅、均衡的显存合计（纹理 1 GB 时约 1.7 GB），是否放宽见 §11。
- **384 MB 里的专项拨款**：

  | 用途 | 额度 | 依据 |
  | --- | --- | --- |
  | 平面地图的数据纹理（`map_sdf_a`、`map_sdf_b`、`map_sdf_out`、`map_glyphs`，RGBA8 不压缩），含外圈 | 约 41 MB：`map_rect` ±1280 m 以内的全分辨率纹理约 37 MB，地图页 `atlasRect` ±1536 m 在 1280–1536 m 的外圈用半分辨率外圈纹理，约 +4 MB | SYS-ATLAS §2.1、SYS-ATLAS §10 |
  | 标记缩略图（目录用，常驻） | 约 1.6 MB | SYS-ATLAS §10；传送卡的大图按需读、关大地图 30 s 后释放 |
  | 外围新增贴图（O2 窗带图集、流畅档的卡片环、电车与站台部件） | ≤ 48 MB | WLD-OUTSKIRTS §11.3 |
  | 窗覆盖纹理（256×256） | 256 KB | WLD-INTERIORS §12 |
  | 扉页静帧（3440×1440，一张） | 约 20 MB，只在扉页期间（Boot），转为实时后释放 | SYS-TITLE §1.3；扉页期间与三维预热同时驻留，按峰值计 |

  常驻部分（不含扉页）合计约 90 MB，留给其余美术贴图的约 294 MB；扉页期间的峰值再多约 20 MB。ENG-PERF §8 的贴图 ≤ 250 MB，在约 294 MB 以内，余量约 44 MB，P0 用金样核实（§11）。
- **进程内存**含音频常驻 ≤ 96 MB（床约 45 MB、一次性声约 15 MB、观者声 7–10 MB、声学 ≤ 8 MB），四档相同（SYS-AUDIO §18.2）；开放室内的碰撞每栋 ≤ 2 MB、室内索引约 50 KB、导航图约 2 MB（WLD-INTERIORS §12）；外围的前沿线距离场与软地板网格约 0.6 MB（WLD-OUTSKIRTS §11.3）；存档峰值 < 1 MB（SYS-SAVE §13）。
- **超采样**（ART-STYLE、ENG-PERF §10.2）：默认不做。极致预设给一个可选项"超采样 1.25×"（`Scaling3DScale` = 1.25、`Scaling3DMode` = Bilinear，属雾幕类），默认关。开启后内部像素是输出的 1.5625 倍：只在设备档为独显高、1080p 输出时列出（约 3.2 MP，在上表极致的内部像素上限以内）；1440p 下约 5.8 MP，超出上限，不提供（SYS-GRAPHICS §1）。选了它预设即显示为"自定义"，按自定义组合处理，不保证本节的预算；P0 在渲染比例 0.5 / 0.59 / 0.67 / 1.0 / 1.25 五档截图并实测开销。
- **渲染目标与阴影图**按 ENG-PERF §11.7 的公式随输出分辨率计算。SMAA 和 FSR1 按输出像素算，所以 4K 输出时明显变大：极致 4K 约 650 MB，上限取 700 MB；精致 4K（FSR1 0.5）约 410 MB。
- 预设按"内部像素上限"换算到最接近的 FSR1 比例，不写死比例（SYS-GRAPHICS §1）。G8 按四个预设各算一遍，并检查单调性：极致 ≥ 精致 ≥ 均衡 ≥ 流畅（SYS-GRAPHICS §10）。
- **统计口径**（详见 ENG-PERF §1.3）：绘制调用读 `Viewport.GetRenderInfo`，主通道用 `RenderInfoType.Visible`，阴影用 `RenderInfoType.Shadow`。引擎把一个自动实例化的连续段记为 1 次，深度预通道不重复计数，所以实际提交给 GPU 的次数约为"不透明 × 2 + 透明"。三角形以 G8 的预测和内核自记的账为准：引擎的图元计数在带 LOD 的 MultiMesh 上不乘实例数。

**楼内视角额度**（WLD-INTERIORS §12；精致预设，其他预设按上表的总量等比缩放）：镜头在开放室内时，室外大部分被室内遮挡体剔除，所以这是另一种视角，不并入 E1–E7、F1 的室外最坏视角，也不挤占 §8 里室外各包的份额。

| 项 | 额度 | 说明 |
| --- | --- | --- |
| 室内主通道三角形 | ≤ 80 万；大厅、中庭、场馆 ≤ 100 万 | 原型实测 30–56 万 |
| 室内主通道绘制调用 | ≤ 250 次 | 实测 53–115 次；室内光柱每间房的棱柱合成 1 次、细尘 1 次，同屏 ≤ 3 组，计在这里 |
| 室内阴影三角形 | ≤ 20 万（只有墙和楼板投影） | 踢脚、窗框不投影 |

- 独显中和两档核显的毫秒数，在手头有的真机上测（G11）；开发机上用 `--quality=` 跑这些预设，只判回归，不判达标。
- 玩家选的预设高于推荐时，不保证上表的帧率；自动调节只往下调，不碰渲染比例（ENG-PERF §11.3）。

**GPU 帧时分配**（按占比分配；在开发机上按实测的总帧时换算成毫秒）：

| 部分 | 占比 |
| --- | --- |
| 阴影（4 级 PSSM，每帧全量重渲） | 22% |
| 深度预通道与不透明物体 | 39% |
| 天空、透明物体、水和特效 | 12% |
| 倒影（SubViewport，按更新间隔平均到每帧） | 5% |
| 后期（Compositor 的描线与边缘光、移轴、光斑，内置 Glow、LUT、SMAA、FSR1） | 15% |
| 余量 | 7% |

- 引擎每帧重渲全部级联，阴影开销与主光转不转无关，所以阴影只按一个份额（22%）核算，不分快慢档。月影用同一盏灯、同一套级联，不另占份额。
- 深度预通道是固定开销：描线要读 normal_roughness 缓冲，预通道不能关（§10）。它算在"不透明物体"的份额里。
- 占比在精致预设下核算（§8）。天气不另占份额：云、雨幕、闪电进"天空"，降水池和溅落进"透明物体和特效"，湿面和积水进"不透明物体"，雨点环进"水"，远雨幕和闪光帧描线进"后期"；它对晴天的总增量另有上限（§8 天气一行）。
- 后期（风格"清透"，ART-STYLE、ENG-PERF §10.2）：描线分两次 dispatch（线遮罩 → 去斑点、抗锯齿与合成），高光肩部与暗角并进移轴合成那次 dispatch，后期合计约 1.3–2.4 ms，按 15% 核算，P0 实测；室外软边光柱、室内棱柱光柱和细尘画在透明阶段，进"天空、透明物体、水和特效"。外围几何的开销进阴影与不透明的份额，按 §8 的 WP-47 一行记账。
- 时间快进（点刻度、预设、拨时间环的前向快进，SYS-TIME §1）、换季转场、点位跳转与传送的帧，切图的雾幕帧，存档缩略图的那一帧（SYS-SAVE §13），以及画面设置生效的那一帧和其后 2 s（SYS-GRAPHICS §4），不计入 G10 的帧时账和自动调节的统计（ENG-PERF §11.3），只按上面的体验指标验收，用 ENG-PERF §12.4 的"前推 24 小时""四季轮换""天气巡回""预设轮换""过场体验"脚本和 F3、F4 路线测。换天气的过渡是慢变化，照常计入。
- 开始页、进场过场与返回标题（Title、Entering、Leaving）的帧不进自动调节的统计，自适应冻结；过场帧与 Playing 在同一位置的预算相同，不靠降画质过关；T0 照常作为 G10 的视角测（SYS-TITLE §11.1、SYS-TITLE §11.4）。

**测量机器**：吞吐和回归都在开发机（本机，RTX 4080 台式机）上测，不设中档参考机（ENG-PERF §12.1）。本机有多个适配器，测量时用 `--gpu-index` 选 RTX 4080，并断言显卡名；预设由 `--quality=` 指定，自动调节关。独显中和核显的指标，在实际可用的设备上测（G11）。

## 3 细节级别与分块（统一定义）

**建筑与地块的细节级别**（以 1080p、垂直视场 60° 为基准；名义距离只是参考，实际按屏幕误差 τ 切换，τ 的定义见 ENG-PERF §5）：

| 级别 | 名义距离 | 内容 | 生成方式 |
| --- | --- | --- | --- |
| L0+ | < 5 m | 贴脸细节：细节平铺、胶条、螺栓、开放室内的 IF | 本机烘焙（D-165）；开发态可 `--gen=live` 实时生成 |
| L0 | < 40 m | 实体窗框、栏杆、倒角、全部贴花、小道具 | 本机烘焙；开发态可实时生成 |
| L1 | 40–150 m | 窗洞内壁与窗台；简化窗框；只保留 0.5 m 以上的道具 | 本机烘焙；开发态可实时生成 |
| L2 | 150–400 m | 体量、屋顶轮廓、窗带 | 本机烘焙 |
| L3 | 400–800 m | 体量；树冠云 | 本机烘焙 |
| L4 | > 800 m | 剪影；常驻内存 | 烘焙后随启动集发；雾幕期间同步加载 |

- **室内另有三级**（WLD-INTERIORS §6.1）：I0 兜底层（进 TileBundle 的 L0，镜头在任何楼体里都至少显示它）、IS 只留壳（墙、楼板、吊顶、楼梯、灯片、门）、IF 完整（壳、家具、生活痕迹、灯）。开放楼整体加载、按层显示：所在层 IF，±1 层 IS；关着的楼只有简化室内或 I0。
- **外围**（WLD-OUTSKIRTS §4）：外围表面按最近可达距离 d_min 套用上表定级；O2 雾中楼顶是另外的常驻合并块（≤ 16 块），不在 L4 内。
- **生成方式**：**全部级别都是烘焙产物，发布版本机烘焙**（D-165）：L0–L3（含外围 O0、O1 和 I0 兜底层）在玩家机器上由与开发烘焙器同一个 `Build()` 生成，第一次需要时生成，按"格 × 级"存成自定义的格包二进制格式 `.tbin`（整体 zstd，TileBundle）写进本机缓存，之后从缓存读；L4 随启动集发（`.res`）（ENG-PERF §5、§8）。开发和 CI 的无界面烘焙器 `--bake=all` 照旧，出参考哈希、给门禁预烘缓存；`-- --gen=live` 只生成、不读也不写缓存。生成都在工作线程上，主线程只挂载。
- **每个表面不超过 65 536 个顶点**（16 位索引）。静态几何按"材质 × 不超过 16–24 m 的块"合并，每块 1–8k 个三角形（ENG-PERF §1.1）。相邻格写统一的格包围盒，避免顶点量化接缝（§7 第 7 条）。
- **三层分工**：格子之间的语义级别 L0+–L4 由自写的流式管理器切换；一个网格内部的细节层次用"索引前缀"形式的网格 LOD（引擎的 `lods`，只换索引、不换顶点）；HLOD 和距离截断用 visibility range（ENG-PERF §1.2、ENG-PERF §4）。
- **植被不跟随格子级别**，按单株选级，有自己的级别表（ENG-PERF §9），其中树的 L0+ 覆盖 0–15 m。
- **四季共用一套模型和替身**：如果 P0 选了半八面体替身，图集约 21 MB（BC7）；四季各烘一套，显存、烘焙时间和包体都要 ×4，换季时还得换资源。季节差异只用季相色调和噪声阈值实现（ENG-PERF §9），冬季裸枝也不另烘替身。
- **级别过渡**：淡入淡出一律在卡通着色器里按 instance uniform 做抖动，0.25 s 完成，不走透明管线；visibility range 的 `fade_mode` 一律设为 Disabled（引擎自带的淡化会强制走透明管线，描线依赖的缓冲也就没有了）。近处植被用嵌套子集缩放过渡。前后两级的平均明度差不超过 3%。

**分块**：64 m 网格的四叉树，每张图一棵，覆盖本图的地图包围盒（清水河是截面线的包围盒，约 ±1.5 km，WLD-OUTSKIRTS §3.5），格号范围 |ix|、|iz| < 512（SYS-MAPS §12）。预算按视角核算；每个格子的上限只是防呆，以防单格失控：

| 级别 | 格子边长 | 每格三角形上限（防呆） | 单格烘焙产物（zstd，缓存里的文件）与加载 |
| --- | --- | --- | --- |
| L0 | 64 m | 60 万 | ≤ 8 MB；读入（读文件、解压、哈希校验、建网格）≤ 30 ms |
| L1 | 128 m | 50 万 | ≤ 6 MB；同上 |
| L2 | 256 m | 50 万 | ≤ 3 MB |
| L3 | 512 m | 50 万 | ≤ 2 MB |
| L4 | 全图（每图一份） | 清水河共约 26 万（校内 23 万，加外围 O1 的 L4）；按图记进 `budgets.json` 的 `maps.<id>` | ≤ 4 MB；雾幕期间同步加载，常驻 |

- 主线程挂载一格的时间另有上限：每帧最多激活 1 格，不超过 1.0 ms（ENG-PERF §5）。开放室内一帧挂一层（约 270 个实例，0.31–0.45 ms），外围 O1 的格子也和校内共用这 1.0 ms（WLD-INTERIORS §6.1、WLD-OUTSKIRTS §11.3）。

## 4 流式加载与速度

加载机制见 ENG-PERF §5 的 TileBundle：`res://` 里的资源用 `ResourceLoader.LoadThreadedRequest`，本机缓存的 `.tbin` 由工作线程任务读入。

- **有效速度**（旁观模式）= min(滚轮档位速度, 6 + 0.5 × 离地高度) × 冲刺倍数（冲刺 ×2）。上限 200 m/s。离地越近，速度越慢。离地高度用常驻的低精度地形高度查询。
- **按速度提高屏幕误差阈值**：τ = 1.5 px × (1 + v / 30 m/s)。另有两道硬门槛：
  - 速度超过 15 m/s，不加载 L0；
  - 速度超过 45 m/s，不加载 L1；
  - 回差：速度分别降到 10 m/s、35 m/s 以下，并保持 0.3 s，才恢复加载。
- **行走模式**：不论步速倍率多大，水平速度上限 12 m/s，低于 15 m/s 的 L0 门槛，所以行走时近处显示的总是 L0（SYS-WALK §2、SYS-WALK §14）。
- **跳转豁免速度律**：点位跳转的路径是已知的，所以不受上面的速度律约束，改用"已知目的地预取 + 到达保证"（UI-NAV §7.5、ENG-PERF §5）。约束只剩两条：
  - 最后 25% 的路程不超过速度律，落地时近景一定是 L0；
  - 到达帧要求目的地各环就绪，否则雾幕多停一会儿，最多 1.2 s。
- **旁观切行走的降落**（SYS-WALK §5）也豁免速度律：落点在切换的那一刻就已知，立即按已知目的地预取。降落主要是竖直的，"最后 25%"那一条不适用；落点各环或碰撞格还没就绪时，镜头按 SYS-WALK §5 第 3 步悬停在落点上方等待。
- **传送、过场与边界**：传送（SYS-ATLAS §7）默认雾幕瞬移，与跳转同样按"已知目的地预取 + 到达保证"处理，目的地是室内时把室内包和碰撞一起插队（WLD-INTERIORS §6.2）；进场过场的路径已知，按 SYS-TITLE §10 沿路预取，不受速度律约束；旁观飞到外围边缘时减速、`edge_fog` 变浓、再被推回（WLD-OUTSKIRTS §8），水平范围与软地板见 WLD-OUTSKIRTS §8.1。
- 加载与卸载半径、预取、优先级、淘汰规则见 ENG-PERF §5。

## 5 深度与近裁剪面

- **反向 Z 由引擎提供**（4.3 起）；Forward+ 的深度格式优先用 D32_SFLOAT_S8_UINT。项目代码不做任何处理。
- **近裁剪面 0.05 m**，旁观和行走相同。主相机远裁剪面 12 km，盖住雾海环（半径约 10 km）和 360° 远景环（WLD-DIORAMA）；远裁剪面、雾海外半径、远景环半径按图从 `backdrop.json` 读，清水河 12 km（SYS-MAPS §12）；开始页的 T0 离中心约 3.48 km，仍在其内（SYS-TITLE §2.1）。在反向 Z 浮点深度下，0.05 m 到 12 km 的精度足够。
- **20 km 外的远景**（日月盘、星空、银河、积雨云卡片、城市天光）画在天空着色器里，不写深度。
- **坐标精度**（SYS-MAPS §12、WLD-OUTSKIRTS §3.5）：按图规定。单图半径（离中心最远的可达点）不超过 8 km，8 km 以内单精度步长不超过约 0.5 mm；清水河的地图包围盒约 ±1.5 km，旁观可达范围离中心不超过 3 km，步长约 0.24 mm；更大的区域拆成几张图。用引擎的单精度构建，不需要双精度。顶点按格包围盒量化，与世界坐标的大小无关。
- **P0 仍要实测**：16 位阴影深度在低太阳掠射面上的痤疮和影子脱离（ENG-PERF §10.1）；镜头贴墙 0.3 m 时，近裁剪面切进墙体后剖切色是否完整（SYS-VIEW §5）。

## 6 阴影、后期、倒影、灯光

全部按 ENG-PERF §10 实现。要点：

- **阴影**（ENG-PERF §10.1）：引擎原生，一盏 DirectionalLight3D，太阳和月亮轮流担任。
  - PSSM 4 级，split 0.03 / 0.12 / 0.40（约 48 / 192 / 640 m），max_distance 1600 m（精致、极致；均衡、流畅是 2 级、1000 / 600 m，ENG-PERF §10.1），blend_splits 开，PCSS 软影 `LightAngularDistance` ≈ 0.45°；软影滤波档位固定为 Soft Medium，四个预设相同（改一次会清空全部已编译管线）。不用 SSAO。
  - 阴影图尺寸、级联数和阴影距离随画面预设（§2、SYS-GRAPHICS §1）：极致 8192²（128 MB），精致 4096²，均衡、流畅 2048² 且只用 2 级；深度一律 16 位。改尺寸只换纹理，改级联和距离不编译，都是即时类（SYS-GRAPHICS §3）；最差值 2048²、2 级（§7 第 17 条）。
  - 室内（WLD-INTERIORS §6.3）：镜头在开放楼内时，主光阴影的第一级范围缩到 8–12 m，0.5 s 内过渡、出楼恢复；改级联分割和阴影距离是即时类、不编译（SYS-GRAPHICS §3 登记为"介质覆盖"）。
  - 天气（SYS-WEATHER §7）：阴影强度再乘 (1 − 0.8 × 阴度)，白天不低于 0.2；最终强度低于 0.01 时（无影蓝调、雨夜无月影、地下、水下） `ShadowOpacity` 和 `ShadowCasterMask` 置 0，阴影通道空跑（ENG-PERF §10.1）。
  - 引擎每帧重渲全部级联，**没有降低远级更新率的接口**。
  - 自写、用全局参数实现的：方向量化（δ ≈ 0.01°，带回差，只在跨过一步时转灯；快速变化时连续转动）；阴影方向高度钳 4°（介质为室内时目标抬到 14°，0.5 s 过渡、出楼还原，ENG-PERF §10.1；取值见 §11）；主光强度 smoothstep(−1°, 4°, h)；退光线（全局参数 `retreat_y`，宣邦楼穹顶的 instance uniform 偏置 +6 m）；无影蓝调里的日月交接（全局 `shadow_strength`，月影最强 0.45）。
- **调色板**（ENG-PERF §1.5）：256×64 RGBA8 的 ImageTexture，登记为全局 `sampler2D`，由 CPU 在 OKLab 里求值后每帧整张 `Update()`（64 KB，PC 上可以忽略）。3D 调色纹理保持静态 32³，时段变化只走 CDL 参数，CDL 每帧烘进运行时 LUT。
- **后期**（ENG-PERF §10.2）：Compositor 在 POST_SKY 画描线和屏幕空间边缘光，在 POST_TRANSPARENT 画移轴和光斑；之后是内置 Glow（柔光）、Tonemap Linear、内置 LUT、抗锯齿。抗锯齿随预设：精致、极致 SMAA 1x，均衡、流畅 FXAA（SYS-GRAPHICS §1），不用 TAA、MSAA。描线按内部分辨率换算线宽，并设最小宽度（ENG-PERF §10.2）。移轴、镜头光斑、光柱、暗角是风格默认，玩家可以关，关时 0.5 s 淡出（SYS-GRAPHICS §2）。
  - 风格"清透"（ART-STYLE §4、ART-STYLE §7）：描线约 1.25 px（1080p）、随底色染色的细线，两次 dispatch（线遮罩 → 去斑点、抗锯齿与合成），仍算一个文件；高光肩部和暗角并进移轴合成那次 dispatch（+0.02 ms 量级）；柔光白天只让高光晕开，17:30 默认格只留 0–0.04（默认 0.02）的全屏柔光；超采样默认不做（§2）。1440p 下后期合计约 1.3–2.4 ms，按 §2 的 15% 核算，P0 实测。
- **光柱**（ENG-PERF §10.2）：软边加法体，画在透明阶段，不投影。室外沿太阳方向的开口圆柱或扁片，每屏 ≤ 8 根，计入"天空与特效"；室内每块受光窗格一根棱柱，每间房合成 1 次绘制、细尘 1 次，同屏 ≤ 3 组，屏幕覆盖率 ≤ 0.6 屏（P0 实测），计入楼内视角额度（§2）；细尘 MultiMesh 每屏 ≤ 600 粒。光柱可以关（风格默认）。
- **倒影**（ENG-PERF §10.4）：SubViewport 加镜像相机，用独立的 World3D（里面只有平涂的 REFLECT 代理和共用的 Sky，没有投影光），每轴 1/4 分辨率，每帧只给一个湖，按预设的刷新间隔更新（每 2–4 帧，最差每 4 帧，SYS-GRAPHICS §1）。倒影材质读调色板行 0，自动跟随时段与季节；夜间画亮窗，灯条读共用灯条表 `refl_lamps`（ENG-PERF §10.3）。不用 SSR 和反射探针。
- **窗灯**（ENG-PERF §10.3）：哈希阈值加 32 个灯光通道（32×1 的全局数据纹理），窗号基址放在顶点属性里；光晕面片用 MultiMesh，亮度由着色器读通道。亮灭曲线按 SYS-TIME §6 的时刻表。
- **路灯**（ENG-PERF §10.3）：光斑用离线生成的 8 m 网格灯光表（全局纹理）。真实的 OmniLight3D 只给不超过 32 盏重点灯（图书馆门厅、开放室内：当前开放楼最多借 4–6 盏，WLD-INTERIORS §12），不投影、开 distance fade、specular 为 0。开放入口的门口灯走灯表，不加光源、不加绘制调用（WLD-INTERIORS §4）。开灯阈值按有效太阳高度 h_eff 和哈希分布，阴雨天灯提前亮（SYS-TIME §6、ENG-PERF §10.3）。
- **显存**：阴影图按预设 8–128 MB，不保留前一版副本；不用带阴影的点光，`positional_shadow/atlas_size` 设 0，省下默认的 32 MB。都要落在 §2 的"渲染目标与阴影图"之内。

## 7 硬规则（违反任何一条都不能合入）

1. **材质只用白名单着色器**：场景材质只能经 `ToonSpec` 和调色板色名获得（ENG-ARCH §3），由 `Campus.Style` 用白名单里的 `.gdshader` 创建 ShaderMaterial，共用 `toon.gdshaderinc`（ENG-PERF §1.4）。禁止 StandardMaterial3D、ORMMaterial3D；禁止运行时新建 Shader、改着色器代码、改 `render_mode` 或 `#define`；禁止逐物体创建材质（逐物体的变化放顶点属性、`INSTANCE_CUSTOM` 或 instance uniform）。新增着色器文件要主代理批准。
2. **不得新增**光源、SubViewport、CompositorEffect、全屏通道、WorldEnvironment 或 Environment。只有 WP-01、WP-03、WP-05 可以新增，而且要先向主代理申请；WP-24 的倒影视口、WP-03 管理的不超过 32 盏重点 OmniLight3D 已登记。
3. **几何**必须通过登记处按格交付，附上每级的几何误差。全部级别烘焙成 TileBundle：发布版本机烘焙（D-165），随包发的只有启动集 `boot_<地图>.pck`（L4、遮挡体等，ENG-PERF §8）；本机烘焙和开发态 `--gen=live` 都调同一个 `Build()`，在工作线程上跑。主线程不生成几何。只有内核能创建 `MeshInstance3D`、`MultiMeshInstance3D`、`OccluderInstance3D` 和 RenderingServer 实例（ENG-ARCH §2）；静态几何经 RenderingServer 挂载，场景节点只给动态物体。
4. **计时与逐帧路径**：
   - 计时只能由 WP-26 通过通道驱动（世界时间例外）。钟点、季节和天气只在 WorldState 那一步推进（WP-34；天气过程由 WP-45a 提供，SYS-TIME §1、SYS-WEATHER §8），世界时间单调递增；风、水、"一拍二"、雨丝只读动画时间 `anim_time`（delta 累加 mod 480），不读钟点。`Engine.TimeScale` 固定为 1；着色器禁用内置的 `TIME`。
   - 内容代码不得用 `System.Random`、`DateTime.Now`、`Stopwatch` 等计时器（G4）。唯一的例外是天气种子：新游戏时由 `ISaveService.NewGame` 取一次熵，写进日志和存档，之后跟着存档走（SYS-WEATHER §6.4、SYS-SAVE §5.5）。系统时钟只有 `Campus.Kernel.Save` 能读，只写进存档的 meta（SYS-SAVE）。
   - 逐帧路径零托管分配：不 `new` 引用类型，不用 LINQ、闭包、装箱和字符串拼接；`StringName` 预先缓存；不在 `_Process` 里 `GetNode`（ENG-PERF §6）。
   - 界面每秒刷新不超过 10 次，由 `HudModel` 采样世界状态、值变了才发信号；不在 `_Process` 里逐帧改控件的文字、尺寸或主题（UI-NAV §9）。界面动效只改 `Modulate`、不在容器里的 `Position` / `Rotation`、instance uniform 和扫过期间的 `ui_night`，不改尺寸、StyleBox、Theme 和文字（UI-VISUAL §11.7）；登记例外（SYS-ATLAS §10）：小地图和大地图可以逐帧写着色器参数和变换（`Position`、`Rotation`、`Scale`），"随镜头"模式下标记层可以逐帧重画；仍然不逐帧改文字、尺寸和主题。
5. **纹理**：PNG 源图经 Godot 导入，导入模式 VRAM Compressed（普通 BC1/BC3，高质量 BC7，法线 RGTC）；需要重复铺贴的用 Texture2DArray。数据纹理（调色板、遮罩、灯表、窗表、树种表）用不压缩的 RGBA8 或浮点格式 ImageTexture，运行时创建。区域包不得自带大于 512² 的贴图（ENG-ARCH §4）。
6. **容器**按 ENG-PERF §1.1 选：静态独有几何离线合并成块；每格同种部件超过约 64 个用 MultiMesh，更少的用共享网格和材质的独立实例（靠 Forward+ 的自动实例化合成一次绘制）；植被、草、粒子用 MultiMesh。MultiMesh 统一用 3D 变换加自定义数据，不用实例色。成批写 MultiMesh 一律用 `MultimeshSetBuffer` 整块写；只有每帧改几个实例的（飘落池每阵风的 3–5 个槽位、少量动物）可以逐实例写。GPUParticles3D 只作备选，用要主代理批准。
7. **顶点格式**：内容模块照常写 float 数据（`System.Numerics`），由内核或烘焙器打包成 `ARRAY_FLAG_COMPRESS_ATTRIBUTES` 的 20 B/顶点：位置 4×u16（按格包围盒归一化，第 4 分量是引擎存的切线角度）、八面体法线 2×u16、UV 2×u16、COLOR RGBA8（色号、AO、标志、1 字节备用）。窗号基址放 UV2 或 CUSTOM0（ENG-PERF §10.3）。**每个表面不超过 65 536 个顶点**；相邻格写统一的格包围盒，避免量化接缝。顶点格式只用 ENG-PERF §2 登记的几种；植被插片格式另登记，可以到 44 B/顶点（ENG-PERF §9）。
8. **discard**：不透明着色器里的 `discard` 和 `ALPHA_SCISSOR_THRESHOLD` 只用于两类：白名单里的镂空类（植被插片、替身、冬季浅滩挖洞、倒影代理丢弃水下片元）和 instance uniform 驱动的抖动淡化分支（ENG-PERF §2）。不得为别的效果写 discard。
9. **运行时不得改动任何会触发管线重编译的设置**；会清空管线的设置不做成画面选项（SYS-GRAPHICS §0 第 3 条）。
   - **固定不改**（启动时定，四个预设相同）：阴影开关、`LightAngularDistance` 的有无、`ShadowBlur` 的有无、软影滤波档位（改一次清空全部已编译管线，连 ubershader 的也清）、阴影深度 16 位、MSAA、TAA、FSR2、CompositorEffect 的 `Needs*` 标志、深度预通道、Environment 的各项 `*Enabled`（Glow 常开，柔光质量只改级数和双三次放大）。
   - **画面设置按生效类别**（SYS-GRAPHICS §3，实现见 ENG-PERF §11.7）：
     - **即时**（只改数值，不编译、不重建缓冲）：阴影图尺寸、PSSM 2 / 4 级、阴影距离、柔光质量、移轴、镜头光斑、光柱、暗角、细节距离（已挂载的格子分帧重写，每帧 ≤ 0.3 ms）、模型 LOD 精度、近景几何叶、植被与草密度、草地范围、倒影刷新、降水与粒子密度、垂直同步、帧率上限。有视觉变化的项在 0.5–1 s 内淡化完成，不硬切（G13）；
     - **雾幕**（重建渲染缓冲，不编译；点"应用"后在 0.3 s 雾幕里批量生效）：显示模式、窗口尺寸、渲染比例、FSR 锐度、抗锯齿、各向异性、细小物件投影；
     - **重启**：图形接口、显卡选择。
   - 启动预热覆盖四个预设和所有单项取值能到达的组合的并集（ENG-PERF §2），所以玩家怎么切都不再编译管线。
   - 时间、季节、天气、介质只经全局着色器参数和全局纹理传入（ENG-PERF §1.5）。天气用到的节点（降水池、檐滴）启动时就在树里，运行时只改 `VisibleInstanceCount`、instance uniform、`ShadowOpacity` 和 `ShadowCasterMask`（SYS-WEATHER §7）。
   - 门禁：每次雾幕淡出之后（含画面设置的雾幕；`--title=1` 时从标题页转为实时那一刻起），`Performance` 的 SURFACE、DRAW 和 Canvas 管线编译计数不再增长，新生成的 MSDF 字形为 0（G16）。界面着色器、MSDF 字形和大页控件在开场雾幕或扉页后预热或预建（UI-VISUAL §11.9）。
10. **版本锁定**：Godot 4.7.2-stable .NET（`tools/godot-version.txt`；csproj 写 `Sdk="Godot.NET.Sdk/4.7.2"`）。升级要经主代理评审；升级时必须重跑表面字节格式的比对门禁（ENG-PERF §12.5）。
11. **内容几何不得依赖时刻、季节和天气**：`Build()` 不得读取世界状态（钟点、季节、天气、观察模式；`BuildContext` 里没有 `IWorldState`，ENG-ARCH §3）。季节和天气的差异只能做成着色器参数（叶量、开花、覆雪、地面遮罩阈值、湿润与积水，ENG-PERF §9），天气要的烘焙数据（`precip_occ`、地面遮罩 2、檐滴点）与天气状态无关，所以改时间、换季、换天气不会让任何烘焙产物（含本机缓存）失效。
12. **碰撞数据**本机烘焙（D-165），与可见几何用同一套参数生成，不拿可见网格当 ConcavePolygonShape3D；每格一个碰撞 `.tbin`（碰撞级 C，只存形状参数，SYS-WALK §13），存在本机缓存里。生成在工作线程上；读缓存的工作线程任务只读 `.tbin`、由参数创建形状；碰撞 body 只在主线程创建、删除和入树，入树前用 shape owner 加完全部形状（Jolt 对已在空间里的 body 逐个加形状是 O(n²)）。开放室内的碰撞按楼、按层各一个包，按房间簇拆成 ≤ 250 个形状的 body，每帧入树 1 个、≤ 0.3 ms（WLD-INTERIORS §6.1）；自动门的门扇不进烘焙碰撞，关好时由运行时门体恢复一块薄盒（WLD-INTERIORS §4.1）；外围没有碰撞数据。
13. **全局着色器参数**必须先登记：ENG-PERF §1.5 的登记表是唯一来源，同步写进 `project.godot` 的 Shader Globals（主代理）。运行时不得 `GlobalShaderParameterAdd`，不得从脚本读回全局参数（`GlobalShaderParameterGet`）。每个参数只有一个写入方。
14. **阴影投影物**：投影物必须在相机能看见的图层上（引擎按"相机可见层 & 物体层 & 主光的 `ShadowCasterMask`"裁剪）。草、插片、落叶、粒子（含降水池）、光晕面片、光锥一律 `cast_shadow = Off`；远处和植被的投影用 `ShadowsOnly` 代理（ENG-PERF §10.1）。天气让阴影强度低于 0.01 时可以把 `ShadowCasterMask` 整个置 0，转晴时提前一帧恢复（ENG-PERF §10.1）。
15. **着色器里按距离的判断**（选级、插片塌缩、淡出）一律用 `MAIN_CAM_INV_VIEW_MATRIX[3].xyz`，不用 `CAMERA_POSITION_WORLD`：阴影通道会执行同一段 `vertex()`，那时后者是灯的位置。颜色一律不用 `LIGHT_COLOR`（G4）。
16. **线程边界**：工作线程只做纯 .NET 计算（`Build()` 与各烘焙子任务，发布版也跑，本机烘焙，D-165）、读写本机缓存的 `.tbin`（自己的解析器，不经 ResourceLoader）、`ResourceLoader` 对 `res://` 的后台加载和 RenderingServer 的资源创建；场景树、`RenderingServer.Instance*`、PhysicsServer3D 的 body 只在主线程调用（ENG-PERF §6）。gen 里禁用 `Parallel` 和 `Task.Run`，并行由内核调度；同时在途的生成任务不超过 max(2, 逻辑核数 − 2)（ENG-PERF §5）。
17. **风格底线不可关**（SYS-GRAPHICS §2）：描线、分阶明暗与按材质的影色、柔光（高光晕开）、高光肩部、平涂贴图、雾、天空、调色板与 LUT、窗灯、路灯光斑与亮窗室内、室内地面与墙上的窗光斑、季节内容（只降密度，不缺席）、一拍二、剖切与介质呈现，任何预设、手动值和自动调节级别都不能关。实时阴影不低于 2048²、2 级；西湖倒影不低于每轴 1/4、每 4 帧刷新。只有移轴、镜头光斑、光柱、暗角（风格默认）可以关，关掉之后的画面不进入验收。最差值写在 `KnobSpec.WorstAllowed` 里（SYS-GRAPHICS §8），`--quality-set` 劣于它时以非零退出码结束；门禁 G17 在每个预设的最差值配置下截图检查（SYS-GRAPHICS §10）。
18. **画面设置不改烘焙、碰撞和世界状态**（SYS-GRAPHICS §0 第 4 条）：画面设置只改运行时的选级和引擎参数，不按预设各烘一套。`Build()` 和 `game/gen` 不感知画面设置（`BuildContext` 里没有 `IQualityService`，`Campus.Gen.*` 不得引用 `Campus.Contracts.Quality`，G4）；碰撞、行走半径、钟点、季节、天气和种子都与画面设置无关。各包只经 `IQualityService` 和 `[QualityResponsive]` 接收设置（SYS-GRAPHICS §8），不读 `graphics.cfg`；每个单项恰有一个负责方（G5）。
19. **存档只走一条路**（SYS-SAVE §9）：存档只经 `ISaveService` 和 `[SaveSection]`；禁止用 Godot Resource、ConfigFile、`StrToVar`、`BytesToVar*`、`GetVar` 存读档；只有 `Campus.Kernel.Save` 写 `user://saves`。快照只在安全时刻拍，主线程 p99 ≤ 0.3 ms；序列化、压缩、缩略图编码、哈希和写盘都在线程池里，缩略图读回用 `GetImage()`，不走 GPU 回读（§8）。设置类文件（`settings.cfg`、`input.cfg`、`graphics.cfg`、`audio.cfg`）读值时只接受基本类型（SYS-SAVE §8）。
20. **室内只在开放清单里**（WLD-INTERIORS §10）：开放清单以外的楼不得有完整室内和楼内碰撞，旁观只看简化室内；可走性（门、卷帘、封口）不随钟点、季节、天气变；会动的门的运行时门体只由观者位置触发、不进烘焙碰撞（WLD-INTERIORS §4.1），以后剧情锁门也只走运行时门体这一条通道（ENG-ROADMAP §3 第 10 条）。楼内视角按 §2 的楼内额度核算。
21. **音频的硬上限**（SYS-AUDIO §2.5、SYS-AUDIO §18）：在播的 `AudioStreamPlayer3D` ≤ 32（硬上限 48），其中开 `AreaMask` 的 ≤ 12；真实声部 ≤ 72（硬上限 96）；音频不得在主线程同步加载素材；只有 `Campus.Audio.*` 能建播放器和改总线（G4）。
22. **本机烘焙要确定**（D-165，ENG-PERF §5）：同一 ABI 下，本机烘焙的产物与 CI 参考烘焙逐字节一致，按每个文件的内容哈希比（G6 的 `--bake-verify`）。gen 和烘焙子任务里禁用 `Math`、`MathF` 的超越函数（`Sin`、`Cos`、`Tan`、`Asin`、`Acos`、`Atan`、`Atan2`、`Exp`、`Log`、`Log10`、`Pow`、`Cbrt` 等，一律改用契约里的 `DetMath`）、`System.Numerics.Vector<T>`、`System.Runtime.Intrinsics`、`Math.FusedMultiplyAdd` 和 `TensorPrimitives`（G4 的 BannedApiAnalyzers）；`Math.Sqrt`、加减乘除和 `Math.Round` 可以用。生成代码用 `ArrayPool` 和预分配缓冲。
23. **`user://` 不用 Godot 资源格式**（SYS-SAVE §8，D-165）：`ResourceLoader`、`ResourceSaver` 一律不得读写 `user://`，不设例外（`.res`/`.tres` 能嵌脚本，读入即执行）。本机缓存和开发共享缓存用自定义的格包二进制格式 `.tbin`，整体 zstd，解析器逐段做边界检查，长度超限就拒收；读入后用 `XxHash128` 与随包的 `res://bake/<地图>/boot/bake.manifest.json` 比对哈希，不符就删掉重烘；写入走 tmp + `Flush` + 改名；`cache.index` 只用于 LRU 和统计，不作信任依据（ENG-PERF §5）。启动集在 `res://` 里，仍用 `.res`。

## 8 额度总账（`budgets.json`）

各包的占比在**精致预设**下核算（SYS-GRAPHICS §10 的验收基准：1920×1080 原生、`--quality=fine --adaptive=0`）；其他预设只核 §2 的总量，各包按同一比例缩放。自定义组合不保证预算。

**本机缓存预算**（D-165；不计入 G6，机制见 ENG-PERF §5）：

- **位置**：`user://cache/bake/<地图>/<ABI>/…`，即导出版的 `%APPDATA%` 下。
- **大小**：一张图烘满约 0.8–1.4 GB（P0 实测，§11），也就是几何类烘焙产物的全部体积；与画面设置、世界状态、存档无关，跨存档、跨画质共用。
- **上限与淘汰**：默认上限 2.5 GB，超出时按"最久未用"淘汰：先淘汰别的图，再淘汰本图的 L0 和室内包。L1–L4 和全图常驻数据不淘汰。
- **剩余空间不足 1 GB 时不落盘**：不写缓存，只在内存里生成、用完即弃，并给一次几秒内淡出的临时提示（INV-3 允许）。
- **时间目标**（开发机，初值，P0 实测）：首次运行到转为实时 ≤ 25 s，平面地图底图 8 线程 ≤ 20 s；开始页上后台预烘满全图 ≤ 4 min；以后的启动仍是冷启动 ≤ 9 s、热启动 ≤ 3.5 s（ENG-PERF §8）。
- **玩家可管**：设置卡的"存储"一行显示占用和本机烘焙进度，"清除缓存"按钮只清缓存（WP-35，ENG-PERF §5）。

## 9 怎么测

完整做法见 ENG-PERF §12，这里只列要点：

- **命令行参数**：截图和基准的默认值是 `-- --pose=V1 --clock=17.5 --season=autumn --anim=240 --flow=0 --mode=fly --ui=0 --seed=1 --weather=clear --weather-seed=1 --quality=fine --adaptive=0 --map=qingshuihe --title=0 --save=off --audio=off`，即默认状态（晴）、动画时钟冻结在 240 s、隐藏界面、精致预设、自动调节关、清水河、跳过开场、不写存档、无声。用 `OS.GetCmdlineUserArgs()` 读，未知参数以非零退出码结束（ENG-GATES §1）。门禁和基准只由命令行决定，不读 `user://`（SYS-GRAPHICS §6）。
- **本机烘焙的参数**（D-165）：`--bake-cache=<绝对路径>`（本机缓存目录，默认 `user://cache/bake/`，开发态默认指向 `UESTC_BAKE_CACHE`）、`--bake-bg=0|1`（后台预烘，默认 1）、`--bake-strict=1`（缓存不命中直接报错退出，默认 0）、`--bake-verify`（G6 的逐文件哈希比对）。`--bake=all` 和 `--gen=live` 保留。`scripts\gate.ps1` 先跑 `--bake=all` 补齐共享缓存，截图类门禁、基准和 G10 一律追加 `--bake-cache=<UESTC_BAKE_CACHE> --bake-bg=0 --bake-strict=1`，默认串不变；G10 另有冷缓存子项（ENG-PERF §12.4、§12.5）。
- **运行时计数**：`Performance` 监视器（`RenderTotalDrawCallsInFrame`、`RenderTotalPrimitivesInFrame`、`RenderVideoMemUsed`、`RenderTextureMemUsed`、`RenderBufferMemUsed`、`PipelineCompilations*`，含 Canvas）；`Viewport.GetRenderInfo` 分主通道和阴影；`Performance.AddCustomMonitor` 加流式加载、字节账、GC 暂停等自定义项。音频的 `audio/main_us`、`audio/real_voices`、`audio/nodes3d`、`audio/virtual`、`audio/resident_kb`、`audio/mix_core_pct`（SYS-AUDIO §18.1）；界面主线程和画布渲染 CPU 由 `Campus.Kernel.Inspect` 接 `SceneTree.ProcessFrame`、`RenderingServer.FramePreDraw`、`FramePostDraw` 记时间戳，不用 `Performance.Monitor.TimeProcess` 算平均（它是每秒内的最大值，UI-VISUAL §12）。
- **GPU 与 CPU 计时**：`RenderingServer.ViewportSetMeasureRenderTime` 打开后逐帧读 `ViewportGetMeasuredRenderTimeGpu` 和 `...Cpu`；分段 GPU 时间用 `RenderingDevice.CaptureTimestamp`；.NET 的 GC 暂停用 `GC.GetTotalPauseDuration()`。测量时锁 GPU 频率，GPU 降频会让测得的时间偏大。
- **命令行基准**：测导出的 release 版，窗口模式（无界面模式不渲染），例如 `UESTC.exe --rendering-driver d3d12 --gpu-index <n> --resolution 1920x1080 --disable-vsync --fixed-fps 60 -- --bench=1 --pose=V1 … --quality=fine --adaptive=0 --frames=600 --out=<路径>`；开发机另跑 `--resolution 2560x1440 … --quality=ultra`，对照 §2 的 8.0 ms。吞吐模式关垂直同步并固定步长；体验模式开垂直同步、按真实时间跑（ENG-PERF §12.4）。
- **画面测试**：设置页的"试跑"与 `--bench` 共用同一套代码，60 s 的 F1、按真实时间、断言窗口有焦点（SYS-GRAPHICS §5）。Movie Maker 是固定步长，只用来录像和截图，不能测帧率。
- **静态预测（G8）**：纯 .NET 测试跑与运行时共用的 C# 选级代码，读烘焙产物的统计 JSON，预测每个视角、每个包的各项数值，与总账对照：
  - 每个视角按 §2 的四种世界状态组合各算一次，取最大；
  - 四个预设各算一遍，检查单调性（极致 ≥ 精致 ≥ 均衡 ≥ 流畅），另算每个预设的最差值配置（SYS-GRAPHICS §10）；
  - 显存按四季共用一套替身计（§3）；
  - 另加行走贴地位姿（眼高 1.62 m，见 ENG-PERF §12.5）；
  - 按图对照 `budgets.json` 的 `maps.<id>`；单列"外围"子项，核对 WLD-OUTSKIRTS §11.2 的分层上限；开放室内的门厅（朝外）、主空间、走廊、楼梯各 1 个位姿按 §2 的楼内额度判；T0 与新游戏过场路径上每 0.25 s 一个采样点（SYS-TITLE §11.4）；
  - 用 G10 实测校准，偏差超过 15% 报警。
- **固定视角**：ENG-GATES §1 的 V1–V11、E1–E7、T0，以及以下路线：
  - **F1**：遵守速度律的 60 秒飞行，用来判是否达标。
  - **F2**：压力路线。用调试开关绕过速度律，在低空以 87 m/s 飞行。只检查不崩溃、没有超过 200 ms 的长卡顿、加载后能恢复到正常级别。
  - **F3**：跳转压力。全部点位（P00–P23）两两互跳，24 个点位时 552 次，判据见 UI-NAV §10。
  - **F4**：传送压力。在全部可传送标记之间随机传送 300 次，旁观、行走各半，判据见 SYS-ATLAS §14.3。
  - **W1–W14**：行走路线 R1–R14 的脚本（SYS-WALK §11、WLD-INTERIORS §13），按体验指标验收；W6–W14 是室内串联路线。
- **世界状态与设置的体验脚本**："前推 24 小时"（以各档流逝速度和拨时间环两种方式，SYS-TIME §8）、"四季轮换"、"天气巡回"（SYS-WEATHER §9）、"预设轮换"（SYS-GRAPHICS §10）、"过场体验"（SYS-TITLE §11.3），在体验模式下跑，只判掉帧率和卡顿（§2），并要求跑完时 DRAW 管线编译计数为 0（G16）；"过场体验"另要求没有超过 50 ms 的帧、"过场流式欠账"为 0、SURFACE、DRAW、Canvas 三项都为 0。脚本的具体步骤见 ENG-PERF §12.4。
- **存档与切图**：保存耗时按 G20 的"保存耗时"项测（F1 循环 10 分钟、每 10 s 强制保存一次，SYS-SAVE §14）；同图重载按 G16 的做法测（SYS-MAPS §13）。
- **声音**：声音门禁用 Movie Maker 录的 WAV（SYS-AUDIO §17、SYS-AUDIO §22），显式 `--audio=on`；其余截图与基准一律 `--audio=off`。音频预算 G21g 随 G10 同一套运行测。
- **增量测试**：用 `-- --without=WP-xx` 关掉一个包，比较开关前后的差值。
- **统计回归（G10）**：ABBA 顺序各跑 5 次，用 Mann-Whitney 检验加位移量判定。合入时跑精致（1080p）和极致（1440p），每晚加跑流畅，只判回归；帧时账只记精致（SYS-GRAPHICS §10）。
- **核显实测（G11）**：每周一次，可选。用"自动推荐 + 自动调节开"跑一遍，再固定推荐预设跑一遍，同时验首次推荐是否正确（SYS-GRAPHICS §10）。
- **预设底线（G17）**：每个预设的最差值配置在 V1、V4、E1、E3 和 V7 夜间截图，自动判描线、投影、倒影和暗部（SYS-GRAPHICS §10、ENG-PERF §12.5）。
- **录像**（G13 与跳变检测）：Movie Maker（`--write-movie <路径>\f.png --fixed-fps 60 --quit-after <帧数>`），加流式屏障（ENG-GATES §1）。

**Environment 与 Sky**（WorldEnvironment 归 WP-05，主光与天空的配置归 WP-03、WP-40）

- 背景用 Sky；环境光源（`AmbientLightSource`）和反射源（`ReflectedLightSource`）都设为 Disabled，卡通材质不用天空的环境光和反射。
- Tonemap 用 Linear；Glow 常开（柔光是风格底线），柔光质量只改级数和双三次放大（`RenderingServer.EnvironmentGlowSetUseBicubicUpscale`，即时、不编译）；Adjustment 开（亮度、对比度、饱和度都为 1，只为了让 LUT 生效），`AdjustmentColorCorrection` 指向运行时 LUT。
- 关掉：Environment 雾、体积雾、SSAO、SSIL、SSR、SDFGI。这些开关运行时一律不切。
- Sky 的 `RadianceSize` 取最小（Size32），`ProcessMode` 设 Incremental；关掉天空环境光以后辐照度图是否还在每帧计算，由 P0 用 RenderDoc 确认。卡通材质不读辐照度图，天空着色器在 `AT_CUBEMAP_PASS` 里直接输出常量，所以云和天气参数每帧变化也不让它变贵。
