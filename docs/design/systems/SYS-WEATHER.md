## 0 结论

1. **天气是第三个世界量**，与钟点、季节平级。对外是"天气格 + 自动 / 手动"；对内是一组连续参数（天气向量，§8）。所有天气表现都只读这组参数，所以切换天气不硬切、不重编译、不增删节点。
2. **天气效果是在色彩脚本上再叠一层"天气修正量"**：调色板关键帧 → 四季修正 → 天气修正 → 转场雾幕 → 介质（SYS-TIME §3）。
3. **自动天气是前向随机过程**（§6）：晴的间隔按钟点加权随机出现，每段天气按手写模板展开，各相时长随机，只走验证过的转移。同一种子加同一串输入得到同样的画面。
4. **验证单位是"状态 × 关键帧 × 季节"的静态格和"转移边 × 光段 × 季节"的动态格**（§9）。任何随机拼接出的画面，要么是验过的静态格，要么是验过的过渡录像里的同类帧，所以都好看。
5. **只新增一个白名单着色器** `precip.gdshader`（雨丝、溅落、檐滴共用），其余并入现有的 toon、雾、天空、水 include 和描线计算通道。
6. 天气种子每个存档一个，每张地图一份前向过程，进图时补算到当前世界时间（§6.4、§6.5）；读档后天气与没退出时逐帧一致（SYS-SAVE）。天气有声音，声音和画面读同一组参数（§2、SYS-AUDIO）。太阳雨不是新的天气格，而是"雨 → 雨后初晴"这条转移边的开头（§2）。

### 0.1 接入要点

- **要让表现随天气变化**：只读 `IWorldState.WeatherNow`（天气向量）和天气类全局参数（`weather_a`、`weather_b`、`weather_fog`、`cloud`、`lightning`、`snow_fx`、`overcast_dir`），不自己判断天气格、不另设天气计时；换天气不增删节点、不切特化开关（§0、§8）
- **要加天气效果的着色器代码**：并入现有的 toon、雾、天空、水 include 和描线计算通道，新增的白名单着色器只有 `precip.gdshader` 一个（§0、§7）
- **要显示或改天气**：读 `Weather`、`WeatherAhead`（界面经 HudModel 采样），改只经 `IWorldControl` 的 `SetWeather`、`SetWeatherIntensity`、`SetWeatherAuto`、`Apply`；本季有没有某种天气用 `IsNative` 判断（§1、§8）
- **要用雨丝、雪花、溅落**：都在 WP-45b 的降水池里，不另开粒子；数量乘画面设置的"降水与粒子密度"，读 `precip_occ` 让檐下、连廊下、屋里无雨（§7）
- **室外表面要有湿润、积水、积雪**：湿润变暗乘材质线表里的响应值，`ROUGHNESS` 不能动（它存的是材质 ID）；积水读地面遮罩 2；积雪 = max(季节基线, 天气累积)；雨停后干净，不做旧、不留水渍（§7）
- **CPU 侧要判断地面湿不湿、有没有积水**：经 `IGroundCover`（WP-38 实现，复用 WP-45b 的公共函数），与着色器同一套阈值，不另写判定（§7）
- **有灯要在湿地面和积水里拉出倒影**：一、二级灯进共用灯条表 `refl_lamps`，水面和湿地面共用，不另设灯条数组（§7）
- **做外围或开放室内**：外围 O0 读地面遮罩 2，有积水和灯条倒影；O1、O2 只做湿润变暗和掠射天光带；室内无雨，开放入口的地垫雨天变深（§2"外围在雨雾中"、§7）
- **要按天气出声**：只读 `WeatherNow` 和 CPU 侧数据（`precip_occ`、地面遮罩 2、檐滴点表），不读回全局参数；远雷只听 `ILightningFeed`（§8）
- **有与天气相关的随机抽取**：用天气种子的计数器子流 StableHash(种子, mapId, epoch, 片段号, 尝试号, 用途)，与帧率和补队列的时机无关，不另取熵（§6.4）
- **切图或读档涉及天气**：切图时 WP-46 在雾幕里调 `IWeatherProcess.Leave`、`Enter`；读档经 `weather`、`map:<id>/weather` 两段的 `Restore` 直接落定，不调 `Reset`，也不重新"保持晴"（§6.5、§8）
- **截图、录像或门禁要指定天气**：用命令行 `--weather`、`--weather-intensity`、`--weather-seed`、`--weather-queue`、`--sunshower`，不合季节的组合以非零退出码结束；"天气巡回"跑完管线编译计数为 0（§8、§9）

## 1 天气清单与界面格

界面上固定 8 格加"自动"（UI-NAV §4.10）；图标为气象站填图符号（UI-VISUAL §6.2），样式见 UI-VISUAL §7.6：

| 格 | 春 | 夏 | 秋 | 冬 | 强度档 |
| --- | --- | --- | --- | --- | --- |
| 晴 | ✓ | ✓ | ✓ | ✓ | — |
| 少云 | ✓ | ✓ | ✓ | ✓ | — |
| 多云 | ✓ | ✓ | ✓ | ✓ | — |
| 阴 | ✓ | ✓ | ✓ | ✓ | — |
| 雾 | ✓ | ✓ | ✓ | ✓ | 轻 / 中（默认）/ 重 |
| 降水 | 雨 | 雨 | 雨 | 雪 | 雨：轻（默认）/ 中 / 重；雪：轻 / 中（默认）/ 重 |
| 雷雨 | ✓ | ✓ | 禁用（可聚焦） | 禁用（可聚焦） | 中（默认）/ 重 |
| 初晴 | 雨后 | 雨后 | 雨后 | 雪后 | — |

- 内部状态：`Clear`、`FewClouds`、`Cloudy`、`Overcast`、`Fog`、`LightRain`、`Rain`、`Thunderstorm`、`AfterRain`、`Snow`、`AfterSnow`。
- 不做：雾霾、冰雹、雨夹雪、大暴雪、沙尘、落地闪电、镜头水滴、全屏模糊、灰黑色的天。
- **换季时手动天气不合法**：在换季雾幕里自动替换（雨 ↔ 雪，雨后初晴 ↔ 雪后初晴，雷雨 → 秋季大雨、冬季大雪），并给一条临时提示，例如"冬季 · 雨转为雪"（UI-NAV §4.9）。点禁用态的雷雨格只提示"春夏才有雷雨"，不替观者换季。
- 太阳雨（§2）没有自己的格，也不是内部状态：它是"雨 → 雨后初晴"这段过渡的开头，界面上算"雨后初晴"。

**英雄帧增补**（SYS-TIME §3.5）：秋 21:30 夜雨（银杏大道湿路面拉出一排路灯竖条倒影）、春 07:20 雨后初晴（P10 的推荐状态）、秋或冬 07:30 晨雾俯瞰（穹顶探出雾海）、夏 18:40 雨后彩虹（虹压在宣邦楼钟楼上，西天火烧云）。第 12 张：秋 17:30 太阳雨（西边落金、东边暗云，金色雨丝，东天淡入一道彩虹；做法见下文"太阳雨"）。每个天气格另有一张代表帧，周评不低于 3 分。

**太阳雨**

- **是什么**：天气过程里"雨 → 雨后初晴"这条转移边的开头 30–90 s。阴度先退、太阳已经出来，降水量再慢慢降到 0。**不新增天气格和界面格，天气向量也不加分量**（§1）。画面上的判定：降水量 > 0.05、阴度 < 0.5、主光强度 `key_strength` > 0.3，与 ART-SKYLIGHT §7 光效的触发写法一致。
- **过渡曲线**：这条边有两种走法。普通走法是雨先停、再放晴；太阳雨走法是阴度在过渡的前 30% 里退到 0.5 以下，降水量在 30–90 s 里按缓出曲线降到 0，之后接雨后初晴的其余部分。时长按世界时间编排，快进时照 §6.5 的规则压缩。
- **画面**：
  - 逆光的雨丝被染成暖金（§3 第 3 条的例外），光柱里的雨丝更亮；
  - 白天的光柱照画，这是"雨中的白天不画光柱"的唯一例外（下）；
  - 湿面闪点（ART-STYLE §5.5）、积水映晚霞；
  - 彩虹在后半段淡入（§5）；
  - 夜间没有：它要主光。
- **自动天气**：雨片段以"雨 → 雨后初晴"收尾，收尾时太阳高于 +8°（在晨昏带以外，§6.2 第 1 条）而且主光强度 > 0.3 时，按 0.5 的概率走太阳雨走法；多出现在春夏午后的雷雨与阵雨、秋季的昼雨之后，夜雨不出（§6.3）。
- **英雄帧与录像**：默认时刻秋 17:30 的太阳雨最好看：西边落金、东边暗云。它在秋季黄昏带里，自动天气生成不到，靠录制路径：17:29 起步、流逝 1×，`--weather-queue="rain:1,after-rain:60" --sunshower=on`，在过渡开始后约 40 s 截取（Movie Maker 固定步长，可复现）。`--weather-queue` 是录制指定转移边的路径，不受 §6.2 第 1 条约束，那一条只管自动生成。`--sunshower=auto|on|off` 只决定下一条"雨 → 雨后初晴"边的走法，默认 auto（按上面的概率抽）（§8）。

**阴雨天的影与光柱**（ART-STYLE §3）

- **影浅、按材质**：阴、雨、雪天的影明度比 r 取 max(r, 0.88 + 0.04 × 阴度)，软光下影很浅；天光色 `ambient.sky` 向 `weather.overcast` 的色相混合（满阴约 C 0.022、h 320）。中性面（白墙、灰石、雪）的影偏珍珠粉紫，有彩材质的影保住身份色，砖红的影还是砖红。
- **层次**：靠云洞光斑、白天的窗灯、物体分界线和顶光两阶撑起，不靠接触暗影（§4）。
- **光柱**：阴天只在亮缝下画云缝光柱；**雨中的白天不画光柱，太阳雨例外**；雾天光柱 ×1.5（ART-SKYLIGHT §7）。
- **描线**：颜色规则和线宽在雨雾里不变（ART-STYLE §4）；闪光帧见 §5。

**外围在雨雾中**（WLD-OUTSKIRTS §4.5）

- 外围走同一套卡通着色器、调色板和共用雾函数，天气自动跟随，几何不随天气变。
- 雾天起雾距离 ×0.4，外围街区约在 300 m 处淡进雾里；雨天随起雾距离一起变淡。雾海升到箱庭外缘截面的上缘。
- 雨：外围 O0（在 `map_rect` 以内）有湿面、积水和灯的竖条倒影；O1、O2 只做湿润变暗和掠射天光带，不做积水（§7）。
- 旁观飞到活动范围边缘时的边缘雾 `edge_fog` 是另一回事，与天气无关（WLD-OUTSKIRTS §8.3）。

**天气的声音**（SYS-AUDIO）

声音只读天气向量和天气在 CPU 侧的数据，不自己判断天气，所以画面上看到什么，耳朵里就是什么。

| 天气 | 声音 |
| --- | --- |
| 晴、少云、多云 | 照常的季节与时段声景 |
| 阴 | 同晴，鸟略少 |
| 雾 | 风 × 0.3，风声和叶声都很弱；远处更闷；鸟叫 × 0.8，晨雾散去时恢复；树冠滴雾水，很稀的滴答 |
| 雨 | 按落点表面分层：树叶、水面、硬地、草地、铁皮雨棚与车顶、玻璃顶、伞面、檐口水帘与雨水管，每种一条床；小、中、大三档素材按降水量交叉；锋面从西湖推来时，雨声也从西边过来；乌鸦叫归零 |
| 雷雨 | 大雨档再加阵风，配远雷（§5） |
| 雨后初晴 | 檐滴、冠下滴水、雨水箅的流水按湿润衰减，与画面上积水干掉同长；鸟叫回弹，春夏蛙声变多 |
| 太阳雨 | 雨床随降水量收小，滴水层先起来；无雷 |
| 雪 | 远处各层变小变闷，近处细声反而更清楚；几乎没有鸟和虫 |
| 雪后初晴 | 融雪的檐滴，枝头雪团落地的"噗"（与飘落池同步） |

- **起止**：手动换天气时，声音和画面一样先起风、再起雨，最后雨水管和雨水箅开始响；停雨时雨声先停，滴水和排水慢慢收。雨停后仍有雨落声属于"天气残留"（§9）。
- 彩虹和闪光本身无声；脚下的湿、积水、雪由观者声按 `IGroundCover` 取（SYS-WALK §1）。

## 3 雨的可读性规则

雨容易伤害三渲二画面的可读性。下面七条保证可读：

1. **雨丝只在逆光、灯锥和暗背景前显形**：透明度 α = (0.15 + 0.24 × 逆光 + 0.3 × 灯锥 + 0.1 × 暗背景) × 亮度个性，上限 0.6；亮度个性每根随机取 0.6–1.7（多数淡、少数亮）；预乘输出的 α 乘 0.7，略带加法，亮背景前也读得出；灯锥读路灯灯光表（`lamp.gdshaderinc`）。影视实践也是前光下雨会消失，必须逆光才拍得出来。
2. **分三层**：近景 0–25 m 用循环盒里的雨丝，一拍二，所有雨丝同一倾角 8°–15°（随风），丝长为一拍步长的 1.1–1.8 倍；线宽按 1.2 cm 的世界宽度换算，夹在 1–1.8 px（内部分辨率），远处不足 1 px 的按覆盖率降透明度；中景 25–400 m 只用"雨幕带"（描线计算通道里的竖条纹调制，随前锋移动）；远景只靠雾和天色。
3. **限量与限色**：雨丝像素覆盖率不超过 4%（雷雨不超过 6%）；颜色比背景亮 0.14（明度），逆光时朝 `sun.light` 的暖白插，最多插 0.7；不用纯白。
   - **太阳雨例外**（§2）：受光的雨丝颜色在"背景 +0.14"和 `sun.light`（OKLCH L +0.06）之间按受光量插值；受光量 = 云影可见度 × 前向散射 fwd³（`precip` 着色器读不到阴影图，不算楼影遮挡）；透明度在第 1 条的公式上再加 0.24 × 受光量，光柱里再加 0.45，上限 0.6；像素覆盖率上限 4% 不变。
4. **两阶不丢**：主光不关；白天的阴影强度不低于 0.2；描线的颜色规则和线宽不变。影色按 ART-STYLE §3 的阴雨规则：影浅（r ≥ 0.88），中性面偏珍珠粉紫，有彩材质保住身份色（§2"阴雨天的影与光柱"）。
5. **雨的存在感主要交给地面和水**：涟漪；20 m 以内的小白王冠溅点（一拍二）；湿面掠射带；积水；亭子、连廊、门廊、候车亭边缘的虚线雨帘。
6. **地标保底**：雨天、雾天照样验收"主体与背景明度差不小于 8"（SYS-TIME §8）；八角穹顶和宣邦楼钟面在点位上的剪影距离不小于 800 m。
7. **不做**：镜头水滴、全屏模糊、体积雨雾、灰黑色的天。

## 4 与四季、昼夜的配合

- **夜雨不死黑**：天比楼亮；湿地面让每盏灯在地上再亮一次。
- **正午阴天、正午雨不发平**：顶光两阶、云洞光斑、物体分界线、白天的窗灯；正午是顺光，雨丝本来近乎看不见，雨感交给涟漪和湿面。
- **雾 + 正午**：雾顶压低，高楼露出雾面受光，避免整屏发白。
- **降水随季节变形**：不会出现雪压在荷花或绿叶上，也不会出现冬天下雨。
- **雪山可见度**：雨后 0.95；阴、雾、雨时可以低于常规下限 0.35，最低 0.15，保留一道最淡的剪影（WLD-DIORAMA §6）。

## 5 闪电与彩虹

- **闪电**：只做远处积雨云的云内闪。天空着色器画被照亮的云团；toon 在 fragment 里加 `EMISSION += 闪光 × (受光 − 影) × (0.5 + 0.5·n.y)`，全场一瞬间翻到受光色，没有投影；描线在闪光帧加深 30%（`line_darken` × 0.7，ART-STYLE §4），柔光加 0.1。主光不参与。节奏：两次闪光之间隔 8–20 s（随机），每次闪光含两个脉冲；每秒不超过 3 次闪光（WCAG 2.3.1）；全画面平均 ΔE 不超过 2；不画落地闪电，不全屏闪白；开"减少动态效果"时关闭；只在主光角速度 ω < 0.05°/s 时出现。
- **远雷**（SYS-AUDIO）：每次闪光由 WP-40 经 `ILightningFeed` 发一个事件（真实秒、方位、仰角、距离、脉冲数，§8）；音频按距离 ÷ 343 m/s 延迟 4–15 s 放一声低沉、遥远的滚雷，不做近雷的炸裂，峰值比环境床高不超过 8 LU；设置里"突发声音"可以调轻或关掉。开"减少动态效果"时闪电不画，但 WP-40 照同一节拍发 `Visible = false` 的事件，雷保留、更远、更少；声音不是闪光，不违反 WCAG 2.3.1。60× 及以上本来就没有闪电，也就没有雷。远雷归音频包（§10）。
- **彩虹**：只在雨后初晴、太阳高度 2°–40° 时出现（34°–40° 之间淡出，见下），位于背对太阳的方向；彩度不超过 0.10、透明度不超过 0.35；同一项加进雾函数的雾色，远山前面也能看到虹。无声。
  - 视觉优先，不用真实的固定 42°（ART-SKYLIGHT §4.12）：主虹半径 R = clamp(max(30°, h_sun + 10°), 30°, 42°)，即 30–42°，随太阳升高放大；太阳在 32° 以下时，虹顶不低于地平线以上 10°。17:30（太阳 5.5°）时 R = 30°，虹顶约在 24.5°，60° 视场的平视镜头里能整道进画面；按真实的 42°，虹顶在 36.5°，出画。超过 32° 后 R 封顶，虹顶随太阳升高下沉（34° 时约 8°），所以**太阳在 34°–40° 之间时彩虹的透明度按 smoothstep 淡出**，到 40° 正好为 0，免得留一道贴地的残虹（ART-SKYLIGHT §4.12）。五条硬边色带总宽 1.4°；副虹在 1.22 R，强度 0.28，色序相反；虹内的天空 +0.05，两虹之间的暗带 −0.012。
  - 太阳雨的后半段，彩虹随降水量降下淡入（§2）。
- **与 CORE-INDEX INV-10 的关系**：闪电是雷雨的持续氛围，彩虹是初晴的天象状态，都不算偶发事件；全片仍只有一个偶发事件。偶发事件本体不变，只加天气版本（SYS-MOTION §10）：雨夜里路灯依次变亮时，积水里的倒影同步变亮（它们读同一张灯光表）；雨天白天，树冠依次抖落一阵积雨；雾天，光晕依次变大。

## 6 自动天气：前向随机过程（WP-45a）

### 6.1 模型

两层前向过程（马尔可夫更新过程的一种）：

- **上层：晴的间隔**。用按钟点加权的非齐次泊松稀疏法（Lewis–Shedler）抽下一段天气的起点。不应期：两段天气之间至少 2.5 h 晴；两段降水之间至少 8 h；任意 24 h 内降水不超过 12 h。
- **下层：片段**。一段天气是一条手写的模板路径（例如 多云 → 阴 → 小雨 → 雨后初晴 → 晴），各相时长从截断对数正态或均匀分布里随机抽；降水强度在验证过的强弱两端之间随机。起点、模板、分支、相长、强度都随机，但只走验证过的转移边、只在允许的光段里转移。
- **前瞻队列**：始终保持未来 24 h 已生成的天气队列，供快进和预报行使用（UI-VISUAL §7.6）。过去 24 h 的队列也留着，不应期规则要用；两段都存进存档（§6.4）。

### 6.2 硬规则（生成时满足，G2 的 lint 复查）

1. **晨昏带内不发生自动转移**：黎明是太阳 −7° 到 +3°；黄昏是太阳 +8° 到 −7°。这同时保护落金初灯的那段黄昏和日月交接（SYS-TIME §2）。秋季约为 06:05–07:56 和 17:16–19:36。
2. **最短时长**（防止"闪一下就停"）：雨 ≥ 45 min，雷雨 ≥ 30 min，雪 ≥ 2 h，雾、阴 ≥ 1.5 h。
3. 雾只在夜里生成，只在太阳高于 +3° 以后散；雷雨只在春夏；雪只在冬季。
4. 出现率低于每千天 1 次的"边 × 光段"直接禁用。
5. 彩虹、闪电的条件见 §5。

### 6.3 参数初值

模拟 100 个种子 × 365 天 × 4 季：

| 季 | 主要片段：每天出现次数 · 常见起点 · 主相时长中位 [范围] |
| --- | --- |
| 春 | 夜雨 0.32 · 22–02 时 · 3.6 h [1.5, 6.5]；午后阵雨 0.08 · 12–15 时 · 1.0 h；春雷 0.02（稀有）；阴天细雨 0.04；晨雾 0.19；多云 0.23；阴 0.08 |
| 夏 | 午后雷雨 0.21 · 13–16 时 · 0.9 h [0.5, 2]；阵雨 0.12；夜雷雨 0.05 · 21–00 时；晨雾 0.25；闷热多云 0.32 |
| 秋 | 巴山夜雨 0.32 · 22–01 时 · 2.8 h [1, 6.5]；昼雨 0.02（稀有）；晨雾 0.23 · 6.1 h；夜雾 0.07；秋阴 0.11；多云 0.15 |
| 冬 | 夜雪 0.35 · 19–23 时 · 5.3 h [2.5, 11]；整日小雪 0.03（稀有）；冬雾 0.24；雪意阴 0.16；多云 0.12 |

- 结果：晴约占 73–84%；平均每天 0.9–1.0 段；24–29% 的日子全天晴；60× 流逝下约每 25 min 真实时间来一段。
- 多样性：日型 44–142 种；相邻两个有天气的日子完全相同的概率是 5–7%。
- 约束全部满足（禁区违规 0，最短间隔 2.5 h，24 h 内降水不超过 12 h）。
- 参数写在 `game/data/weather/chengdu/`（片段模板、钟点权重、时长分布、转移边），P0 后按截图调（§12）。按天气剧本分目录，清水河在 `map.json` 里写 `weatherProfile = "chengdu"`（SYS-MAPS §3），以后别的图可以换剧本。
- **太阳雨**（§2）：转移边表里给"雨 → 雨后初晴"加一个走法参数：收尾时太阳高于 +8°、主光强度 > 0.3 时，按 0.5 的概率走太阳雨走法，否则走普通走法；抽取用同一套计数器子流（用途 = 太阳雨）。它只改这条边的过渡曲线，不改相长和出现率，上面的统计结果不变。

### 6.4 随机数与复现

- 每次抽取用计数器子流：StableHash(种子, mapId, epoch, 片段号, 尝试号, 用途)，与补队列的时机、帧率无关。换季、钉住时 epoch + 1。子流含 `mapId`（SYS-MAPS §5）：每张图一份前向过程，同一个种子在不同的图上抽出不同的天气，互不干扰。
- **种子**：**每个存档一个**。
  - 新游戏时由 `ISaveService.NewGame` 取一次熵（G4 登记的唯一熵源例外），写进日志和存档的 `weather` 段；之后跟着存档走，读档时不重新取（SYS-SAVE §5.4）。
  - `--weather-seed=<u32>` 只作用于新游戏，给出时不取熵；与 `--slot`、`--load` 同时给出时以非零退出码结束（§8）。门禁和截图默认 `--save=off`，每次都按 `--weather-seed` 新开。
- **复现**：同一构建 + 同一种子 + 同一串输入（命令行、Movie Maker 固定步长、脚本化的时间推进）得到同样的画面。不要求"倒回去复现"，因为时间不能逆转；读档是换一个世界实例（`IWorldState.Instance` 加 1），不算倒流（SYS-SAVE §5.2）。此外：
  - **读档后续跑**：在安全时刻拍的存档，读回后给相同的输入和相同的 dt 序列，天气的选择、天气向量、前瞻队列与没退出时逐帧、逐位一致（SYS-SAVE §5.3）；
  - **已生成的队列也存**：过去 24 h 和前瞻 24 h 存进存档的 `map:<id>/weather` 段，所以补丁改了 `game/data/weather` 的参数，观者已经看到的天气和预报也不变，队列以后的部分才按新参数生成（SYS-SAVE §5.4）；
  - **进图补算与节奏无关**：补一次与分几次补，得到同样的队列（G2，SYS-MAPS §13）。

### 6.5 时间与天气

世界时间 `WorldHours` 只增不减（SYS-TIME §1）：

- **自由流逝**：天气队列按世界时间推进。60× 及以下按世界时间编排过渡；360× 及以上，每次过渡的真实时间不少于 1.5 s。
- **点刻度、预设、拨表盘**：跳到下一次出现的那个钟点，最多 24 h，用时不超过 3 s；快进中天气按前向过程完整推进（最多几段，微秒级），画面只做一次"起点天气 → 终点天气"的过渡，放在快进的 30–80% 段。
- **换季**：世界时间不变；当前相就地映射（雨 ↔ 雪、雷雨 → 雨或雪、初晴 ↔ 雪后初晴），在换季雾幕里完成；之后的队列丢弃，按新季节的参数从当前片段结束处前向重排。
- **暂停**：天气冻结，但雨丝照下（它和风一样按 `anim_time` 走）。开始页（T0）停着时同此（SYS-TITLE）。
- **进图**（SYS-MAPS §5）：每张图一份前向过程。离开时冻结在离开那一刻（`IWeatherProcess.Leave`）；进图时从离开时的世界时间前向补算到现在（`Enter`），规则同快进，微秒级；离开超过 72 h 时 epoch + 1、从现在起重排，不去生成很长的历史；离开期间换过季，先按换季映射 `Reseason`，再补算。都在切图的雾幕里完成，画面直接落定，不做过渡。
  - 第一次进某张图：自动天气、晴、epoch 0，从现在起生成。
  - 手动选的天气属于当前图的过程；去别的图再回来，手动选择还在。
  - 读档时天气由存档的天气段直接恢复，恢复的就是存档那一刻，进图时不用补算（§8）。

### 6.6 固定点

- **新游戏**：新时间线从秋 17:05、晴、自动天气起，保持晴到秋季黄昏带结束（约 19:36）；进场过场推到 17:30 停住（完整版以 60× 推进，简短版、关和跳过的倍率按 SYS-TIME §1），交还控制时转 1×（SYS-TITLE §6）。完整、简短、关、跳过都按同一条世界轨走，所以任何种子下新游戏交还控制时的画面都相同。第一段天气最早在交还控制（17:30）后约 2.3 h 出现，中位 9.8 h。
  - **"保持晴"是清水河默认状态的一部分**：`map.json` 的 `world.quietUntilDusk = true`（SYS-MAPS §3），意思是默认状态的天气是"自动 + 保持晴到本季黄昏带结束"。新游戏的起始图套用本图默认状态；以后别的图写 false 就不保持晴。
  - **读档不重新"保持晴"**：保持晴的窗口本身存在存档里，到点自然结束（SYS-SAVE §5.4）。读档时也不调用 `IWeatherProcess.Reset`。
- **回到落金初灯**：换到秋季（正向换季转场）+ 快进到下一个 17:30（已在 17:22–17:40 之间就不动）+ 流逝恢复 1× + 自动天气 + 保持晴到黄昏带结束；种子不变。这是清水河上的语义；对其他地图泛化为"回到本图默认状态"（`IWorldControl.ResetDefault()` 读当前图的 `world.default`，`quietUntilDusk` 为真时才保持晴，SYS-MAPS §5）。它是同一实例里的正向转场，不换实例（SYS-TITLE §6）。
- **应用点位推荐**：前向跳到推荐钟点，再把推荐天气钉住一段（从推荐钟点前 0.5 h 到后 2 h），之后自然演化，模式仍是自动。推荐里没写天气的点位按晴钉住。英雄帧都靠钉住保证。

## 7 光照、云与降水的实现（WP-45 及各系统包）

- **天光方向**（阴、雨、雪）：toon 的 light() 里，N·L 改用 `normalize(mix(LIGHT, 天光方向, 阴度))`，天光方向取主光方位、仰角 55°；过渡带宽从 0.02 放到 0.06。顶面和朝主光一侧受光，其余在影里，仍是两阶。
- **投影**：阴影强度乘 (1 − 0.8 × 阴度)，所以白天最低是 0.2，满足 §3 第 4 条"两阶不丢"。乘上主光自身的强度后低于 0.01 时（日月交接、夜雨没有月影），设 `ShadowOpacity = 0` 并把 `ShadowCasterMask` 置 0，阴影通道空跑；恢复时提前一帧恢复 mask，再淡入投影。这两项不是特化开关（P0 核实，§12）。
- **灯提前亮**：通道按有效太阳高度 h_eff = h − 6° × 阴度 − 4° × 降水求值（SYS-TIME §6）。
- **调色板修正**：阴天主光 −1.0 EV、大雨 −1.3 EV；影明度比 r 取 max(r, 0.88 + 0.04 × 阴度)，天光色 `ambient.sky` 向 `weather.overcast` 的色相按阴度混合（ART-STYLE §3）；雨后初晴饱和 +0.08（WP-37）。
- **云**（WP-40）：天空着色器的半分辨率通道里求视线与 1.5 km 高平面的交点，采噪声按云量取阈值；积云硬边三阶上色，层云满覆盖留亮缝，积雨云沿用夏季卡片。地面云影采同一张噪声，乘进退光线乘子；太阳低于 10° 淡出。云的漂移 = f(世界时间) + g(`anim_time`)。
- **降水池**（WP-45b）：1 个 MultiMeshInstance3D，8192 实例，透明、不受光、写 FOG，启动时就入树；运行时只改 `VisibleInstanceCount` 和 instance uniform。相机循环盒的半边长：雨 18 m、雪 14 m。雪花只在这个池里，季节飘落池只装枝头落下的雪团（SYS-MOTION §11.3、SYS-MOTION §13.6）；降水池着色器另读 `incident`、`incident_route`，偶发事件的雨天版本靠它（SYS-MOTION §10.8）。数量：小雨 1500，大雨 6000–8192，大雪 4000；乘画面设置的"降水与粒子密度"（SYS-GRAPHICS §3）。雨丝下落 7 m/s，一拍二每步 0.58 m，丝长取一步长；倾角小雨 5°、大雨 15°、雷雨 25° 并加阵风。
  - **太阳雨着色**（§2、§3 第 3 条）：降水池着色器按受光量把雨丝的颜色从"背景 +0.14"插到 `sun.light`，受光量 = 云影可见度 × fwd³；光柱里另加亮。读的都是已有的全局参数（主光方向与强度、云影、`weather_a`），不加参数、不加特化开关。
- **光柱**（§2）：雨中的白天不画光柱；太阳雨时照画；阴天只在亮缝下画云缝光柱；雾天 ×1.5（ART-SKYLIGHT §7）。
- **遮挡**：烘焙后随启动集发布（D-165）的俯视遮蔽高度图 `precip_occ`（2 m/px），雨丝低于顶面就缩到 0，所以檐下、连廊下、屋里无雨。它覆盖 `map_rect`（全图数据纹理的范围，清水河 ±1280 m，SYS-MAPS §10），外围 O0 也在里面；商业街的拱形采光顶、立人楼外廊、平台下街廊这类半室外空间按室外介质，降水由它挡在顶下（WLD-INTERIORS §2.0）。溅落 512 个槽位，落在相机周围 30 m 的网格上；水面不画溅落，改画雨点环。檐滴：L0 格的 TileBundle 带本机烘焙（D-165）出的滴水点，大雨时连成水帘，雨停后再滴 60–120 s。
- **湿润与积水**（WP-04、WP-15、WP-24）：
  - 新增一张地面遮罩 2（RGBA8，不压缩）：R 积水潜势，G 建筑遮蔽（檐下、雨篷、连廊为 0），B 树冠遮蔽（运行时乘叶量），A 保留；
  - 湿润变暗：wet = 湿润 × 暴露 × 材质响应（响应值写在材质线表里，沥青 1、玻璃 0）；受光色和影色 × (1 − 0.28·wet)；ROUGHNESS 不能动，它存的是材质 ID；
  - 高光条复用水面的主光反光带函数；夜间读共用的灯条表 `refl_lamps`（16×2，4 Hz 更新），水面和湿地面共用，各湖不另设灯条数组；每列的排布（灯的 x、y、z 与通道号，第二个纹素存颜色行号）以 WLD-WATER §7.3 为准，一、二级灯进表，三级景观灯不拉竖条（MAP-QSH-ADDITIONS §8.5）；
  - 积水倒影：反射视线沿 `precip_occ` 步进 8–12 次，碰到顶面画建筑或树的剪影色，否则画解析天空，夜间叠灯条；不用 SSR，也不加平面反射。
  - **外围**（WLD-OUTSKIRTS §4.5）：O0 在 `map_rect` 以内，读地面遮罩 2，有湿面、积水和灯的竖条倒影；O1、O2 不论是否落在 `map_rect` 内（东西两侧的 O1 有一部分在范围内），都按外围的顶点标志不读地面遮罩 2，只做湿润变暗和掠射天光带，不做积水。
  - **开放室内**（WLD-INTERIORS）：室内无雨；开放入口门口的地垫雨天变深：地垫多在檐下，它的湿润不乘建筑遮蔽，只乘湿润量，算一条雨天的生活痕迹；进门以后地面是干的。
  - **CPU 侧的同一判定**（SYS-AUDIO）：WP-45b 把湿润与积水的公共函数开放给 `IGroundCover`（WP-38 实现），C# 一份、着色器一份，同一套阈值；观者的溅水声和脚下的积水涟漪用同一个判定，不会出现"有涟漪没水声"（SYS-WALK §1）。G2 比对两边在抽样点上的结果。
  - **湿痕只随天气**：建筑立面和地面都不做旧（D-174、ART-RENOVATION），上面只有天气湿痕和季节落物（落叶、花瓣、积雪）；湿润变暗和积水在雨停后按湿润衰减干净，不留水渍、雨痕或流挂。
- **雾**：共用雾函数的签名不变，天气只修正它的输入；天气雾只作用于室外，介质呈现的混合度会把它换成室内、地下、水下的值（SYS-VIEW §5）。
- **风**：风量乘 (1 + 1.2 × 风暴度)，另加湍流；雨丝倾斜、雪的横漂、云速都读同一个风场（SYS-MOTION §3）。风暴时银杏摆角放到 4°。

## 8 状态、参数与接口

> 天气过程的接口（`IWeatherProcess`、`WeatherBoot`、`WeatherTick`、`WeatherQueueItem`）和本节类型的最终写法以 ENG-ARCH §3 为准。

- **天气向量**（每帧插值）：云量、云型、积雨云量、阴度、降水量、降水类型（雨 → 雪）、湿润、积水、雾密度倍率、贴地雾、风暴度、新雪（0–1 的累积量，积雪 = max(季节基线, 天气累积)，WLD-VEGETATION §9.5）、彩虹、闪光。
- **全局着色器参数**（登记进 ENG-PERF §1.5）：`weather_a`（云量、阴度、降水量、降水类型）、`weather_b`（湿润、积水、风暴、彩虹）、`weather_fog`（雾密度倍率、贴地雾顶高、贴地雾密度、远雨幕）、`cloud`（漂移、云型、积雨云量）、`lightning`（闪光、方位、仰角、种子）、`snow_fx`（新雪亮度、冠雪、融雪湿）、`overcast_dir`（天光方向）。
- **全局纹理**：`cloud_noise`（512² RGBA8，可平铺）、`precip_occ`（`Image.Format.Rh`，2 m/px，约 3.3 MB）、`refl_lamps`（16×2 RGBAF）、地面遮罩 2。

- **存档里的天气**（SYS-SAVE §2、SYS-SAVE §5.4）：

  | 段 | 范围 | 存 | 不存（读档时重建） |
  | --- | --- | --- | --- |
  | `weather` | 全局，顺序 20 | 本存档的天气基础种子（u32） | — |
  | `map:<id>/weather` | 按图，顺序 21 | epoch、下一片段号与尝试号；过去 24 h 和前瞻 24 h 已生成的队列；自动 / 手动、手动格与强度；钉住窗口、"保持晴"窗口；湿润、积水、新雪、檐滴余量 | `WeatherNow`（由队列和时间求出）、闪电节拍；手动换天气或换季替换的过渡进行中时存终点 |

  - **快照**：主线程在 `FramePriority.Save`（1000）那一步调用两段的 `Capture`（`map:<id>/weather` 段经 `IWeatherProcess.Capture(map)` 取本图的状态），返回不可变的 DTO，不做 I/O（SYS-SAVE §4.2）。`map:<id>/weather` 段在没有手动换天气或换季替换的过渡时才算落定（`IsSettled`）；自动天气的自然演化不算过渡，读档后自然接得上。
  - **恢复**：读档先恢复世界段和天气段，再切图（SYS-SAVE §5.1、SYS-MAPS）。各段的 `Restore` 经 `IWeatherProcess.Restore(map, s)` 立即生效、不做过渡；不调用 `IWeatherProcess.Reset`，也不重新"保持晴"。手动天气不合本季时按换季替换表替换并记一次修复（§1、SYS-SAVE §5.6）。
  - **切图**不改天气段的格式：每张到过的图各存一份 `map:<id>/weather`。
- **音频读什么**（SYS-AUDIO）：音频只读 `WeatherNow` 和天气在 CPU 侧的数据（`precip_occ`、地面遮罩 2、檐滴点表），不读回全局参数（ENG-ARCH §2 的规则）；远雷只听 `ILightningFeed`。

- **每帧顺序**：WorldState（−1000）推进钟点、季节之后求天气向量；主光（−900）按阴度改投影；调色板（−800）叠加天气修正；通道（−700）用 h_eff；动态（−650）写风、降水数量和闪电。
- **命令行**（ENG-GATES §1）：
  - `--weather=auto|clear|few-clouds|cloudy|overcast|fog|light-rain|rain|thunderstorm|after-rain|snow|after-snow`，截图默认 `clear`；
  - `--weather-intensity=<0–1>`、`--wet=<0–1>`；
  - `--weather-seed=<u32>`：只作用于新游戏（§6.4）；与 `--slot`、`--load` 同时给出时以非零退出码结束（SYS-SAVE §12）；
  - `--sunshower=auto|on|off`：只决定下一条"雨 → 雨后初晴"边走不走太阳雨（§2），默认 auto，截图默认串不加；
  - `--weather-remaining=<分钟>`：当前状态还剩多久，之后交给生成器；
  - `--weather-queue="cloudy:30,rain:90,after-rain:45"`：直接指定一串状态，用来录指定的转移边；不合法就以非零退出码结束；
  - 不合季节的组合与未知值一样，以非零退出码结束，日志给出替换建议。

## 9 验收

- **静态格**：状态 × 关键帧 × 季节，降水和雷雨另验强弱两端；自动可达约 218 格，手动另加其余格。并入 SYS-TIME §8 的矩阵，在集中测试时跑：L16 正交表的一列放"天气组"，总数不变；另加一组天气轮换和"季 × 天气"联表（ENG-GATES §1）。视角轮换加入外围视角 V11、E7（WLD-OUTSKIRTS §13.1），查雾天外围约在 300 m 处淡出、O0 雨天有积水和灯条倒影。
- **动态格**：转移边 × 光段（夜、晨低日、白天、昏低日）× 季节，约 136 格；用约 48 段 `--weather-queue` 录像全部覆盖，集中测试时全量跑；判据同 SYS-MOTION §12（相邻帧 ΔE），闪电帧打标记另判。"雨 → 雨后初晴"在白天和昏低日两个光段里，太阳雨走法和普通走法各录一段（`--sunshower=on|off`），太阳雨段另查：雨丝受光着色只出现在降水量 > 0.05、阴度 < 0.5、主光强度 > 0.3 的帧，像素覆盖率 ≤ 4%，光柱和彩虹按 §2 出现。
- **另录**：跳转与拨表盘的一次过渡、快进经过降水、换季替换、手动 ↔ 自动、过渡途中打断、"减少动态效果"下的同样几条。
- **地标豁免**：浓雾下主要地标（八角穹顶、宣邦楼钟楼）仍可辨认，按实例偏置做雾豁免（同宣邦楼穹顶的退光线偏置）。
- **G2**：过程的确定性快照、lint、统计范围、补队列节奏无关、换季模糊测试、新游戏 2000 个种子在交还控制时都是晴；同一种子在不同 `mapId` 上抽出不同的队列；进图补算一次与分几次补，队列相同（SYS-MAPS §13）；太阳雨走法的抽取只与子流有关，与帧率无关；`IGroundCover` 的 CPU 判定与着色器在抽样点上一致（SYS-AUDIO）。
- **G20**（SYS-SAVE §14）：读档后天气续跑等价（选择、天气向量、前瞻队列逐帧、逐位一致）；补丁改了天气参数后读旧档，已生成的队列不变；读档不重新"保持晴"。
- **G21 声音**（SYS-AUDIO）："天气巡回"的录像同时录声音，查声音的天气残留（雨停后仍有雨落声）；手动换天气的录像查声音的起止顺序（风先起、雨随后、排水最后）；远雷与闪光事件一一对应、延迟在 4–15 s 内。
- **G16**："天气巡回"脚本跑完，管线编译计数为 0。
- **一票否决**（ENG-GATES §3）的天气项：天气残留（雨停后仍有雨丝、替换后仍是上一种相态、雨停后仍有雨落声）；闪电硬切或全屏闪白；出现未验证的转移边。
- **性能**：天气在 ENG-BUDGET §8 单列一行：GPU 不超过 5%，绘制调用不超过 16，CPU 不超过 0.1 ms，显存约 5 MB 加地面遮罩 2。增量（P0 实测，§12）：晴到多云 +0.05–0.15 ms，阴和雾约 0（投影仍在，只是变淡，开销与晴相当；夜雨没有月影时阴影通道空跑），小雨 +0.3 ms，大雨和雷雨 +0.6–0.8 ms，大雪 +0.3 ms。最坏组合是"夏夜雷雨"（满叶、灯全亮、湿路灯条、积水、雨幕），列在 ENG-BUDGET §2；冬夜基准显式给 `--weather=snow --weather-intensity=1`（ENG-BUDGET §2）。
