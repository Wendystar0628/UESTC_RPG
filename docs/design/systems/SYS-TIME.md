## 0 结论

时刻和季节都能在界面上调，每一种组合都要好看，切换自然过渡、不能硬切；所有表现以视觉效果为先，真实数据只作参考（CORE-INDEX）。

1. **默认状态**：秋季 17:30、1×、晴、自动天气，天气保持晴到秋季黄昏带结束（约 19:36，SYS-WEATHER §6.6）。它是**新游戏的终态和新存档的初值**（SYS-SAVE §5.5）：新游戏的过场从秋 17:05 正向推到 17:30 停住（完整版以 60× 推进，简短版、关与跳过的倍率按 §1），交还控制时转 1×，所以任何种子下新游戏交还那一刻的画面都相同（SYS-TITLE §3、SYS-TITLE §6）。默认状态的叙事和基准视角都作为新游戏过场的终点。"落金初灯"是默认状态的名字。
   - **按图**：默认状态是每张图的 `world.default`（SYS-MAPS §3）；清水河的就是上面这一组，名字"落金初灯"。新游戏从起始图的默认状态开始；新游戏一律从落金初灯开始（SYS-SAVE）。
   - **开始页**显示最近存档的世界状态，流逝停住（`IAppFlow` 冻结），`AnimTime` 照走（SYS-TITLE §7.2）；没有存档时显示预览世界，即新游戏的终态。
2. **世界状态有三个量**：
   - 钟点 c ∈ [0, 24)；
   - 季节 s ∈ [0, 4)。s 是循环量，0、1、2、3 四个整数锚点分别对应春、夏、秋、冬；
   - 天气：对外是"天气格 + 自动 / 手动"，对内是一组连续参数"天气向量"（SYS-WEATHER §0、SYS-WEATHER §8）。自动天气是只向前推进的随机过程（SYS-WEATHER §6）。
   - 世界时间 `WorldHours` 单调递增，钟点由它换算（§1）。时间不能逆转：时间环只能往前拨，天气只做前向推进。单调的范围是同一个世界实例（`IWorldState.Instance`）；读档和新游戏是换实例，不算倒流（SYS-SAVE §5.2）；关着游戏的那段现实时间不计（SYS-SAVE §6）。
   - **跨图**（SYS-MAPS §5）：世界时间、季节、流逝倍率和 `AnimTime` 全局共享，只有一条时间线，切图不变；天气按图各一份前向过程，进图时补算到当前世界时间。
   - 风、水、"一拍二"所用的动画时间 `AnimTime` 与世界时间分开，仍按 480 s 一个周期循环。
3. **太阳和月亮按美术轨迹运行**，不按天文计算。正午的太阳高度有上限，避免画面变成平光；秋季 17:30 仍然正好是 5.5°、241°。
4. **调色板的关键帧按太阳高度索引，不按钟点**，按"太阳高度 × 晨/昏 × 四季"组织，再叠一层天气修正量（§3.1）。CPU 在 OKLab 色彩空间里插值后写入一张全局调色板纹理，只改纹理内容，不切特化开关，管线编译计数不增。
5. **季节变化全部做成连续参数**，靠"阈值生长"表现：插片缩放、插片换成枝条笔触、地面遮罩阈值、按法线方向覆雪。不换模型，不重建格子，不切特化开关、不新增管线编译。天气同样只改参数（SYS-WEATHER §0）。
6. **过渡要有美感**：
   - 改时间：像延时摄影一样向前快进到下一次出现的那个钟点，最长 3 s。
   - 换季：正向转场，相邻一季约 4 s、隔一季 5.5 s（以 §5 为准），依次是扬起、雾幕、落定，同时有一阵风从西湖向东推过全校。
   - 换天气：天气向量连续插值，按 SYS-WEATHER §6.5 的编排过渡，不硬切。

### 0.1 接入要点

- **要读钟点、季节、日月或天气**：C# 只经 `IWorldState` 读（Kernel 服务，WP-34），不自己写计时器；着色器不读 C# 对象，只读 WorldState 写的全局着色器参数（§1）
- **要改时间、季节、天气或套用推荐状态**：只经 `IWorldControl`；时间只向前（`SetClock` 跳到下一次出现、`Advance`、`FlowTo`），换季一律正向转场；读档经存档段 `world` 恢复，不经 `IWorldControl`；`Freeze` 只给测试构建（§1）
- **节点每帧要用本帧的世界状态**：用 `ProcessPriority` 排在 WorldState（−1000）之后，取值与 ENG-ARCH §3 的 `FramePriority` 表一致，任何两步不得同值（§1"每帧顺序"）
- **要写全局着色器参数**：用 `RenderingServer.GlobalShaderParameterSet`，参数先登记进 ENG-PERF §1.5 的登记表（项目设置 Shader Globals）；数组做成数据纹理；禁止从脚本读回全局参数（§1）
- **着色器要用时间**：禁用内置 `TIME`，周期动画读 `anim_time`（`AnimTime`，480 s 循环，与世界时间无关）；`Engine.TimeScale` 固定为 1，暂停不用 `SceneTree.Paused`（§1；SYS-MOTION §1.6）
- **内容随时刻、季节、天气变化**：不换模型、不重建格子、不切特化开关、不新增管线编译；颜色从全局调色板纹理读（当前行与季相行），季节变化走连续参数、阈值生长和地面遮罩（§3.1、§4"实现"）
- **要用新的颜色（色名、季相色）**：由 WP-04 登记进调色板、WP-37 定值，所有着色器读同一张调色板纹理；季相行已排满 60 行（§3.1、§3.3）
- **要加光源或用主光**：只有一盏主光（DirectionalLight3D，WP-03 驱动，日月轮流担任），颜色和强度经调色板与全局参数进卡通材质，不改灯的颜色属性（§2）
- **有灯、窗、屏幕要随时刻亮灭**：接进 WP-39 的灯光通道，时刻表写在 `game/data/maps/<地图>/lighting-schedule.json`，不新增灯光通道；按太阳高度求值的灯类曲线用有效太阳高度 h_eff（§6）
- **界面要显示世界状态或天气**：经 HudModel 的 0.1 s 采样读，不直接读 WorldState；界面主题由 `UiThemeClock` 写 `ui_night`，WorldState 不写（§1"界面读数"）
- **世界实例换了（读档、新游戏）**：`IWorldState.Instance` 变化的那一帧，自己的过渡直接落到新值，不做过渡；不跨实例比较 `WorldHours`（§1）
- **内容要进时季验收**：在窗口模式下用默认命令行串截图，等流式队列为空、管线编译计数不再增长再存；"前推 24 小时""四季轮换""天气巡回"跑完 DRAW 编译计数为 0（§8）

## 1 世界状态与控制（WP-34）

契约写在 ENG-ARCH §3 中。下面是摘录，字段名和类型以 ENG-ARCH §3 为准，两处有出入时改本节：

- **形态**：WorldState 是 Kernel 的一项服务（不单独做 Autoload，ENG-ARCH §2），实现类挂在 Kernel 下，按下文"每帧顺序"表里的 `ProcessPriority` 每帧推进。天气过程（WP-45a，`game/systems/weather`）由 WorldState 在同一步里调用，不另设计时器。内容代码只通过 `IWorldState` 读，不能自己写计时器；着色器不读 C# 对象，只读全局着色器参数（见"每帧顺序"）。WP-34 同时实现存档段 `world`（SYS-SAVE §2）；读档经它恢复，不经 `IWorldControl`；`Freeze` 只给测试构建。
- **测试与截图**：冻结状态由命令行参数给出（`--clock=17.5 --season=autumn --anim=240 --flow=0 --weather=clear --weather-seed=1`，用 `OS.GetCmdlineUserArgs()` 读；完整的默认串和天气参数见 ENG-GATES §1、SYS-WEATHER §8；默认串末尾还有 `--map=qingshuihe --title=0 --save=off --audio=off`），Boot 解析后交给 WorldState；未知参数和不合季节的天气直接以非零退出码结束。用 `--slot`、`--load` 读档时，世界状态只来自存档，与 `--clock` 等世界类参数同时给出时以非零退出码结束（SYS-SAVE §12）。
- **世界时间与钟点**：
  - 世界时间 `WorldHours` 单调递增，只由流逝、拖动时间环、跳转、`Advance` 和 `FlowTo` 推进；**同一个世界实例里**任何操作都不让它减小。`Freeze` 和命令行只设定初值。
  - **换实例**：新游戏、读档是换一个世界实例（`IWorldState.Instance` 加 1，SYS-SAVE §5.2），不算倒流；跨实例比较 `WorldHours` 没有意义。"回到落金初灯"不换实例（SYS-TITLE §6）。
  - **读档**：`WorldHours`、offset、季节、流逝倍率原样恢复。存的是追随目标 x\*，恢复时 x = x\*，不做快进；保存时过渡还在进行的，取终点（SYS-SAVE §4.2）。
  - **没在玩的时间不计**：关着游戏的那段现实时间不计入世界时间，读档不补算（SYS-SAVE §6）；开始页（Title）停留期间流逝由 `IAppFlow` 冻结；系统睡眠恢复后的第一帧 dt 夹到 100 ms。
  - **切图**（SYS-MAPS §5）：不改 `WorldHours`、季节、流逝倍率，也不改 `Instance`；雾幕期间世界时间照常走（1× 下只差几秒）。
  - 钟点 `Clock = (WorldHours + offset) mod 24`。offset 只在换季时重算，用来保持太阳在弧线上的位置 u 不变（§5）：钟点数字可能变小，但太阳不倒走，`WorldHours` 也不减。
  - 过午夜时钟点从 24 接回 0，世界时间照常增加。
  - 天气队列、云的漂移、积水的干涸都按世界时间推进，所以它们也只会向前走。
- **换实例的那一帧**（SYS-SAVE §5.2）：`Instance` 变化的那一帧，钟点弹簧、换季转场、天气过渡一律直接落到新值，不做过渡；主光的方向量化与月影淡入、窗灯与路灯的逐盏错开、界面主题的回差切换也一样。这一刻总在遮挡之下，不算硬切。
- **钟点追随**：采用临界阻尼弹簧的精确解（Holden 的写法），对任意帧间隔 dt 都稳定。设 y = 2 ln2 / 半衰期，j0 = x − x*，j1 = v + y·j0，则：
  - x′ = e^(−y·dt)·(j0 + j1·dt) + x*
  - v′ = e^(−y·dt)·(v − y·j1·dt)

  追随的是世界时间：目标 x* 只增不减；每帧把 x′ 夹在 [x, x*] 之间，越过目标时速度置 0，所以钟点只向前走、不过冲。拖动时半衰期 0.15 s；dt 上限 100 ms。
- **拖动时间环**（`ClockSetMode.Drag`）：只能顺时针。把手顺时针每转 15° 目标前进 1 h，每拖满一圈 +24 h；逆时针拖时把手停在原处，目标不变。拖动中天气的目标是队列在当前世界时间的状态，过渡不短于 1.5 s，途中可以改目标（SYS-WEATHER §6.5）。
- **跳转钟点**（`SetClock(h)`）：点击刻度、点预设时，跳到**下一次出现**的钟点 h：前进量 Δ = (h − Clock) mod 24，最多 24 h；已在该钟点就不动。拨到比当前更早的钟点，就是快进到次日的那个钟点。`.` 键是 `Advance(1)`，按住连续前进（UI-NAV §5）。两者都做延时摄影式快进，用时 = 0.6 + 0.18 × 前进小时数，上限 3 s。快进期间：
  - 长影扫过地面；
  - 云按世界时间积分，所以会加速漂移；
  - 窗灯按哈希错开，依次亮起或熄灭；
  - 跨过日出或日落时，主光在蓝调时段完成交接（§2）；
  - 天气按前向过程完整推进（最多几段，微秒级），画面只做一次"起点天气 → 终点天气"的过渡，放在快进的 30%–80% 段（SYS-WEATHER §6.5）。
- **自动流逝**：
  - 六档：**暂停**、**1×**（默认）、**10×**、**60×**、**360×**、**1440×**，速率是世界秒 / 真实秒。
  - 暂停只冻结世界时间和天气；`AnimTime` 照常走，雨丝照下（SYS-WEATHER §6.5）。
  - 天气：自动时按世界时间沿前瞻队列推进。60× 及以下按世界时间编排过渡；360× 及以上，每次过渡的真实时间不少于 1.5 s（SYS-WEATHER §6.5）。
  - **季节不自动推进**。
  - **开始页**（Title 状态，SYS-TITLE §6、SYS-TITLE §7.2）：`IAppFlow` 记下当前倍率后 `SetFlow(0)`，`AnimTime` 照走；继续时交还控制再恢复原倍率，不改写存档里的倍率；开始页停着的时间不计入世界时间。返回标题时先保存，再暂停流逝。

  拖动钟点时流逝暂停，松手 1 s 后继续。
- **`FlowTo(clock, rate)`**（SYS-TITLE §6、SYS-TITLE §7.4）：以 `rate` 正向流逝，到下一次出现的 `clock` 时正好停住（流逝变为 0）。
  - **取值**：`clock` 是钟点（小时，0 ≤ clock < 24，例如 17.5），"下一次出现"与 `SetClock` 同一语义，只会向前；`rate` 必须是 `Flow` 的取值之一（0、1、10、60、360、1440），否则抛 `ArgumentOutOfRangeException`。
  - **停点**：由 WorldState 在 `FramePriority.WorldState`（−1000）那一步里夹住，不越过一帧、不过冲；途中天气照前向过程推进。
  - **取消**：调用 `SetFlow` 或再次 `FlowTo`，会取消上一次还没到点的 `FlowTo`。
  - **新游戏的过场**用它：新建实例（秋 17:05、晴）→ `FlowTo(17:30, 倍率)`，完整版 60×、简短版 360×、关与跳过 1440×，是同一条世界轨 → 交还时 `SetFlow(1)`。所以交还那一刻钟点正好是 17:30:00，与跳过的终态逐位相同（SYS-TITLE §6）。
- **回到本图默认状态**（`ResetDefault()`，SYS-MAPS §5）：读当前图的 `world.default` 与 `quietUntilDusk`：正向换季转场（§5）+ 快进到下一次出现的默认钟点 + 流逝 1× + 自动天气 + `quietUntilDusk` 为真时天气保持晴到本季黄昏带结束；天气种子不变，不移动镜头（SYS-WEATHER §6.6）。在清水河上就是：换到秋季、快进到下一个 17:30（已在 17:22–17:40 之间就不动）、保持晴到约 19:36，按钮名取 `world.defaultName`，仍是"回到落金初灯"。它是同一实例里的组合正向转场，不换实例，与新游戏不同（SYS-TITLE §6）。
- **每帧顺序**（与 ENG-ARCH §3 的 `FramePriority` 表、ENG-PERF §6 的帧内顺序一致）：用节点的 `ProcessPriority` 固定，值越小越先执行，与场景树里的顺序无关；任何两步不得同值（同值时按场景树顺序执行，说不清谁先谁后）。

## 2 美术太阳与月亮（WP-34）

**太阳**：

- 白天：令 u = (c − 日出) / (日落 − 日出)，高度 h = H · sin(πu)^1.15。指数大于 1，让黄金时刻比正弦曲线长约 15%。
- 方位从日出方位线性走到日落方位。
- 夜间沿用同一公式取负，H 取 24°。
- 方向向量 = (cos h·sin A, sin h, −cos h·cos A)，坐标约定见 CORE-INDEX。
- **约束**：秋季 17:30 必须正好是 5.5°、241°，以保留默认状态的全部设计。按上面的公式，秋季日落方位取 248.5° 时，17:30 正好落在 5.48°、241.0°；默认状态的黄昏（17:22–17:40 前后）太阳从约 6.9° 降到 3.7°，方位约 239°→243°。

| 季 | 日出 / 日落钟点 | 日出 / 日落方位 | 正午高度上限 H | 美术意图 |
| --- | --- | --- | --- | --- |
| 春 | 06:50 / 19:20 | 98° / 262° | 55° | 清晨西边雪山被照亮，日照金山 |
| 夏 | 06:10 / 19:55 | 85° / 272° | 62° | 日落故意压在西岭雪山的剪影上 |
| 秋 | 07:35 / 18:05 | 113° / 248.5° | 41° | 默认状态：沿银杏大道投下长影 |
| 冬 | 07:55 / 17:55 | 117° / 244° | 34° | 低角度暖阳，雪地上的影子发蓝 |

美术轨迹压低正午高度，有两个好处：避免平光；把方位角速度控制在每小时 14° 以内，阴影更稳定。

**月亮**：

- 走美术弧线：四季都在黄昏从方位 62° 升起（与默认状态相同，保证 V8 和 P14 在任何季节都能把月亮框进画面），夜间最高 48°（夏季 38°），黎明落在 300° 附近。
- 四季默认都是满月。季节转场时月相不跟着日期变，否则 4 s 内会闪过几次盈亏。
- 月盘按全局参数里的月盘受光方向做球面明暗，直径放大到真实的 1.5–2 倍（ART-SKYLIGHT §5.3、ART-SKYLIGHT §4.11）。

**主光交接**（只有一盏主光，DirectionalLight3D，太阳和月亮轮流担任，ART-SKYLIGHT §3.1）：

- 太阳高度从 −2° 降到 −7° 这段是"无影蓝调"，阴影强度为 0：全局 `shadow_strength` = 0，主光的 `ShadowOpacity` 也设 0。在这段里任选一帧，把主光转到月亮方向；引擎每帧重渲全部级联，这一帧就换完，不需要分帧换级。
- 转向的那一帧 `shadow_strength` 必须是 0。快速拖动时一帧就跨过整段蓝调，也在这一帧转向，并按 0 处理。太阳低于 −7° 以后 `ShadowOpacity` 恢复为 1，月影的深浅只由 `shadow_strength` 控制。
- 太阳高度从 −7° 降到 −12° 时，月影淡入到 0.45，比日影浅。月亮高度低于 15° 时，月影为 0，15°–20° 之间淡入。0.45 用全局 `shadow_strength` 在 light() 里实现，不用 `ShadowOpacity`（会越过卡通阈值，ART-SKYLIGHT §3.1）。
- 主光的颜色和强度取调色板与关键帧（月光约 0.18–0.2，§3.2），经调色板和全局参数进卡通材质，转向时不改灯的颜色属性。
- 黎明时按相反顺序进行。
- 这样不会出现影子在某个钟点突然从另一个方向冒出来的问题。
- 天气：阴、雨、雪时投影另乘 (1 − 0.8 × 阴度)，白天不低于 0.2，两阶明暗改用"天光方向"（SYS-WEATHER §7）；日月换向的规则不变，换向那一帧的 `shadow_strength` 仍必须是 0。

**退光线**：

- 太阳高度从 2.5° 降到 0.3° 时，受光区域的下限从 −10 m 升到 80 m，带 3 m 软边。这就复现了 ART-SKYLIGHT §3.4 的退场顺序：地面 → 低层 → 高层 → 穹顶。
- 宣邦楼的穹顶加 +6 m 偏置，保证它最后一个暗下。
- 日出时按相反顺序进行，穹顶最先受光。
- 实现：高度线是全局参数 `retreat_y`，由主光那一步每帧写；穹顶的 +6 m 是该实例上的 instance uniform；light() 的方向光分支按 smoothstep(R − 1.5, R + 1.5, 世界高度 + 偏置) 乘受光（ART-SKYLIGHT §3.4、ART-STYLE §2.5）。

**阴影方向钳制**：

- 阴影方向的高度不低于 4°。日盘可以继续下落，两者之间最多差 4°，看不出来。日月盘在天空着色器里用全局参数的真实方向画，不受这条钳制（ART-SKYLIGHT §4.11）。镜头在室内（介质为 Interior）时，阴影方向的最低高度抬到 14°（待验证，§10），0.5 s 过渡、出楼还原，让 17:30 普通窗的光斑也能落到地板上（ENG-PERF §10.1、WLD-INTERIORS §6.3）。
- 主光强度 = smoothstep(−2°, 4°, h)：0° 时约 0.26，0.5° 时约 0.38，日出日落的受光面仍看得见颜色；−2° 以下为 0，无影蓝调不受影响。
- 月亮当主光时，主光强度 = smoothstep(−7°, −12°, h_sun) × smoothstep(−2°, 4°, h_moon)：太阳落到 −7° 以下才开始有月光，月亮自身低于 −2° 时为 0。
- **方向量化**：主光方向在高度和方位上各按 δ ≈ 0.01° 量化，带回差，只在目标方向跨过一步时转灯；拖动、跳转、换季这类快速变化（ω > 1°/s）时不量化，连续转动。明暗交界线和影子用的是同一个内置方向，天然同步。不做按 ω 分档、新旧阴影图淡化和快档代理隔帧渲。阴影的配置（PSSM 4 级、按设备档的阴影图尺寸）和量化细节见 ENG-PERF §10.1。

## 3 色彩脚本（WP-37）

### 3.1 组织方式

- **关键帧按太阳高度索引**：高度取 −24、−12、−6、−3、0、3、6、12、25 和正午，分晨、昏两侧，共 19 个键，每季一套，共 4 套。手调的 12 张基准关键帧各锚在示例钟点的秋季太阳高度上（黄金锚在 5.4753°，秋 17:30 正好等于该帧），25° 以上按正午归一；19 键里其余的键由插值补出。这样任何季节的日落自动就是"日落"那一帧。
- **每个键存的内容**（影子以明度为主、按材质推导，不做"阴影一律蓝紫"，没有接触影，ART-STYLE §3）：
  - 约 40 个全局色名：天空 10 段、雾 2、主光色、天光色 `ambient.sky`（只用它的 a、b）、`shadow.1`（中性参考面的影，推导值）、描线染色色 `line.warm`、`line.cool`、地面暖反光 `bounce.ground`、室内暖调 `interior.warm`、光柱远端色 `shaft.far`、各建筑家族的受光色和影色。`shadow.contact`、`line.building`、`line.tree` 三个色名不使用（色号保留）；
  - 标量：影明度比 r、中性混合下限 w_min、描线加深 `line_darken`、雾密度、霾带高度、柔光（`GlowBloom` 与高光阈值，ENG-PERF §10.2）、暗角强度与色调、CDL 四个参数、星空可见度、云量。
- **不需要手调 4 × 19 套**：只手调秋季的 12 张基准关键帧（§3.2），再加四季的修正量（§3.3）和少量季节专属覆盖。其余颜色按 ART-STYLE §8.3 和 ART-STYLE §3.2 的规则推导：
  - 受光色 = 固有色 × 主光色 × 饱和增益；
  - 影色：明度 L = 受光 L × r × r_mat；彩度 ×1.1（植被 ×0.85，增彩上限 +0.03）；色相从**固有色**出发向 `ambient.sky` 的色相小转，最多 8°（植被 15°），黄、橙不往绿转，非绿色材质的影不落橄榄区；中性材质（固有色彩度 < 0.06）再混入天光色，权重至少 w_min（ART-STYLE §3.2）。
  - 室内：调色板行 2（室内影色）按上一条"影色"的规则推导，r_in = 0.80，`ambient.sky` 换成 `interior.warm`；行3（室内受光色）的目标在OKLab中只抬L：L=min(0.9,受光色L×1.27)，C取原受光色的C、不随增益放大，色相不变，越出色域只降彩度；按默认`interior_light.x=1.27`反算存色，使影+g×(受光−影)合成后达到目标（ART-STYLE §3.4）。
  - 约束（WP-37 自检，§8）：浅色面的影 L 白天 ≥ 0.74、默认格 ≥ 0.68；有彩材质的影保住身份色。
- **叠加顺序**：关键帧（§3.2）→ 四季修正与季节专属覆盖（§3.3）→ **天气修正量**（SYS-WEATHER §2、SYS-WEATHER §7）→ 转场雾幕（§5）→ 介质（SYS-VIEW §5）。
  - 天气修正量按天气向量（SYS-WEATHER §8）连续插值，晴天为 0。主要几项：阴天主光 −1.0 EV、大雨 −1.3 EV；影明度比 r 取 max(r, 0.88 + 0.04 × 阴度)（软光，影浅），`ambient.sky` 向 `weather.overcast` 的色相混合阴度那么多（满阴约 C 0.022 / h 320）；雨后初晴饱和 +0.08；关键帧里的"云量"由天气改写（SYS-WEATHER §2）。
  - 天气修正同样只改调色板纹理的内容，不切特化开关；底线照旧：禁止中性灰和灰黑色的天（SYS-WEATHER §3）。
- **插值方式**：
  - 颜色在 OKLab 里插值。色相差超过 60° 的天空色带改用 OKLCH，并强制经过洋红过渡。例如从金色 #F7B072 到蓝色 #4A62A8，OKLab 的中点 #9F8C97 发灰，OKLCH 的中点 #C475A3 正是黄昏的洋红。
  - 时间轴用单调三次 Hermite（不过冲），季节轴用 smootherstep，光强在 log2 域里插值，雾密度在对数域里插值，方向用 slerp。
  - 相邻关键帧色相差超过 40° 时，中间插一张隐藏的子帧。
- **运行时**：WP-37 的 C# 求值器在每帧顺序的"调色板"一步（§1）用双精度算出结果，每帧不超过 0.3 ms，写进一张 256×64 的 RGBA8 Image，再用 `ImageTexture.Update()` 整张上传（64 KB）。这张 ImageTexture 登记为全局 `sampler2D`，所有着色器读同一张（ART-STYLE §8.5）：
  - 第 0 行是当前色，第 1 行是灯照色，第 2、3 行是室内影色和室内受光色，用 `texelFetch` 读；
  - 第 4–63 行是植被的季相行，沿季节轴过滤（线性过滤加循环寻址，冬 → 春自然衔接；全局采样器能否带这些提示待 P0 原型确认（§10），不行就手工读两次插值）；
  - `Update()` 只能整张更新，尺寸和格式不能变，但不重新分配、不换 RID，材质不会失效。需要省带宽时，可以拆成"当前色 256×4，每帧更新"和"季相 256×60，不超过 10 Hz"两张；
  - 纹理里存 sRGB 字节，解码方式见 ART-STYLE §8.5。

  详见 ENG-PERF §1.5。

- **描线加深** `line_darken` 是 ART-STYLE §4.2 线色公式里的线性乘子，越小线越深：白天与晨昏 0.14–0.15；夜间四帧（深夜、黎明前、入夜、夜晚）按"描线比阴影暗 0.06–0.10"（§3.4）反解为 0.58–0.70，夜间的 `line.warm`、`line.cool` 取 #4C4050、#3E4C6A；蓝调 0.35 作过渡。

- **农田四季**：春油菜花黄；夏稻田浓绿；秋收割后的金色稻茬，田埂上几垛稻草；冬霜灰色，田埂露出暗土。田块之间的田埂、灌渠画成一格格的平涂。作物色进调色板的季相行（`bloom.yellow`、`crop.*`，§3.3），由 WP-04 登记、WP-37 定值。
- **林泽杜鹃绿地**：春季一片片粉红的杜鹃花，其他季节按常绿灌木。
- **草坪轨道**的草随校内草坪换色；**行道树**按 WLD-VEGETATION §2 的树种走季相。
- **积雪**按法线自动覆盖外围的屋面、树冠、栏杆顶（下文"建筑和树冠覆雪"）。
- 外围的声音只从雾里来：远处城市的宽带车流底噪放在外围外缘以外，按方位和作息（早晚高峰最响、2:00–5:00 最低）变化；栏杆外那条空街本身不发车声，静止的电车也不出声（SYS-AUDIO §4.6）。

**下雪**：由天气决定，不按钟点（SYS-WEATHER §1、SYS-WEATHER §6.3）。

- 冬季的降水格是雪（轻 / 中 / 重），雪只在冬季出现；换季时雨和雪在雾幕里就地互换（SYS-WEATHER §1）。
- 自动天气下以夜雪为主：每天约 0.35 次，多在 19–23 时开始，主相时长中位 5.3 h，范围 2.5–11 h；另有稀有的整日小雪和"雪意阴"（SYS-WEATHER §6.3）。
- 起落按天气过渡编排（SYS-WEATHER §6.5），快进时也不会硬切（SYS-MOTION §11.3）。
- 积雪 = max(季节基线, 天气累积)（SYS-WEATHER §2）：不下雪的冬季白天也是"雪后"的样子，地面和枝头的积雪常在；下雪时步道也会白。
- 英雄帧"冬夜下雪"和点位推荐里的雪（UI-NAV §6）靠钉住天气保证（SYS-WEATHER §6.6）；截图要下雪时显式给 `--weather=snow`。

**实现**（由 ENG-PERF §9 统一负责，不换模型、不切特化开关、不新增管线编译；做法是"全局参数 + 两张全局纹理 + MultiMesh"）：

- **数据通路**：
  - **全局参数**：季节（连续 s、转场的起点季节、目标季节、转场进度）由 WorldState 那一步每帧写入（§1）；风量、覆雪量、雾幕强度等由各自的系统每帧写入。名字以 ENG-PERF §1.5 的登记表为准。
  - **两张全局纹理**：调色板（§3.1，季相行管颜色）和**树种表**（32×8 RGBA32F：每个树种的叶量 A 与开花量 B 的四季锚点、摆幅、枝条笔触所在的 Texture2DArray 层号、季相色行号、是否落叶）。树种数据写在 JSON 里，启动时转成纹理。
  - **MultiMesh**：植被是 MultiMeshInstance3D（近池每个"母模型 × 级"一个动态 MultiMesh，远池 64 m 一块静态，ENG-PERF §9）。每株参数放 `INSTANCE_CUSTOM`（稳定种子、变体、风向上的位置、树高）；稳定种子来自实体 ID，不用 `INSTANCE_ID`。每张插片的数据放 CUSTOM0–2。不用实例色。
- **逐株错相**：每棵树由稳定种子取一个哈希值，得到季节偏移 o ∈ [±0.06]，即局部季节 s_i = s + o。
- **叶量 A**：
  - 插片在 vertex() 里缩放：scale = smoothstep(h2, h2 + 0.08, A)。
  - "落掉"的插片换成 Texture2DArray 里的枝条笔触层（层号查树种表），并缩到 0.6；换层的判断用 flat varying 传给 fragment()。这样冬季的裸枝剪影不需要任何新几何。
  - 团块按 smoothstep(0.15, 0.6, A) 向团心收缩。
  - 阴影通道自动执行同一个 vertex()，叶量缩放和风自动跟到影子上，不需要另写深度程序。但阴影通道里 `CAMERA_POSITION_WORLD` 是灯的位置，凡是按距离的判断（分级、近处插片塌缩）一律用 `MAIN_CAM_INV_VIEW_MATRIX[3].xyz`（门禁检查）。
- **开花**：花就是该树种的插片换成季相色。樱花、蓝花楹、蜡梅、玉兰都这样做。
- **替身与树冠云**：L2 替身（团块低模或半八面体替身，P0 对比后定，见 §10、ENG-PERF §9）读季相行的色调，叶量用噪声阈值控制。冬季替身用 `tree.bare` 暖灰紫，覆盖率不低于 0.35。冬季树冠云沿法线最多收缩 1.5 m。
- **地面覆盖**：地面遮罩扩展为 RGBA8：
  - R：银杏落叶潜势；
  - G：其他落叶和花瓣；
  - B：积雪潜势（草坪 1、步道 0.5、车道 0.2、球场与跑道 0.2、檐下 0）。球场和跑道积雪要薄，冬季仍认得出场地配色，这是身份特征；
  - A：保留（ENG-PERF §1.5）。

  覆盖 = step(噪声, 遮罩 × 季节量)，配合 `fwidth` 抗锯齿。季节推进时，色块从树根处长出来。积雪那一项的季节量取 max(季节基线, 天气累积)（SYS-WEATHER §2）；雨天的湿润和积水用另一张地面遮罩 2（SYS-WEATHER §7），不占这张遮罩的通道。遮罩导入时不压缩（RGBA8），免得 BC 压缩把阈值推偏（ART-STYLE §6.4）。
  - **范围**（SYS-MAPS §10、WLD-OUTSKIRTS §4.5）：地面遮罩覆盖全图数据纹理的范围 `map_rect`（清水河 ±1280 m）；街道带 O0 在范围内，和校内一样读遮罩。外围 O1、O2 和截面上缘不论是否落在 `map_rect` 内，都不读地面遮罩，覆盖潜势按面类别写进顶点（草 1、步道 0.5、车道 0.2、屋面按法线），配程序噪声做阈值生长；`toon.gdshaderinc` 按外围的顶点标志选择数据来源，不按片元是否落在 `map_rect` 内，所以 `map_rect` 的边线穿过 O1 也不出接缝（WLD-OUTSKIRTS §4.5）。
- **建筑和树冠覆雪**：按法线 y 分量计算，(N.y − 0.55) / 0.35，再乘以 AO。fragment() 里的 `NORMAL` 是视空间，先用 `INV_VIEW_MATRIX` 转成世界法线；AO 烘进顶点（着色器读不到 SSAO）。外围的屋面、树冠、栏杆顶同样成立（WLD-OUTSKIRTS §4.5）。
- **荷花**：用 MultiMesh（东湖一角和西湖入水口各一个，共约 600 个实例）。荷叶、荷花、莲蓬的尺寸和下垂角都是 s 的函数，有四种状态：小荷钱、满塘、残荷、枯梗。
- **季节氛围粒子**（WP-38）：
  - 春：樱瓣；秋：落叶；冬：枝头落下的雪团（SYS-WEATHER §2）。三者共用一个飘落池，容量 160。
  - 下雪时的雪花和下雨时的雨丝由降水池负责，跟着天气走（SYS-WEATHER §7）。两池的具体分工以 SYS-MOTION §11.3、SYS-MOTION §13 为准。
  - 夏夜的萤火虫：分布在西湖岸、湿地、东湖荷角三个区，只在镜头 60 m 以内出现。64 只，1 次绘制。雨天减量（SYS-WEATHER §10）。
  - 飘落池和萤火虫都是 MultiMesh，位置在 vertex() 里由 `AnimTime` 解析算出：不存状态，截图和录像可复现。一拍二统一用 T12 = floor(anim_time × step_rate) / step_rate（`step_rate` 默认 12，SYS-MOTION §2.2）。GPUParticles3D 只作备选（它有状态，截图复现要固定种子再预跑，SYS-MOTION §13）。
- **风量**：春 1.2×、夏 0.8×、秋 1.0×、冬 0.6×，夜间再乘 0.7；天气再乘 (1 + 1.2 × 风暴度)，雾天 ×0.3（SYS-WEATHER §2、SYS-WEATHER §7）。
- **雪山**：可见度和雪线作为季节参数，晴天的可见度下限 0.35，保证每个组合都至少有一道淡剪影；阴、雾、雨时最低可到 0.15，仍留一道最淡的剪影，雨后初晴 0.95（SYS-WEATHER §4）；夜里画成月光下的银灰（WLD-DIORAMA §6）。

## 5 过渡

**换季转场**：季节可以任意选，一律用正向转场（扬起 → 雾幕 → 落定）。相邻一季 4 s，隔一季及以上 5.5 s，各段按比例拉长。季节值 s 一律向前展开（例如秋 → 夏依次经过冬、春），中间的季节藏在雾幕里；画面一律按下表走：粒子只往下落，不倒放，中间态藏在雾幕里。不做倒放效果：那样看起来像时间倒流。

| 时间 | 发生什么 |
| --- | --- |
| 0–0.8 s · 扬起 | 阵风加强到 2.5 倍，飘落池扩到 160 片，喷出上一季的叶、瓣或雪 |
| 0.6–2.6 s · 雾幕 | 起雾距离与剪影距离一起向近处收（远处先沉、近处后沉，沉没程度约等于雾密度 ×1.8，初值），柔光 +0.1，整体提亮不超过 25%（ART-SKYLIGHT §6.4） |
| 2.0–4.0 s · 落定 | 新一季的粒子落下；地面覆盖再用 2–4 s 阈值生长到位 |

- **声音**（SYS-AUDIO §7.2）：0–0.8 s 一阵风声涌起（风床 +6 dB，叶声变密）；1.2–2.4 s 季节层（鸟、虫、蝉、蛙）在雾幕段交叉，不会出现"冬天的蝉"；落定段风声回落；转场期间散布只保留 30%。减少动态效果时不做"扬起"的风声，声景 0.5 s 交叉。
- **风过换季**：季节进度从西湖开始，向东推过全校。每棵树的相位 = 0.6 × hash + 0.4 × 它在风向上的位置，最多错开 0.3。
- **太阳**：换季时保持太阳在弧线上的位置 u 不变，黄昏仍是黄昏。世界时间 `WorldHours` 不变，只重算钟点的 offset（§1），钟点数字平滑改写，可能变小，但太阳不倒走。
- **天气随换季**：当前天气不合新季节时，在雾幕里就地替换（雨 ↔ 雪、雨后初晴 ↔ 雪后初晴、雷雨 → 秋季大雨或冬季大雪），并给一条临时提示（SYS-WEATHER §1、UI-NAV §4.9）；自动天气的队列丢弃，按新季节的参数从当前片段结束处向前重排（SYS-WEATHER §6.5）。
- **防止中间态难看**：
  - 每个元素只在"两个好看的端点"之间做阈值切换，单个树冠团块沿 OKLCH 走"绿 → 黄绿 → 金 → 橙 → 锈红"；
  - 禁止草与雪、花与叶直接混色；
  - 中间态主要藏在雾幕和粒子后面；
  - 转场途中可以被打断，从当前 s 重新定目标。

**改时间的声音**（SYS-AUDIO §7）：一次性声按真实秒排程，与流逝倍率无关；快进和拨时间环时散布 × 0.3；钟声、傍晚广播在流逝超过 10× 时不敲不播，快进跳过的整点和时段也不补（§6）。

**换天气**：手动点天气格、自动天气的相变、快进途中"起点天气 → 终点天气"的过渡，都只让天气向量（SYS-WEATHER §8）连续插值，不硬切、不增删节点、不编译管线。声音上风先起、雨随后、排水声最后出现（SYS-AUDIO §5.1）。编排、时长和速率规则见 SYS-WEATHER §6.5；自动转移不进晨昏带、各种天气的最短时长见 SYS-WEATHER §6.2；闪电与彩虹的条件见 SYS-WEATHER §5；验收见 SYS-WEATHER §9。动态那一侧的做法见 SYS-MOTION §12。

**改时间、换季、换天气同时发生**（`WorldTransition` 是位标志，三位可以同时置上）：

- **定目标的顺序**：季节 → 钟点 → 天气。先按目标季节定太阳弧线和 offset；再在新季节里定目标钟点（向前，§1）；最后按新季节、新钟点取目标天气，不合季节的先替换。点位推荐的 `Apply(WorldPreset)` 和"回到落金初灯"都按这个顺序。
- **共享的效果只做一次，取较大值**：阵风倍数、雾幕浓度、柔光增量、整体提亮各取几者中较大的一个；雾幕的时长取较长的一个。
- 途中被打断时，从各量的当前值按同一顺序重新定目标。

**减少动态效果**：改时间、换季、换天气都改为 0.5 s 的雾幕交叉淡化；闪电关闭（SYS-WEATHER §5）。开关是设置里的"减少动态"（存 `user://settings.cfg`，UI-NAV §8）；首次启动时的默认值读系统设置 `DisplayServer.AccessibilityShouldReduceAnimation()`（返回 1 为开，0 或 −1 为关），之后以用户的设置为准。

- **窗灯的亮法**：每扇窗按 smoothstep(θ_i, θ_i + Δ, L) 亮起，Δ 随通道变化速率自适应。正常速率下单扇窗在 0.3 s 内亮起；快进和快速拖动时间环时也不会闪烁。

## 7 与动态、偶发事件的协调（WP-26）

- **拖动不影响动画节奏**：拖动钟点、快进时，风、水、"一拍二"照常走，只有云按世界时间积分。雨丝和风一样按 `AnimTime` 走（SYS-WEATHER §6.5）。
- **偶发事件的触发条件**：ω < 0.05°/s，且距离上一次转场超过 20 s。
  - ω：暂停、1× 满足；10× 时太阳最快的时段约 0.044–0.051°/s，以实时的 ω 为准；60× 及以上、拖动和快进中不满足。
  - 转场：改时间、换季、观者换天气、点位跳转、模式切换都算；自动天气的缓慢演变不算。
  - 银杏大道路灯的亮灯比例 ≥ 0.5 时：用原版，银杏大道的路灯依次亮一遍（SYS-MOTION §10）。默认状态下已经满足：秋季晴天约 17:27（太阳低于约 6°）起比例过半，17:30 约 0.6。比例按 h_eff 求值（§6），所以阴雨天更早进入原版。亮度增量取相对值并限幅，夜间路灯已满亮时只加 35%，避免过曝。
  - 白天：沿同一条路线依次抖落东西。秋天落叶，春天落花瓣，冬天枝头落雪，夏天树冠依次轻摇。
  - 天气版本（SYS-WEATHER §5）：雨夜里路灯依次变亮时，积水里的倒影同步变亮；雨天白天，树冠依次抖落一阵积雨；雾天，光晕依次变大。
- **全片只有一个偶发事件**（INV-10）。观者触发的过渡不计入；闪电（雷雨的持续氛围）和彩虹（初晴的天象）也不算偶发事件（SYS-WEATHER §5）。
- **开始页与过场**（SYS-TITLE §7.2）：Title、Entering、Leaving 期间禁止偶发事件；交还控制的那一刻算一次转场结束，"距上一次转场超过 20 s"从这一刻重新计时。传送、切图、读档也算转场。
- **声音**（SYS-AUDIO §6.4、SYS-AUDIO §7）：声音的散布按真实秒，与偶发事件同一套计时；60× 及以上不出钟、广播和交班音。偶发事件本身无声，它引起的抖落、积雨、旗动有声。

## 8 验收（WP-41，配合 ENG-GATES）

- **验收基准**：精致预设、1920×1080 原生、自动调节关（`--quality=fine --adaptive=0`，SYS-GRAPHICS §10）。低预设的口径见 SYS-GRAPHICS §10。
- **集中测试**（ENG-GATES §2 的测试节奏，D-167）：
  - 默认状态跑全部审查视角；
  - 按 L16 正交表，抽 8 组"视角 × 关键帧 × 季节 × 天气组 × 预设"的组合：天气组占一列（SYS-WEATHER §9），预设作为一个因子（SYS-GRAPHICS §10），截图总数不变；
  - 4 季 × 12 个关键帧，共 48 个组合（晴），每个组合轮换 2 个视角；视角轮换里加入外围视角 V11、E6、E7（WLD-OUTSKIRTS §13.1）和 T0（`--title=1`，SYS-TITLE §11.2）；
  - 天气的静态格（状态 × 关键帧 × 季节，降水和雷雨另验强弱两端）加一组天气轮换；
  - 天气的动态格（转移边 × 光段 × 季节）：约 48 段 `--weather-queue` 录像全量跑一遍（SYS-WEATHER §9）；
  - 脚本："前推 24 小时"（各档流逝速度和拨时间环两种方式都跑）、"四季轮换"、"天气巡回"；
  - 拼出 4 × 12 的截图联表，另拼"季 × 天气"联表，由风格负责人逐格按 5 分制打"好看"分，任何一格低于 3 分就返工；联表至少一格是外围视角；
  - 英雄帧（§3.5 的 12 张）必须达到 4 分以上，每个天气格的代表帧不低于 3 分；英雄帧另跑一遍流畅预设，不低于 3 分（SYS-GRAPHICS §10）。
- **怎么出图**：
  - 一律在**窗口模式**下截图：无界面模式（`--headless`）不渲染，也不编译着色器；窗口不能最小化。组合由命令行参数给出，默认串是 `-- --pose=V1 --clock=17.5 --season=autumn --anim=240 --flow=0 --mode=fly --ui=0 --seed=1 --weather=clear --weather-seed=1 --quality=fine --adaptive=0 --map=qingshuihe --title=0 --save=off --audio=off`（见 ENG-GATES §1、SYS-MAPS §11、SYS-AUDIO）。
  - 每张图都要等流式加载队列为空、`Performance` 的管线编译计数不再增长之后再存（门禁 G7，ENG-GATES §2）。
  - "前推 24 小时""四季轮换""天气巡回"三条脚本和天气录像用 Movie Maker 出帧序列：`--write-movie out.png --fixed-fps 60 --quit-after N`，再加"流式屏障"（各环都就绪才推进下一帧），保证同一构建、同一种子下帧序列可复现（门禁 G13）。无硬切检测就在这串帧上算。
  - 天气录像另录：跳转和拨时间环的一次过渡、快进经过降水、换季替换、手动 ↔ 自动、过渡途中打断，以及"减少动态效果"下的同样几条（SYS-WEATHER §9）。
- **无硬切检测**：过渡期间，相邻两帧的平均 OKLab ΔE 不超过 2，最大局部 ΔE 不超过 6，有雾幕遮罩的区间除外；闪电帧打标记另判（SYS-WEATHER §5、SYS-WEATHER §9）。阴影方向变化按 ENG-PERF §10.1 的方向量化规则检查：慢变时只在跨过量化步时转灯；快速变化时连续转动；日月换向只发生在 `shadow_strength` = 0 的帧。时间只向前：帧序列里 `WorldHours` 不得减小，太阳在弧线上的位置不得倒退（换季时 u 保持不变，§5）。单调性只在同一个世界实例里检查，实例切换的那一帧以 `Instance` 区分（SYS-SAVE §5.2）；新游戏过场里的前推（完整版 60×，简短版、关与跳过的倍率按 §1）按同一条世界轨检查，跳过的终态与完整播放逐位相同（SYS-TITLE §11.2 的 G2）。
- **管线编译判据**：雾幕之后（有开始页时从标题页转为实时那一刻起），`Performance.Monitor.PipelineCompilationsSurface`、`PipelineCompilationsDraw` 和 `PipelineCompilationsCanvas` 的计数不得再增长；"前推 24 小时""四季轮换""天气巡回"三条脚本跑完，DRAW 编译计数为 0。改时间、换季、换天气只改参数值和全局纹理的内容，不切任何特化开关（ENG-GATES §2）。
- **调色板逐行自检**，即影色自检，按 ART-STYLE §3 做（推导规则 ART-STYLE §3.2，夜间与阴雨 ART-STYLE §3.6）。白天和黄昏的影只查明度和身份色，不查"偏蓝紫"；只有夜间判蓝紫：
  - 中性材质（固有色彩度 < 0.06）的影色相落在当前 `ambient.sky` 色相 ±30° 内；ART-STYLE §3.7 里标明暖影的暖墙（如宿舍暖米黄墙）不算中性材质，按暖影判；
  - 有彩材质（固有色彩度 ≥ 0.08）的影色相与固有色相差 ≤ 20°、影的彩度 ≥ 0.6 × 受光彩度；非绿色材质（色相不在 100°–160°）的影不落在 100°–150°（橄榄区）；
  - 浅色面（受光 L ≥ 0.85）的影 L：白天 ≥ 0.74、ΔL 0.13–0.20；默认格 ≥ 0.68、ΔL 0.18–0.24；
  - 夜间暗部仍落在蓝紫区间（w_min 0.35 保证）；
  - 主体与背景的明度差不小于 8，雨天、雾天照样验收（SYS-WEATHER §3）；
  - 夜间暗部的 L* 不低于 12；
  - 跳色的面积不超过上限：夜间窗灯不超过画面的 15%，售货机的屏幕与展示窗计入这一项（WLD-LIFE §4.5）；室内的大面积色只约束固有色，窗光斑、光柱、暖影这些光造成的颜色不受限（WLD-INTERIORS §8.4）。
- **画面明度分布**（与 ART-STYLE 的 WP-04 / WP-05 交付验收同口径）：默认格（V1、P00）画面 OKLab L 中位数 ≥ 0.62；白天格（上午到午后，晴）≥ 0.74；L < 0.30 的像素 ≤ 5%（不含描线）。
- **天气的一票否决**：天气残留（雨停后仍有雨丝、替换后仍是上一种相态）、闪电硬切或全屏闪白、出现未验证的转移边（ENG-GATES §3、SYS-WEATHER §9）。
