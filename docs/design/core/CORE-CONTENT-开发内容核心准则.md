## 0 结论

做内容时最容易忘的是怎么做，不是做什么：先守"开发方式"和"开发流程"，再做内容。

**开发方式**
1. **不过度工程化**：只写本单要的；不为假想的扩展加抽象层、配置项和插件点；不加防御性兜底、临时开关和调试残留；不写证据溯源、校验和、proof 和审计报告；不自加门禁、检查脚本和测试脚手架（WF-RULE §1，D-201）。
2. **测试最小**：只测本包的真实行为，不堆矩阵、不锁全局集合；默认快检，碰启动、行走、存档才加核心专项；没改相关文件不重跑（WF-RULE §9、§10）。
3. **改设计必清旧**：同一批迁完所有使用方，删旧代码、旧测试和旧文档，不留兼容层、旧入口和对照表（WF-RULE §10，D-209）。
4. **架构要好**：发现明显不好的架构，先说清怎么改再修，不绕过、不打补丁糊过去（WF-ROLE §6）。
5. **主线版先跑通**：简化几何、默认参数、占位资源都行；不改契约、数据格式和目录归属，不留临时接口（WF-RULE §8）。

**开发流程**
6. **改哪里**：只改本包独占目录；契约、共享工程文件、着色器、程序集引用写申请；不改 `docs/design/`（WF-BUILD §1）。
7. **贴近主线**：开工先看 merged.log 并 `git rebase main`；自己分支小步提交，不推送、不合并、不 stash；能独立合入的先交候选（WF-RULE §7、§10）。
8. **收尾从简**：跑 `gate.ps1 -Wp` 的快检，截几张图，按短头部回报，证据只给路径（WF-ONBOARD §4，WF-COMMS §3）。

**规范约定**
9. **写法**：随机只用契约的 `Rng` 与 `StableHash`，计时只经内核，材质只经 `ToonSpec`，颜色只用色名，gen 里超越函数用 `DetMath`；Godot API 先查 `docs/godot-api/signatures.txt`（ENG-ARCH §2，G4）。
10. **边界**：gen 是纯 .NET；显示经 `IRenderHost`；声音、存档、天气、地图数据、观者与镜头各走自己的接口（ENG-ARCH §2）。
11. **坐标与命名**：单位米，x 东、y 上、z 南，地面高度读 `ITerrain`；名字一看就懂；代码只用 `res://`，不手写 `uid://`，场景由代码生成，不写 GDScript（CORE-CONVENTIONS §1、§3，WF-BUILD §1）。

**内容底线**
12. **画风**：清透干净的三渲二日式动画背景，不做旧、不脏，影子浅而透（INV-5，ART-STYLE，D-174）。
13. **画面不能变差**：任何时刻、季节、天气都要好看；碰渲染、生成器、材质的改动要能和基线截图对上（INV-5、INV-8）。
14. **精度底线处处满足**：比例对，有倒角和收边，没有光秃的拉伸体块；细节按精度区 K1–K5 分级（INV-11，ART-FIDELITY §0）。
15. **内容禁区**：不出现人物与肖像；场景里的字一律简体中文；日式元素只限日常街景；关着的楼只做外壳、窗卡和简化室内（INV-4、INV-6、INV-7、INV-11）。
16. **不是地图复刻**：格局大体对，其余可风格化；增删只写覆盖层并写明理由（INV-9，MAP-QSH-ADDITIONS）。
17. **世界与界面**：时间只向前；几何不随时季天气变；只有旁观与行走两种模式；3D 画面里不叠标签（INV-2、INV-3、INV-8、INV-10）。
18. **预算是合入条件**：三角形、绘制调用、帧时、体积都在额度内（INV-12，ENG-BUDGET §7）。

## 1 细则在哪

每条的细则见它后面括号里的小节；全局不变量 INV-1–INV-12 的条文见 CORE-INDEX §3，门禁见 ENG-GATES §2。内容与画面的底线补充如下：

- **去粗糙靠最低合格构件、自定义法线和描线，不靠堆细节**（ART-MODELING §7）。表面属于哪个精度区读导出的精度区数据，不自己判断；底线不拿来换预算，细节密度在本包额度内按区取舍（ENG-BUDGET §8）。
- **共同口号**："走进剧场版动画的校园，清透、敦实、干净、有生活。"建模时拿不准风格取舍，回到这句话（ART-MODELING §6）；造型与质感拿不准时，看 ART-STYLE §1 的参考场景怎么做，读代码，不只看图。
- **任何时刻、季节、天气都要好看**：四季、昼夜和天气一律视觉效果优先，真实情况只作参考；照片和 OSM 只用来定结构，材质、色彩、陈设和标识按氛围做艺术化处理（CORE-INDEX §1）。
