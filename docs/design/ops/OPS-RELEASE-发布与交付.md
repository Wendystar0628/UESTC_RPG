## 0 结论

1. **构建信息只有一个来源**：仓库根的 `version.txt` 加当前提交，生成 `<版本>+<提交>`；界面、存档、日志、诊断和压缩包名都读它（ENG-ARCH §4）。
2. **正式用户目录固定**：`%APPDATA%\UESTC\`，不带版本号，所有版本共用；开发态用 `UESTC_DEV` 和 `UESTC_WPxx`，不碰它。
3. **一个公开版本** = `main` 上的标签 `v<版本>` + 分发压缩包 `UESTC-<版本>-win64.7z` + 地图数据包 `map-data-<版本>.zip`，三者版本号相同。
4. **更新解压到新目录**，不覆盖旧目录；卸载程序和清理用户数据是两件事，分开做。
5. **试玩出问题时交回诊断包**：默认只含日志和诊断摘要，存档由玩家另选。
6. **许可分四类**：代码与脚本用 MIT；原创美术、音频、文案与设计文档保留所有权利；OSM 派生数据按 ODbL 1.0；第三方素材按各自许可（§7）。

### 0.1 接入要点

- **要显示或记录版本**：只读构建信息 `<版本>+<提交>`（来自 `version.txt` 加当前提交），别处不另写版本号；`version.txt` 只由主代理在发版时改（§1）
- **判断存档能不能读**：只看存档自己的各层版本号，构建信息只用于显示和定位问题（§1）
- **要读写用户数据**：正式版的 `user://` 是 `%APPDATA%\UESTC\`，不带版本号、不改名；开发态用 `UESTC_DEV`、`UESTC_WPxx`；门禁和基准不读任何 `user://` 文件（§2）
- **改了导出配置、用户目录或存档格式**：要再走一遍干净环境验证；在回报里点明改了哪一项，由主代理安排（§3）
- **打启动集或地图数据包**：启动集 `boot_<地图>.pck` 由 WP-02 打、导出入口 `scripts/release/` 调用；地图数据包由 WP-08 打，外围部分由 WP-47 提供，内容与安装包里的是同一份字节（§3、§5）
- **写日志**：本机路径写成 `user://…`，不写出 Windows 用户名；日志与诊断摘要的字段以 ENG-PERF §12.6 为准（§6）
- **复现试玩问题**：按诊断包或存档里的提交号检出代码复现，结论写进回报（§6、ENG-GATES §5）
- **引入第三方素材或代码**：插件与第三方代码只收 MIT、Apache、BSD、ISC、OFL；登记进 `third_party.json` 或 `game/data/audio/licenses.json`，汇总进 `LICENSES.txt`（§7）
- **写许可页、`LICENSES.txt` 或数据包说明**：与 `README.md` 的"许可"一段对同一类内容写同一种许可，并指向本版本的 `map-data-<版本>.zip`（§5、§7）
- **场景或文案涉及学校标识**：本作不是校方作品；校徽、红十字换成原创图形（§7）

## 1 版本号与构建信息

- **版本号**：`version.txt` 一行 `主.次.修订`，只由主代理在发版时改（ENG-ARCH §4）。
- **构建信息**：`Build` 写作 `<版本>+<提交>`，例如 `0.4.0+a1b2c3d4e5f6`；工作区有未提交的改动时提交号带 `-dirty`。对外发布的构建必须来自干净的提交，带 `-dirty` 的构建不发布。
- **谁读它**：开始页片名块的版本行（SYS-TITLE §2.3）、存档 meta 的 `build`（SYS-SAVE §3.2）、日志第一行与诊断摘要（ENG-PERF §12.6）、分发压缩包和地图数据包的文件名（只取版本号）。别处不另写版本号。
- **兼容性**只看存档自己的各层版本号（SYS-SAVE §3.6）；构建信息只用于显示和定位问题。拿到一份诊断包或存档，按里面的提交号检出代码就能复现。

## 2 用户数据目录

- **正式版**：`user://` 是 `%APPDATA%\UESTC\`（ENG-ARCH §2）。里面有存档、设置、本机烘焙缓存、日志和导出的诊断包，清单见 CORE-CONVENTIONS §5.3、ENG-PERF §8。
- **不带版本号，也不再改名**：新旧版本读写同一个目录，所以更新后存档和设置照常沿用。目录名一旦随公开版本发出，改名就等于让玩家"丢了存档"，所以不改。
- **开发态隔离**：主检出用 `UESTC_DEV`，工作树用 `UESTC_WPxx`；门禁和基准不读任何 `user://` 文件（ENG-GATES §1）。在开发机上试玩导出版，用的才是 `UESTC`。

## 3 导出与发布

1. **准备**：主代理在主检出的 `main` 上改 `version.txt`，提交并推送；工作区必须干净。
2. **导出**：运行导出入口 `scripts/release/`，一条命令依次完成：`dotnet build` → `--headless --import` → `--export-release` → 各图启动集与 `bake.manifest.json` → 写入构建信息与 `LICENSES.txt` → 7-Zip 打包 `UESTC-<版本>-win64.7z`（LZMA2，`-mx=9`，ENG-PERF §8）→ 附上 WP-08 打好的 `map-data-<版本>.zip`（§5）。产物放仓库里不进 git 的 `build/`。
3. **检查**：G6 通过（安装目录与压缩包体积、`--bake-verify`，ENG-GATES §2），压缩包与数据包的文件名版本号与 `version.txt` 一致。
4. **发布**：在这个提交上打标签 `v<版本>` 并推送；在 GitHub 仓库的发布页（对应这个标签）上传压缩包和地图数据包，说明里写版本号、构建信息和 §4 的更新方法。
- **导出会改 `project.godot`**：Godot 导出时把等于引擎默认值的项从 `project.godot` 里删掉，其中 `rendering/lights_and_shadows/directional_shadow/16_bits=true` 会被删（引擎规范化，不是误改）。导出之后（以及在主检出跑过导出类门禁之后）要把这个文件恢复到提交的版本，保留显式的 `16_bits=true`，不要把导出改过的 `project.godot` 提交。
- **首次外发前走一遍干净环境**：在一个没装 .NET SDK、Godot、没有 `UESTC_*` 环境变量的普通 Windows 账户里：解压 → 启动（首次运行在扉页期间本机烘焙）→ 走一段、保存、退出 → 把下一版解压到另一个目录启动 → "继续"读到刚才的存档。以后改了导出配置、用户目录或存档格式，再走一遍。

## 4 安装、更新与卸载

整包分发，没有安装器。仓库 README 和发布说明照下表写给玩家：

| 操作 | 做法 | 用户数据 |
| --- | --- | --- |
| 安装 | 解压到任意有写权限的目录，运行 `UESTC.exe`。首次运行在扉页期间本机生成起始视角周围的内容，之后在开始页后台补齐（ENG-PERF §8） | 首次运行时在 `%APPDATA%\UESTC\` 建立 |
| 更新 | 新版本解压到新目录，从新目录运行；不要解压覆盖旧目录，否则旧版的程序集和启动集会残留，与新版混在一起。新版能继续以后，再删旧目录 | 存档、设置自动沿用；本机缓存按缓存键和 ABI 自行失效、只重烘改了的部分，不用手动清（ENG-ARCH §4） |
| 回到旧版 | 运行旧目录里的程序 | 新版写过的存档在旧版里显示为"来自更新的版本"，只读，不会被旧版写坏（SYS-SAVE §7） |
| 卸载程序 | 删掉安装目录 | 不受影响 |
| 清理用户数据 | 删掉 `%APPDATA%\UESTC\`；只想腾磁盘空间时，用设置卡"存储"一行的"清除缓存"（UI-NAV §4.6） | 删目录会删掉存档、设置、缓存和日志，不可恢复；"清除缓存"不动存档和设置 |

## 5 地图数据包（ODbL）

地图数据按 ODbL 1.0 提供（WLD-OUTSKIRTS §6.4）。每个公开版本附一份 `map-data-<版本>.zip`，与分发压缩包放在同一个发布页。

- **内容**：
  1. 本版本实际使用的派生数据库：各图的 `campus.json`、`network.json`、`zones.json`、`outskirts.json` 和 `overlay/` 下的全部覆盖层（含室内覆盖层），与安装包里的是同一份字节；
  2. `README.txt`：来源（© OpenStreetMap contributors）、各快照的日期、Overpass 查询原文、ODbL 1.0 声明与全文地址、对应的标签 `v<版本>`，以及在该标签下用 `pipeline/` 重建这些文件的命令。
- 派生数据库因故不能直接附上时，改附完整的重建材料：该标签下的 OSM 快照与元数据（`pipeline/raw/<地图>/`）、查询语句、管线与它的全部输入（含高度补充等数据）、覆盖层；按 `README.txt` 的命令能重建出与本版本相同的字节。
- **谁打包**：WP-08 的管线打包，外围部分（`outskirts.json`、外围覆盖层、查询原文与快照日期）由 WP-47 提供；导出入口把它和压缩包放在一起（§3）。
- **指向同一份**：仓库 README 的许可一段、许可页（SYS-VIEW §6）和安装包的 `LICENSES.txt`，都写明本版本的 `map-data-<版本>.zip` 和它所在的发布页。

## 6 故障处理与诊断

- **日志**：`user://logs/godot.log`，每次启动轮换、保留最近 5 次；每行带所属工作包、当前图和流程阶段，第一行是构建信息（ENG-PERF §12.6）。日志里的本机路径写成 `user://…`，不写出 Windows 用户名。
- **导出诊断**：操作说明页的"导出诊断"（UI-NAV §4.6）把日志和诊断摘要打成 `UESTC-diag-<版本>-<序号>.zip`，写进 `user://diagnostics/`，然后在文件管理器里打开这个目录（ENG-PERF §12.6）。默认只含日志和摘要；存档要玩家另外勾选才附上。游戏不联网，诊断包由试玩者自己发回。
- **诊断摘要**包括构建信息、显卡与驱动、画面预设与改过的项、地图与位姿、季节钟点天气与天气种子、本机缓存与烘焙失败的键、最近一次成功保存的时间和最近一次保存失败的原因；字段以 ENG-PERF §12.6 为准。
- **常见情况**：

| 情况 | 先做什么 |
| --- | --- |
| 启动或加载停在失败页 | 用失败页的"复制错误信息"或"重试"（SYS-TITLE §1）；再从操作说明页导出诊断 |
| 改了画面设置以后进不了游戏 | 用游戏外的"恢复画面设置"入口（SYS-GRAPHICS §6），再正常启动 |
| 提示无法保存 | 看存档页写的原因（SYS-SAVE §4）；退出时按提示选择重试、返回游戏或仍然退出 |
| 闪退 | 闪退时不强行保存，上一代存档仍然有效（SYS-SAVE §4.4）；重新启动后导出诊断，上一次运行的日志在保留的份数内 |
| 游戏内界面打不开 | 手动打开 `%APPDATA%\UESTC\logs\`，把里面的文件发回 |

- **试玩者交回**：诊断包，加一句话：在哪、做了什么、看到了什么。代理按诊断包里的提交号检出代码复现，结论写进回报（ENG-GATES §5）。

## 7 许可

本作各部分的许可如下（D-170）；对外的权威文本是仓库根目录的 `LICENSE` 和 `README.md` 的"许可"一段，由主代理维护。

| 原创美术、音频、文案与设计文档（含 `docs/design/`） | 保留所有权利 | `README.md` 的"许可"一段 |

- **第三方的许可白名单**：插件与第三方代码只收 MIT、Apache、BSD、ISC、OFL（ENG-WP §5；C# 移植的 earcut 是 ISC，ENG-ARCH §1）。例外：只在开发机上运行的工具链依赖（Python 管线的传递依赖等，例如 pyproj 带进来的 certifi，MPL-2.0）可以用 MPL-2.0，条件是不进游戏导出、不把源码或库文件放进仓库，并在 `third_party.json` 里标为仅开发用；音频素材的来源与许可按 SYS-AUDIO §14 登记。
- **不是校方作品**：`README.md` 开头写明这是个人创作，不是电子科技大学的官方作品，与学校没有关联；每个版本的发布说明也写这一句。场景里的校徽、红十字换成原创图形（D-065、ART-STYLE §11）。
- **说法一致**：`README.md` 的"许可"一段、许可页（SYS-VIEW §6）、安装包的 `LICENSES.txt` 和地图数据包的 `README.txt`，对同一类内容写同一种许可；改许可时先改 `LICENSE` 与 `README.md`，再同步其余几处。
