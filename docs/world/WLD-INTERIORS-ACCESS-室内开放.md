# WLD-INTERIORS-ACCESS · 室内开放

> **范围**：本文规定不分图的室内开放规则：精选开放的原则与共用约定，门的开与关（含自动门的设计取向），关着的楼，开放更多楼的做法。
> **不在本文**：室内加载、生成器、风格、痕迹、楼梯与碰撞（WLD-INTERIORS-BUILD）；开放的屋顶与高处、电梯（MAP-QSH-INTERIORS）；清水河各楼的开放范围、陈设与观景时刻（MAP-QSH-INTERIORS-LIBRARY，含开放楼总表）；各楼外观（各区 MAP-QSH 文档）；自动门的运行时规则与导航图（SYS-WALK-BOUNDS §3、§8）；行走控制器（SYS-WALK）；楼内介质（SYS-VIEW）；声音（SYS-AUDIO）；地图门口传送（SYS-ATLAS）；契约（`game/contracts/`）。
> **查阅**：先读 §0；开放原则与共用约定看 §1；门看 §2；关着的楼看 §3；新开一栋楼看 §4

## 0 结论

1. **精选开放，不全量开放**：只开少数室内和登记的高处，其余楼只做外壳、窗卡和门厅卡（§1）。
2. **开不开放只看有没有注册提供者**；清单在 `interiors.json`，增删须经主会话审批（§1）。
3. **一眼看出能进**：开放入口的门固定敞开，门口有暖光、地垫和绿色开放牌；关着的门是实体，玻璃里是门厅卡，走近推不开（§2）。
4. **楼里能进的房门和开放路线上的楼梯间防火门是自动门**：走近推开，闭门器关上，不加交互键（§2.1）。
5. **从外面看一律糊过去**：窗里是窗卡；旁观飞进关着的楼看到简化室内，镜头在楼体里至少显示 I0 兜底层（§3、SYS-VIEW-MEDIUM §2）。
6. **再开一栋楼不改契约和流式架构**（§4）。

### 0.1 接入要点

- **判断一栋楼能不能进**：只有 `interiors.json` 里注册了提供者的开放部分和 MAP-QSH-INTERIORS §4 登记的高处可走；清单外的楼进不去、不加载室内，其余屋顶门锁着（§1、MAP-QSH-INTERIORS §4）
- **新开一栋楼或扩大开放范围**：按 §4 做
- **做门**：开放入口的门固定敞开；能进的房门和防火门登记为 `DoorLeafDecl`；封口和锁着的门是静态几何，表面类型 `DoorClosed`（§2、WLD-INTERIORS-BUILD §5）
- **读自动门的开度或阶段（声音、声学门户）**：读 `IInteriorDoors`，不自己推算；运行时规则见 SYS-WALK-BOUNDS §3，门的状态不进存档（§2.1）
- **画关着的楼**：窗里是窗卡，门玻璃里是门厅卡，门后不做实体门厅；简化室内和 I0 的显示规则见 SYS-VIEW-MEDIUM §2，由 `interior.shell` 统一生成（§3）
- **区域包做楼的外观**：每栋楼的入口都登记进室内索引（关着的记 `Open = false`）；立面开间网格和窗位类型调平面内核取（§3、WLD-INTERIORS-BUILD §2）

## 1 开放原则与共用约定

全量开放在性能上做得到，否决它的是内容质量、整图逐楼的巡游验收和本机缓存体积。精选开放的室内多数只开局部楼层，去处少而精；平面内核和按层的提供者接口让扩大开放不用推翻。

- **数据**：开放清单是 `interiors.json`，每项写名称、一句话范围、提供者、开放楼层、开放入口、封口和负责包；入口的门中心、朝向、门外落点（门外 2.5 m）和净宽就是室内索引的 `EntranceDecl`，一律读数据和索引，文档不复制坐标。开放清单增删时核对一次"清单 = 注册的提供者 = 门开着的楼"（G5），日常不跑；巡游只走固定路线加改到的楼。精选室内属于所在的图，不另开 `MapKind.Interior`（SYS-MAPS）。
- **范围写到"楼层 × 区域"**：边界用现实里本来就有的东西收口：锁着的铁栅门、关着的防火门、玻璃隔断、伸缩门、书架墙、卷帘门。封口记 `DoorClosed`，顶 ≥ 1.5 m，缝 < 0.5 m；往里看是简化室内或门厅卡；封口门锁着，不会推开。
- **房间的门**：公共房间多数不设门；能进的房间（教室约三成、个别办公室和实验室、各处登记的主空间）用自动门；其余房门锁着。
- **入口**：每个开放入口的门口表现按 §2。
- **半室外**（外廊、步行街、平台下街廊）按室外介质，降水由 `precip_occ` 挡在顶下，进房间或店里才切室内介质。
- **看进去例外**：登记为"看进去"的路径和大玻璃从室外就要看见真实几何，镜头 150 m 以内加载 IS 层；其余开放楼从外面看照样是窗卡。清水河的登记见 MAP-QSH-INTERIORS-LIBRARY §2。
- **层数与层高**：OSM 的层数错误按各区调研修正，在记录里改层数。
- **高处**：其余屋顶锁着，只有登记的高处可走（MAP-QSH-INTERIORS §4）。
- **点位**：室内与高处点位 `Entry = Door`，位置读 `waypoints.json`（UI-NAV-WAYPOINTS §1）。

## 2 门的区分：开与关

**全图一条规则：门开着就能进，门关着就不能进。** 楼里能进的门平时也关着，但观者一走近就自动推开；推不开的门是锁着的。

| 线索 | 开放的入口 | 关着的入口 |
| --- | --- | --- |
| 门扇 | 固定敞开：开到 90° 贴墙，有门吸；感应门常开。几何二选一，由 `EntranceDecl.Open` 在烘焙时定 | 关着：玻璃映天，地锁、读卡器红点、"请刷卡进入"小贴纸 |
| 门里 | 亮着的真门厅，已预取 | 门玻璃里是门厅卡，比开放楼的门里暗一阶 |
| 门口 | 暖光池铺到台阶和地垫（灯表里一盏整夜全亮的门口灯，不加绘制调用）；深色地垫；绿色开放牌：楼名、开放范围一行、绿箭头（`sign.green`） | 没有光和地垫，台阶落叶多，贴"非开放时间 / 请刷卡" |
| 组团大门与店铺 | 开放的组团闸机翼门收起、绿箭头亮；开放的食堂拨开门帘、店门开灯亮 | 其余组团翼门关着、红叉灯；门帘后是关着的玻璃门；卷帘半落或全落 |
| 楼里的门 | 能进的房门和防火门：视窗亮、门缝漏光，走近推开（§2.1） | 锁着的门：视窗暗、读卡器红点，走近不动；铁栅门、伸缩门、书架墙同属此类 |

- **主要靠前三条**（门开着、门里亮、门口有光），白天黑夜都成立。3D 画面里不叠加标签、描边或光柱。
- **声音**：开放入口门无开关声；关着的门被撞上时玻璃轻震加地锁"咔嗒"，不出电子提示音（SYS-AUDIO）。

### 2.1 楼里的门：走近推开，闭门器关上

- **哪些门**：能进的房间的门，开放路线上的楼梯间防火门和走廊玻璃门，登记在提供者的 `InteriorLayout.Doors`（`DoorLeafDecl`）。封口门、锁着的房门和没有门扇的门洞不登记。
- **设计取向**：观者走近，门自动推开；离开后闭门器缓缓关上，不会把人关在门扇里；不加交互键，不出电子提示音。
- **与世界状态无关**：门的静止状态（敞开、能推开、锁着）在 `build()` 时定死（INV-8）；门的状态不进存档，读档和切图后直接关好。
- **运行时规则**：触发半径、动作时序、碰撞、声音与数量上限见 SYS-WALK-BOUNDS §3。

## 3 关着的楼：外壳、窗卡、门厅卡与简化室内

- **窗卡**：窗里一律是窗卡：室内视差（深度 3、4.5、6 m 三档）、家具剪影、窗帘或百叶、灯光色块；5 m 以内也不换实体几何。窗卡不对应真实房间，窗灯按稳定哈希和灯光通道亮灭（ART-COLORSCRIPT §3）。窗卡种类（约 15 种，按房间用途分）以数据为准。
- **窗位类型**：立面生成时先按楼型骨架标出楼梯间列、走廊尽端、卫生间列，其余按楼的类别配比，所以外面看大致合理，进楼后这三处天然一致。
- **玻璃投影**：关着的楼外壳是空心的，玻璃要投影，否则低太阳穿过窗洞在楼后漏出条纹光；开放楼内玻璃不投影（WLD-INTERIORS-BUILD §3.2）。
- **关着的门**：门扇是实体几何（把手、地锁、读卡器红点），墙段记 `DoorClosed`；门玻璃里是**门厅卡**（门厅、闸机绿灯、楼层索引牌、电梯门剪影），必须有内容，不能是空盒子（ART-FIDELITY §2.0 的 B11）。关着的入口也登记进室内索引（`Open = false`；清单外的已有建筑登记在 `interiors.json` 的 `closedEntrances`），不生成室内导航门户。
- **简化室内与 I0 兜底层**：旁观飞进关着的楼时的显示内容、加载时机和 I0 的规则以 SYS-VIEW-MEDIUM §2 为准。简化室内由平面内核按同一套楼型骨架出，与窗位、开放后的完整室内同源。
- **精度**：关着的楼内属精度区 K4 (c)，只判底线：闭合、有厚度，不空、不黑、不透天（ART-FIDELITY §1.1、§2.0）。行走模式下关着的楼进不去，也不加载简化室内。

## 4 开放更多室内

不改契约，也不改流式架构：做法如下。

1. 开工前：外壳和窗卡已做好、入口已作为关着的入口登记、开放范围定到"楼层 × 区域"并用封口收口、楼型和房间类型选好。
2. `interiors.json` 加一项（清单增删须经主会话审批）。
3. 注册提供者：没有地标空间的普通楼只在世界文件的记录里写楼型，不写代码；有门厅、中庭、展厅的楼写一个 `[InteriorProvider]`，普通部分仍调平面内核。`interiors.json` 的 `providerId` 指向已注册的专属提供者，或注册工厂声明的前缀；工厂产品由注册器按图创建、缓存和逆序释放，不为每栋楼增加空子类。
4. 补门的表现：入口设为 `Open`、换入口部件、登记门口灯；楼里的门登记 `DoorLeafDecl`。
5. 补声学声明（SYS-AUDIO），没写时音频退到声学网格加射线，只是听起来泛。
6. 进 G15；需要时补点位和路线。

开放前后无缝替换：窗卡、门厅卡、简化室内与完整室内同源（WLD-INTERIORS-BUILD §2），从外面看开放楼仍是窗卡，只有门口从"关门 + 门厅卡"换成"敞开 + 门口灯 + 地垫 + 开放牌"。

**无主体块**（无 OSM 主体的体块，如图书馆周边附属块、孤儿楼群）一律不开放，只做外壳加窗卡，归属的区文档负责外观、窗卡选型和入口登记。
