# ART-COLORSCRIPT · 色彩脚本、四季与灯光时刻表

> **范围**：本文规定色彩脚本的组织方式与情绪取向、四季修正与专属覆盖、难看时段的改造、英雄帧、四季内容与季节变化的原则、灯光与生活痕迹的时刻表设计意图。
> **不在本文**：世界状态、时间规则与美术日月（SYS-TIME）；过渡的编排（SYS-MOTION §3）；天空、主光、阴影、雾的观感取值（ART-SKYLIGHT）；天气的画面（SYS-WEATHER）；季节氛围粒子与风量（SYS-MOTION-ENV §6）；植物规则（WLD-VEGETATION）；外围农田（WLD-OUTSKIRTS）。
> **查阅**：先读 §0；色彩脚本、四季修正与英雄帧看 §1；四季内容看 §2；灯光与生活痕迹的时刻表看 §3

## 0 结论

每种时刻、季节、天气的组合都要好看；调色板、季相和灯光全是数据与参数，不换模型。世界状态与时间规则见 SYS-TIME。

1. **调色板关键帧按太阳高度索引**，按"太阳高度 × 晨昏 × 四季"组织，再叠天气修正；所有颜色读同一张调色板纹理（§1.1）。
2. **12 张英雄帧单独手调**，逐张验收"好看"，也是点位推荐状态的来源（§1.5）。
3. **季节变化全是连续参数**，靠"阈值生长"表现，不换模型、不重建格子、不新增管线编译（§2）。
4. **灯光按画面需要设计**，不照搬真实作息；曲线按有效太阳高度求值，阴雨天灯提前亮（§3）。

### 0.1 接入要点

- **内容随时刻、季节、天气变化**：不换模型、不重建格子、不切特化开关、不新增管线编译；颜色读调色板纹理（§1、§2）
- **灯、窗、屏幕随时刻亮灭**：接 WP-39（夜景灯光与时刻表） 的灯光通道，曲线写进本图 `lighting-schedule.json`；按太阳高度求值的曲线用有效太阳高度 h_eff（§3）

## 1 色彩脚本

### 1.1 组织方式

- **关键帧按太阳高度索引，不按钟点**：分晨、昏两侧，四季各一套。手调的是秋季 12 张基准关键帧（§1.2），再加四季修正量（§1.3）和少量季节专属覆盖，其余颜色按 ART-STYLE-SHADING §2、ART-STYLE §2 的规则推导。任何季节的日落自动就是"日落"那一帧。
- **每个键存**：天空五段渐变（太阳侧 / 背阳侧）、雾色与距离、主光色与强度、天光色、影明度比、描线加深、后期参数、窗灯路灯比例、星空与云量。键位与数值以 `game/style/palette/keys/` 下的 JSON 为准。
- **影以明度为主、按材质推导**：不做"阴影一律蓝紫"，没有接触影；中性材质的影偏天光色，有彩材质的影保住身份色（ART-STYLE-SHADING §2）。
- **叠加顺序**：关键帧 → 四季修正与季节专属覆盖 → 天气修正量（SYS-WEATHER §2）→ 转场雾幕（SYS-MOTION §3）→ 介质（SYS-VIEW-MEDIUM §1）。天气修正只改调色板纹理的内容，不切特化开关；晴天为 0。
- **插值**：金色到蓝色之间要经过黄昏的洋红，不能是发灰的中点；时间轴用不过冲的单调插值。做法在 `game/style/palette/keys/ColorScriptCurves.cs`。
- **运行时**：求值结果写进一张全局调色板纹理，所有着色器读同一张（ART-STYLE §2.5、ENG-PERF §1.5）。

### 1.2 秋季基准关键帧的情绪

每帧的色值以 `autumn.keys.json` 为准，下表只记取向。**黎明更冷更淡、偏青粉；黄昏更暖更艳、偏洋红金。** 日出、日落是一天里颜色最足的两帧：主光橙金，影浅，天光补光取天空的粉与粉橙，墙的影是粉玫瑰色、不发褐。

### 1.3 四季修正与专属覆盖

四季修正量以 `seasons.json` 为准，取向如下：

| 季 | 取向 |
| --- | --- |
| 春 | 天顶更亮更淡、偏青；主光偏奶白；雾乳白；光晕多一点 |
| 夏 | 天顶更深更艳；日落饱和度更高；能见度更好；积雨云 |
| 秋 | 基准；落叶粒子 |
| 冬 | 天顶更淡；主光正午也偏暖；影明度比略抬（雪地反光）；雾珍珠色；夜间路灯光斑放大，雪花被灯照亮 |

白天格的影明度比叠加后有上限，保证白天明暗差；冬季白天的季节感靠天色、主光和雪。

**季节专属覆盖**（手调，数据在 `seasons.json`）：夏季积雨云（白顶、蓝紫阴面，傍晚火烧云）；冬季雪（中性面，影偏蓝）与下雪时的薰衣草灰天；外围农田作物色进季相行（WLD-OUTSKIRTS-BAND §3.2）。

### 1.4 难看时段的改造

| 问题 | 改造办法 |
| --- | --- |
| 正午太平 | 积云覆盖 25%–35% 且云影在地面移动；天顶彩度够；树荫光斑、水面闪点、物体分界线撑起层次；描线不加粗；玻璃映天蓝再叠白斜条 |
| 夜晚死黑 | 天顶、阴影、描线的明度有下限；暗部仍偏蓝紫；月光作主光，保留明暗分阶；天空必须比建筑亮；深夜整体曝光抬高、路灯全亮、湖面倒映灯光；暖色灯配蓝色的夜 |
| 阴天、雾、雨 | 见 SYS-WEATHER §2–§4；底线：禁止中性灰和灰黑的天 |

### 1.5 英雄帧

12 张必须单独手调，逐张验收"好看"；它们也是点位推荐状态（UI-NAV-WAYPOINTS §1）的来源，推荐里的天气靠"钉住"保证（SYS-WEATHER-PROCESS §1.6）。英雄帧是验收样张，不是取舍原则。

1. 秋黄金（默认状态）· 晴
2. 春清晨：日照金山 + 满树樱花 · 晴
3. 夏午后：积雨云 + 满湖荷花 · 晴
4. 夏夜：银河 + 萤火虫 · 晴
5. 冬雪后正午 · 雪后初晴
6. 冬夜下雪：路灯光锥里的雪花 · 雪
7. 秋蓝调：交班的钟 · 晴
8. 秋 21:30 夜雨：银杏大道湿路面拉出一排路灯竖条倒影
9. 春 07:20 雨后初晴：洗过的蓝天下日照金山（P10 的推荐状态）
10. 秋或冬 07:30 晨雾俯瞰：八角穹顶探出雾海
11. 夏 18:40 雨后彩虹：虹压在宣邦楼钟楼上，西天火烧云
12. 秋 17:30 太阳雨：西边落金、东边暗云，金色雨丝（SYS-WEATHER §2）

## 2 四季内容

原则：每个季节取"最上镜"的一刻；不同时间开的花可以同时出现。本节只写各季的通用取向；具体景物与位置按图写在各图文档（清水河见 MAP-QSH-INDEX 下各区的 SEASONS 文档与 MAP-QSH-VEGETATION）和 WLD-VEGETATION。

| 季 | 植被与地面 | 水与天空 | 生活痕迹 |
| --- | --- | --- | --- |
| 春 | 花带与新绿连成片，地面一层薄花瓣，草坪嫩绿 | 雨后清透，淡积云；早晨日照金山 | 车筐里落着花瓣 |
| 夏 | 水生花满塘，落叶树浓绿，树荫里的光斑 | 水色偏绿；高耸的积雨云，傍晚火烧云；雪山最清楚；夜里萤火虫和银河 | 毕业季：阳台手写横幅、楼下一排行李箱；树干上的蝉蜕 |
| 秋 | 落日金光斜铺全校，秋色树（金黄、锈红、正红），落叶铺满；金色以落日光为主 | 冷空气过后的通透天，高积云，满月 | 节庆小物（可选） |
| 冬 | 落叶树只剩裸枝，枝头一线雪，雪中露金，蜡梅；草坪大半盖雪 | 湖面不结冰，泡沫线变宽变白；夜雪；雪后初晴的正午；薰衣草灰的雪意阴天 | 雪人；雪地上的脚印和单车车辙（不画人）；考试周图书馆通宵亮灯 |

**外围**走同一套着色器、调色板和雾，几何不随世界状态变；农田与绿地的四季、外围积雪见 WLD-OUTSKIRTS-BAND §3.2。

**下雪**由天气决定，不按钟点（SYS-WEATHER §1、SYS-WEATHER-PROCESS §1.3），积雪的取法见 SYS-WEATHER §6；英雄帧里的雪靠钉住天气保证。

**季节变化的原则**（做法归 ENG-PERF-LIGHT §1，植物规则归 WLD-VEGETATION）：

- 全部是连续参数加阈值生长，不换模型、不重建格子、不切特化开关。
- **逐株错相**：每棵树按稳定种子取一个小的季节偏移，同一季里不整齐划一。
- **叶量与开花**：叶量让插片缩放、落掉的插片换成枝条笔触，冬季裸枝剪影不需要新几何；开花就是插片换成季相色（樱花、蓝花楹、蜡梅、玉兰同理）；阴影自动跟着叶量和风。
- **地面覆盖**（落叶、花瓣、积雪）用地面遮罩加噪声阈值长出来，季节推进时色块从树根处长出；屋面、树冠按法线朝上的程度先白；外围的取法见 WLD-OUTSKIRTS-BAND §3.2。
- **荷花**四种状态：小荷钱、满塘、残荷、枯梗。
- **季节氛围粒子**：春樱瓣、秋落叶、冬雪团、夏夜萤火虫的节奏和出没见 SYS-MOTION-ENV §2.1、§6。
- **风量**随季节、昼夜、天气变化，系数见 SYS-MOTION-ENV §6.4。
- **雪山**可见度和雪线是季节参数，晴天有下限；夜里画成月光下的银灰（WLD-OUTSKIRTS-DIORAMA §6）。

## 3 灯光与生活痕迹的时刻表

按画面需要设计，不照搬真实作息。时刻表按图放在 `game/data/maps/<地图>/lighting-schedule.json`（通道、曲线、灯组阈值、窗灯上限以它为准），切图时换成新图的；外围和开放室内都接进这些通道，不新增灯光通道。

**有效太阳高度**：凡按太阳高度求值的曲线（窗灯总体、路灯、售货机屏幕等）一律用 h_eff = h − 6° × 阴度 − 4° × 降水，所以阴雨天灯提前亮、推迟熄；晴天 h_eff = h。主光交接、退光线和界面主题仍按真实高度 h。

**设计意图**（数值见 JSON）：

- **默认状态的黄昏是"初灯"**：17:22–17:40 全校窗灯从约两成亮到约七成，17:30 约四成；一级区的主路灯、主轴大道和广场外圈这一**初灯组**在太阳 8° 到 4° 之间逐盏亮起，17:30 约六成，霞光和灯光同框；其余路灯和景观灯入夜才亮齐；每盏刚亮时偏暗，随天色变暗升到满；日出时按相反顺序熄。
- **窗灯**：每扇窗按哈希错开，单扇窗约 0.3 s 内亮起，快进时也不闪烁；白天有下限（阴、雨）。
- **各类楼的亮灯性格**：图书馆类的公共学习楼全校第一个亮灯、一层层熄灭，深夜只留一两处灯作为灯岛；宿舍成片亮但留出疏密，深夜熄成零星亮点；教学楼整齐亮起、夜里熄；科研楼通宵低亮；食堂清晨先亮；球场、场馆晚间亮；店招营业时段亮、深夜减半。具体时刻以 `lighting-schedule.json` 为准，清水河各楼的设定见各区的 SEASONS 文档。
- **景观灯**：后半夜熄一半；雕像投光整组关；冬夜路灯光斑放大，让雪地上的光斑不连成一条。
- **室内与外围**：灯罩自发光跟随所属通道，白天灯灭则不发光；开放入口门口灯属初灯组、整夜亮，作为"能进"的信号；开放楼公共区夜里留安全出口绿灯与应急灯；外围路灯比校内主轴晚亮，"初灯"先从校内亮起。
- **可复现**：亮灭完全由哈希决定，同一钟点、季节、天气向量下结果相同，与怎样到达无关。

**生活痕迹**：

- 白天：单车被骑空，聚到教学楼前；晴天一半阳台晒被子，冬季雪后初晴全楼晒（WLD-LIFE-FAUNA §2）。夜里晾晒减少，车场重新停满。
- 雨天：晾晒收起，门口撑开的伞，"小心地滑"黄牌。
- 黄昏：2–3 只一组的乌鸦静止停在楼顶或架空线上；夜里和雨雪天不出现（WLD-LIFE-FAUNA §1）。
- 痕迹一律是干净的新样子：晾晒整齐，单车不锈，海报不卷边。
