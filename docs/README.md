# CORE-INDEX · 《电光年华》开发总纲

> **范围**：本文是全项目唯一的顶层，只放每次开发都要掌握的全局：核心准则与信息地图。
> **不在本文**：任何具体内容（作品取舍、规则细则、设计、数值、清单）都在下层文档，按 §1 按需读；作品与范围在 CORE-SCOPE；不变量全文在 CORE-INVARIANTS；角色入口在 WF-ENTRY。
> **查阅**：先读 §0；信息在哪、仓库目录、文档地图看 §1

## 0 核心准则

**这是什么**：《电光年华》，校园题材的独立 RPG，本阶段只做观光规则集；Godot 4.7.2 .NET（C#），只做 PC；作者的个人作品，处在 demo 阶段（CORE-SCOPE）。

「做成什么样」各条与 INV（CORE-INVARIANTS）、作者明确禁止的事是硬约束，其余是默认做法、按判断用；冲突时依次听作者、硬约束、主线不中断。

**怎么干活**
1. **全局在顶层，细节按需读**：本文只给全局；先在 §1 查到信息在哪，文档按标题找，读它的 §0 与接入要点，要细节时 grep `docs/SECTIONS.md`，按行号只读那一节，不整份通读（WF-DOC §1）。
2. **实现优先，精度按 demo 阶段定**：精度、样本量、测试和验收按 demo 阶段定，看不出差别的不追，数值按数量级判断，不预设包体与内容规模上限；不降的是画面质量和架构底座；先接进主线跑通，bug 按严重程度修，不挡核心体验和架构的先提交后修，修不收敛就停（WF-RULE §8、§14、§15）。
3. **不过度工程化，不重写现成的**：引擎内建或成熟开源库能做的就用它；只写本单要的，做完就停，多出的想法写在回报末尾；不为假想的扩展加抽象、配置和开关，不写校验和与 proof 报告，不自加门禁和测试脚手架；一次性产物用完就删（WF-RULE §1、§13，ENG-CODE §3）。
4. **测试最小，快检过就推**：默认只跑快检，碰启动、行走、存档才加几分钟内的核心专项；过了就推，没有新改动或新失败不复测；专项失败的阻断项先修、其余登记不挡推送；测试只守契约、主线和回归，测行为不钉实现；测量、验证都在后台跑，不操作作者桌面（WF-RULE §4、§9，ENG-CODE §6）。
5. **改设计必清旧、修问题找根因、查全局**：设计和修问题都先参考相关同类主流游戏的做法；遇到问题先查别处有没有同样的写法、数据或机制，有就同批修齐，不只修眼前一处；工程问题在架构的根上改，不加特例、兜底、开关或绕过；改设计同一批迁完所有使用方，删掉旧代码、旧测试和旧文档，不留兼容层（WF-RULE §10、§14）。
6. **直接改主线，统一编译**：在 `main` 上只改本包独占目录的文件；施工子代理只写不编译，指挥统一编译、修错、快检后提交推送；回滚用 `git revert`；共享文件和契约写申请（WF-RULE §7，WF-FLOW §3.1，WF-BUILD §1）。
7. **排活先判轻重，不向作者出选项**：要拍板的写给主会话；新需求先判插队、等当前这批还是按轻重排，改到在做或排着的活就同批改它们的描述；不预判时间，定期的事按开发节点触发、不按日历；改了高层信息当场更新观察台（WF-STATUS §2，WF-RULE §3，WF-COMMS §6）。
8. **两个指挥怎么协作**：主会话（Claude）管画面、文档与评审，Codex 主线（GPT）管工程，各开子代理；活和状态只看施工队列，给对方发话写来信（位置见 §1），一条一件，标【需定】【待审】【知会】，5 行内，再发一句提醒（WF-COMMS §4，WF-ROLE）。

**怎么写文档**
9. **一份权威，同批改齐**：同一信息只在一处，别处给指向；改一条规则先按文档索引（文档地图 → 主文档 §0 → SECTIONS）查出讲同一主题的文档，同批改到一致；文档冲突按 WF-DOC §6 判（WF-DOC §4.2，WF-RULE §12）。
10. **写给旗舰大模型**：读者按字面执行：写规则本身、适用范围和做到哪算完；默认做法加一句理由，例外至多一个出口；"必须""禁止"只给硬约束；不写铺垫、成堆的例子和会过期的日期、进度（WF-DOC §4.2）。
11. **分层放、写精简**：文档只写结构、规则、设计目标和导向，各类信息按 §1 的位置放；顶层只放全局，具体内容下放；指针一层到底写到"编码 §小节"；能一句说清不写一段；超了上限挑整份里最该压的压，再压会丢信息就稍放宽上限，仍超按子主题拆；新内容先找家（WF-DOC §1、§4、§5）。
12. **名字一看就懂**：改名、改结构全量改到最新，不留旧名（WF-DOC §3）。

**怎么写代码**
13. **结构**：依赖只朝下，生成层是纯 .NET；规则值与数据各一份：规则数引用定义处，坐标、ID、尺寸写进按图数据，不写字面量；先复用再新写；不留死代码；文件过约 600 行就拆（ENG-ARCH §2，ENG-CODE §2、§3）。
14. **边界与确定性**：显示、材质、声音各经自己的服务，材质只经 `ToonSpec` 和白名单着色器；随机只用 `Rng`、`StableHash`，遍历字典先排序，同机同输入同输出；改契约同批迁完所有使用方；Godot API 先查 `docs/godot-api/signatures.txt`（ENG-ARCH §2、§3）。
15. **失败就报错，构建期做完**：不吞异常，不写"拿不到就用旧值"的兜底；构建期能算好的（编译、生成、判鲜）不放到运行时，启动只读现成结果；碰渲染、逐帧代码、烘焙、存档先读 ENG-BUDGET-RULES 的接入要点（ENG-CODE §4，ENG-ARCH §4）。

**做成什么样**
16. **画风**：清透干净的三渲二日式动画背景，任何时刻、季节、天气都要好看；碰画面的推送由主会话跑固定机位截图看一眼，审美以作者为准（INV-5、INV-8，ART-STYLE）。
17. **精度底线与禁区**：处处比例对、有倒角收边，外观全新不做旧；不出现人物；场景里的字用简体中文；日式元素只限日常街景（INV-4、INV-6、INV-7、INV-11）。
18. **不是地图复刻**：格局大体对，其余可风格化；地图只改项目的世界文件并写明理由，不从 OSM 等外部地图取数据（INV-9，D-252）。
19. **世界规则**：时间只向前，几何不随时季天气变，只有旁观与行走两种模式，3D 画面里不叠标签（INV-2、INV-3、INV-8）。

### 0.1 接入要点

- **派单、写简报**：不抄核心准则，写"核心准则见 §0"。
- **改一条核心准则**：先改它指向的细则，再改这里的一句；引用核心准则写标题，不写条号。
- **往本文加内容**：只加每次开发都要的全局；具体内容写进下层，这里至多列一个标题或一句话加指向（WF-DOC §1）。
- **新增主文档、改仓库顶层目录或某类信息的存放位置**：同批改 §1（WF-DOC §7）。

## 1 信息地图

每类信息只在一处；先在这里查到位置，再按需读。

**信息在哪**：
- **钩子注入**：开工时送来核心准则、本节和自己的入口卡（WF-ENTRY）；改到某个路径时送来管它的文档的接入要点；没送到就手动读。
- **规则、设计目标与导向**：`docs/`，按下面的文档地图找，小节用 `docs/SECTIONS.md` 定位。
- **实现**：代码，签名与契约以源码为准。
- **数值、坐标、ID 与清单**：数据文件（按图数据在 `game/data/`）。
- **为什么这样定、是否生效**：CORE-DECISIONS，按 D 编号查。
- **要做的活和状态**：施工队列 `.collab/status/施工状态.md`。
- **双方的沟通**：来信在 `.collab/notes/<收件方>/`；任务单、请求、调研与交回也在 `.collab/`（WF-COMMS §1）。
- **过程与历史**：git。
- **作者看的全局**：观察台 `dashboard/`（WF-COMMS §6）。

**仓库目录**：
- `game/`：Godot 工程，C# 代码、着色器、契约与按图数据。
- `pipeline/`：离线生成按图数据的管线。
- `scripts/`：构建、门禁、截图、文档索引与清理脚本。
- `docs/`：规则与设计文档。
- `.collab/`：协作目录（队列、来信、任务单、调研、协作工具），不进 git。
- `dashboard/`：作者观察台。
- `tools/`：锁定的 Godot 版本号。
- `output/`、`build/`：构建、测试、截图、缓存与导出产物，不进 git，可删可重建。

**文档地图**：只列主文档的编码与标题，子文档列在各主文档的 §0 里；看标题判断要不要读。

**协作**（`workflow/`）：WF-ENTRY 角色入口卡；WF-RULE 全员守则；WF-BUILD 施工边界；WF-FLOW 开发流程；WF-COMMS 交接与通信；WF-ROLE 参与者与分工；WF-MODEL 模型、子代理与额度；WF-STATUS 施工状态与队列；WF-DOC 文档写法。

**工程**（`engineering/`、`ops/`、`tools/`）：ENG-ARCH 工程架构；ENG-CODE 代码结构准则；ENG-GATES 验收与门禁；ENG-BUDGET 性能预算；ENG-PERF 性能工程；OPS-RELEASE 发布与交付；TOOL-PREVIEW 内容预览。

**计划与登记**（`core/`、`engineering/`）：CORE-SCOPE 作品与范围；CORE-INVARIANTS 全局不变量；ENG-WP 工作包；ENG-ROADMAP 扩展路线；CORE-CONVENTIONS 约定；CORE-DECISIONS 决策登记；CORE-GLOSSARY 术语表。

**画面**（`art/`）：ART-STYLE 风格基础；ART-FIDELITY 视觉精度；ART-MODELING 风格化造型；ART-SKYLIGHT 天空、光照与大气；ART-AMBIENCE 日式日常街景；ART-RENOVATION 老楼翻新。

**系统与界面**（`systems/`、`ui/`）：SYS-VIEW 观察模式与旁观漫游；SYS-WALK 行走模式；SYS-TIME 时间与季节；SYS-WEATHER 天气；SYS-GRAPHICS 画面设置；SYS-MOTION 动态与事件；SYS-SAVE 存档；SYS-MAPS 多地图；SYS-ATLAS 平面地图与传送；SYS-TITLE 开始页与启动；SYS-AUDIO 音频；UI-NAV 界面与操作；UI-VISUAL 界面视觉语言。

**世界规则**（`world/`，不分图）：WLD-TERRAIN 地形；WLD-WATER 水体；WLD-VEGETATION 植被；WLD-INTERIORS 室内；WLD-OUTSKIRTS 边界与外围；WLD-DIORAMA 箱庭截面与远景；WLD-LIFE 动物、生活痕迹与街道家具。
