# PLAN-WP · 工作包与阶段

> **范围**：本文规定工作包的划分原则（WP-00（契约、桩与拆除）至 WP-55（共享单车运行与取还））、阶段与主线闸口；每包一行的包表、插入项、候选包、子包拆法在 PLAN-WP-LIST。
> **不在本文**：独占目录以 `ownership.json` 为准；文档的主责与贡献以各文档文件头的 `owners`、`contributors` 为准；施工状态见 WF-STATUS 与 `.collab/status/`；派工简报模板见 WF-MODEL；契约与分批冻结（ENG-ARCH §3）；引擎与框架版本、插件清单（ENG-RELEASE §1、§7）；预算核账（ENG-BUDGET §3）；开放室内清单的审批（WLD-INTERIORS-ACCESS §4）；`map.json` 字段的增改（SYS-MAPS §2）；音频素材与版本库（SYS-AUDIO §8）；门禁见 ENG-GATES。
> **查阅**：先读 §0；阶段与主线闸口看 §1；各包一行、插入项、候选包与子包拆法看 PLAN-WP-LIST；派工的一方读全文，子代理只读本包在 PLAN-WP-LIST §1 的那一行和派工简报

## 0 结论

子文档：**PLAN-WP-LIST 工作包一览与子包拆法**，放每包一行的包表（规格文档、依赖、归属侧、主线版）、插入项、候选包和子包拆法；开工时看自己那一行、拆子包时读它。

1. 包从 WP-00 编到 WP-55；每包一行：规格文档、依赖、归属侧、主线版交什么。独占目录看 `ownership.json`，状态看 WF-STATUS；大包可再拆，子包共用原包的目录和程序集（PLAN-WP-LIST §2）。
2. 主线版先行：闸口之前每包按 PLAN-WP-LIST §1 的"主线版"列交付，后置细节留到闸口之后；闸口以主线冒烟（G5）通过为准（§1，WF-RULE §8）。
3. 建模完成度是主线（D-183）：派工先做建筑、部件、分区、植被、街道家具、箱庭与室内包，再做游泳、生物、角色本体等系统新功能，不等 WP-02（格子分级、烘焙与流式加载）、按桩开工。
4. 计划域只写划分与阶段；契约冻结、版本与插件、开放室内清单、预算核账这些工程维护事项各归工程与世界域的文档（见上方"不在本文"）。

### 0.1 接入要点

- **主线闸口之前**：只交 PLAN-WP-LIST §1 本包"主线版"列写的东西，细节留到闸口之后（PLAN-WP-LIST §1）
- **闸口之后排细节**：按施工队列里本包的行做（PLAN-WP-LIST §1.2）；PLAN-WP-LIST §1.3 的候选范围在定下归属与编号之前不开工

## 1 阶段与闸口

| 阶段 | 内容 | 闸口 |
| --- | --- | --- |
| 主线闸口 | 主线打通（PRD-SCOPE §3）：各包主线版全部接通；从扉页、开始页、新游戏或继续，到飞行与行走、切换时间季节天气、小地图与传送、存档退出再继续，完整走一遍；地形、道路、水体、楼宇体量成形，主要地标认得出；默认状态风格方向对、无明显卡顿 | 主线冒烟（G5）通过；随后第一次集中测试 |
| 闸口之后 | 各区包按预设同时做细节，不设先后评审的串行门；各区的四季昼夜与行走附属文档主线之后；精选室内按 I1、I2、I3 顺序 | 风格负责人看图横向比对 |
| 收尾 | WP-26（动态与偶发事件）、WP-39（夜景灯光与时刻表）接上所有通道；做集中测试（ENG-GATES §1）；主会话统一调优，按实测核账 GPU 与主线程余量 | ENG-GATES-VETO §2 全部清单通过 |

测试节奏见 ENG-GATES §1：每包先过快检再推送，碰启动、行走、存档时加核心专项，其余门禁在集中测试时全量跑，不跟着阶段或时间走。

**阶段名**（阶段号只有一位数字，与点位 P00–P23 不是一回事）：P0 是骨架与原型阶段，P1 到主线闸口，P2 是闸口之后，P3 是收尾；文档里仍标 P0 的待验证项以实测定值，验证前用文中的初值。
